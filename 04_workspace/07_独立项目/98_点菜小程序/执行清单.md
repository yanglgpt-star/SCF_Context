> **目标**：把 dishes/ 目录下 364 个 .md 文件解析成结构化 JSON，摸清数据全貌

### □ 1.1 编写数据清洗脚本

创建文件 `scripts/parse_dishes.js`，用 Node.js 实现以下功能：

#### 1.1.1 遍历目录结构

```javascript
// 需要实现的关键逻辑：
// 1. 遍历 dishes/ 下所有子目录（aquatic, breakfast, condiment, dessert, drink, meat_dish, semi-finished, soup, staple, vegetable_dish）
// 2. 对每个条目判断是文件还是目录：
//    - {category}/{name}.md           → 单文件模式
//    - {category}/{name}/index.md     → 目录模式（少数情况）
//    - {category}/{name}/{name}.md    → 目录中有同名 md
// 3. 如果遇到子目录，扫描其中的图片文件（jpg/png/webp/jpeg/gif）
```

#### 1.1.2 解析 Markdown 提取字段

```javascript
// 用正则提取以下字段：
// - name:       # 标题（去掉"的做法"后缀）
// - difficulty: /预估烹饪难度：(★+)/  → 转为 1-5 数字
// - calories:   /预估卡路里：(\d+)/  → 数字
// - ingredients: 从「## 必备原料和工具」到「## 计算」之间的列表项 → 数组
// - steps:      从「## 操作」到「## 附加内容」之间的步骤文本 → 数组
// - tips:       从「## 附加内容」到末尾的文本（去掉尾部版权声明）
// - description: # 标题和 ## 必备原料之间的第一段描述文本
```

#### 1.1.3 判断荤素（is_meat）

```javascript
const MEAT_CATEGORIES = ['meat_dish', 'aquatic'];
// meat_dish 和 aquatic → 直接标记为荤菜 true
// vegetable_dish → false
// staple、soup、breakfast → 根据食材关键词进一步判断
//   包含"肉"、"鸡"、"鸭"、"鱼"、"虾"、"蟹"、"猪"、"牛"、"羊"、"蛋" → true
//   否则 → false
```

#### 1.1.4 输出文件

```javascript
// 输出到 scripts/dishes_data.json
// 格式：[{ name, category, difficulty, calories, is_meat, ingredients, steps, tips, description, images }]
```

## Phase 2：标签补全（Step 2 — 最重要的体力活）

> **目标**：为每道菜补充业务标签（餐次、受众、口味等）

### □ 2.1 AI 批量标注（用你帮我完成）

我会帮你写一段脚本，根据每道菜的以下信息自动推断标签：

- 菜名
- 分类目录（category）
- 食材清单（ingredients）
- 描述文本（description）

推断内容：

| 标签字段 | 可选值 | 判断依据 |
| :--- | :--- | :--- |
| `meal_type` | 早餐, 午餐, 晚餐, 下午茶 | 早餐类 → 早餐；含"咖啡/奶茶/甜点" → 下午茶；默认 → 午餐/晚餐 |
| `target` | 大人, 小孩, 全家 | 含"辣/椒/酒" → 大人；含"蒸蛋/豆腐/软烂" → 小孩；默认 → 全家 |
| `taste` | 清淡, 微辣, 重辣, 酸甜, 香辣, 五香, 咖喱, ... | 根据菜名和食材关键词 |
| `cook_time` | 数字（分钟） | 根据难度星级估算：★→10min, ★★→20min, ★★★→40min, ★★★★→60min, ★★★★★→90min |
| `tags` | 快手菜, 下饭菜, 减脂, 硬菜, 家常, 烤箱菜, ... | 根据关键词匹配 |
