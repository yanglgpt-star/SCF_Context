# 磁力贴搭建内容工厂 — 整体方案

> 版本：v1.0　|　日期：2026-09-17
> 定位：亲子（3-8 岁儿童 + 家长）
> 形态：一期平面拼贴，二期扩展立体搭建
> 形状体系：市面标准通用磁力片套装

---

## 一、结论先行

在展开细节之前，先把三个最关键的判断放在前面。这三点决定了整套方案的技术路线。

### 判断 1：第 2 步「AI 模拟能不能拼成功」不能交给大模型

这是整个流程里最容易踩的坑。你原本的设想是「用 AI 把草稿图用磁力贴形状模拟一遍，看能不能成功」——直觉上这是让 AI 看图然后画出来。

但这里有一个根本区别：

| | 生成问题 | 求解问题 |
|---|---|---|
| 特征 | 答案不唯一，合理即可 | 答案唯一可验证，对就是对、错就是错 |
| 适合谁做 | 大模型 | 确定性算法（求解器） |
| 你的第 2 步 | | ✅ 属于这一类 |

大模型画出来的拼贴图，**看起来像**但经不起推敲：边对不齐、有缝隙、用了你手里没有的形状、数量超出库存。你拿它去搭建实物时才发现搭不出来——返工成本全在线下。

正确做法是：**用几何求解器给出确定答案**（能拼 / 不能拼 / 能拼出 87% 相似度），大模型只负责它擅长的部分——理解草稿画的是什么、给简化建议、写文案。详见 [02-可拼贴性求解引擎.md](02-可拼贴性求解引擎.md)。

### 判断 2：你的流程缺了最关键的一环——「步骤分解」

看你要的最终产物：**搭建流程图 + 搭建视频**。

但你的 6 步流程里，**没有任何一步在产出「分步搭建序列」**。第 4 步的「填写实际的搭建图」是一个静态的成品图，不是「第 1 步放什么、第 2 步放什么」。

没有有序的步骤序列，就没有流程图，也没有视频。这是当前流程里最大的缺口，必须补上，而且要补在**求解阶段就自动产出**（而不是等实物搭完再人工回忆）。

### 判断 3：一份「步骤数据」，三种输出

流程图、视频、小程序演示，三者不是三份工作，而是**同一份结构化步骤数据的三种渲染**。

```
                     ┌─→ 静态流程图（SVG 信息图）
结构化步骤数据 ───────┼─→ 搭建视频（Remotion 逐帧渲染）
  (JSON)             └─→ 小程序交互演示
```

这是整个方案的架构支柱。只要步骤数据建模对了，三种产物是自动的、批量的、可复用的。

## 二、原流程诊断

### 2.1 你给的流程

```
1. 灵感/主题 → 生成草稿图
2. AI 用磁力贴形状模拟草稿图，验证能否成功
3. 手动搭建实物 → 拍照
4. 填写实际搭建图 + 各形状数量
5. 放入材料库
6. 对照实物，检查草稿图和模拟搭建的完善
```

### 2.2 六个缺口

| # | 缺口 | 后果 | 补充方案 |
|---|---|---|---|
| 1 | **缺零件体系建模** | 第 2 步的「能否成功」没有判定基准——你手里有哪些形状、各几片？ | P0 阶段：形状库 + 套装库存建模 |
| 2 | **缺步骤分解** | 产不出流程图和视频，最终目标直接落空 | P2 求解时自动产出有序步骤序列 |
| 3 | **校验位置太靠后** | 草稿生成 → 手工校验 → 返工，循环成本高 | 校验前移：在「约束下生成」，而不是「生成后校验」 |
| 4 | **缺难度与年龄分级** | 亲子定位下，3 岁和 8 岁能搭的东西完全不同 | P2 输出难度评分，P1 选题按年龄分档 |
| 5 | **缺发布与数据回流** | 发布是终点不是闭环，做久了会不知道拍什么 | P6：发布数据回流到 P1 选题库 |
| 6 | **缺版本管理** | 同一作品有草稿/模拟/实物多版本，容易混乱 | 资产库以「作品」为聚合根，版本挂在下面 |

### 2.3 最该改的一处

第 3 步「手动搭建实物」和第 2 步之间是**断裂**的。

理想状态下，第 3 步应该是**照着方案搭**（方案已经告诉你每步放哪片、什么颜色），而不是**重新摸索着搭**。你现在的人工搭建过程其实是在替求解器做它该做的事。

改过来之后，第 3 步的价值就变成了：**验证求解器 + 采集真实素材（照片/视频）+ 记录实际偏差**，而不是「试错」。

## 四、各阶段设计要点

### P0　零件体系建模（最容易跳过，但最不能跳过）

没有这一步，后面所有「可行/不可行」的判断都是空谈。

需要固化三样东西：

| 对象 | 内容 | 示例 |
|---|---|---|
| **形状库** | 形状 ID、几何参数（边长、角度、圆弧半径）、颜色可选值 | `SQ-A`（正方形，边长 7.5cm）、`TRI-E-A`（等边三角形，边长 7.5cm） |
| **套装** | 一个套装包含哪些形状、各几片 | 「基础 100 片装」= 正方形 ×24、等边三角 ×20、直角三角 ×16、长方形 ×8、扇形 ×4 |
| **坐标系** | 拼贴的离散化基底 | 以正方形边长为单位 `a`，建立三角网格（详见 02 文档） |

**一条关键几何约束先说在前面**：标准磁力片里，正方形的 90° 角和等边三角形的 60° 角**在同一平面内无法无缝共边拼贴**。这意味着平面拼贴要分成两个「角度族」处理——平面作品主要用**直角系**（正方形 / 等腰直角三角形 / 长方形 / 扇形），等边三角形系主要留给立体搭建。这个问题在 [02-可拼贴性求解引擎.md](02-可拼贴性求解引擎.md) 里有完整说明。

### P1　选题与草稿

**选题库**是内容的源头，按亲子定位分档：

| 档位 | 年龄 | 题材 | 片数规模 |
|---|---|---|---|
| 启蒙 | 3-4 岁 | 几何形状、简单动物（鱼、鸟）、数字 | 5-12 片 |
| 进阶 | 5-6 岁 | 字母、交通工具、花朵、房子 | 12-30 片 |
| 挑战 | 7-8 岁 | 复杂动物、场景、对称图案 | 30-60 片 |

**草稿生成的关键改动**：不要「随便画一张然后看能不能拼」，而是**在提示词里就带上可拼性约束**：

- 造型简单、大色块、少细节、边界清晰
- 强对称优先（对称造型天然易拼）
- 正视角、平面、无透视、无阴影
- 主体居中、背景干净

这样能把后续求解的成功率从「碰运气」提到「大概率一次过」。

### P2　可拼性求解（关键技术环节）

这一步是整个项目的技术心脏，单独成文：[02-可拼贴性求解引擎.md](02-可拼贴性求解引擎.md)

输出物清单：

| 输出 | 用途 |
|---|---|
| 拼贴方案（每片的形状/位置/旋转/颜色） | 供渲染和搭建 |
| **有序步骤序列** | 流程图和视频的原料 |
| 形状用量清单 | 备料、库存核对 |
| 覆盖率 / 相似度评分 | 「能不能成功」的量化答案 |
| 难度评分（片数、颜色数、对称性） | 选题档位匹配 |
| 拼贴图（SVG/PNG） | 对照、封面、素材 |

### P3　实物搭建与采集

改为「照方案搭」之后，这一步的工作变成标准化采集：

- **每一步拍一张**（跟步骤序列一一对应）——这是视频素材的基础
- **整段过程录像**（固定机位 timelapse）——备用素材
- **成品多角度照片**（正面 / 45 度 / 俯视）——封面和详情页
- **实际用量回填** ——如果和方案不符，记录差异原因（缺件？颜色替换？）

> 采集规范建议一次定死：画布尺寸、机位高度、光源、背景色。后期批量出片时一致性远比单张精美重要。

### P4　资产入库与差分复盘

「材料库」不是一个文件夹，而是一个**可检索、可复用、可二次创作的结构化资产库**。数据模型见 [03-资产库与内容管线.md](03-资产库与内容管线.md)。

差分复盘要做的事：用视觉模型对比「模拟拼贴图」和「实物照片」，输出差异报告——哪几片位置不同、哪些颜色被替换、整体相似度多少。这些偏差反过来修正求解器参数（比如某个形状的实际尺寸和标称不符）。

### P5　内容生产

三种产物从同一份步骤数据渲染：

| 产物 | 技术 | 说明 |
|---|---|---|
| 静态流程图 | SVG 渲染 | 每步一张带标注图，拼成一张信息图；也可做成轮播图 |
| 搭建视频 | Remotion（React → MP4） | 逐帧精确控制，可批量渲染，可参数化时长/节奏 |
| 小程序演示 | 同 SVG 数据 + 交互 | 可暂停、可回退、可点击某片 |

**重要建议：视频不要用 AI 视频生成器做。**搭建过程是精确的几何变换，AI 视频生成器会变形、会幻觉出不存在的零件、无法保证跨帧一致。用程序化渲染，100% 准确、可复现、可批量出 100 条。详见 03 文档。

### P6　发布与数据回流

| 平台 | 路径 | 备注 |
|---|---|---|
| 小程序 | 微信云开发 | 与已有项目同一技术栈，可复用 |
| 抖音 / 小红书 | 一期人工发布 + 素材规格规范化 | 个人主体无开放发布 API，不要在这上面提前投入 |
| 数据回流 | 手动/半自动记录播放、点赞、收藏、评论关键词 | 定期回看，反哺 P1 选题库 |

## 五、工具与大模型选型

> 模型迭代很快，下表给到的是**模型家族与选型逻辑**。实际接入时按当时最新版本确认一次。

### 5.1 图像生成（草稿图）

| 方案 | 优势 | 建议 |
|---|---|---|
| **即梦 Seedream**（字节） | 中文语义理解好，和抖音生态同源 | **首选**：草稿生成主力 |
| **Nano Banana Pro**（Google Gemini 图像） | 图像编辑、局部改图能力极强 | **首选**：草稿返修（「把翅膀改成方形」这类迭代） |
| 通义万相 / 混元生图 | 国内可用，稳定 | 备选 |
| Midjourney | 出图质量高 | 备选，但对「可拼贴」约束遵循一般 |

### 5.2 视觉理解（草稿解析 / 实物对比 / 偏差检测）

| 方案 | 用途 |
|---|---|
| **Claude Sonnet 5 / Opus 5** | 结构化输出最稳：图片 → JSON（形状、轮廓、简化建议）。做 P2 的热启动和 P4 差分报告 |
| **Qwen3-VL**（阿里） | 国内部署、成本低，可做批量差分检测 |
| Gemini 系列 | 备选，视觉理解强 |

**分工边界**：VLM 负责「看懂」和「给建议」，求解器负责「算准」。VLM 输出永远只作为参考/热启动，最终结果以求解器为准。

### 5.3 可拼性求解（核心，需自研）

| 组件 | 选型 |
|---|---|
| 轮廓处理 | OpenCV（轮廓提取）+ Shapely（多边形运算） |
| 精确覆盖求解 | 自研 DLX（Dancing Links / Algorithm X），规模小、纯代码可控 |
| 带约束优化 | Google OR-Tools CP-SAT（库存约束 + 最少片数/最少形状种类） |
| 语言建议 | Python 做算法侧，产出 JSON；前端/渲染侧用 TypeScript |

### 5.4 渲染与视频

| 环节 | 选型 | 理由 |
|---|---|---|
| 拼贴图 / 流程图 | 自研 SVG 渲染器 | 磁力片要精确画，现成图表工具做不到 |
| 视频 | **Remotion** | React 写视频，逐帧精确、可参数化、可批量 |
| 备选视频方案 | Manim（Python）/ Blender + Python | 动画更华丽，但上手成本高 |
| 配音 | 火山引擎 TTS / MiniMax / ElevenLabs | 亲子内容建议真人感强的音色 |
| 字幕 | 直接用脚本文本 / Whisper 对齐 | — |

**不要用**：Sora、可灵等 AI 视频生成器做主流程。可作为片头氛围空镜的补充。

### 5.5 存储与发布

| 环节 | 选型 |
|---|---|
| 资产库（一期） | 本地文件 + Git（JSON + 图片/SVG），零成本、可版本管理 |
| 资产库（二期） | 微信云开发 或 Supabase，支持检索与协作 |
| 小程序 | 微信云开发（与 99_益智游戏 项目同栈，能力可复用） |
| 发布 | 一期人工；素材按平台规格批量导出 |

## 七、路线图

### 一期：跑通单条流水线（目标：能稳定产出 1 个可发布视频）

| 里程碑 | 交付 | 验收标准 |
|---|---|---|
| M1 零件建模 | 形状库 + 库存表 | 标准套装的 6 种形状参数齐全 |
| M2 求解器 | 输入轮廓 → 输出拼贴方案 | 对 20 个给定轮廓，求解成功率 ≥ 70% |
| M3 渲染器 | SVG 拼贴图 + 分步图 | 渲染结果与求解数据 100% 一致 |
| M4 视频产出 | Remotion 渲染一条完整搭建视频 | 时长 30-60 秒，含配音字幕 |
| M5 端到端 | 主题 → 草稿 → 求解 → 搭建 → 入库 → 出片 | 全流程走通 3 次，人工介入点清晰 |

### 二期：提效与扩展

- 立体搭建求解（引入物理稳定性判定）
- 批量化：一次选题生成 N 个草稿、批量求解、排队渲染
- 资产库上线检索与标签体系
- 小程序 Demo 上线

### 三期：内容矩阵与数据驱动

- 发布数据回流 → 选题评分模型
- 模板化选题生成（哪些题材数据好，自动扩产）
- 多平台一键分发（在合规前提下）

## 八、风险与待确认项

| # | 风险/待确认 | 影响 | 应对 |
|---|---|---|---|
| 1 | 实测形状尺寸与标称不符 | 求解出的方案搭不上 | P0 阶段用卡尺实测，尺寸进形状库 |
| 2 | 曲线造型（圆弧、动物轮廓）无法纯几何覆盖 | 求解成功率低 | 引入「相似度」而非「必须精确」；造型选型偏方正 |
| 3 | 颜色不匹配 | 出片效果差 | 求解时把颜色作为软约束，优先匹库存颜色 |
| 4 | 立体搭建的稳定性判定 | 二期主要难点 | 二期单独设计，不在本期范围 |
| 5 | 平台发布政策变化 | 分发受限 | 一期不依赖任何非官方 API |
| 6 | 步骤数据的 schema 反复改 | 返工 | 先定 v1 schema，宁简勿全，渲染层与数据层解耦 |

### 需要你确认的三件事

1. **实测形状清单**：你手上的套装具体有哪几种形状、各多少片？（P0 的输入，我按标准套装给了默认值，需要你核对）
2. **出片节奏**：一期目标是一周几条？这决定是否要在一期就上批量渲染。
3. **小程序的角色**：是「作品展示 + 步骤教学」，还是「家长下单买套装」？定位不同，二期优先级不同。
