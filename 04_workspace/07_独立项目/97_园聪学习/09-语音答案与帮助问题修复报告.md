# 园聪学习语音、答案与帮助问题修复报告

> 修复版本：MVP v0.2.1  
> 日期：2026-08-23

## 1. 问题与根因

| 问题 | 根因 | 修复结果 |
|---|---|---|
| 读题声音僵硬 | 一道题被拆成 7 个很短的数字/词语片段，语速和停顿不自然 | 改为 3 段完整短句，语速调慢到 155，加入儿童易理解的自然停顿和“想一想”语气 |
| 只读前半段，后面无声 | 同一个音频对象在 `onEnded` 回调中立即切换 `src`，开发者工具偶发未完成解码；重播时旧回调也可能干扰新队列 | 每段间增加 90ms 缓冲；加入播放批次 ID；重播会取消旧队列；单段失败先跳过，连续失败才降级 |
| `3-1` 选项中没有 `2` | 10以内加减法升级后恢复了旧版未完成会话；旧题实际是 `3+1`，但新页面因缺少运算类型将其显示为减法 | 新会话增加 `version: 2`；旧会话自动失效；恢复前校验运算类型、计算结果和选项；显示前再次确保选项包含正确答案 |
| 帮助直接显示答案 | 旧逻辑按答案生成 `1、2、3…` 数数文本，本质上泄露结果 | 帮助只讲计算方法，并播放完整语音提示，不读取、不拼接当前答案 |

## 2. 新读题方式

加法示例 `3+1`：

```text
小兔原来有，3根胡萝卜。
又送来了，1根。
想一想，现在一共有几根呢？
```

减法示例 `3-1`：

```text
小兔原来有，3根胡萝卜。
后来拿走了，1根。
想一想，现在还剩下几根呢？
```

相比旧版，播放片段从 7 段降为 3 段，句子内部由系统语音一次生成，数字与量词不会被生硬拆开。

## 3. 新帮助方式

### 加法帮助

页面提示：

> 把两边放在一起，从1开始一个一个数。

语音提示：

> 先把两边的胡萝卜放在一起。再从一开始，一个一个慢慢数。

### 减法帮助

页面提示：

> 先拿走指定数量，再数一数剩下的。

语音提示：

> 先拿走题目说的胡萝卜。再数一数，盘子里还剩下几根。

帮助过程不引用 `question.answer`，不会直接说出或显示正确答案。

## 4. 答案安全机制

一份会话只有同时满足以下条件才允许恢复：

1. 会话版本为 2。
2. 状态为进行中且未超过 30 分钟。
3. 正好包含 5 道题。
4. 每题明确标记为加法或减法。
5. 保存答案等于重新计算的答案。
6. 三个选项中包含正确答案。

任一条件不满足都会丢弃旧会话并生成新题。进入每道题时还会再检查一次正确答案是否在选项中。

## 5. 音频与包体

- 语音文件：34 个自然短句与帮助片段。
- 格式：有效 RIFF/WAV，本地离线播放。
- 采样率：10kHz、16-bit 单声道，在语音清晰度与小程序包体之间取平衡。
- 音频目录约 1.7MB。
- 预计主包约 1.76MB，低于 2MB 基线。
- 项目打包时排除测试、Markdown 文档和 HTML 原型。

## 6. 自动测试

最终结果：**13/13 通过**。

新增专项测试：

- T11：旧版会话必须失效，新版每题选项必须包含正确答案。
- T12：预计主包资源必须小于 2MB。
- T13：帮助必须包含加减法计算方法，且不得直接读取答案。

原有 1,000 局随机测试继续通过，共验证 5,000 道十以内加减法题。

## 7. 建议人工复测

1. 清除开发者工具缓存或重新编译，确保旧会话被替换。
2. 连续完成至少 3 局，频繁点击“再听一次”，检查三段语音是否全部播放。
3. 在每一段播放期间快速点击重播，确认不会串音或只播前半段。
4. 专门观察 `3-1`、`10-10`、`1+9` 的答案选项。
5. 分别在加法和减法题点击“帮帮我”，确认只讲方法、不说答案。
