## 一、需求概述

### 1.1 背景与问题

采购计划共 **32 个字段**，其中业务配置类占 **23 个**（品牌、品类、三个采购企业、两组差价、两个账期、五项订单阈值、三项二期字段等）。实际业务中**同一套采购条件反复使用**是常态：

- 同一品牌 / 品类 / 企业链路，按月或按季度滚动下单
- 已关闭的旧计划重新启用，只改日期和金额
- 两个计划只差一个企业或一个差价参数

现状下用户只能点「创建采购计划」，从零手填 20 多个字段，重复劳动且易出错。

### 1.2 目标

以一条已有采购计划为模板，一键带出全部业务配置，用户**只需调整差异项并补填日期**即可保存。

### 1.3 非目标

| 不做的事 | 原因 |
|---------|------|
| 批量复制（多选多条计划一次性复制） | 本期无此场景 |
| 跨对象复制（如把采购订单复制成计划） | 对象语义不同，字段无法映射 |
| 「模板库」概念（脱离计划独立维护模板） | 本期复制对象就是计划本身 |
| 复制时一并复制执行进度 | 见 §五：新计划必须是全新的待执行状态 |

### 1.4 名词定义

| 名词 | 定义 |
|------|------|
| **源计划** | 被复制的那条已有计划。全程**只读**，不因复制发生任何变化 |
| **复制计划** | 复制动作产生的新计划。是一条**普通的新建计划**，编码全新、执行态归零 |
| **业务配置类字段** | 描述「采购条件」的字段，可跨计划复用 —— 复制 |
| **执行态字段** | 描述「这条计划执行到哪了」的字段，不可复用 —— 重置 |
| **唯一键** | 采购计划的业务唯一标识，见 §五 |

## 二、交互设计

### 2.1 入口

采购计划列表页，操作列的「**复制**」按钮。

**按钮配色**：紫色（`#722ed1`），与执行=绿 / 关闭=橙 / 删除=红 / 判断详情=蓝区分。

**按钮顺序**：位于「关闭」与「删除」之间。

### 2.2 可用范围：全状态可用

| 源计划执行状态 | 是否允许复制 |
|------|------|
| 待执行 | ✅ |
| 执行中 | ✅ |
| 已完成 | ✅ |
| 已关闭 | ✅ |

> 复制是**全状态可用**的操作，不同于「执行 / 编辑 / 删除 / 关闭」等受执行状态限制的操作。已完成、已关闭的计划往往是最有价值的模板来源 —— 把复制限制在「待执行」会砍掉主要使用场景。

### 2.3 弹窗行为

点击「复制」后，系统打开**采购计划创建表单弹窗**（复用「创建」与「编辑」共用的同一张表单）：

| 界面要素 | 复制时的表现 |
|---------|------------|
| 弹窗标题 | 「复制采购计划（源：{源计划编码}）」 |
| 计划编码 | 已自动生成新编码，用户可改 |
| 业务配置字段 | 预填源计划的值（见 §四.1） |
| 执行态字段 | 归零 / 重置（见 §四.2） |
| 预计开始 / 结束日期 | **留空**，用户必填（见 §四.3） |
| 保存按钮 | 点击后走与「创建」完全相同的校验链路 |

**关键约束**：弹窗关闭或点击「取消」时**不产生任何数据**，列表无变化、源计划无变化。

### 2.4 与「创建」「编辑」的关系

| 动作 | 入口 | 表单内容 | 保存时的分支 |
|------|------|---------|-------------|
| 创建 | 「创建采购计划」按钮 | 全空 | 新建 |
| **复制** | 操作列「复制」按钮 | 源计划业务配置 + 执行态归零 + 日期清空 | **新建** |
| 编辑 | 点击「采购计划编码」链接 | 源计划全部字段（含执行态） | 更新 |

三者**共用同一张表单与同一套校验规则**，复制不引入任何额外的表单或校验逻辑。

## 三、用例 UC01-A 复制采购计划

| 字段 | 说明 |
|------|------|
| 用例名称 | 复制采购计划 |
| 用例编号 | UC01-A |
| 用例简述 | 采购经理以一条已有采购计划为模板，快速创建条件相同或相近的新计划 |
| 主执行者 | 采购经理 |
| 前置条件 | 用户已登录系统并具有采购计划创建权限；列表中已存在至少一条采购计划 |
| 后置条件 | 系统生成一条新的采购计划编码，新计划执行状态为「待执行」、计划状态为「启动」；**源计划不受任何影响** |

**主要路径**：

1. 用户在采购计划列表的操作列点击「复制」
2. 系统打开采购计划创建表单，标题显示「复制采购计划（源：{源计划编码}）」
3. 系统将源计划的**业务配置**预填到表单（见 §四.1）
4. 系统同时执行**执行态重置**：计划编码重新生成、已完成金额与完成率归零、执行状态置「待执行」、计划状态置「启动」
5. 系统**清空预计开始日期与预计结束日期**，要求用户重新填写
6. 用户核对并按需调整各字段，补填预计日期
7. 用户点击「保存」，系统按 UC01 的校验规则进行校验
8. 校验通过，系统保存为新计划，提示「已复制采购计划 {新编码}（源 {源编码}）」

**替代流程**：

- **6a. 用户关闭弹窗或点击「取消」**：不产生任何数据，返回计划列表
- **7a. 校验不通过**：按 UC01 的替代流程处理，拒绝保存并提示原因

## 四、字段处理规则（核心）

按原型 plan 对象的 32 个字段逐项判定：**复制 23 项 / 重置 8 项 / 清空 2 项**（8 项重置中 1 项为 PRD 定义而原型无对应字段，见 4.2 ）。

### 4.1 直接复制：业务配置类（23 项）

| # | 字段 | 说明 | 复制后取值 |
|---|------|------|-----------|
| 1 | 采购层级 | 二级采购 / 三级采购。**决定第 7、11–13、15 项是否显示** | 与源计划相同 |
| 2 | 品牌 | | 相同 |
| 3 | 品类 | | 相同 |
| 4 | 采购总金额 | 目标金额。不参与唯一性校验 | 相同 |
| 5 | 采购企业 1 | | 相同 |
| 6 | 采购企业 2 | | 相同 |
| 7 | 采购企业 3 | 仅三级采购有 | 相同；二级采购下隐藏且置空 |
| 8 | 差价 1 类型 | 比例 / 固定 | 相同 |
| 9 | 差价 1 比例 | 类型为「比例」时有值 | 相同 |
| 10 | 差价 1 金额 | 类型为「固定」时有值 | 相同；无值填 0 |
| 11 | 差价 2 类型 | 仅三级采购有 | 相同；二级采购下隐藏 |
| 12 | 差价 2 比例 | 同上 | 相同；二级采购下清零 |
| 13 | 差价 2 金额 | 同上 | 相同；二级采购下清零 |
| 14 | 账期 1 | 单位：天 | 相同 |
| 15 | 账期 2 | 仅三级采购有 | 相同；二级采购下隐藏且清零 |
| 16 | 订单最低单价 | | 相同 |
| 17 | 订单最高单价 | | 相同 |
| 18 | 订单最低数量 | | 相同 |
| 19 | 订单最高数量 | | 相同 |
| 20 | 订单最低总价 | | 相同 |
| 21 | 最低开票率 | **二期字段**，表单中禁用 | 有值就带上，无值填 0 |
| 22 | 最低合作期限 | **二期字段**，表单中禁用 | 有值就带上，无值填 0 |
| 23 | 最低贸易金额 | **二期字段**，表单中禁用 | 有值就带上，无值填 0 |

> **差价 1 / 差价 2 的类型互斥**：按类型只回填比例或金额其中一个，另一字段为 0。复制后表单须按类型正确切换显隐。
>
> **二级采购的联动清空**：`采购层级 = 二级采购` 时，采购企业 3、差价 2、账期 2 三项在界面上隐藏并清零 —— 该联动规则由创建表单既有逻辑负责，复制只是触发它。

### 4.2 必须重置：执行态类（8 项）

| # | 字段 | 复制后的值 | 原因 |
|---|------|-----------|------|
| 1 | 采购计划编码 | **重新生成** | 唯一标识，不可复用 |
| 2 | 已完成总金额 | `0` | 新计划无执行记录 |
| 3 | 完成率 | `0.00%` | 随已完成金额归零 |
| 4 | 执行状态 | `待执行` | 新计划从零开始 |
| 5 | 计划状态 | `启动` | 待执行 ↔ 启动是固定映射 |
| 6 | 实际执行日期 | 空（列表显示 `-`） | 尚未执行 |
| 7 | 实际结束日期 | 空（列表显示 `-`） | 尚未关闭 |
| 8 | 子编码流水号 | `0` | **PRD 定义字段，原型无**。上线时后端须一并归零，否则新计划会沿用源计划的子编码序号 |

> **编码生成规则**：新编码由系统按「下一个可用序号」自动生成。若预览时生成的编码已被占用（例如连点两次「复制」），保存时自动顺延到下一个可用序号，保证编码唯一。

### 4.3 清空：日期（2 项）

| # | 字段 | 复制后的值 |
|---|------|-----------|
| 1 | 预计开始日期 | **留空，用户必填** |
| 2 | 预计结束日期 | **留空，用户必填** |

详见 §五.1 —— 这是本功能唯一需要专门决策的一点。

## 五、业务规则

### 5.1 预计日期不予复制，一律清空

**规则**：预计开始日期与预计结束日期不复制，一律留空，要求用户重新填写。

**理由有二**：

1. **唯一键冲突**：预计日期是采购计划唯一键的组成部分（见 5.2）。若原样复制且源计划为「待执行 / 执行中」，新计划保存时**必然被唯一性校验拒绝**。
2. **自动执行导致状态失控**：系统有「预计开始日期到达时自动执行」规则。源计划的预计开始日期若已过期，复制出的新计划在用户尚未反应过来时就会被系统自动置为「执行中」，产生非预期状态。

**取舍说明**：日期是复制场景中**最需要变、也最不该猜**的字段 —— 用户复制一条计划，通常正是因为要换一个执行周期。让用户填 2 个日期，换来 23 个字段不用填，收益已经很大。

> 若后续觉得过于生硬，可在日期旁增加一个弱化的「按原周期填充」按钮（点击后填 今天+1 ~ 今天+1+原周期天数），但**不作为默认行为**。本期不做。

### 5.2 唯一性校验不受影响

复制**不新增任何校验逻辑**。复制出的计划就是一条普通新计划，完全沿用 UC01 的强制校验与唯一性校验链路。

**唯一键定义**（详见主文档 `采购计划管理-PRD.md` §三）：

```
二级采购：品牌 + 品类 + 采购企业 1 + 采购企业 2 + 预计开始日期 + 预计结束日期
三级采购：品牌 + 品类 + 采购企业 1 + 采购企业 2 + 采购企业 3 + 预计开始日期 + 预计结束日期
```

**校验有效范围**：仅对 **计划状态 ≠ 关闭** 的有效计划校验。

| 执行状态 | 计划状态 | 是否参与唯一性校验 |
|---------|---------|------------------|
| 待执行 | 启动 | ✅ |
| 执行中 | 启动 | ✅ |
| 已完成 | 关闭 | ❌ |
| 已关闭 | 关闭 | ❌ |
| 已删除 | 关闭（逻辑） | ❌ |

> **上线注意**：原型阶段未实现唯一性校验，因此复制保存永远成功。上线后若用户从「待执行 / 执行中」的计划复制且未改日期，会被拒绝并提示源计划编码 —— 这是**预期行为**，不是缺陷。

### 5.3 源计划只读

复制过程**不得修改源计划的任何字段**。这一点在「执行中」计划上尤其重要 —— 源计划可能正在参与订单匹配。

### 5.4 执行态不予复制

新计划必须是全新的「待执行 / 启动」状态，已完成金额与完成率一律归零。复制**不是**「续用」，而是「以旧计划为模板新建」。

### 5.5 与「编辑」的区别

| | 编辑 | 复制 |
|---|------|------|
| 作用对象 | 源计划**本身** | 产生**新计划** |
| 编码 | 不变 | 重新生成 |
| 保存分支 | 更新 | 新建 |
| 执行态 | 保留 | 归零 |

### 5.6 权限

复制沿用**采购计划创建权限**，不单独设权。无创建权限的用户不应看到「复制」按钮。

## 六、异常与边界场景

| # | 场景 | 预期行为 |
|---|------|---------|
| 1 | 复制「二级采购」计划 | 采购企业 3 / 差价 2 / 账期 2 隐藏且值为空 |
| 2 | 复制「三级采购」计划 | 三个企业、两组差价、两个账期全部带出，且差价类型（比例 / 固定）对应正确 |
| 3 | 复制「已完成 / 已关闭」计划 | 允许；新计划为「待执行 / 启动」，完成率 0.00% |
| 4 | 复制「执行中」计划 | 允许；**源计划不受任何影响**（关键：不可污染源数据） |
| 5 | 复制后直接关闭弹窗 | 不产生任何计划，列表无变化 |
| 6 | 复制后未填日期直接保存 | 被必填校验拦截，提示「请选择预计开始日期」 |
| 7 | 复制后填了与源计划完全相同的日期，源计划为「执行中」 | 原型阶段：保存成功；上线后：被唯一性校验拒绝，提示源计划编码 |
| 8 | 源计划的差价类型为「固定」 | 差异金额回填，比例字段为 0，表单按类型正确切换显隐 |
| 9 | 源计划日期已过 | 日期已清空 → 新计划不会在刷新后被自动置为「执行中」 |
| 10 | 连续复制同一条计划 | 每保存一次序号 +1，编码递增不重复 |
| 11 | 复制后「保存」失败（校验不通过） | 弹窗保持打开，用户可继续修改；不产生半成品数据 |
| 12 | 复制出的计划是否参与订单匹配 | **状态为「待执行」时不参与**；执行后才参与 |

## 七、验收标准

| # | Given | When | Then |
|---|-------|------|------|
| 1 | 一条「三级采购」计划，采购企业 3、差价 2、账期 2 均有值 | 点击「复制」 | 弹窗预填全部 23 项业务配置，三企业、两组差价、两账期均有值且类型正确 |
| 2 | 一条「二级采购」计划 | 点击「复制」 | 采购企业 3 / 差价 2 / 账期 2 三行隐藏，且值为空 |
| 3 | 任意计划，其完成率为 62.50%、已完成金额非 0 | 点击「复制」 | 弹窗中完成率显示 `0.00%`，编码为新值，执行状态「待执行」、计划状态「启动」 |
| 4 | 任意计划，其预计日期有值 | 点击「复制」 | 预计开始日期与结束日期**两个输入框均为空** |
| 5 | 已打开复制弹窗，未填日期 | 点击「保存」 | 拦截并提示「请选择预计开始日期」，**列表数量不变** |
| 6 | 已打开复制弹窗 | 点击「取消」或关闭 | **列表数量不变**，源计划字段全部不变 |
| 7 | 一条「执行中」的源计划 | 点击「复制」并保存成功 | 源计划所有字段（含完成率、完成金额、执行状态）**逐字段不变** |
| 8 | 同一条计划 | 连续执行 3 次「复制并保存」 | 3 条新计划编码互不相同 |
| 9 | 列表中有 4 种执行状态的计划 | 查看操作列 | 每条都有「复制」按钮；执行 / 关闭 / 删除按钮仍按原规则受状态限制 |
| 10 | 一条任意计划 | 点击「采购计划编码」链接进入编辑并保存 | 走**更新**分支（不新增计划），提示「采购计划已更新」 |

## 八、与其他功能的关系

| 相关功能 | 关系 |
|---------|------|
| **创建采购计划 (UC01)** | 复制复用其表单、校验与唯一性规则；复制是「带初值的创建」 |
| **编辑采购计划** | 复制生成的表单与编辑表单是同一张；区别在于编辑走更新、复制走新建 |
| **执行采购计划 (UC02)** | 复制出的计划状态为「待执行」，需用户手动执行（或等预计开始日期到达自动执行）才参与订单匹配 |
| **关闭 / 删除** | 复制按钮的可用性**不受**这两个操作的状态限制 |
| **订单判断 / 匹配** | 复制出的计划在「待执行」状态下**不参与**订单匹配 |

## 九、非功能性要求

| 项 | 要求 |
|---|------|
| 性能 | 点击「复制」到弹窗完成回填无可感知延迟（字段回填为纯前端操作） |
| 数据一致性 | 编码唯一性须在保存时兜底校验，避免并发或连点产生重复编码 |
| 并发 | 复制与源计划的执行 / 关闭操作并发时，源计划状态以数据库为准，复制不得回写源计划 |
| 权限 | 无采购计划创建权限的用户不可见「复制」按钮，后端接口亦须校验 |
| 审计 | 复制为新计划，其创建日志与普通新建计划一致，无需额外记录来源编码（来源仅体现在一次性的 Toast 提示中） |
