# 优化需求：采购计划品牌/品类改为可选

## 一、需求背景

当前采购计划创建时，品牌、品类为必填字段。实际业务中，部分采购计划可能不限定具体品牌或品类（如"不限品牌的通用采购"）。为使系统更贴合业务，将品牌/品类从"必填"调整为"可选"。

**业务含义确认**：

| 确认项 | 结论 |
|--------|------|
| 品牌/品类为空时的含义 | **不限**（允许任何品牌的订单） |
| 为空是否参与唯一性约束 | **不参与** |
| 订单推送是否需要品牌/品类 | **仍需要**（订单侧必填，用于匹配） |

---

## 二、规则调整

### 2.1 采购计划字段必填性

| 字段 | 原规则 | 新规则 |
|------|--------|--------|
| 品牌 | 必填 | **可选**（为空=不限） |
| 品类 | 必填 | **可选**（为空=不限） |

### 2.2 唯一性约束调整

唯一键规则保留，但**品牌/品类为空时该维度不参与唯一性判断**：

```
二级采购唯一键：品牌 + 品类 + 采购企业1 + 采购企业2 + 预计开始日期 + 预计结束日期
三级采购唯一键：品牌 + 品类 + 采购企业1 + 采购企业2 + 采购企业3 + 预计开始日期 + 预计结束日期

规则：
- 品牌为空 → 品牌不参与唯一性判断
- 品类为空 → 品类不参与唯一性判断
- 其余维度（采购企业、日期）仍必填，参与唯一性判断
```

**示例**：

| 计划 | 品牌 | 品类 | 唯一键判定 |
|------|------|------|-----------|
| 计划X | 华为 | 手机 | 华为+手机+企业+日期 |
| 计划Y | 华为 | 空 | 华为+企业+日期 |
| 计划Z | 空 | 空 | 企业+日期 |

计划X 和计划Y 因维度不同不冲突；计划Y 和计划Z 因品牌品类都为空则按剩余维度（企业+日期）判定。

### 2.3 订单侧约束

订单推送（IF02）时，品牌、品类**仍为必填**，用于系统自动匹配计划。

---

## 三、匹配算法重新设计

### 3.1 匹配度计算

订单到达后，对每个执行中的计划计算"匹配度"：

| 维度 | 订单值 vs 计划值 | 判定 | 得分 |
|------|----------------|------|------|
| 品牌 | 计划有品牌 且 与订单一致 | ✅ 强命中 | +1 |
| 品牌 | 计划品牌为空（不限） | ⚪ 弱命中 | +0 |
| 品牌 | 计划有品牌 且 与订单不一致 | ❌ **排除该计划** | — |
| 品类 | 计划有品类 且 与订单一致 | ✅ 强命中 | +1 |
| 品类 | 计划品类为空（不限） | ⚪ 弱命中 | +0 |
| 品类 | 计划有品类 且 与订单不一致 | ❌ **排除该计划** | — |

### 3.2 匹配优先级（更新）

```
第 1 层：强命中数降序 — 品牌/品类都具体命中的最优先
第 2 层：执行时间升序 — 最早执行的最优先
第 3 层：完成率降序 — 完成率越高越优先
第 4 层：剩余金额升序 — 剩余越少越优先
```

### 3.3 匹配示例

```
订单：品牌=华为，品类=手机

计划A：华为/手机    → 强命中2  排序1 ✅
计划B：华为/空      → 强命中1  排序2
计划C：空/空        → 强命中0  排序3
计划D：苹果/手机    → 品牌不一致 → 排除

结果：A > B > C
```

### 3.4 边界场景

| 场景 | 处理 |
|------|------|
| 多个"不限"计划 | 按优先级排序（执行时间/完成率/剩余金额） |
| 精准计划额度不足 | 订单判断拒绝后，跨计划重试自动尝试下一个（含不限计划） |
| 所有计划都是"不限" | 订单可匹配任何执行中计划，完全靠优先级区分 |
| 只剩一个执行中计划且全空 | 直接匹配该计划 |

## 四、判断规则调整

品牌、品类匹配判断改为**条件性执行**：

| 判断维度 | 原逻辑 | 新逻辑 |
|---------|--------|--------|
| 品牌匹配 | 订单品牌与计划品牌一致 | 计划品牌为空时**跳过**该判断；计划有品牌时仍需一致 |
| 品类匹配 | 订单品类与计划品类一致 | 计划品类为空时**跳过**该判断；计划有品类时仍需一致 |

## 五、接口调整

### IF02 请求参数

| 字段 | 原必填 | 新必填 |
|------|--------|--------|
| brand | 是 | **是**（订单侧保持必填） |
| category | 是 | **是**（订单侧保持必填） |

> 说明：IF02 是订单判断接口，订单侧的品牌/品类仍必填，无变化。

## 六、界面调整

| 页面 | 调整 |
|------|------|
| 创建/编辑采购计划表单 | 品牌、品类去掉红色 `*` 必填标记；允许为空 |
