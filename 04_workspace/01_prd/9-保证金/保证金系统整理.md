## 一、保证金概述

### 1.1 定义

也叫押金，在客户交易时使用一小部分资金作为担保，目的是提升毁约成本，促使客户完成最终交易，一方面订单时效性的产生的毁约风险。

### 1.2 保证金业务类型（共16种）

| 编号 | 业务类型 | 说明 |
|------|----------|------|
| 0 | 充值 | 保证充值 |
| 1 | 抢单 | 一件代发抢单冻结保证金 |
| 2 | 串码 | 更换串码 |
| 3 | 取消订单 | 撤销订单、毁单 |
| 4 | 物流补贴 | 无 |
| 5 | 撤销订单 | 2022年10月11日之后无数据 |
| 6 | 毁单 | 供应商毁单 |
| 7 | 退货追单 | 采购单撤销导致的退货追单、供应商毁约导致的退货追单 |
| 8 | 物流异常 | 串码异常、物流信息异常等 |
| 9 | 接龙抢单 | 群接龙抢单 |
| 10 | 采购入仓 | 采购入仓订单 |
| 11 | 扣罚订单 | 虚假物流扣罚 |
| 12 | 修改物流 | 修改物流单号保证金扣罚 |
| 13 | 运费 | 电子面单月结 |
| 14 | 转账 | 企业保证金出现账户转移 |
| 15 | 特邀竞价报名 | 暗盘参与竞价冻结保证金 |

### 1.3 保证金状态（共7种）

| 状态编码 | 状态 | 说明 |
|----------|------|------|
| 0 | 充值 | 保证金充值 |
| 1 | 冻结 | 抢单扣除基于合作关系设置的保证金（默认50）；抢单接龙冻结保证金（默认20每台，最大200）；修改物流冻结保证金（30）；采购商退货追单扣除采购1元保证金 |
| 2 | 扣除 | 串码交换扣除保证金；物流申请扣除保证金；电子面单扣除保证金（运费）；超时扣除保证金 |
| 3 | 解冻成功 | 无 |
| 4 | 解冻返回 | 解冻保证金 |
| 5 | 已返还 | 运费返还 |
| 6 | 收入 | 能良-电子面单运费 |

## 五、无仓保证金扣罚（来源：`无仓保证金扣罚 · 云效 Thoughts · 企业级知识库.pdf`）

### 5.1 背景介绍

保证金也叫押金，在客户交易时使用一小部分资金作为担保，目的是提升毁约成本，促使客户完成最终交易。客户需要在钱包里充值保证金，才能进行相应的抢单。

因供应商原因（如虚假物流，货物不对）被平台扣罚时，系统无法对订单发起追缴，只能线下找供应商追缴，存在供应商不缴纳情况，造成业务损失，需要实现全链路合规管控与损失追偿。

### 5.2 保证金余额校验

#### 5.2.1 保证金余额校验业务流程

```mermaid
flowchart TD
    A[供应商发起抢单] --> B[获取全局通用配置]
    B --> C[获取品牌品类配置]
    C --> D{保证金余额 > 配置值}
    D -->|否| E[提示保证金余额不足]
    D -->|是| F[允许抢单]
    F --> G[供应商抢单页面提示冻结金额]
    G --> H{冻结金额判断}
    H -->|余额 >= 冻结金额| I[抢单成功]
    H -->|余额 < 冻结金额| E
```

#### 5.2.2 保证金余额第一道校验配置

**可选择条件：**
1. 应用对象：全部、无仓、醒柜（单选）
2. 订单类型：普通订单、加急订单、超时订单、高价订单、推荐给供应商订单、小狮达订单（下拉多选）
3. 品类（下拉多选）
4. 品牌（下拉多选）
5. SPU（下拉多选）
6. SKU（下拉多选）

未填写时的字段默认为【全部】。

输入保证金余额，生成一条规则，此规则下的订单必须满足【保证金余额】大于xx元才能对订单抢单，供应商抢单进行第一次拦截。

**规则生效的优先级：**

```mermaid
flowchart TD
    subgraph 规则维度
        A1[只选订单类型] --> B1[该类型下所有品牌品类SPU_SKU生效]
        A2[只选品牌] --> B2[该品牌下所有品类SPU_SKU生效]
        A3[只选品类] --> B3[该品类下所有品牌SPU_SKU生效]
        A4[选品牌+品类] --> B4[该品牌+品类下所有SPU_SKU生效]
        A5[选品牌+SPU] --> B5[该SPU下所有SKU生效]
        A6[选完整SKU维度] --> B6[精确到SKU]
    end
    subgraph 判定原则
        C[规则判定时 按照更详细的规则执行]
    end
    B1 --> C
    B2 --> C
    B3 --> C
    B4 --> C
    B5 --> C
    B6 --> C
```

**添加规则约束：**
同一应用对象维度下，不允许存在完全相同的配置规则，重复则提示"同一应用对象的该维度规则已存在，不允许重复创建"。

#### 5.2.3 保证金余额第二道校验配置


3. 订单类型：普通订单、加急订单、超时订单、高价订单、推荐给供应商订单、小狮达订单（下拉多选）

### 5.3 无仓扣罚

#### 5.3.1 虚假物流扣罚

**扣罚规则：**
- 从发货时间计算，超过24小时物流无流转信息，生成扣罚订单，200元/单
- 扣罚原因：虚假物流-24小时无揽收信息
- 从发货时间计算，超过96小时物流无信息：自动退货追单，不扣除采购方保证金（24小时已经扣过了）

**完整业务流程：**

```mermaid
flowchart TD
    S[供应商抢单成功] --> S1[填写物流到当日发货]
    S1 --> T1[执行物流模块定时任务]
    T1 --> T2{TEST-444/PRE-150<br>7天未签收流转和无流转信息}
    T2 -->|有物流更新| N1[正常流程]
    T2 -->|无物流更新 超22小时| A1[订单流转至异常订单]
    A1 --> A2{供应商24小时内是否处理}
    A2 -->|修改物流| A3[采购商审核]
    A3 -->|审核通过| N1
    A3 -->|审核不通过| A1
    A2 -->|未处理 超24小时| B1[执行TEST-196<br>扣罚账单生成]
    B1 --> B2[生成虚假物流扣罚账单200元]
    B2 --> B3[订单流转至退货追单]
    B3 --> B4[供应商可在22小时内申诉]
    B4 --> C1{是否申诉}
    C1 -->|是| C2[取消扣罚]
    C1 -->|否| C3[到申诉截止日期]
    C3 --> C4[执行TEST-244<br>扣罚账单定时任务]
    C4 --> D1{供应商保证金是否充足}
    D1 -->|充足| D2[直接扣除保证金200元]
    D1 -->|不足| D3[生成扣罚账单 状态:已生成]
    D3 --> D4[排款时产生负向账单 状态:未支付]
```

**快速造数据：**
采购方界面，【今日付款】【物流扣罚】选择添加扣罚订单，可直接生成一笔虚假物流扣罚账单。

## 六、无仓扣罚机制规则明细（来源：`无仓扣罚机制`）

### 6.1 物流修改次数扣罚

```mermaid
flowchart LR
    A[发货时间22小时内] --> B{当日发货当日修改}
    B -->|是| C[免责 无次数限制]
    B -->|否| D{当日发货 次日修改}
    D -->|月修改次数 <= 3| E[免责]
    D -->|月修改次数 > 3| F[50元/次]
```

- 扣罚规则：发货时间22个小时内
- 当日发货，当天修改：免责，无次数限制
- 当天发货，次日修改：免责3次/月，超次数50元/次

### 6.2 物流填反申请扣罚

```mermaid
flowchart TD
    A[物流填反申请] --> B{发货至今是否超过24小时}
    B -->|未超过| C[可修改]
```

## 七、群接龙冻结保证金（来源：`群接龙冻结保证金（25_11_19） · 云效 Thoughts · 企业级知识库.pdf`）

### 7.1 产品信息

- 原型地址：<http://10.10.10.4/TKUXKU/?id=41gg3n&p=%E6%97%A0%E4%BB%93%E4%BF%9D%E8%AF%81%E9%87%91&g=1&sc=3>
- 飞书文档：<https://z25vwhbapd.feishu.cn/wiki/JEtgwI3E5i9jFakjMlLcDKT5nSc>

### 7.2 整体流程

```mermaid
flowchart TD
    A[集采发布报价] --> B[供应商出价抢单]
    B --> C{判断供应商类型}
    C -->|白名单| D[按参数配置扣除 配置金额即上限]
    C -->|非白名单| E[按30元/单扣除 上限10000]
    D --> F[立即冻结保证金]
    E --> F
    F --> G[运营平台成交]
    G --> H[供应商发货]
    H --> I[执行orderCenterCreate定时任务]
    I --> J[运营平台拣货]
    J --> K{分批入库}
    K -->|是| L[保证金分批解冻]
    K -->|否| M[一次性入库]
    L --> N[入库完成]
    M --> N
    N --> O{完成拣货时判断}
    O -->|入库/成交 >= 50%| P[不扣罚保证金 全部返还]

    Q --> R
```

### 7.3 扣费规则

群接龙供应商按照白名单和非白名单计算扣除保证金。

**运营平台字典配置：**
- 保证金扣罚：`marketing_deposit`
- 保证金上限：`marketing_limit_deposit`

**白名单供应商：**
- 按照参数配置扣除（配置内金额就是上限）

**非白名单供应商：**
- 按照每单30元扣除，上限10000

### 7.4 扣费计算场景

```mermaid
flowchart TD
    A[非白名单供应商] --> B[抢单冻结计算]
    B --> C{30*抢单数 >= 10000}
    C -->|是| D[冻结10000 达到上限]
    C -->|否| E[按30*抢单数冻结]
    D --> F[成交后计算]
    E --> F
    F --> G{30*成交数 >= 10000}
    G -->|是 仍达上限| H[按上限10000扣除]
    G -->|否 未达上限| I[按30*成交数扣除]
    H --> J[按比例解冻 10000/成交数*入库数]
    I --> K[剩余部分解冻返还]
    J --> L[完成拣货时]
    K --> L
    L --> M{入库/成交 >= 50%}
    M -->|是| N[不扣罚 全部返还]
    M -->|否| O[按规则扣罚]
```

**场景1：成交前达到上限，成交后未达上限**
按正常扣，剩余全部解冻返还。后续部分拣货也按照正常解冻扣除，比例整体结果向下取整。完成拣货时：拣货入仓数量/成交数量\*100% >= 50%，不扣保证金，余下全部解冻。

例：非白名单——抢单400，冻结保证金30\*400>=10000，冻结10000；成交300，30\*300<=10000，按照30\*300扣除，解冻1000返回保证金。后续部分拣货也按照30\*数量解冻扣除。

**场景2：成交前达到上限，成交后也达到上限**
达到上限时不解冻保证金，后续部分拣货按照比例解冻扣除，比例整体结果向下取整。完成拣货时：拣货入仓数量/成交数量\*100% >= 50%，不扣保证金，余下全部解冻返还。

例：非白名单——抢单400，冻结保证金30\*400>=10000，冻结10000；成交350，30\*350>=10000，按照10000扣除，解冻0返回保证金。后续部分拣货按照比例 10000/350\*数量 解冻扣除。若成交数量350单，拣货入库175单，然后点击【完成拣货】，先把剩余保证金返还，175/350>=0.5则不扣罚保证金。

### 7.5 操作步骤

**整体流程：**
集采报价 → 供应商出价（扣除保证金） → 成交 → 供应商发货 → 执行定时任务 → 运营平台拣货 → 入库完成（退还保证金）

**详细步骤：**
1. 群接龙集采发布报价
2. 供应商抢单
3. 出价后，立即冻结保证金（非白名单商户：30\*数量）
4. 运营平台成交
5. 供应商发货
6. 执行采购单推订单中心定时任务（订单模块——orderCenterCreate）
7. 运营平台拣货：填写串码，可以分批入库，保证金分批解冻

**查看保证金入口：**
供应商平台 → 财务 → 钱包 → 保证金

### 7.6 部分拣货场景

```mermaid
flowchart TD

    B --> C[解冻4*30=120元]
    C --> D[剩余1单有瑕疵或不想要]
    D --> E[直接点击完成拣货]
    E --> F{4/5*100% >= 50%}
    F -->|是| G[全部返还保证金]
    F -->|否| H[按规则扣罚]
```

**场景1：成交冻结保证金未达上限（1000元）**
成交5单，拣货4单入库，剩余1单有瑕疵（或者不想要），直接完成拣货。
- 本单5\*30=150元冻结保证金
- 入库4单，解冻4\*30=120元
- 剩余1单，直接点击【完成拣货】退还剩余全部保证金
- 因为4/5\*100%>=50%，故全部返还保证金

- 免责毁单——拒绝：拒绝后，保证金流水无变更
- 免责毁单——同意：保证金全额返还，保证金金额同等增加
