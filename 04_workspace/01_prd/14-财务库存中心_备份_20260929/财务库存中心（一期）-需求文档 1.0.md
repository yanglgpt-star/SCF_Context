# 一、业务概况

## 1.1 组织架构

### 1.1.1 组织架构图

本系统围绕一句话分工组织起来：**业务管实物，财务管价值**。涉及五个部门/团队：

1. **业务库存中心** —— 业务事实的权威来源。输出主数据、11 类单据流水、库存数量快照；对"货有没有、动没动、动了多少"负全责。
2. **财务部** —— 存货价值的唯一权威。输出成本单价、库存金额、库龄、跌价准备、会计凭证、月结与对账结论；对"这批货值多少钱、会计怎么记"负全责。
3. **采购部** —— 采购价格与采购附加费用（运费、关税、报关费）的原始输入方。这是财务算不出来的原始事实，只能由采购侧提供。
4. **销售部** —— 销售价格、销售退货、客户档案与关联方标识的输入方。
5. **研发部（IT）** —— 系统研发、测试、部署与运维。

一句话概括边界：**交易是否成立由业务决定，会计怎么记由财务决定。**

### 1.1.2 岗位职责

1. **财务部**

    - **财务经理：** 制定存货核算政策——计价方法、入库成本口径、采购附加费用分摊规则、跌价计提规则；审批月结与反结账；当数量对得上而金额对不上时，负责给出差额构成的解释。
    - **存货核算会计：** 复核单据核算结果；执行并复核跌价计提；生成凭证清单并导出金蝶格式；处理跨期补录单；维护二级内部结算价目表（带生效期）。
    - **总账会计：** 维护金蝶总账存货类科目余额，作为**金额对账的基准**；核对本系统凭证清单与总账的一致性。
    - **税务专员：** 进项税勾选与发票匹配（走金蝶，本系统不重复做）；逐场景判断是否构成视同销售；确认出口退税触发条件。

2. **业务库存中心**

    - **业务负责人：** 作为业务事实的权威方，确认单据类型归属（尤其是"调拨"与"一级货权转移"的判定）；对已锁账期间的数据缺失，配合走当期补录流程。
    - **仓储/单证专员：** 推送出入库单据与主数据；维护批次号与序列号（SN）；在日切时点出具库存数量快照；处理改单、作废通知。

3. **采购部**

    - **采购经理：** 提供采购不含税/含税单价、税率、运费与关税金额及其分摊方式；确认"运费/关税是否计入存货成本"的最终口径。
    - **采购专员：** 维护供应商档案（含纳税人识别号、是否关联方）；分别推送"暂估入库"与"发票到达"两个独立事件。

4. **销售部**

    - **销售负责人：** 维护客户档案与关联方标识；确认销售退货、换货、以旧换新的单据拆分方式。
    - **销售专员：** 推送销售出库单据；3C 整机场景下必须在出库行上提供序列号。

5. **研发部（IT）**

    - **产品经理：** 与财务部、业务库存中心确认字段口径与页面交互；维护接口字段定义；推动 W1 接口评审会收口。
    - **开发人员：** 实现数据接入适配层、核算引擎、投影查询、凭证导出与对账程序。
    - **测试专员：** 以 UAT 算例为基线验证计量结果；验证幂等、顺序、并发与重放一致性。
    - **运维人员：** 部署环境、备份容灾、监控告警；并行期值守。

## 1.2 业务画像

### 1.2.1 经营状况

1. 业务形态为**纯贸易 / 零售 / 电商**，**没有生产环节**——因此不设原料库、在制品库，也**不引入标准成本法**。库存成本只能靠"买入价 + 采购附加费用"逐笔累计出来。
2. 经营品类集中在**3C 数码与出行商品**。这类商品的贬值**不是随时间均匀发生的，而是被新品发布驱动的**——一台旗舰手机在新品发布当天可能直接跌掉三成。因此跌价计提必须**库龄法 + 3C 上市周期法双轨取孰高**，不能只按库龄。
3. 主体结构上存在**多个法人主体**，且法人之间存在**集团内货权转移**（关联交易）。这类转移不开票，但**按会计准则仍必须作价、出凭证、确认损益，并在合并层抵消**。

### 1.2.2 运营状况

1. 一期系统规模：**11 类单据、28 张数据表、13 个凭证模板、5 张报表、12 个 PC 端页面、69 条功能需求（FR-01–FR-69）、10 条非功能需求（NFR-01–NFR-10）**。
2. 存量数据接管：上线日即**开账日**，期初库存由**金蝶存货余额倒推为主、财务指定评估价兜底**，一次性导入并经双人复核锁定。开账日必须与业务库存中心的快照时点**完全一致**。
3. 性能基线：单据处理 **≥100 单/秒**；余额查询 **<3 秒**；**10 万 SKU 月结 <10 分钟**；并发 50。
4. 上线节奏：**8 周上线**。W1 收口接口评审会；W3 前给出业务量级方可设定压测场景；W8 进入并行期。上线后与旧方式**并行 1 个完整月结周期**。
5. **切换与回滚**：并行期内新旧两套口径同时出数、逐月比对；比对通过后一次性切换，旧方式**停用不停查**（历史报表保留只读）。回滚以"重新启用旧方式出账"为界——**本系统已生成的凭证清单与事件日志不回滚、不删除**。回滚只切换权威方，不销毁已产生的记录。
6. **部署与容灾**：一期按单机房部署，数据库**日全备 + 增量备**。容灾目标（RPO / RTO）与运维责任人**待 IT 在并行期前确认**（外部输入 D-12）。
7. **业务量级待确认**（SKU 数、日单据行数、峰值倍数、历史保留年限）——须由 IT 在 W3 压测前给出。架构取向已锁定为"批量计算"，但容量参数不到位就无法设定压测场景。

### 1.2.3 业务特点

1. **货权与实物分离**。同一批货，"在不在我的仓"与"算不算我的存货"是两件事：代销、寄售、借入的货**在我仓里但不算我的存货**；货权已转、客户未提货的货**不算我的存货但仍在我仓里**。系统必须能把这两个口径分开表述。
2. **同一个仓库、同一个批次下可能存在多个货主**。若按仓库或批次看库存，两个货主的数量会被净额相抵，真实的差异被隐藏。
3. **只动权属、不动实物的业务占比不低**。一级货权转移（法人之间）、二级货主重分配（部门/代采项目之间）都不改变任何仓库的在库数量，但在账上必须新增或清空一整条库存记录。
4. **存在"账面进出、实物不动"的情形**（直发、库内转手、空转）。这三者在单据上长得一模一样，但账务处理截然相反——直发**必须**记进销、库内转手**严禁**记进销、纯空转**不应确认收入**。
5. **作价来源分两级**：一级货权转移的价格是**交易数据**（由交易双方确定，财务只取价、只校验，**不定价**）；二级内部结算价是**政策数据**（财务维护的带生效期价目表）。两者的去向完全不同。

### 1.2.4 商业模式

1. 自营贸易赚取进销差价，库存成本直接决定毛利，因此**成本算错等于利润算错**；
2. 代采业务中，公司替委托方采购、货权已转但实物可能仍在公司仓内，形成**代采项目维度的二级货主分摊**，用于内部考核；
3. 集团内关联主体之间的货权转移形成**内部未实现毛利**，在合并层必须抵消，否则集团存货与利润双双虚增；
4. 对下游（业务库存中心）反向输出**库存价值月报**（成本单价、库存金额、库龄、跌价准备），使业务侧看到的价值口径与财务一致。

# 二、业务详述

## 2.1 主数据管理

1. 商品管理：商品编码、名称、规格、计量单位、是否批次管理、**上市日期**（3C 上市周期法的唯一输入，必须可维护，否则双轨跌价中的 LAUNCH 档空转）。

2. 仓库管理：仓库编码、名称、**仓库类型**（自营 / 平台 / 海外 / 在途 / 虚拟）、所属法人、是否参与存货核算。

    > 注意：**仓库只描述物理形态，不决定权属**。"平台仓的货一定算我们的"是错误假设——权属由一级货主决定。

3. 货主管理：一级货主（= 法人主体，与金蝶账套一一对应）、二级货主（= 内部管理维度，如部门、事业部、代采项目）。每个货主维护是否为内部主体、是否关联方、生效区间。一级货主编码属 **A 级主数据**，一旦发布永不复用。

4. 单位换算管理：物料编码 + 业务单位 + 基本单位 → 换算率。**核算一律以基本单位数量为准**；换算率未维护时**拒绝入账**，不允许按 1:1 兜底。

5. 计价方法配置：按**核算单元** `(商品, 仓库, 一级货主)` 配置。一期同时支持三种方法——**移动加权平均 `MA`（全局默认）、个别计价 `SI`、先入先出法 `FIFO`**；配置缺失时回落全局默认 `MA` 并告警。

6. 跌价规则配置：库龄档与上市周期档各自的分段天数与计提比例。

7. 费用分摊规则：单据类型 + 费用类型（运费 / 关税 / 其他）+ 分摊基准（按金额 / 按数量 / 按重量）。

8. 供应商与客户档案：含纳税人识别号、是否关联方（决定合并层是否需要抵消）。

9. 二级内部结算价目表：按物料、转出方、转入方维护，支持**固定价**与**加成价**两种形式，带生效起止日期与审批状态。

10. 系统参数：一期只用一项——**负库存容差**，默认 0（即**禁止负库存**，出现负数量按 `E-NEGATIVE-QTY` 拒收）。

11. **组套与拆装（一期不做）**：不建组套主数据、不支持拆装单。若存在"一套商品拆成单件卖"或"单件组装成套"的业务，须先明确成本还原规则（按组套成本比例还原到子件，还是按子件成本重建组套成本）——**该口径待确认（外部输入 D-08）**。确认前组套与拆装一律按独立物料处理，不自动还原成本。

## 2.2 数据接入

1. 接入方式：**API 对接为主，Excel/CSV 文件导入保留**。两种入口**共用同一套校验、同一套幂等、同一套错误回执**——文件导入不是另一条技术路线，只是同一套字段的另一种装载方式。

2. 报文结构：所有报文共用一个信封（批号、来源系统、字段版本、对象类型、推送时刻、记录数、记录数组）。**法人不进信封**——法人是行级属性，一批里可以混法人。

3. 对象类型：主数据、单据、动作报文、数量快照（业务 → 财务），价值回传（财务 → 业务）。

4. 校验与错误回执：报文校验、主数据存在性、枚举、单位换算、四轴完整性、货主上下级、跨法人判定、期间锁账、负库存——**13 个错误码全部在校验层产生**，拒收时必须能说清**哪一行、哪个字段、错在哪**。

5. 幂等：分三层——**传输幂等**（按行，防同一条报文重推）、**事件幂等**（按单据，防同一版本的同一单据算两次）、**结果幂等**（引擎是纯函数，输入相同则输出逐位相同）。重复的请求返回**零变化**而不是报错——报错会让上游以为失败而无限重试。

    但判重必须分两支：**键命中且行集合完全相同** → 返回零变化（幂等重推）；**键命中但行集合不同** → 返回**冲突错误**。第二支绝不能也返回零变化——那会把"同一个键携带了不同内容"静默吞掉，是资金与库存错账的入口。

6. 数量快照：业务侧在日切时点出具 `(物料, 仓库, 批次)` 维度的数量，**不含金额**，专供数量对账比对。快照同时携带 `owner_l1`（一级货主）与 `is_internal`（是否内部主体）两个标记——前者用于货主层对账（视 O-07 落地情况而定），后者用于存货总额口径核对。

7. 明确不需要业务侧提供的数据：本系统自算的成本、出库成本、库存金额；库位、货架、拣货路径等仓储执行细节；订单主体；审批流节点；非库存类单据。

## 2.3 单据处理

1. **11 类单据**：采购入库、采购退货、销售出库、销售退货、调拨、盘点、其他入库、其他出库、一级货权转移、二级货主重分配、期间补录。

2. 单据分三组：

    - **A 组·伴随物理移动**：采购入库/退货、销售出库/退货、调拨、盘点、其他出入库；
    - **B 组·不动实物只动权属**：一级货权转移、二级货主重分配；
    - **C 组·账面进出实物不动**：直发、库内转手、空转。

    B 组与 C 组无法塞进采购/销售单据，因此必须有独立的货权变更单与独立的判定规则。

3. **调拨的实现方式**：一张单 + 两行，两行单据类型都是"调拨"，靠仓库编码与出入方向区分，**共用同一个单号**。不拆成"调拨出库单 + 调拨入库单"——拆了会让幂等键失效，重推即重复入账。

4. **调拨与一级货权转移的判定（只一条）**：调出仓与调入仓是否属**同一**一级货主——是则走调拨（按成本同额结转，**不产生任何损益**）；不是则必须走一级货权转移。业务推错的，财务侧**拒绝并回执**，**不做自动升级**（自动升级等于财务替业务定价）。

5. 单据状态分三个位：**业务状态**（草稿 / 已提交 / 已审核 / 生效 / 作废，业务侧维护）、**红冲标记**（财务侧维护，业务不推）、**核算状态**（待核算 / 已核算 / 已冲销，财务侧维护）。

6. **作废闸门是核算状态，不是"有没有下游引用"**。已核算的单据一律不可撤销，只能走反向单 + 红字凭证。

7. 改单：原单未核算时直接替换；已核算时**追加两组事件**（反向事件 + 新的正向事件，版本号 +1），**不是删了重来**。

8. 其他出入库的分项：其他入库按金额来源分五类（原物归还、受赠入库、受托代销/寄售、借入他方货物、无对价杂项）；其他出库按是否回来分六类（内部领用、报废毁损、赠出送样、借出、委托代销发出、货权已转实物才出库）。**只有内部领用、报废毁损、赠出送样是真费用**，其余不是。

    > **盘盈不走其他入库**——盘盈由盘点单（`STOCKTAKE`）自动派生，不从这条通道进。

9. 暂估与发票到达是**两个独立事件**，业务侧必须分别推送。差额**不追溯重算，只调当期**。

10. **以旧换新（一期不设独立单据）**：拆成"一笔销售出库 + 一笔旧货入库"两张单推送。收回旧货走哪条路**待确认（外部输入 D-07）**——候选一，按"不含税金额 = 折价额"作采购入库；候选二，按其他入库 `IN-1` 原物归还处理、金额来源另定。确认前一律按**不含税公允价值**入账、科目走营业外收入，**不按零对价只增数量**。

## 2.4 存货核算

1. 核算维度：**余额表按四轴** `(物料, 仓库, 批次, 一级货主)`；**核算单元（均价池）只有三轴** `(物料, 仓库, 一级货主)`——**批次不进均价池**。批次只影响库龄与跌价基数。

    > 为什么批次不进均价池：若按批次各建一个均价池，同一核算单元内会出现多个互不独立的均价，出库时该取哪个池无法判定。

    一期即同时启用移动加权平均、个别计价、先入先出法三种方法；**个别计价与先入先出法单元额外启用成本层 `t_inventory_layer` 承载批次 / SN 级成本**，成本层是核算单元的内部成本明细，批次仍不进均价池、不改变余额表与全部报表的粒度。

2. **入库成本口径（最上游的一个数）**：`入库入账金额 = 不含税金额 + 本行分摊的采购附加费用`。**税额绝不进成本**——税额只进"应交税费—应交增值税（进项税额）"。含税金额进成本会同时虚增存货、少计进项税，**两个错一起犯**。

3. **在移动加权平均单元中，只有采购入库会改变移动平均单价**；**个别计价与先入先出法单元则表现为新建成本层**。其余所有场景都在"消费"这个价。两个例外改的是另一个核算单元的均价：调拨的入库腿、一级货权转移的转入侧。

4. 入库：重算均价（新金额 ÷ 新数量，单价保留 6 位）。**入库只舍入单价，不回改金额**。

5. 出库：取当前核算单元均价，出库金额 = 数量 × 均价（保留 2 位）。**出库不重算均价**。

6. **舍入差异只在出库产生**（出库金额是算出来的，落 2 位必然有尾差），按笔累加，月末用一张独立凭证一次性结转。

7. 出清：出库后数量归零但金额不为零时，剩余金额全额结转。

8. 销售退货入库按**原出库成本**回冲；采购退货出库按**当前均价**结转，差额进当期损益。这两个方向相反，是"撤销历史"与"当下成交"的区别。

9. 过账顺序：**按业务日期 + 当日序号**，同日**入库优先**，同类型按单号。**单号不能当排序键**（单号不单调、有补单、有外部单号、有前缀差异）。

10. 并发：同一核算单元串行、跨核算单元并行。锁的最小单位就是核算单元——锁整张表吞吐崩塌，锁单行保护不了均价。

11. 余额的持久化用**乐观锁**（按维度键 + 版本号更新，影响 0 行则重查重算重写）。不用"读出来算好再写回去"。

12. 数量守恒与金额守恒是引擎出口的**硬校验**，不通过则整单回滚，**错误数据根本不落库**。

## 2.5 货权变更（重点）

1. 这是本系统**存在的理由**。货权变化分四类事件：伴随物理移动的（采购、销售、退货）与不伴随物理移动的（**一级货权转移**、**二级货主重分配**）。后两类必须独立成单。

2. **一级货权转移（法人之间）**：

    - 必作价——价格来自交易数据，财务**只取价、只校验，不做定价**；
    - 必出凭证；
    - 必产生会计损益；
    - 集团内主体之间转移的，还必须在合并层做**未实现损益抵消**。

3. **二级货主重分配（部门/代采项目之间）**：

    - 按内部结算价作价（政策数据，来自带生效期的价目表）；
    - 差额进二级内部损益，属**管理口径**；
    - **不出会计凭证**——二级货主不是法人、不是会计主体。

4. **二级层"一个数量、两个金额"**：

    | 金额 | 怎么算 | 能不能加总回一级层 |
    |---|---|---|
    | 会计分摊额 | 二级数量 × **一级层均价** | **能**——这是硬校验，不平整单回滚 |
    | 内部结算额 | 按内部结算价逐笔累计 | **不能**——差额即内部未实现毛利，**不做等式校验** |

    > 对第二个金额做等式校验是把管理口径当会计口径，会天天误报。

5. 五条派生规则：

    | 规则 | 内容 |
    |---|---|
    | R1 | 一级货权转移必作价、必出凭证、必产生会计损益 |
    | R2 | 二级重分配按内部结算价作价，差额进二级内部损益（管理口径），不出会计凭证 |
    | R3 | 存货均价池只在一级层建立；二级另维护内部结算价（独立于均价池，不参与加总） |
    | R4 | 存货总额 = Σ 一级层中"内部主体"的金额，**二级层绝不相加** |
    | R5 | 二级内部结算价不影响会计——不影响一级层成本、存货总额、会计凭证、跌价计提 |

6. 取价三条铁律：**按业务日期取价 → 取到即快照 → 调价不追溯**。第二条尤其重要：取到的价必须写进单据行，重算不回查配置，否则调一次价，历史内部损益全变。

    五种价格类型必须分清，混用即口径事故：`biz_price` 业务价（业务侧的原始报价）· `cost_price` 存货成本价（本系统算出的核算单元均价）· `transfer_price` 一级货权转移作价（**交易数据**，交易双方确定，财务只取价、只校验、不定价）· `internal_price` 二级内部结算价（**政策数据**，财务维护的带生效期价目表，支持固定价与加成价）· `financing_fee` 资金占用 / 服务费（**一期未落地**）。一级作价来自交易数据、二级作价来自政策数据，**绝不互相推导**。

7. 作价在凭证上表现为"一个价、三个数"：基准价、加成率、最终取值。固定价时基准价与加成率为空；加成价时三者都有。

8. 一级货权转移有四个子形态（集团内跨法人货同仓 / 集团内跨法人货也移动 / 对外转移货留我方仓 / 对外转移货随货权走），四种的账务处理不同，其中"货留我方仓"是代采业务的典型形态。

9. 撤销规则：**已核算的一律不可撤销**，只能开反向货权变更单 + 红字凭证。

10. 一期由本系统出具"货权变更单"临时承载，二期整体搬迁至产权交易中心。**迁移换生产方，不改数值**。

## 2.6 库存查询与报表

1. 库存余额查询：按四轴组合查询数量、金额、均价；支持按货主、按仓库、按批次、按物料类别过滤；**必须能单独列示虚拟仓与在途仓的余额**。

2. 收发存明细：期初 + 本期入 − 本期出 = 期末，数量与金额两列并列。数据源自期间快照，可重建。

3. 单价追溯：任一时点的任一笔出库金额，可反推到"用了哪个价、这个价从哪来、由哪几笔入库构成"。这是对"成本可追溯"这一目标的直接兑现。

4. 库龄查询：按批次下钻的库龄分布，是跌价计提的输入。

5. **两个数量口径必须分开命名**：在库数量（物理在库，仓库口径，含代销与借入）与权属数量（归属某一法人，货主口径，不含外部法人）。

6. **两个金额口径必须并列展示、必须带口径标注**：库存金额（存货口径，对外唯一权威值）与内部结算金额（管理口径，非会计，**不允许单独当作"库存金额"使用**）。

7. 批次日清、金额月结——查询页上的每个数字都要能标出"这是哪个口径、截止哪个时点"。

## 2.7 跌价计提

1. 计提范围：**只对内部主体（`is_internal = 1`）的库存计提**。外部货主的货不进存货，也不计提。

2. 计提维度：下钻到 `(物料, 仓库, 批次, 一级货主)`。

3. **双轨取孰高**：

    - **库龄法**：按入库时间分层排队，逐层按库龄档取比例，汇总；
    - **上市周期法**：按物料上市日期计算上市天数，按档取比例，作用在当前在库金额上；
    - **最终计提 = 两者取高**（逐项取高再汇总，不是先汇总再取高）。

4. 本期计提 = 本期应有准备 − 上期已计提。正数补提、负数转回。**凭证只记变动额，不是记应有额**。

5. 凭证按法人分别出，不做集团合并出账。

6. 库龄分档与上市周期分档的比例是**建议默认值**，需财务部确认后写入配置。

## 2.8 凭证生成

1. **13 个凭证模板**：采购入库、销售出库、调拨、盘亏、盘盈、跌价准备、舍入差异结转、采购退货出库、销售退货入库、一级货权转移、集团内未实现损益抵消、其他入库（受赠入库）、其他出库。

2. 三条总则：**借贷必平**（不平拒绝落库）、**按法人分账**（合并层凭证单独标记来源）、**凭证日期 = 记账期间首日**。

3. 二级货主重分配**不产生凭证**，但有一张分摊账承载"一个数量、两个金额"。

4. 凭证上**绝不出现二级货主**——辅助核算只带一级货主。

5. 科目映射按单据类型、借贷方向、物料类别、仓库类型、价差类型等维度取**最具体的一条**。价差三分类（价格差 / 数量差 / 汇率差）**不可合并**，分别落不同科目。

6. 一期**不直推金蝶**，只生成凭证清单并按金蝶格式导出 Excel，由财务手工过账。

7. 采购入库凭证的**贷方必须分腿**：「应付账款—货款（不含税 + 进项税额）」与「应付账款／其他应付款—运杂费（本行分摊的采购附加费用）」。合并成一条会让分录不平——含税货款并不包含附加费用。采购退货出库方向相反、同理。

8. **其他入库与其他出库的科目去向**：

    - 其他入库（受赠入库）——借：库存商品（不含税公允价值）／贷：营业外收入；
    - 其他出库——内部领用 → 借：管理费用或销售费用（按领用部门）；报废毁损 → 借：待处理财产损溢；赠出送样 → 借：销售费用；三类均贷：库存商品。**只有这三类是真费用。**
    - 其他出库第 6 类"货权已转、实物才出库"**不生成凭证**——会计影响已在一级货权转移出账时发生，此笔只结转数量、不动金额。
    - 以上科目口径**待财务部最终确认**。

9. 集团内未实现损益抵消**含回转**：内部购入方把该存货对外售出时，按已售出比例**回转**原抵消分录；期末按"已对外售出数量 ÷ 内部购入数量"拆分已实现与未实现。

10. **期间补录单不新建模板**——按补录所涉业务实质套用对应模板，凭证来源标记 `PERIOD_ADJUST`，并附原业务日期用于追溯。

11. **出口退税一期不在本系统落地**。触发条件与计算方法**待财务部税务确认（外部输入 D-13）**；确认前出口业务的存货成本按普通销售出库口径结转，退税单独列示、不并入成本。

## 2.9 对账

1. **两条对账口径不能混用**：

    | 对账项 | 跟谁对 | 维度 | 频率 |
    |---|---|---|---|
    | 数量对账 | 业务库存中心的**日切快照** | `(物料, 仓库, 批次)`；能否上到货主层取决于业务侧是否建货主维度 | 日 |
    | 金额对账 | **金蝶总账**存货类科目余额 | 法人层 + 合并层两段 | 月 |

    > 数量对账能否上到货主层，取决于业务库存中心是否也建货主维度——这是**唯一一项我方给不出默认值的外部依赖（O-07）**。未落地前，数量对账按 `(物料, 仓库, 批次)` 比对，货主层降级为财务侧自查。

2. **数量求一致，金额求可解释**——这是最重要的一句话。数量差一个都要查清楚；金额允许不一致，但**必须能解释差额的构成**（计价方法、费用分摊、舍入规则）。

3. 一致性分级：编码、数量、日期、批次、货主这五样属**强一致**（错一个就是事故）；金额类全部属**各自独立**（对不上是正常的，解释不清才是事故）。

4. 差异定位：先分类（数量差异还是金额差异，两者对手不同，绝不混着报）→ 数量差异按物理层下钻到具体单据、由责任方修数据重推；金额差异先确认数量已一致、再逐项核口径。

5. 处理时效：数量差异 T+1 定位、T+3 处理完成；金额差异月结前 5 个工作日定位、前 3 个工作日完成。

6. 对账结果与差异定位报告入库留痕，作为月结的输入之一。

7. **对账程序必须用与引擎不同的实现**——同一份代码自己校验自己，等于没校验。

8. **自证对账**：用事件日志重放重建余额，与投影余额逐行比对，两条路径的实现必须独立。这是引擎"可重建"这一设计前提的自身证明，与"跟业务对数量、跟金蝶对金额"是两回事，不能互相替代。

## 2.10 期间与月结

1. 期间管理：引入会计期间与**锁账标志**。**日结只做校验、不锁账；月结即锁账**。

2. **月结六关**：

    1. 日常对账（数量日清、金额月结）
    2. 守恒校验（数量守恒、金额守恒、二级会计分摊额加总校验）
    3. 跌价计提
    4. 舍入差异结转
    5. 凭证生成与导出
    6. 月结对账与报表定稿

    六关串行通过后归档期间快照、回传库存价值月报、打上锁账标志。

3. **锁账后的三条路，语义不同、不可互换**：

    | 情形 | 走哪条路 |
    |---|---|
    | 账还没锁、单据要改 | **改单**（追加两组事件，版本号 +1） |
    | 账已锁、"上次结错了" | **反结账**（须审批留痕，重开后重放受影响区间、重建凭证、重新锁账；旧快照版本保留） |
    | 账已锁、"漏了一笔" | **当期补录单**（必审；**一律按当期口径量价**，原业务日期只用于追溯） |

4. 反结账**禁止"回滚 / 删行重推"**——那会让三种幂等、重放与审计同时失效。正确做法是追加反向事件与修正事件。

5. 迟到单据：**已锁账期间禁止入账**，确需补记走当期补录单。

6. 审批：一期**不建审批流引擎**——保留"待审 / 已审核"状态位与一个审核动作，记录审核人与审核时间；预留审批网关接口，二期换实现不动调用方。

## 2.11 价值回传

1. 财务侧在月结后向业务库存中心回传**库存价值月报**，内容包括：成本单价、库存金额、库龄分布、跌价准备。

2. **两个金额口径并列回传、且必须带口径标注**。这看似是细节，实则是最容易复发的一条红线：业务侧若拿"内部结算金额"当"库存金额"用，两个数字就会打架，且因为契约里写了、实现里没区分，比单纯的算错更难发现。

3. 业务侧展示"库存金额"时，**只能引用存货口径那一行**；内部结算金额必须与存货口径成对出现。

# 三、报表与第三方系统

## 3.1 报表

1. **库存余额表**：按四轴展示数量、金额、均价；支持按货主、仓库、批次、类别下钻；**虚拟仓与在途仓可单独列示**。

2. **收发存明细表**：期初 + 本期入 − 本期出 = 期末，数量与金额并列；按法人分账。

3. **单价追溯表**：从任一笔出库金额反推取价来源与构成过程，用于审计与答疑。

4. **跌价计提表**：按四轴逐行展示库龄法金额、上市周期法金额、最终取孰高后的应有准备、上期已计提、本期变动额。

5. **库存价值月报**（对外分发）：向业务库存中心回传的成本单价、库存金额、库龄分布、跌价准备；**两个金额口径并列并标注**。

6. **对账与差异报告**（配套）：数量对账差异清单、金额对账差异清单、差异定位结论。

## 3.2 第三方系统

1. **业务库存中心**

    业务关联说明：通过 API 对接（Excel/CSV 导入保留），接收主数据、11 类单据流水、动作报文与库存数量快照；同时向业务侧回传库存价值月报。**这是本系统唯一的外部依赖方**。

2. **金蝶总账**

    业务关联说明：本系统是**唯一成本源**，金蝶侧关闭存货核算；存货与成本凭证由本系统生成凭证清单并导出 Excel，由财务手工过账。**金额对账以金蝶总账存货类科目余额为基准**。

3. **产权交易中心**

    业务关联说明：**一期不落地**。一期的货权变更由本系统出具"货权变更单"临时承载，按可剥离形态设计（自带价格与来源、状态机自洽、事件驱动、不直接改余额），二期整体搬迁时换生产方、不改数值。

4. **审批/OA 系统**

    业务关联说明：一期**不集成**。保留待审/已审核状态位与单点审核动作，预留审批网关接口，二期可接入集团统一审批流而不改动调用方。

# 四、重难点和用户期望

- （决策层）**痛点**：集团有多个法人主体，法人之间的货权转移既不开票、也不走销售流程，财务手工判断记不记账、记多少，全凭经验，合并报表时内部利润虚增查不出来；**期望**：一级货权转移必作价、必出凭证、必产生损益，集团内的自动在合并层抵消，任何一个对外数字都能带口径标注。

- （决策层）**痛点**：库里的货"在不在我的仓"和"算不算我的存货"长期混在一起，代销、寄售、借入、已售未发几种情形的账务处理没有统一规则，口径不一致导致存货总额说不清；**期望**：权属由货主决定而不是由仓库决定，同一套规则覆盖全部情形。

- （决策层）**痛点**：成本口径依赖金蝶的存货核算，规则不透明、不可追溯到单据，任一对外数字追溯不回去；**期望**：任一时点的任一笔出库成本都能反推到"用了哪个价、这个价从哪来"。

- （管理层）**痛点**：业务侧也有"库存金额"报表，但算出来的数与财务不一致，两个数字打架，每次都要人工解释；**期望**：明确金额的权威方是财务，业务展示金额必须标注口径来源，且两个金额口径必须成对出现。

- （管理层）**痛点**：3C 商品的贬值由新品发布驱动而不是由时间驱动，只按库龄计提会严重低估跌价；**期望**：库龄法与上市周期法双轨取孰高，3C 商品在新品发布后能及时反映减值。

- （管理层）**痛点**：月末结账前要跑大量人工核对，结完账发现错了只能手工改表，改完又不知道影响了哪些数；**期望**：月结六关串行、结完即锁账；结完账发现"结错了"走反结账、"漏了一笔"走当期补录，两条路各自留痕。

- （管理层）**痛点**：跨期补一笔账时，按原业务日期回填会把已经出过的报表数字改掉，报出来的数与当时报出去的数不一致；**期望**：跨期补录一律按当期口径量价，原业务日期只用于追溯，不改历史。

- （管理层）**痛点**：其他出入库的场景五花八门（内部领用、报废、赠样、借出、委托代销、货权已转实物才出库），塞进自由文本的"原因"里，事后想统计一笔费用都统计不出来；**期望**：按金额来源和"会不会回来"分类，每类有明确的金额来源与科目去向。

- （执行层）**痛点**：业务推来的单据里带着自己算的成本和金额，与财务算法不一致，每次都要人工判断以谁为准；**期望**：业务只推事实与原始价格输入（采购价、税率、运费关税），成本与金额一律由财务算，推来的成本财务侧一律忽略。

- （执行层）**痛点**：同一个仓库、同一个批次下有两个货主时，按仓库看库存两个货主的数量会互相抵消，真实的差异被隐藏，事后无从追溯；**期望**：余额按物料、仓库、批次、货主四个维度记录，货主维度不可省略。

- （执行层）**痛点**：调拨单和跨法人的货权转移单混着推，推错了要人工退回、口头说明、再让对方重推，来回沟通成本高；**期望**：系统按"调出调入是否同一货主"自动判定，推错时明确拒绝并回执原因，不自动升级。

- （执行层）**痛点**：运费、关税这类采购附加费用靠手工分摊，分摊方式每次不一样，入库成本随之波动；**期望**：分摊规则按单据类型与费用类型配置，分摊基准可选金额/数量/重量，一次配置持续生效。

- （执行层）**痛点**：单位换算靠人工按 1:1 或凭经验折算，换算率没维护时也不报错，导致数量口径悄悄错掉；**期望**：核算一律以基本单位数量为准，换算率未维护时直接拒绝入账，不做兜底。

- （执行层）**痛点**：业务改了单、作了废，财务侧毫不知情，账实不符越滚越大；**期望**：改单与作废必须发通知，已核算的一律不可撤，只能走反向单加红字凭证。

- （执行层）**痛点**：同一批数据推两次就重复入账，网络重试、消息重投、手工重跑都会造成重复；**期望**：三层幂等——传输层按行去重、事件层按单据去重、引擎本身是纯函数，重复请求返回零变化而不是报错；但同一个键携带了不同内容时必须报冲突，不能也返回零变化把变更悄悄吞掉。

- （管理层）**痛点**：上线切换没有明确边界，回滚时不知道该保留什么、销毁什么，事后说不清哪些数字已经对外报过；**期望**：并行 1 个完整月结周期、逐月比对；回滚只切换权威方，已生成的凭证清单与事件日志一律保留、不删除。

- （管理层）**痛点**：组套拆装、以旧换新、出口退税这类边缘业务没有明确口径，开发时各按各的理解做，做出的结果互相不认；**期望**：一期明确不做的业务一律写明"不做 + 候选口径 + 待确认项"，不留空白给人猜。
