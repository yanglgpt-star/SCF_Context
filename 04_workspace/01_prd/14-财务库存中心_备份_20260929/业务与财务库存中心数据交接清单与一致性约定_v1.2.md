## 0. 文档目的

业务库存中心（上游，管实物与数量）与财务库存中心（下游，管价值与金额）是两个团队各自建设的系统。两者之间唯一必须提前谈定的东西就是**数据契约**：给什么、给到什么颗粒度、哪些必须一模一样、哪些允许不一样。

本文件回答四个问题：

1. **业务库存中心应该输出哪些数据？**（第 2 章 · 交接清单）
2. **哪些数据两边必须保持一致？**（第 3 章 · 一致性矩阵）
3. **每个数据由谁定义、往哪个方向流、谁有权改？**（第 4 章 · 定义权归属）
4. **不一致时怎么办？**（第 7 章 · 差异处理流程）

## 1. 总原则

### 原则一：单一事实来源（Single Source of Truth）

每一类数据只能有一个"权威来源"，另一方只读不改：

| 数据类别 | 权威来源 | 另一方 |
|---|---|---|
| 物料、仓库、供应商、客户、批次/SN 档案 | **业务库存中心** | 财务只读（可补维护财务专用字段） |
| **一级货主编码（= 法人主体）** | **双方共同确认后由业务维护** | 财务只读；**A 级主数据，须一字不差** |
| 数量、仓库归属、单据业务事实 | **业务库存中心** | 财务只读 |
| 采购价格、进项税、采购附加费用 | **业务/采购系统** | 财务只读 |
| **一级作价（`transfer_price`）** | **交易数据（销售单 / 合同 / 逐笔录入）** | 财务**只取价 + 校验，不做定价** |
| **二级内部结算价（`internal_price`）** | **财务库存中心价目表 `t_internal_price`**（一期） | 业务只读引用；二期随产权交易中心迁移 |
| 成本单价、库存金额、跌价准备、凭证 | **财务库存中心** | 业务不参与 |
| 库存数量快照（对账用） | **业务库存中心** | 财务用于比对 |
| **总账金额（对账用）** | **金蝶（总账系统）** | 财务侧对账比对 |

> 双写必冲突。任何一方"顺手也算一下"的地方，最后都会变成对不上的账。
>
> **作价的两个来源必须分清**（设计 `0.4` / 框架 4.6）：**一级作价是交易数据**（来自对外销售单、合同或集团内逐笔录入），财务中心**不做配置、不做定价**，只按业务日期取价 + 校验 + 快照；**二级作价是政策数据**，做成带生效期的价目表，**按业务日期取价、取到即快照、调价不追溯**。

### 原则二：业务提供"事实"，财务做"解释"

业务推过来的每一行都是**不可再解释的事实**：某天、某仓、某物料、进出多少数量。财务的职责是基于事实和会计政策，算出"这批货值多少钱"。

因此：

- 业务**不要**推成本、金额（调拨成本、出库成本、库存金额），推了也会被财务忽略，只会造成口径混乱；
- 业务**必须**推原始价格输入（采购单价、税率、运费、关税），因为这是财务无法自己知道的原始事实。

### 原则三：数量求一致，金额求可解释

这是本文最重要的一句话：

- **数量维度**：两边必须**完全一致**，差一个都要查清楚（数量是客观事实）；
- **金额维度**：两边**允许不一致**（业务按采购价估、财务按移动平均算，本就不同），但**必须能解释差额的构成**（计价方法、费用分摊、舍入规则）。

> 对账时把"数量差异"和"金额差异"混在一起报，是财务库存项目最常见的返工原因。数量差异是数据问题，金额差异多数是口径问题，处理方式完全不同。

## 2. 交接清单：业务库存中心应该输出什么

### 2.1 主数据（一次性初始化 + 增量同步）

| 主数据 | 业务必须提供 | 财务自行维护（业务不用管） |
|---|---|---|
| **物料** | 物料编码、名称、规格、计量单位、物料类别、是否批次管理、是否 SN 管理、**上市日期（3C 必备）**、启用状态、更新时间 | 计价方法、跌价规则类别、默认会计科目 |
| **仓库** | 仓库编码、名称、**仓库类型（自营仓 / 平台仓 / 海外仓 / 在途 / 虚拟仓）**、**所属法人（= 一级货主）**、是否参与库存核算 | 仓库对应的科目映射 |
| **一级货主** | **货主编码、名称、是否法人、所属账套（金蝶）、是否内部（`is_internal`）、生效区间** | 存货总额与跌价以此层为准 |
| **二级货主** | 货主编码、名称、所属一级货主 | 内部结算价、分摊账 |
| **供应商** | 供应商编码、名称、纳税人识别号、是否关联方、往来单位类型 | 应付科目映射 |
| **客户** | 客户编码、名称、纳税人识别号、是否关联方 | 收入/成本科目映射 |
| **批次 / SN** | 批次号或 SN 号、物料编码、生产/入库日期、有效期（如有） | 库龄计算、跌价归属 |
| **单位换算** | 物料、业务单位、基本单位、换算率、生效区间 | 换算率缺失时拒绝入账 |

**五条硬要求**：

1. **编码一旦发布，永不复用**。停用物料重新启用给新货，是财务库存最致命的坑——历史成本会串到新物料上。
2. **上市日期（launch_date）必须可维护**，且用于 3C 上市周期跌价计提。没有它，跌价双轨的 LAUNCH 档就是空转。
3. **SN 号必须出现在出库单据行上**（**一期硬要求**），否则个别计价（每台单独结转成本）无法落地。
4. **一级货主编码是 A 级主数据**（F18）——它是库存的第四根轴，也是法人归集与凭证账套的依据。编码不一致，两个系统无法按法人对账，**跨法人转移与合并抵消全部落空**。
5. **单位换算率由谁权威必须谈死**（F10）——**核算一律以基本单位数量为准**，业务单位只作展示。换算率缺失时**拒绝入账并回执**，**不允许按 1:1 兜底**（静默兜底会让数量对账永远差一笔）。

> **仓库类型与存货权属是两件事**（F14 + C-12）：仓库类型描述**物理/运营形态**（自营仓、平台仓、海外仓、在途、虚拟仓）——原来的"原料库/成品库/在制品库"是**制造业**分类，与本项目纯贸易/电商画像不符。**存货权属不挂在仓库上**——四轴引入后，同一批货在不同一级货主下权属不同，与放在哪个仓无关；权属由**一级货主的 `is_internal`** 决定。

### 2.2 单据流水（日常推送的核心）

必须推送的单据类型清单（共 **11 类**，覆盖纯贸易/电商全场景 + 货权变更）：

| 序号 | 单据类型 | 方向 | 典型业务场景 | 定义方 |
|---|---|---|---|---|
| 1 | 采购入库 `PO_IN` | 入库 | 供应商到货入库 | 业务 |
| 2 | 采购退货出库 `PO_RET` | 出库 | 退回供应商 | 业务 |
| 3 | 销售出库 `SO_OUT` | 出库 | 发货给客户 | 业务 |
| 4 | 销售退货入库 `SO_RET` | 入库 | 客户退回 | 业务 |
| 5 | 调拨 `TRANSFER` | 双向 | **同一一级货主**下的仓间转移（必须含调出、调入两个仓） | 业务 |
| 6 | 盘点 `STOCKTAKE` | 双向 | 盘盈 / 盘亏 | 业务 |
| 7 | 其他入库 `OTHER_IN` | 入库 | 借用归还、赠品、样品回收 | 业务 |
| 8 | 其他出库 `OTHER_OUT` | 出库 | 领用、报废、赠出、借出、样品送出 | 业务 |
| 9 | **一级货权转移 `OWNER_TRANSFER`** | 双向 | **跨法人**货权转移（视同销售） | 业务 + 财务 |
| 10 | **二级货权重分配 `OWNER_REASSIGN`** | 双向 | **同一法人体内**二级货主之间的重分配 | 财务（管理口径） |
| 11 | **跨期补录 `PERIOD_ADJUST`** | 双向 | 已锁账期间发现漏记时的唯一通道（**必审**） | 财务 |

> **前 8 类由业务推给财务**；**9 / 10 是一期货权变更的临时载体**（产权交易中心二期才落地，届时搬迁过去）；**11 是财务侧的单据**，业务不推。
> **跨法人不是调拨**：调出仓与调入仓不属于同一一级货主时，业务不能推 `TRANSFER`——应推 `OWNER_TRANSFER`。财务侧适配层会**拒绝并回执原因**，**不做自动升级**（自动升级等于财务替业务定价）。

**每行单据必须携带的字段（最小集）**：

| 字段 | 必填 | 说明 | 一致性等级 |
|---|---|---|---|
| 单据号 | Y | 业务系统唯一单号 | A |
| 行号 | Y | 单据内行序，与单据号共同构成唯一键 | A |
| 单据类型 | Y | 上表 11 类之一，语义须与控制表一致 | B |
| 业务日期 | Y | 决定入账期间与成本计算顺序 | A |
| 仓库编码 | Y | 调拨单需调出、调入两个 | A |
| **一级货主** | **Y** | **库存第四根轴；法人归集与凭证账套的依据** | **A** |
| 二级货主 | **Y** | 内部管理维度，但**行级必填**（缺失即 `E-OWNER-L2-MISSING`：二级货主缺失） | B |
| 物料编码 | Y | 必须已存在于财务侧主数据 | A |
| 数量 | Y | 业务单位数量 | A |
| **基本单位数量** | **Y** | **核算一律以此为准**；可空则由换算表推出 | **A** |
| 计量单位 | Y | | A |
| 批次号 / SN | 条件必填 | 批次管理的物料必填；3C 整机必须有 SN | A |
| 来源单号 | N | 上游订单号，便于追溯 | C |
| 制单人 / 最后修改时间 | N | 便于排查 | C |
| **推送时间 `pushed_at`** | **Y** | **迟到判定的依据**（F15） | **A** |
| **单据状态（业务）** | Y | `DRAFT`/`SUBMITTED`/`APPROVED`/`EFFECTIVE`/`VOID` | B |
| **红冲标记（财务）** | — | 由财务侧维护，业务不推 | C |

> **单据状态为什么拆成两列**（F12）：原契约只有一个"单据状态（生效/已作废）"，把**业务状态**与**财务红冲标记**压在一个字段里。二者语义不同——业务"作废"是业务事实，财务"红冲"是账务处理结果，两者可以不同步（已核算的作废只能走反向单 + 红字凭证）。契约只约定**业务状态**（B 级），**财务红冲标记由财务侧独立维护**（C 级），两边语义对齐但不共用一个字段。

### 2.3 价格与费用输入（财务算不出、只能由业务给）

| 数据 | 说明 | 为何必须业务给 |
|---|---|---|
| 采购不含税单价 / 含税单价 | 二选一，配套税率 | 财务无法凭空知道采购价 |
| 税率 / 税额 | 用于进项税凭证 | 税务属性来自采购 |
| **采购附加费用**（运费、关税、报关费） | 金额 + 分摊方式（按金额/数量/重量） | **最容易被漏掉的一项**，直接决定入库成本 |
| 币种 / 汇率 | 有跨境采购时必填 | 影响成本折算 |
| 估价入库金额 | 无发票入库时由业务或财务给定 | 一期允许财务手工补录 |
| **发票到达 / 结算事件**（`settle_status`） | **暂估入库**与**发票到达**是**两个独立事件**，业务侧须**分别推送**；发票到达时携带**关联的暂估单据号**（`estimate_ref_doc`） | **F19 / D-04**：财务侧收到发票到达事件后才可能做暂估冲回 |

> **⚠️ 暂估入库这一行有两件事，别混成一件**（F19 / D-04）：
>
> | | 内容 |
> |---|---|
> | **为什么必须是两个事件** | 暂估入库时发票未到，金额是估的；发票到达后才是实际价。**合成一个事件，财务侧就永远不知道"估的什么时候变成实的"**，暂估永远冲不掉，存货科目挂着估计值过年 |
> | **推送要求** | 采购入库行带 `settle_status = ESTIMATED`；发票到达时**另推一次**该行（或推结算事件），带 `settle_status = SETTLED` + `estimate_ref_doc` 指向原暂估单 |
> | **一致性等级** | 暂估金额与结算金额均为 **B 级**（业务权威）；**差额的账务处理由财务侧决定**（D-04 锁定为"不追溯、只调当期"，见设计 `5.6.6`），业务侧不推调整分录 |
> | **一期兜底** | 业务侧推不出结算事件时，**财务可手工补录**（本表"估价入库金额"原口径保留）——但**手工补录的每一笔须留痕**，月结时须能列出"手工补录清单" |
>
> **一句话**：业务侧至少要让财务侧**知道"这批货的票到没到"**。给不出结算事件，暂估就退化成永远冲不掉的挂账。

> ⚠️ **建议 W1 就把"运费、关税是否计入存货成本、怎么分摊"谈死。** 这一项漏掉，采购入库成本必然对不上，且发现时往往已经跨月。

### 2.4 库存数量快照（专供对账）

| 项目 | 约定 |
|---|---|
| 内容 | **`(物料, 仓库, 批次)`** 维度的**数量**（物理层）；**是否加一级货主维度见下方 O-07** |
| 时点 | 日切快照（T 日日终，`as_of` 须与财务侧落库一致）+ 月末快照 |
| **是否给金额** | **不给**。业务侧"金额"口径（多为数量 × 最新采购价）与财务移动平均口径必然不同，给了只会制造假差异。**金额对账的对方是金蝶总账，不是业务系统**（F04） |
| 用途 | 数量对账的**唯一**比对基准 |

> **快照维度是否上到货主层——取决于 O-07（契约变更项）**：
>
> 财务侧已把一级货主作为第四根库存轴。业务侧的快照是否也带一级货主，**不由我方单方决定**，须与业务团队协商：
>
> | 情形 | 数量对账维度 | 效果 |
> |---|---|---|
> | **O-07 未决（一期现状）** | `(物料, 仓库, 批次)` | 按**物理层**对账；法人间调拨在两边都不改变物理总量，能对上 |
> | **O-07 确认业务侧也建货主维度** | `(物料, 仓库, 批次, 一级货主)` | 可做到**权属层**对账；能提前发现"货在但权属挂错"的差异 |
>
> **在 O-07 有结论前，一期按物理层对账，不预设"业务侧一定建货主维度"。** 这是本契约唯一的**外部依赖项**，也是本契约 2.4 能否升级的前提。
>
> **`as_of` 必须落到位**（F15）：日切时点不能只在快照表里出现一次，上下游两边要**用同一个时点**——业务侧快照的 `as_of`、财务侧单据的 `pushed_at`、财务侧余额的 `as_of_date` 三者口径一致，否则对账永远差一笔（差的是边界那一天的单据）。

### 2.4b 金额对账的基准（**新增，F04**）

金额对账**不由业务侧提供金额**——业务侧没有金额权威，其"库存金额"多为数量 × 最新采购价，与移动平均口径必然不同。

| 项目 | 约定 |
|---|---|
| 对方 | **金蝶总账**（不是业务系统） |
| 维度 | `(法人, 物料, 仓库)` |
| 层级 | **法人层** + **合并层**（分别出） |
| 频率 | 月结 |
| 差异处理 | 先确认数量已一致（数量未平时金额差异无意义），再核对口径（采购价、运费分摊、舍入、计价方法） |

### 2.5 变更与异常通知

| 通知类型 | 内容 | 时效要求 |
|---|---|---|
| 改单通知 | 原单号 + 修改后完整内容 + 修改时间 | 当日或 T+1；**已锁账期间不可改单**（见 `5`） |
| 作废通知 | 单号清单 + 作废时间 + 作废原因 | 当日或 T+1；**已锁账期间不可作废** |
| 主数据变更 | 编码停用 / 类别调整 / 单位换算变更 | 提前通知，**换算变更只对新单生效** |
| **货主变更** | 一级/二级货主新增、停用、层级调整 | **提前通知**（A 级主数据，影响四轴与账套） |
| 盘点审批结果 | 盘点差异的最终审批结论 | 月结前 |
| 数据补推 | 历史区间补推（含明确区间与原因） | **及时；跨期补推只能走当期补录单**（见 `5`） |

### 2.6 明确**不需要**输出的数据

防止过度交付、也防止职责混乱：

- ❌ 业务侧自己算的成本、出库成本、库存金额（财务不采纳）
- ❌ 库位、货架、拣货路径、作业进度等仓储执行细节
- ❌ 采购订单、销售订单主体（如需要，只提供订单号作为来源单号）
- ❌ 审批流节点、待办状态
- ❌ 非库存类单据（费用、资产、人事）

### 2.7 三层幂等键（**不是一件事**）

传输幂等**只是第一层**——单靠「单据号 + 行号去重」不够，重放（反结账）还会重复触达事件层。三层幂等如下（与《通用数据接口字段定义》v1.0 `§2.6` 一致）：

| 层 | 键 | 防什么 | 重复时的行为 |
|---|---|---|---|
| **传输幂等**（按行） | `batch_id + doc_no + line_no` | 同一条报文重推 | **行集合相同 → 零变化**（自动跳过，计入"去重"而非"失败"）；**行集合不同 → 冲突错误** |
| **事件幂等**（按单据） | `(doc_type, doc_no, version_no)` | 同一版本的同一单据算两次 | **行集合相同 → 返回零 delta 且不报错**；**行集合不同 → 冲突错误** |
| **结果幂等** | 纯函数 `(event, ctx) → Posting` | 重放结果不可复现 | 同一输入必得**逐位相同**的输出 |

> **重复请求返回「零变化」而不是报错**——报错会让上游以为失败而**无限重试**；幂等重推（行集合相同）必须回**零变化**。
>
> **但「键命中而行集合不同」必须报冲突错误**（不是零 delta）——同键携带不同行集合，若一律返回零 delta 会**静默吞掉变更**，酿成资金 / 库存错账。冲突错误码见《通用数据接口字段定义》v1.0 `§2.6`（一期暂用 `E-HEADER-INVALID`，建议二期增 `E-IDEMPOTENT-KEY-CONFLICT`）。

### 2.8 契约缺口 G-08：其他出入库的金额来源标记与权属字段（**字段层待解冻**）

《财务库存中心（一期）出入库场景与数据交接对照》v1.0 `§8` 列出的契约缺口 **G-08**：`OTHER_IN`（其他入库）/ `OTHER_OUT`（其他出库）的**差异化字段目前只有 `reason`**——**缺金额字段、缺「金额从哪来」的来源标记、缺权属表达**（无金额、无 `valuation_source` / `valuation_basis`、无原单号、无 `is_recoverable` 等）。

- **后果**：没有「金额从哪来」的标记，财务无法判断这笔金额该**取数**还是该**估价**，也判断不出要不要审——只能靠 `reason` 里的自由文本**人工逐笔判**。
- **现状**：属**字段层待解冻事项**（待 W1 按《出入库场景与数据交接对照》`§S-05` / `§S-12` 两张「差异字段与举例」表逐类补齐）；**凭证侧已部分缓解**——设计 `§8.1` 已新增 `8.1.12` 其他入库（受赠）与 `8.1.13` 其他出库两个模板，覆盖其他入库（受赠）与其他出库三类真费用；**字段缺失部分仍未解冻**。

## 3. 一致性矩阵（核心章节）

把每一个数据项归入三级之一，双方按级履约：

- **A 级 · 强一致**：必须同源同值，不一致即为缺陷，必须修数据
- **B 级 · 口径一致**：语义、时点、范围定义必须一致，具体值允许不同，但必须可对照
- **C 级 · 各自独立**：各算各的，不要求一致，只要求可解释

| 数据项 | 等级 | 权威来源 | 一致性要求 | 不一致的后果 |
|---|---|---|---|---|
| 物料编码 / 仓库编码 | **A** | 业务 | 一字不差，禁止复用 | 成本串味、历史断链 |
| **一级货主编码** | **A** | **双方确认后由业务维护** | **一字不差，禁止复用** | **四轴断裂、凭证入错账套、合并抵消落空** |
| 供应商 / 客户编码 | **A** | 业务 | 一字不差 | 凭证挂错往来单位 |
| 单据号 + 行号（唯一键） | **A** | 业务 | 一致，用于幂等去重 | 单据重复入账或漏入 |
| 数量 | **A** | 业务 | 完全一致 | 账实不符（必须清零） |
| **基本单位数量 / 换算率** | **A** | 业务 | 完全一致，缺失即拒绝入账 | 数量级错误，最严重 |
| 业务日期 | **A** | 业务 | 完全一致（决定入账期间与成本顺序） | 跨期错账、成本顺序乱 |
| **推送时间 `pushed_at`** | **A** | 业务 | 与 `as_of` 口径一致 | 迟到判定错误 |
| 批次号 / SN 号 | **A** | 业务 | 完全一致 | 库龄、跌价、个别计价全失效 |
| 仓库归属（所属法人） | **A** | 业务 | 一致 | 凭证入错主体 |
| 单据类型语义 | **B** | 业务 | 每类的业务边界须书面定义（**11 类**） | 入出库方向判错 |
| **单据业务状态语义** | **B** | 业务 | `EFFECTIVE`/`VOID` 含义一致 | 已作废单据被计入 |
| **二级货主** | **B** | 业务（**必提供**） | 层级归属一致；**行级必填** | 管理口径报表错分；缺失即 `E-OWNER-L2-MISSING` 行级拒绝 |
| 日切时点 / 快照口径（as_of） | **B** | 双方约定 | 同一时点，不能各取各的 | 对账永远差一点 |
| 组织与仓库分组口径 | **B** | 双方约定 | 报表维度统一 | 报表拼不起来 |
| **对账容差 / SLA** | **B** | **双方书面确认** | 写入契约后即为验收标准 | 一方说"可接受"另一方说"超限" |
| 采购价格、税率 | **C** | 业务 | 提供即可，财务按会计政策使用 | 成本失真 |
| **一级作价 `transfer_price`** | **C** | 交易数据 | 财务只取价 + 校验，不做定价 | — |
| **二级内部结算价 `internal_price`** | **C** | 财务价目表 | 业务只读引用 | — |
| 库存金额 | **C** | 财务 | 不要求与业务一致 | 需能解释差额构成 |
| 成本单价 | **C** | 财务 | 业务不参与 | — |
| 跌价准备 | **C** | 财务 | — | — |
| 会计凭证 | **C** | 财务 | — | — |
| **财务红冲标记 `red_flag` / 核算状态 `cost_status`** | **C** | 财务 | 业务不推、不引用 | — |

> 一句话记忆：**编码、数量、日期、批次、货主这五样是 A 级，错一个就是事故；金额类全是 C 级，对不上是正常的，解释不清才是事故。**
> **`as_of` 落到三处**（F15）：业务快照的 `as_of`、单据的 `pushed_at`、财务余额的 `as_of_date`——三者必须同一口径。只在快照表里约定时点是不够的，边界那天推来的单据会两边各算一次或都不算。

## 4. 定义权与数据流归属（四象限）

第 3 章回答"哪些必须一致"，本章回答更靠前的一个问题：**每个数据项由谁定义、往哪个方向流、谁有权改**。定义权不划清，一致性就是空谈——因为没人知道该按谁的定义去对。

### 4.1 先分清三种权利

同一个字段上其实叠着三种权利，必须分清：

| 权利 | 含义 | 归属规则 |
|---|---|---|
| **定义权** | 这个指标的口径、算法、单位由谁说了算 | 一事一主，只能有一个 |
| **数据权（权威源）** | 这个数据的正本存在谁那里 | 与定义权同源，禁止双写 |
| **变更权** | 改口径要谁签字 | 独立项自主改；共同项必须双方确认 |

> **最危险的结构是"定义权在 A、数据权在 B"**——A 改了口径 B 不知道，两边立刻对不上，且谁也说不清是谁的错。所以本契约的一条基本约定是：**定义权与数据权必须同源**。

### 4.2 四象限归属矩阵

#### 象限① 业务定义 → 推给财务（业务唯一权威，财务只读）

| 数据 / 指标 | 财务如何使用 | 变更权 |
|---|---|---|
| 物料 / 仓库 / 供应商 / 客户 / 批次·SN 档案 | 建立核算维度与科目映射 | 业务；停用、复用须提前通知财务 |
| **一级货主编码（= 法人主体）** | **第四根库存轴；法人归集、凭证账套、合并抵消** | **双方确认后由业务维护；层级调整须双方书面确认** |
| 二级货主（内部管理维度） | 内部分摊账、管理报表 | 业务 |
| **单位换算率（业务单位 ↔ 基本单位）** | **数量换算，核算一律用基本单位** | 业务；**换算变更只对新单生效** |
| 物料上市日期 `launch_date` | 3C 上市周期跌价（LAUNCH 档） | 业务 / 市场 |
| **11 类单据流水**（单号·行号·业务日期·数量·单位·批次SN·**货主**） | 核算引擎输入，一切成本的起点 | 业务（**其中一级作价 `transfer_price` 是交易数据**） |
| 采购不含税价、税率、运费/关税、币种汇率 | 计算入库成本与进项税 | 业务 / 采购；**分摊规则须双方共同定**（属象限③） |
| 库存数量快照（`物料,仓库,批次`，**是否含货主见 O-07**） | 数量对账的唯一基准 | 业务 |
| 改单 / 作废 / 主数据变更通知 | 触发财务侧重算与红冲 | 业务 |

#### 象限② 财务定义 → 回传业务（财务唯一权威，业务只读引用）

| 数据 / 指标 | 财务口径算法 | 业务用途 | 变更权 |
|---|---|---|---|
| **存货成本单价** | 移动加权平均 / 个别计价 / 先入先出法（三法一期均支持，按核算单元配置） | 成本展示、毛利预演 | 财务（随会计政策） |
| **库存金额（存货口径）** | 数量 × 成本单价；**一级货主层、仅 `is_internal = 1`** | **看板 / 报表的"库存金额"必须引用此值**——**这是对外唯一权威值** | 财务 |
| 库存数量（权属口径） | 一级货主层 | 权属视图 | 财务 |
| 库存数量（在库口径） | 物理层（仓库, 批次） | 与数量对账基准一致 | 财务 |
| 库龄 / 库龄分布 | 按批次最早入库日推算，**下钻到一级货主** | 滞销识别、补货参考、清仓 | 财务 |
| 跌价准备 / 减值清单 | 库龄 + 上市周期双轨孰高，**仅 `is_internal = 1`** | 清仓、促销、减值联动 | 财务 + 财务部 |
| 存货周转天数 / 周转率 | 销售成本 ÷ 平均存货 | 经营看板、部门考核 | 财务 |
| 资金占用 | 库存金额 + 库龄加权 | 现金流与采购节奏 | 财务 |
| 收发存报表（金额列） | 财务口径 | 采购、运营看板 | 财务 |
| 财务账面数量 | 核算后余额 | 与实物数量对账 | 财务 |
| **内部结算金额** | 二级内部结算价累计（`internal_amount`） | 二级货主考核、内部分润 | 财务 |
| **内部结算损益** | 内部未实现毛利（`internal_amount − alloc_amount`） | 内部损益分析 | 财务 |

> **这是本契约最重要的一条治理动作**：业务系统里若要有"库存金额"这一列，应**引用财务回传值，不允许业务自算**。第 6 章红线三（双方各算一套成本）由此根治——不是禁止业务展示金额，而是让金额只有一个权威源，业务展示即"消费财务数据"。
>
> **⚠️ 两个金额口径必须并列回传、必须标注口径（C-17）**：二级层是**一个数量、两个金额**——
>
> | 金额 | 口径标注 | 能否加总 | 用途 |
> |---|---|---|---|
> | `alloc_amount`（分摊金额） | **一级货主层 · 存货口径** | **能**加总回一级层（硬校验） | 对外唯一权威值 |
> | `internal_amount`（内部结算金额） | **管理口径 · 非会计** | **不能**加总 | 二级考核，**禁止单独当"库存金额"用** |
>
> **若不区分口径**，业务侧必然挑一个当"库存金额"——**红线三以新形式复发**，而且这次是"契约里写了、实现里没区分"，更难发现。**契约强制一条**：业务侧展示"库存金额"**只能引用存货口径那一行**；内部结算金额必须与存货口径**成对出现**，**单独使用即口径错误**。
>
> 一期没有接口时，回传方式可为：财务侧出《库存金额 / 库龄 / 跌价》报表定期发给业务，或双方共用同一张报表，待接口就绪后改为自动推送。

#### 象限③ 共同定义（双方协商，写入契约，任一方变更需对方书面确认）

| 事项 | 为什么必须共同定 | 拍板方 |
|---|---|---|
| **11 类单据类型的业务边界** | 决定入出库方向与成本影响 | 双方 + 财务部 |
| **一级货主编码规则与层级口径** | 四轴的基础，A 级主数据 | 双方 + 财务部 |
| **调拨 vs 跨法人转移的判定** | 同一一级货主 = 调拨；不同 = 货权转移（视同销售） | 双方 + 财务部 |
| 单据业务状态语义（生效 / 作废） | 决定单据是否计入 | 双方 |
| 日切时点 `as_of` / 快照口径 | 决定对账基准是否同源 | 双方 |
| 组织与仓库分组（报表维度） | 决定两边的报表能否拼起来 | 双方 + 管理层 |
| **计量单位与换算率** | 最严重的数量级差异来源 | 双方 |
| 批次 / SN 编码规则 | 决定追溯与个别计价能否落地（一期） | 双方 |
| 数量精度 / 小数位 | 决定舍入差异大小 | 双方 + 财务部 |
| 采购附加费用的分摊规则 | 决定入库成本口径 | 双方 + 财务部 |
| **对账容差阈值与对账 SLA** | 决定何时判为异常 | 双方（**书面确认，设计不单方设定**） |
| **改单 / 作废 / 跨期处理的例外规则** | 决定重算边界；**已锁账期间不可改单/作废**，漏记走当期补录单 | 双方 + 财务部 |

#### 象限④ 相互独立（各管各的，互不干涉）

| 归属 | 独立事项 |
|---|---|
| **业务侧独立**（财务不介入） | 库位、货架、拣货路径、波次、作业效率、订单履约、仓储 KPI、采购/销售订单主体、审批流 |
| **财务侧独立**（业务不介入） | 会计科目映射、凭证模板与借贷规则、计价方法配置、跌价规则与计提比例、舍入规则与差异科目归属、税务处理、财务核算主体与合并口径、**期间锁账与反结账**、**内部结算价目表（一期）**、审计留痕 |

> 象限④ 的含义是"**不必征求对方同意**"，不等于"对方看不到"。任一方向另一方了解某个指标怎么来的，走只读引用即可，不改变定义权归属。

### 4.3 归类判断规则（遇到新字段怎么定）

四个问题按顺序问，第一个答"是"的就是它的归属：

1. 它是**客观事实**吗（数量、日期、编码、批次、采购价）？→ **象限①**，业务定义，推给财务
2. 它是按**会计政策算出来的价值**吗（成本、金额、跌价、周转、资金占用）？→ **象限②**，财务定义，回传业务
3. 它影响**双方能不能对上**吗（口径、时点、单位、精度、阈值）？→ **象限③**，共同定义
4. 它只在**一方内部使用**吗（库位、科目、凭证、税务）？→ **象限④**，相互独立

### 4.4 一页速查

| 数据 / 指标 | 象限 | 定义方 | 流向 | 变更权 |
|---|---|---|---|---|
| 物料 / 仓库 / 供应商 / 客户编码 | ① | 业务 | 业务 → 财务 | 业务 |
| **一级货主编码（= 法人主体）** | **①** | **双方确认后由业务维护** | 业务 → 财务 | **双方（A 级主数据）** |
| 二级货主（管理维度，**行级必填**） | ① | 业务 | 业务 → 财务 | 业务（**B 级主数据；每行必提供，缺失即整行拒绝，财务侧不兜底**） |
| 批次号 / SN | ① | 业务 | 业务 → 财务 | 业务 |
| 数量、计量单位、业务日期 | ① | 业务 | 业务 → 财务 | 业务（换算率属③） |
| **基本单位数量** | **①** | **业务** | 业务 → 财务 | **业务（缺失即拒绝入账）** |

| **内部结算金额（管理口径·非会计）** | **②** | **财务** | 财务 → 业务 | 财务（**须与存货口径成对出现**） |
| **二级内部结算价 `internal_price`** | **②** | 财务价目表 | 财务 → 业务 | 财务（一期在库存中心，二期迁交易中心） |
| 库龄 / 跌价准备 / 周转天数 / 资金占用 | ② | 财务 | 财务 → 业务 | 财务 |
| 单据类型边界、单据状态语义 | ③ | 双方 | 双向 | 双方 |
| **调拨 vs 跨法人转移的判定** | **③** | 双方 | 双向 | 双方 |

## 5. 时序与节奏约定

| 项目 | 一期约定 | 二期目标 |
|---|---|---|
| 推送方式 | **API 对接为主通道**（协议 / 鉴权 / 推拉模式**待定**）；**Excel/CSV 日批（T+1）保留**为过渡与手工补录通道 | 协议定型 + 准实时；两条通道**共用同一套字段与校验**，不产生两套逻辑 |
| 日切时点 | 统一 T 日 23:59:59 | 同 |
| **迟到单据** | **已结账（锁账）期间禁止入账**；当期未结账的迟到单按真实业务日期入账 | 同（口径不变，锁账自动化程度提高） |
| **跨期漏记** | 走**当期补录单 `PERIOD_ADJUST`**（必审），**一律按当期口径量价** | 同 |
| 对账频次 | 数量：日清；金额：月结 | 数量：日清；金额：日清 |
| 快照留存 | 每日快照留档，月结快照长期保留 | 同 |

> **⚠️ 迟到单据的口径以 v1.2 为准（C-03，与 v1.1 相反）**：v1.1 写的是"迟到单据允许，财务按业务日期插入重算"——**这一条与引擎决策 E-04 直接冲突，已作废**。
>
> 现口径分两种情况：
>
> | 情况 | 处理 | 依据 |
> |---|---|---|
> | 历史单据的业务日期落在**未结账期间** | **允许**，按真实业务日期入账并重算该维度 | E-01 排序键 `(biz_date, seq_in_day)` 可复原 |
> | 历史单据的业务日期落在**已锁账期间** | **拒绝入账**，回执原因；漏记只能开**当期补录单** | E-04 / E-07 |
> | 已锁账期间确认需要更正 | **反结账**（走审批、留痕）后按正常单据处理；或直接开当期补录单 | E-09（两条路语义不同，不互相代替） |
>
> **为什么不能"自动插到正确位置重算"**：E-01 的排序键里 `seq_in_day` 是**当日序号**，产生时就分配了。跨期回填**复原不出那个序号**——同一天里谁先谁后无从判断，重算结果不可复现。所以**跨期一律按当期口径量价**（E-10），**不允许追溯复原历史成本**。
>
> **对业务的唯一要求不变**：业务日期**必须是真实业务发生日**，不能填推送日。区别在于——v1.1 里"填错日期"只是重算问题，v1.2 里"填错日期 + 已锁账"就是**直接拒绝入账**。

## 6. 三条红线（历史踩坑榜前三）

| 红线 | 现场表现 | 后果 | 防范措施 |
|---|---|---|---|
| **改单/删单不发通知** | 业务改了单据，财务侧毫不知情 | 账实不符，越滚越大，月底集中爆发 | 契约里强制改单/作废通知；财务侧做"单据指纹"比对，发现差异主动告警；**已锁账期间不可改单/作废** |
| **主数据编码变更或复用** | 停用的物料编码被重新启用给新货 | 历史成本串味，无法追溯 | 编码只停用不复用；停用需提前通知；**一级货主编码同为 A 级，同样只停用不复用** |
| **双方各算一套成本** | 业务报表也有"库存金额"，但算法不同 | 两个数字打架，互相指责，无人能解释 | 明确金额权威方是财务；业务如需展示金额，须标注口径来源 |
| **⚠️ 红线三的新形态：挑错金额口径**（C-17） | 财务回传了**两个金额**——存货口径（`alloc_amount`）与内部结算金额（`internal_amount`），业务侧挑了后者当"库存金额"展示 | **同样是两个数字打架**，而且这次**契约里写了、实现里没区分**，比自算成本更难发现；法人合并与存货总额随之失真 | **两个金额必须并列回传 + 强制口径标注**；业务侧展示"库存金额"**只能引用存货口径**；内部结算金额**必须与存货口径成对出现，单独使用即口径错误** |

## 7. 差异处理流程

```
发现差异（数量：日清 / 金额：月结）
   ↓
第一步：分类——是数量差异，还是金额差异？两者对手不同，绝不能混着报
   ↓
数量差异 → 对手是业务库存中心的日切快照
          → 按（物料, 仓库, 批次）下钻【物理层，O-07 未决前不上货主】
          → 比对双方单据明细 → 定位到具体单据 → 责任方修数据并重推 → 财务侧重算 → 复对
   ↓
金额差异 → 对手是【金蝶总账】，不是业务系统（F04）
          → 维度：(法人, 物料, 仓库)；层级：法人层 + 合并层分别出
          → 先确认数量已一致（数量未平时金额差异无意义）
          → 再核对口径：采购价、运费分摊、舍入规则、计价方法、一级货主归属
          → 口径问题 → 修订契约文档（版本化）并双方确认
          → 算法问题 → 财务侧重算
   ↓
关闭差异 → 记录到对账报告，注明原因与处理方式（便于审计追溯）
```

> **为什么金额差异的对手不是业务系统**：业务侧**没有金额权威**——它的"库存金额"多为数量 × 最新采购价，与移动平均口径必然不同。**拿业务金额去核财务金额，对出来的全是假差异**，只会消耗对账人力。真正的金额权威只有两个：**财务侧存货账** 与 **金蝶总账**。
>
> **为什么数量差异的维度不含货主**：见 `2.4` 的 O-07——业务侧是否建货主维度**不由我方单方决定**。在 O-07 有结论前，数量对账按**物理层**做（跨法人转移在两边都不改变物理总量，能对上）。**代价**：权属挂错（货在但记在错的一级货主名下）**在物理层对不出来**，只能靠财务侧的四轴余额自检发现。
>
> **数量的"日清"与金额的"月结"不是同一个对手**：数量日清比的是**业务快照**（同源，必须清零）；金额月结比的是**金蝶总账**（跨系统，允许有可解释差异）。这一点混淆过很多次。

**建议的处理时效**：

| 差异类型 | 定位 | 处理完成 |
|---|---|---|
| 数量差异 | T+1 | T+3 |
| 金额差异 | 月结前 5 个工作日 | 月结前 3 个工作日 |
| 口径类差异 | 立即识别 | 当期修订契约，下期生效 |

## 8. W1 接口评审会 Checklist

开会时逐条过，每条都要有明确结论和责任人：

- [ ] **11 类单据的范围边界确认**（每类一句话定义，尤其"其他出入库"包含哪些场景；**重点确认新增三类**：`OWNER_TRANSFER` / `OWNER_REASSIGN` / `PERIOD_ADJUST` 由谁发起）

- [ ] **一级货主编码表确认**（编码、名称、所属账套、`is_internal`、生效区间）——**A 级主数据，须一字不差**
- [ ] **一级货主编码规则与层级口径**（编码规则谁定、层级调整走什么流程）

- [ ] 物料上市日期（launch_date）由谁维护、在哪里维护
- [ ] 主数据变更的同步机制（重点：编码停用、**货主层级调整**、单位换算变更）
- [ ] 改单 / 作废的通知方式与时效；**已锁账期间不可改单/作废，漏记走当期补录单**——双方确认这条口径
- [ ] **迟到单据口径确认**：已结账期间禁止入账、跨期漏记走当期补录单、**一律按当期口径量价**（与 v1.1 相反，须明确告知业务侧）
- [ ] 日切时点与对账快照口径（as_of）——**落到三处**：业务快照 `as_of`、单据 `pushed_at`、财务余额 `as_of_date` 须同口径
- [ ] 库存快照是否包含金额（建议：不包含）
- [ ] **业务系统是否需要展示"库存金额"？若需要，确认引用财务回传值而非自算（第 4 章象限②）**
- [ ] **若财务回传两个金额口径：确认业务侧展示"库存金额"只用存货口径那一行，内部结算金额必须成对出现、不得单独使用**（C-17）
- [ ] **价值类指标的回传方式与频次（一期无接口时：财务出报表定期给，还是双方共用一张报表）**
- [ ] **金额对账的对手是金蝶总账**（不是业务系统）——双方确认这一点，避免拿业务金额去核财务金额
- [ ] **对账容差阈值与对账 SLA 双方书面确认**（契约给的是确认后的取值，不是设计单方设定）
- [ ] 逐条走一遍第 4.4 节一页速查表，确认每个数据项的**定义方、流向、变更权**无异议
- [ ] 差异处理的 SLA 与双方责任人
- [ ] 本契约文档的版本管理与变更流程（谁提、谁审、谁发布）

### 9.6 货权变更单 `OWNER_TRANSFER` / `OWNER_REASSIGN`（**新增，一期临时载体**）

> **背景**：产权交易中心一期不落地，货权变更由财务库存中心出**临时货权变更单**承载，按**可剥离**形态设计——自带价格与 `price_source`、`is_accounting_event` 显式分列一二级、**不直接改余额，只产生事件**。二期随交易中心**搬迁，不是重写**。

### 10.1 O-07：业务侧是否也建货主维度（**本契约唯一的外部依赖项**）

这是 v1.2 新提出的**契约变更项**，也是本契约中**唯一不由我方单方决定**的一条。

| 项目 | 内容 |
|---|---|
| **问题** | 业务侧的快照与单据是否也带**一级货主**维度？ |
| **为什么必须问** | 财务侧已把一级货主作为**第四根库存轴**，但业务侧是否同样建维度，决定了 `2.4` 快照维度能否上到货主层 |
| **影响面（若确认建）** | `2.2` 单据行一级货主必填；`2.4` 快照维度升为 `(物料, 仓库, 批次, 一级货主)`；`3` 矩阵中货主维度的一致性等级从 B 升为 A；`7` 数量差异可按**权属层**对账，能提前发现"货在但权属挂错" |
| **影响面（若不建）** | 一期维持**物理层**对账 `(物料, 仓库, 批次)`；**权属挂错在数量对账中查不出来**，只能靠财务侧四轴余额自检；跨法人转移与合并抵消仍可做（财务侧有货主），但两边无法按货主对账 |
| **决策方** | **业务库存中心团队 + 财务部**，我方只能提出与说明影响 |
| **本契约的处理** | **在 O-07 有结论前，一期按物理层对账，不预设"业务侧一定建货主维度"**；本项作为**外部依赖项**列在此处，不由设计单方面假设 |
