0. 怎么读这份文档

0.1 一句话

每一节都是"给一张单据、算一遍、看余额变成什么、出什么凭证"。 所有场景共用同一套主数据与同一个起点结存，因此各节的数字可以横向对照——不必重新理解语境。

0.2 ⚠️ 一期 / 二期标注（重要，先看这条）

本文覆盖的计价方法里，只有移动加权平均是一期落地：

计价方法本文出现位置一期是否启用依据
移动加权平均 MA§CA-01.1是（一期唯一）核算引擎设计要点 v1.3 §2
先进先出 FIFO§CA-01.2二期可选同上；框架 v1.4 §7.5
个别计价（单品单价）SI§CA-01.3二期（0.3 已定）同上；出入库对照 v1.0 §2.0

设计文档的原话是：

计量层 Measure　策略化。MA（一期）/ SI / FIFO（二期）。
——《核算引擎设计要点》v1.3 §2

二期上 SI / FIFO 就是加一个策略实现，其余三层不动。
——同上 §2

所以本文 §CA-01.2 / §CA-01.3 是"预留能力演示"，不是一期要实现的功能。 写出来有两个实际用处：① 让业务确认一期用 MA 得到的数可以接受；② 让二期换策略时，有现成的对照基线（同一批单据、三种方法、出库成本差 50.00，见 §CA-01.4）。

配套的一条硬约束：SN 号必须出现在出库单据行上——否则二期的个别计价（每台单独结转成本）无法落地。这条一期就要在字段上留好（出入库对照 v1.0 §3 S-10）。

0.4 销售出库三种情形的理解

需求中的"同一级货主、二级货主 / 同一级货主、不同二级货主 / 不同一级货主、不同二级货主"，本文按出库单据行上标的的 (owner_l1, owner_l2) 与库存实际所在层 (owner_l1, owner_l2) 的关系拆成三种情形（见 §CA-06）：

情形出库行标的（谁卖给客户）库存所在层（货权在谁账上）中间需要什么
情形一OWN-A / OWN-A-1OWN-A / OWN-A-1无——直接出库
情形二OWN-A / OWN-A-2OWN-A / OWN-A-1先做二级重分配 OWNER_REASSIGN
情形三OWN-B / OWN-B-2OWN-A / OWN-A-1先做一级货权转移 OWNER_TRANSFER

这个理解的落点：出库本身永远只在一个核算单元上结转成本；"不同货主"带来的复杂度全部落在出库之前的那张货权变更单上。三种情形的横向对比见 §CA-06.4。

0.7 两个核心公式（后文反复引用）

F1 入库（唯一会改变均价的动作）
   new_qty    = old_qty + base_qty
   new_amount = old_amount + (不含税金额 + 本行分摊费用)
   new_price  = round(new_amount / new_qty, 6)

F2 出库（不改变均价）
   取当前核算单元均价 → amount_delta = round(base_qty × 均价, 2)
   new_qty = old_qty − base_qty
   new_amount = old_amount − amount_delta
   new_price = 旧均价（不重算）
F3 舍入差异
   rounding_diff += amount_delta − base_qty × 均价     → 累加进 rounding_diff_acc

CA-01.3　个别计价（SI · 单品单价）—— 二期

拣货时业务指定具体批次或序列号（或由仓库拣货回传），成本跟着被指定的那一件走：

出 150 台 = 03-01 批 80 台 + 03-05 批 70 台
        = 80 × 10.00 + 70 × 12.00 = 800.00 + 840.00 = 1,640.00

结存 = 03-01 批 20 台 × 10.00 = 200.00
     + 03-05 批 30 台 × 12.00 = 360.00
     = 50 台 / 560.00
     单位成本 11.200000 —— 注意这是**两个成本层的加权**，不是任何一层的均价

SI 与 FIFO 的区别：FIFO 的拣货顺序由系统按入库先后定；SI 的拣货顺序由业务指定。所以同一批单据、同样出 150 台，两者成本可以不同（本例 1,600.00 vs 1,640.00）。

计价方法出库成本（150 台）结存数量结存金额结存单位成本一期是否启用

差异区间 50.00（1,600.00 ~ 1,650.00）——同样两张采购单、同样出 150 台，三种方法下当期的出库成本相差最多 50.00，且全部落在当期主营业务成本，期末存货金额也相差同额。

这就是为什么一期必须先把 MA 定死、且不能中途换法：换一次方法，历史每一期的成本、毛利、存货余额都会变；且换法之后与前期的数不可比。

CA-01.5　含税拆税 + 费用分摊（MA 入库的完整形态）

起点：接 §CA-01.1 的 03-05 之后——M0001 @ WH01 / OWN-A，200 台 / 2,200.00 / 均价 11.000000。

单据：PO-202603-0003，2026-03-06（在原共用起点的 03-05 之后、03-10 出库之前——起点已含 03-05 那单，故本单不能再早于 03-05），数量 50 台，含税金额 5,650.00，税率 13%，运费 300.00（分摊基准 AMOUNT）。

       税额       = 5,650.00 − 5,000.00 = 650.00

2  分摊附加费用
       allocated_cost = 300.00（一票一料，全额归本行；一经落行即入成本，不再回改）

3  入账基数
       = 不含税金额 + 本行分摊费用 = 5,000.00 + 300.00 = 5,300.00

4  F1 移动平均入库
       new_qty    = 200 + 50 = 250
       new_amount = 2,200.00 + 5,300.00 = 7,500.00
       new_price  = round(7,500.00 / 250, 6) = 30.000000

要点

  • 含税金额绝不进成本 —— 含税入成本会同时虚增存货、少计进项税，两个错一起犯。
  • 运费 / 关税一类分摊费用必须 W1 谈死口径（契约 §10.2）——漏掉这一项，采购入库成本必然对不上，且发现时往往已经跨月。
  • base_qty 是核算口径（不是 qty）：换算率缺失时拒绝入账，不做 1:1 兜底。

要点

  • 按原出库成本冲回，不按当前均价重算。 这一条不是可选项——按当前均价重算，一次退货会把已结转的历史成本改写，当期损益被退货"重写"，前期的报表也跟着变（上面 7.14 就是被重写出来的假数）。
  • orig_so_doc（原销售出库单号）必填。缺它整行拒绝入账，回执 E-SRC-DOC-MISSING。业务不给这个单号，退货就无法正确处理。
  • 入数量，但不重算成本层——用原价。数量 ↑、金额 ↑（按原成本），不回改已结转的历史成本。

CA-03　调拨 TRANSFER —— 出库腿 + 入库腿（同一条单的两行）

单据：TR-202603-0001，同一一级货主 OWN-A，WH01 → WH02，数量 10 台。
落库形态：业务侧推 1 张单、2 个仓；适配层展开为 2 行（doc_no 同一个，靠 warehouse_code + is_in 区分）。

doc_no = TR-202603-0001
  line 1: warehouse_code = WH01（调出）, is_in = 0, line_no = 1
