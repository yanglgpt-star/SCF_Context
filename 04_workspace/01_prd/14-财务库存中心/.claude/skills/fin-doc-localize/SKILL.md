# 财务库存中心 · 文档本地化与术语统一

> ⚠️ **本 skill 最容易出错的一步是「范围界定」，不是"替换"本身。**
> 本项目真实教训：用户说「去掉全部英文，用中文替代」→ 做完全中文版 → 用户随即收窄为「**只是表和表的字段**用中文替代，其他还可以用英文」→ 整个交付物作废重做。
> **所以：范围没被明确界定之前，不要开始替换。**

---

## 第一步（不可跳过）：界定范围

先把「换什么 / 留什么」列成表，**交用户确认**，再动手：

| 类别 | 换？ |
|---|---|
| **数据库表名** | ✅ 换 |
| **字段 / 列名** | ✅ 换 |
| 枚举值（如 `MOVING_AVG`、`OWN`、`CONSIGNMENT`） | ❌ 留 |
| 状态码 | ❌ 留 |
| 错误码（`E-11`、`E-12`、`E-13`） | ❌ 留 |
| 服务与方法名（如 `NegativeStockConfigService`、`resolvePolicy`） | ❌ 留 |
| 页面号（`P01`–`P16`） | ❌ 留 |
| 单据号（`PO-202603-0001`、`OT-202603-0001`） | ❌ 留 |
| 公式符号（`D`、`M1`、`V1`） | ❌ 留 |
| 参数类型值（`enum`、`string`、`decimal(2)`、`object`） | ❌ 留 |
| 示例主数据编码（`OWN-A`、`M0001`、`WH01`、`SN-0003`） | ❌ 留 |
| 报文对象名（`master_data`、`document`、`snapshot`…） | ⚠️ 看情况——文档当具名数据物件用时**译** |
| 真库列 vs 枚举取值同名（`transfer_price` 是列 → 译；`biz_price` 是 `price_type` 取值 → 留） | ⚠️ **按语义判** |

**一句话判据**：**是"库里的表/列"就译；是"码"（枚举 / 状态 / 错误 / 服务名 / 单据号 / 页面号 / 类型值 / 示例编码）就留。**

---

## 第二步：写法约定

- **每处首次出现括注原码**，形如「**中文（原 `code`）**」；**其后一律用中文**。
- **原件不动**——新建一份带准确后缀名的文件（如 `…（表与字段中文版）.md`），**原件保持字节级不变**（改完复 md5 校验）。
- 文首加**一行编者说明**：本文件是什么、口径一字未改、**冲突以原文为准**、技术实现对照原版。

---

## 第三步：词典来源（**权威顺序**）

| 优先 | 来源 |
|---|---|
| 1 | 详细设计文档 `#### x.y.z 中文名 \`t_xxx\`` 标题 → **表名** |
| 2 | 详细设计文档「中文字段 \| 字段」表 → **字段**（schema 首选，228 条） |
| 3 | PRD 自带的「中文 \| \`码\`」对照、`\`码\`（中文）` |
| 4 | 原文（需求文档）——词典外的遗漏条目去这里取 |
| — | 手工拍板覆盖冲突（**PRD 自称优先于详细设计的异名**） |

**已知的刻意对齐**：`doc_no`→业务单号、`unit_price`→移动平均单价、`amount`→结存金额、`owner_l2`→**二级产权人**（避开已废弃的「二级货主」）。

**已知跨文档异名（别改，只报告）**：`own_unit_price`/`own_amount` 在详细设计 4.3.7 叫「自有结转单价/金额」，在详细设计 `:100` 与 PRD 叫「二级自有均价/二级自有结存金额」。

---

## 第四步：废弃称谓

| 废弃 | 改用 |
|---|---|
| 二级货主 | **二级产权人** |
| 适用法人 | **适用一级货主** |

⚠️ **例外**：既有**对象名**不改——`t_owner_allocation`（二级货主分摊账）、`t_owner_balance_l2`（二级货主结存表）。

---

## 第五步：校验（必做）

```bash
cd "04_workspace/01_prd/14-财务库存中心"

# 1) 原件字节未变
md5 "财务库存中心项目-整体PRD_v1.0.md"        # 记录改前 md5，改后必须一致

# 2) 掩掉括注后查反引号奇偶（否则括注自己的反引号会误报）
# 3) 表格列数异常 = 0；分隔行数 前后一致
# 4) 词典内可解析的裸记号残留 = 0（类型值如 object、示例编码除外）
```

**参数表特别处理**：若原文有「参数中文名 | 参数英文名 | 参数类型 | 参数含义」这类 4 列表，**删「参数英文名」列**，原码折进中文名格（首现括注）。**表头措辞保持「参数中文名」**，不要改成「参数名称」。

---

## 禁止操作

1. **范围没界定就动手**——本 skill 的头号禁令。
2. **把"码"也一并中文化**——枚举 / 状态 / 错误 / 服务名 / 单据号 / 页面号 / 类型值 / 示例编码一律留英文。
3. **覆盖原件**——一律新建文件。
4. **改既有对象名**（如表名里的"二级货主"）。
5. **提交 commit**。
