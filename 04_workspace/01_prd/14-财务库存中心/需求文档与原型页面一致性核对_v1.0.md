## 一、核对方法与口径

| 维度 | 文档侧来源 | 原型侧来源 | 比对方式 |
|---|---|---|---|
| 搜索条件 | 每页 `#### 搜索条件` 表 | 运行时 DOM：每页 `.bar` 内的查询控件 | 逐名比对 |
| 列表字段 | 每页 `#### 字段说明` 表 | 运行时 DOM：每页 `thead th` | 逐名比对，原型侧扣除「操作」列 |
| 按钮标签 | 每页 `#### 按钮交互` 表 | 运行时 DOM：工具栏 `[data-act]` + 行内 `td.act [data-act]` | 集合双向差 |
| 按钮容器 | 同上表「点击后的交互」列 | 点击后实际打开的元素（弹窗 / 表单 / 抽屉 / 跳页 / 仅提示） | 容器类型比对 |

**标签归一化**：`NFKC` → 去 `*` `` ` `` `★` `☆` 与方括号 → 折叠全部空白 → 统一全半角括号。**两侧同时归一**（只归一侧会造成大量假「未找到」，本轮已踩过）。

**容器判定**：文档「点击后的交互」列中出现「弹窗 / 弹出 / 弹框 / 对话框」记 `弹窗`，出现「抽屉 / 侧滑 / 侧栏」记 `抽屉`，出现「跳转 / 进入明细」记 `跳页`。原型侧由运行时实际打开的容器标注。表单弹窗归入 `弹窗` 一类（同为实现层模态）。

## 五、按钮标签：2 处结构差异

文档按钮表 85 行、原型 101 个按钮。**原型有而文档没有 = 17 个；文档有而原型没有 = 0 个。**17 个集中在两处：

### 5.1 `[查看]` —— 14 个页面的行按钮，文档从未记录

| 项 | 内容 |
|---|---|
| 出现页面 | P01、P02、P03、P05–P15（**14 页**） |
| 未出现的页面 | P04 —— 其操作列已被 6 个行按钮（查看计量结果 / 查看标准化事件 / 报文对照 / 查看原始报文 / 执行计算 / 重新计算）占满，无位可放 |
| 原型行为 | 打开行详情弹窗，按当前行逐字段渲染（含只读副本，副本内不含任何运行时抓手） |
| 文档记载 | **15 页的 `#### 按钮交互` 表均无此行** |

**成因**：`build_html.py:121-122` 的 `row_buttons()` 在拼装行按钮时无条件补一条 `("查看","")`：

```python
if not any(l == "查看" for l, _ in act):
    act.append(("查看", ""))
```

即 `[查看]` 是**渲染层自动兜底**，不来自任何页面配置，因此建文档时不可能被写进去。

**判断**：这是原型侧多出来的通用能力，不是文档漏写业务按钮。倾向**在文档各页按钮表补一行 `[查看]`**（说明「打开行详情弹窗，展示当前行全部字段」），而不是从原型删掉——它是「点任意行都能看明细」这一交互约定的唯一入口。

### 5.2 P14 的按钮表漏了 `[查询]` 与 `[重置]`

| 项 | 内容 |
|---|---|
| 文档现状 | P14 `#### 按钮交互` 表（第 1125–1139 行）第 1 行直接是 `[下载期初导入模板]`，**没有 `[查询]` / `[重置]`** |
| 其余 14 页 | **全部**都有这两行，文案统一：`[查询] 按当前搜索条件重新加载… / 重新查询并刷新列表`、`[重置] 清空全部搜索条件 / 清空条件并恢复默认查询` |
| 原型现状 | P14 工具栏有 `[查询]` `[重置]`，行为与其他页一致 |
| 旁证 | P14 有 5 个搜索条件（期间 / 仓库 / 一级货主 / 商品 / 导入状态），有筛选条件却无查询按钮，逻辑上不成立 |

**判断**：文档侧漏写，**补两行即可**，无歧义。

## 七、`[下载期初导入模板]`：文档说下载文件，原型开列清单弹窗

单列一条，因为它与「弹窗 / 抽屉」之争是两码事——**文档规定的不是容器，而是动作本身**。

| 项 | 内容 |
|---|---|
| 文档原文 | `[下载期初导入模板] \| 下载期初数据导入模板 \| 下载 `initial_balance_import_template.xlsx`（期初数据导入模板文件）模板，列名与顺序即表头校验判据 \| 无权限限制` |
| 原型实现 | `proto.js` MCOPY 表：`{k:'cols', h:'期初数据导入模板 · 列清单', ok:'知道了', sub:'列名与顺序即表头校验判据；列缺失或顺序不符则整批拒绝'}` |
| 实际效果 | 开一个只读列清单弹窗，**唯一的按钮是「知道了」，没有任何下载动作**，也拿不到 xlsx |

**成因**：静态原型无法真正落盘文件，与另外 14 个「导出 / 下载」类按钮（P03 导出源单日志、P04 导出待计算清单、P05/P06 导出 Excel、P07 导出流水报表、P08 导出 SN 资产表、P09 导出批次报表、P10 导出对账异常清单、P11 导出波动底稿、P12 导出资产减值测试底稿、P13 导出标准收发存报表 / 导出金蝶标准凭证引入表、P15 导出负库存监控台账）一样，只能给提示语。

**问题在于不一致**：其余 14 个导出类按钮的处理是「toast 提示已导出」，只有这一个是「开弹窗展示内容」。三者取其一：

| 方案 | 做法 |
|---|---|
| (a) 对齐其他导出类 | 改成 toast 提示，与 14 个同类按钮统一 |
| (b) 保留弹窗、补下载动作 | 弹窗内加「下载模板」按钮，`<a download>` 指向内联的 xlsx/csv data URI |
| (c) 保留现状、改文档 | 文档改为「打开列清单弹窗，列名与顺序即表头校验判据」 |

倾向 **(b)**——它既保住原型想表达的「列清单即校验判据」这层信息，又兑现文档承诺的下载动作；静态页里用 data URI 可以真下载。
