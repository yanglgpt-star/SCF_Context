# 第一章 项目概述、业务模式与系统定位



### 1\. 业务痛点与建设背景

在传统的供应链与 ERP 体系中，仓储物理作业（库位管理、拣货打包、批次移动）与逻辑资产核算（法定纳税主体、内部产权人毛利、单品移动均价）长期强耦合于单一 WMS，导致以下核心矛盾爆发：

- **权责与货位绑定**：多法人实体、多内部产权人团队共用仓库时，实物移位频繁导致账面货权错乱；

- **成本与毛利失真**：数码 3C 价格波动剧烈、二手商品“一机一况一价”、电动车强监管车架号溯源等特征，无法在传统加权平均下反映单机真实利润；

- **跨法人财税合规风险**：跨公司调拨、代售在物理出库时未及时生成合规交易流水与开票依据，引发税务合规隐患；

- **系统架构已达承载上限**：实物作业高并发与财务核算强一致性相互制约，月结关账时无法阻断动态作业，导致历史报表无法定格。

    

### 2\. 四大主营业务模式

1. **自营采销（自有物理仓）**：外部采购入库至自建仓，自营电商渠道销售，由自有仓打包发货；

2. **自营采销（三方合作仓）**：外部采购入库至三方合作仓（3PL），平台销售后指令三方仓发货；

3. **以销定采（一件代发 / Dropshipping）**：前端销售产生订单后向供应商下达采购代发指令，供应商直发消费者，实物不经过己方物理仓；

4. **代储代发（受托代管 / VMI）**：供应商将货物存放在我司仓库，实物属外部资产。供应商销售后通知我司履约发货，我司仅计收仓储操作与配送服务费。

# 第二章 多级货主账户体系与内部交易架构



### 1\. 三层货主账户设计

系统建立独立的复合多层账户模型：

1. **一级账户（法人实体）**：具有独立法人资格的法定实体，承担法定会计核算、纳税申报、进项销项发票开具，形成外部法定资产负债表与利润表；

2. **二级账户（管理单元 / 产权人）**：法人内部的事业部、利润中心、个人承包团队，承担内部结算收入、内部转让成本、经营毛利和存货周转效率考核；

3. **受托代管账户（外部供应商）**：针对代储代发商品设立的备查账簿，账面价值恒为 0，实物变动不计入公司法定资产与负债；

4. **账户复合主键唯一性**：

    $\text{AccountKey} = \langle \text{LegalOwnerID}, \text{AmibaOwnerID}, \text{WarehouseCode}, \text{SKUCode}, \text{AssetType} \rangle$

    

### 2\. 内部转移定价（Transfer Pricing）机制

当货物在不同法人或产权人之间调拨、代售时，系统通过定价引擎计算内部结算价格：

- **成本价平转 \(****`COST_PRICE`****\)**：$P_{transfer} = Cost_{source}$，适用于同法人不同产权人之间的协同移库；

- **成本加成率 \(****`COST_PLUS`****\)**：$P_{transfer} = Cost_{source} \times (1 + MarkupRate\%)$，适用于跨法人合规转让（满足税务公允交易原则）或产权人间有偿结算；

- **协议固定价 \(****`FIXED_PRICE`****\)**：$P_{transfer} = Price_{agreed}$，适用于集团统采统销的固定协议单品。

    

### 3\. 销售出库“跨货主穿透自动交易”机制

针对“签约销售店铺法人与发货实际持仓法人不一致”场景，系统在销售出库时执行“先内部货权转让，后对客出库”的穿透事务（在同一个本地事务内闭环）：

1. **核对主体**：系统检测到 `Sales_Legal != Stock_Legal` 或 `Sales_Amiba != Stock_Amiba`；

2. **算价与出库**：持仓方按转让价 $P_{transfer}$ 出库，结转账面成本 $Cost_{source}$，确认内部收入 $P_{transfer}$ 与内部毛利；

3. **买入与对客出库**：销售方按 $P_{transfer}$ 作为采购成本入库，随后以 $P_{transfer}$ 结转对外销售的主营业务成本，并以对客售价确认销售收入；

4. **触发外部开票**：若跨一级法人，系统生成 `CROSS_LEGAL` 流水并外发 MQ，通知外部结算系统生成增值税开票申请。

# 第三章 计价核算引擎、费用分摊与全流程数值算例



### 1\. 计价引擎分类与计算公式

- **个别计价法 \(Individual Identification Method\)**：专用于二手 3C、高价值数码与带车架号的电动车。以单个 SN 建立资产档案并绑定成本 $C_{sn}$。出库成本等于出库 SN 历史成本求和：

    $TotalCost_{out} = \sum_{i=1}^{n} C_{sn_i}$

- **移动加权平均法 \(Moving Weighted Average Method\)**：专用于无 SN 的配件、标品。每次入库刷新均价，出库结转平移：

    $P_{new} = \frac{A_{old} + (Q_{in} \times P_{in})}{Q_{old} + Q_{in}}$

    $Cost_{out} = Q_{out} \times P_{current}$

- **先入先出法 \(First-In First-Out Method\)**：不重算均价，按入库批次先后逐层消耗。出库成本等于从最早入库层起、依次消耗各成本层的数量与单价乘积之和：

    $Cost_{out} = \sum_{k} (Q_{consume,k} \times P_{layer,k})$

    成本层按入库日期升序排列，从最早层起逐层消耗直至满足出库数量；出库舍入差异须定义在**层成本**上（$\sum$ 各层被消耗数量 $\times$ 各层单价），**不得用核算单元均价计算**。

    

### 2\. 采购暂估与发票差异回溯分摊模型

采购到货但发票未到时，按采购订单（PO）暂估价入库。发票到达后，总差异 $\Delta Amount = (P_{invoice} - P_{po}) \times Q_{batch}$ 按存货当前在库与已售状态进行比例吸收：

- **在库吸收额**：$\Delta A_{stock} = \Delta Amount \times \frac{Q_{remain}}{Q_{batch}}$，全额计入在库总额，刷新在库移动均价；

- **已售损益额**：$\Delta A_{cogs} = \Delta Amount \times \frac{Q_{sold}}{Q_{batch}}$，生成成本调整单计入当期主营业务成本差异。

    

### 3\. 采购附加成本资本化（Landed Cost）与费用分摊

采购运费、关税、装卸杂费计入存货资产。分摊模型支持：

- **按金额分摊 \(****`BY_AMOUNT`****\)**：用于关税、保费，按货值权重分配；

- **按数量分摊 \(****`BY_QTY`****\)**：用于单件贴标、固定卸货费；

- **按重量/体积 \(****`BY_WEIGHT`**** / ****`BY_VOLUME`****\)**：用于干线运费、跨境海空运费。

- 分摊增加的成本同样按在库与已出库状态进行动态吸收并更新均价。

# 第六章 异常流程核算专题攻坚



### 1\. 负库存两阶段闭环核算模型

当实物到货并发货，但采购单据录入延误时，若策略允许负库存，系统按以下方案执行：



```Plain Text
【阶段一：负库存出库】
实物出库(缺口ΔQ) ──► 取暂估单价(P_est) ──► 记负数量(-ΔQ)与负金额 ──► 锁定均价为 P_est ──► 登记挂账表(OPEN)
                                                                                            │
                                                                                            ▼ 采购补录
【阶段二：采购到货冲平】
采购入库(Q_in, P_actual) ──► 冲平负数量 ──► 价差: (P_actual - P_est) * ΔQ ──► 自动出【成本调整单】计损益
                                                                                            │
                                                                                            ▼
                                                    剩余存货(Q_in - ΔQ)按 P_actual 写入均价 ──► 挂账置为 RESOLVED
```



- **阶段一（暂估出库）**：结存数量记为负数，账面金额为 $- (\Delta Q \times P_{est})$，**均价强制锁定为 **$P_{est}$（禁止金额除以数量产生数学异常）。写入 `inv_negative_stock_log`，状态为 `OPEN`。

- **阶段二（到货冲平与补差）**：后续采购到货 $Q_{in}$（单价 $P_{actual}$）：

    1. 冲平缺口 $\Delta Q$，剩余 $Q_{in} - \Delta Q$ 件存货以 $P_{actual}$ 记入在库均价；

    2. 计算历史出库少结转或多结转的损益：$\Delta Cost = (P_{actual} - P_{est}) \times \Delta Q$；

    3. 自动生成 `COST_ADJUST` 单据，借记或红字冲减“主营业务成本\-负库存补差”，核销挂账记录为 `RESOLVED`。

        

### 2\. 尾差自动平账机制（Penny Rounding Adjust）

商品经多次出库后数量变为 `0.0000`，但因浮点四舍五入残留 `0.01` 或 `-0.02` 元时：

- 引擎触发条件：`current_qty == 0 AND current_total_cost != 0`；

- 自动生成调整流水：调整数量为 0，调整金额为 $- current\_total\_cost$；

- 分录：**借：主营业务成本（尾差调整），贷：库存商品**；

- 强制刷新余额表金额与单价为 0，防止微小残差污染下一次加权计算。

    

### 3\. 零成本（0元赠品/样品）入库防稀释

供应商随货赠送 0 元赠品，若直接加权会大幅拉低均价导致后续毛利虚高。系统通过在入库单打标 `asset_nature = 'GIFT'`，自动将其路由至独立的**产权人虚拟赠品子账户**（如 `AMIBA_GIFT`），与正常销售存货账户隔离核算。



### 4\. 逆向退货防假货与超退拦截

- **销退超额拦截**：$\sum Q_{returned} + Q_{current} \le Q_{original}$，超出原销售单数量直接抛错；

- **SN 溯源防假**：退货 SN 必须在 `inv_sn_ledger` 中存在、属于原销售单且状态为 `SOLD`。串货或非原单 SN 拒绝入账，转入售后异常待查件。

# 第七章 经营风控与扩展管控模型



### 1\. 成本波动监控与预警模型 \(`inv_cost_fluctuation_log`\)

实时捕捉录入错误或价格异动。

- 波动绝对值：$\Delta P = P_{curr} - P_{prev}$

- 波动幅度：$Ratio = \frac{P_{curr} - P_{prev}}{P_{prev}}$

- **风控级别**：

    - **黄色预警 \(WARN\)**：$|Ratio| \ge 10\%$ 且 $|\Delta P| \ge 20$ 元 $\rightarrow$ 生成告警通知推送财务看板；

    - **红色阻断 \(CRITICAL\)**：$|Ratio| \ge 30\%$ 且 $|\Delta P| \ge 100$ 元 $\rightarrow$ 阻断过账，进入“财务待复核单据池”，需财务主管审核审批放行。

        

### 2\. 进销存期间收发存汇总模型 \(`inv_period_balance`\)

月结法定报表核心，严格遵循收发存恒等式：

$\text{期末数量 } EndQty = BeginQty + InTotalQty - OutTotalQty$

$\text{期末金额 } EndCost = BeginCost + InTotalCost - OutTotalCost + CostAdjustAmount$

关账时引擎自动执行恒等式检验，差额不为 0 则阻断月结。



### 3\. 存货库龄推导与跌价准备分析模型 \(`inv_stock_aging`\)

- **SN 个别计价商品**：按单台 SN 绝对天数计算：$AgeDay = DATEDIFF(Now(), InTime)$；

- **标品移动平均商品（FIFO 逆向倒扣法）**：

假定当前结存是由最近入库批次构成的。系统从当前统计日倒序遍历历史采购批次，从未售结存量中依次扣减，将结存量还原至各历史入库日，推导各区间账龄分布；

- **跌价准备建议测算**：

    $ProvisionAmount = \sum (\text{各库龄段在库金额} \times \text{预设跌价计提比例})$

    自动出具资产减值测试建议表，辅助财务计提资产减值准备。

### \[P01\] 业务源单接入台账 \(`/raw-data/biz-bills`\)

- **定位**：接入层原始报文日志，用于排查接口通信、单据丢失及重试。

- **搜索条件**：

    - `业务单号`：文本输入，支持模糊搜索；

    - `单据类型`：下拉单选（采购入库 / 采退出库 / 销售出库 / 销退入库 / 业务调拨 / 盘盈 / 盘亏 / 一件代发）；

    - `一级法人`：下拉单选，源自法人主数据；

    - `物理仓库`：下拉单选，源自仓库主数据；

    - `商品 SKU`：文本输入，支持精确查询；

    - `处理状态`：下拉单选（全部 / 待处理 / 处理成功 / 处理失败）；

    - `接收时间范围`：日期时间双选框（快捷项：今日 / 近7天 / 近30天）。

- **按钮与操作**：

    - 顶部按钮：`[查询]`、`[重置]`、`[导出源单日志]`、`[批量重试记账]`；

    - 行级操作：`[查看原始 JSON 报文]`（弹窗展示）、`[重试过账]`（失败单据）、`[查看生成流水]`（成功单据跳转 P05）。

- **列表字段及取值说明**：

    - `raw_id` \(接入流水号\)：数据库自增主键，全局唯一，纯文本展示；

    - `biz_bill_no` \(业务单据号\)：上游推送单号，可点击下钻看详情；

    - `bill_type` \(单据类型\)：上游操作类型，蓝底 Tag 展现；

    - `source_system` \(来源系统\)：`WMS` / `OMS` / `ERP_PO`，灰底 Tag 展现；

    - `legal_owner_id` \(一级法人\)：法人编码与简称，如 `LEGAL_SH01(上海公司)`；

    - `warehouse_code` \(物理仓库\)：仓库编码与名称，如 `WH_KS01(昆山一号仓)`；

    - `sku_code` \(商品 SKU\)：报文中的 SKU 编码；

    - `raw_qty` \(原始数量\)：报文原始申报量，数值保留 4 位小数；

    - `raw_price` \(原始单价\)：报文单价（PO 暂估价），货币格式 `¥#,##0.0000`；

    - `received_time` \(接收时间\)：网关接收时间戳，`YYYY-MM-DD HH:mm:ss`；

    - `process_status` \(处理状态\)：`SUCCESS` 成功\(绿\) / `FAILED` 失败\(红\) / `PENDING` 处理中\(黄\)；

    - `error_msg` \(失败原因\)：接口校验报错文本，红色文本，超长 Tooltip 提示。

### \[P02\] 财务处理单据总台账 \(`/processed-bills/index`\)

- **定位**：展示经过财务中心拆解、衍生、转价后的财务单据（整单层级）。

- **搜索条件**：

    - `财务单号`：文本输入；

    - `财务单据类型`：下拉单选（财务采购入库 / 调拨出库 / 调拨入库 / 内部交易结算单 / 对客销售出库 / 虚拟采购代发单 / 虚拟销售代发单）；

    - `关联业务原单号`：文本输入；

    - `出库方法人`：下拉选择；

    - `入库方法人`：下拉选择；

    - `单据状态`：下拉单选（已过账 / 已冲销 / 挂起待冲平）；

    - `记账日期范围`：日期范围选择框。

- **按钮与操作**：

    - 顶部按钮：`[查询]`、`[重置]`、`[导出财务单据]`；

    - 行级操作：`[查看单据详情]`（滑出抽屉）、`[打印财务凭据]`、`[红字冲销 (限主管)]`。

- **列表字段及取值说明**：

    - `fin_bill_no` \(财务单号\)：财务唯一单号，加粗纯文本；

    - `fin_bill_type` \(财务单据类型\)：会计单据类型，彩色 Tag 展现；

    - `source_biz_no` \(关联业务原单\)：来源业务单号，链接文本跳转 P01；

    - `from_owner` \(出库方主体\)：`出库法人 - 出库产权人` 组合文本；

    - `to_owner` \(入库方主体\)：`入库法人 - 入库产权人` 组合文本（无则为空）；

    - `warehouse_code` \(作业仓库\)：物理仓或虚拟仓编码（如 `WH_IN_TRANSIT`）；

    - `total_qty` \(单据总数量\)：汇总该单行数量 $\sum qty$，数值保留 4 位小数；

    - `total_cost` \(总成本金额\)：汇总不含税成本 $\sum (qty \times cost)$，货币格式 `¥#,##0.00`；

# 第十三章 系统运行治理闭环与数据安全机制



### 1\. 核心数据三层穿透链路 \(Audit Trail\)

系统建立从业务端到报表端的完整三层证据链，任何一笔资产变动均可实现双向穿透追溯：

### 2\. 严格反关账（反结账）风控与数据回滚机制

已封账的历史会计期间原则上**严禁修改**。若发生重大审计调整必须反结账：

1. **严格逆向级联要求**：若当前为 11 月，需反结账 9 月，必须**先反结账 10 月**，严禁跳跃反结账；

2. **作业强排他锁**：反结账期间，系统锁定该法人下所有实时业务单据过账，禁止产生新的业务流水；

3. **数据链式重算**：补录调整后，重新跑批滚动计算后续各月份的期初、出库成本与期末结存，通过收发存恒等式校验后方可重新封账。

    

### 3\. 三账一致性每日自动对账平台

系统部署每日凌晨定时巡检任务（Daily Reconciliation Job）：

1. **实物在架一致性**：$\sum \text{WMS 物理在架良品量} \equiv \text{业务库存中心在库总量} \equiv \text{财务库存余额表 } current\_qty$

2. **在途存货一致性**：$\text{WMS 已发未收调拨量} \equiv \text{财务库存系统在途虚拟仓存量}$

3. **差异熔断机制**：若发现三方数量不符，自动触发报警工单，标明差异 SKU 与单据，并在差异未排查完毕前**阻断该 SKU 的月末自动结账**。

    

### 4\. 数据安全与产权人行级数据隔离

- **集团 CFO / 总账会计**：具备全公司所有一级法人、二级产权人的存货资产、转移价格、成本及毛利的查看与结账权限；

- **法人财务人员**：仅具备所属法人实体及下属产权人的存货资产与凭证操作权限；

- **二级产权人单元负责人**：采用行级数据权限隔离（Row\-Level Security），仅能查看自身产权人组织名下的商品库存量、内部买入成本、内部转移收入与产权人毛利，**严格屏蔽集团统一外部采购进价及其他产权人的经营数据**。

    

### 5\. 高性能与大数据量历史归档策略

- **核心流水表分区**：`inv_cost_journal` 采用 `posting_date` **按月度进行 Range 分区**，单表支持亿级数据毫秒级精准查询；

- **冷热数据分层**：运行超过 3 年且已封账的历史流水，系统自动通过 ETL 工具抽取归档至只读的冷数据分析引擎（ClickHouse / Apache Doris），释放生产 OLTP 数据库的存储和计算压力，保证在线记账引擎的高并发强一致性。
