# 资金台账重要726——金融助手报表管理线上化实施方案

> 方案对象：将 `资金台账重要726.xlsx` 的业务能力迁移至“金融助手—报表管理”  
> 方案日期：2026-07-30  
> 本方案仅描述产品、数据和实施路径，不包含本次系统开发或数据处理。

> 数据权威原则：**金融助手系统是唯一权威数据源，Excel 仅作为只读核对来源**。报表直接读取金融助手数据；Excel 不作为默认迁移、覆盖或回写来源。

## 1. 建设目标

将现有依赖第三方在线文档的资金台账，建设为可持续运营的金融助手报表能力，实现：

- 一套数据：采购、库存、出货、收付款、保证金和费用统一关联；
- 一套口径：资金占用、资金收益、财务成本、毛利和净利润集中计算；
- 一套流程：导入、校验、提交、复核、锁定、调整全程留痕；
- 多维分析：按项目、BU、区域、负责人、平台、客户、供应商、品牌和品类查询；
- 风险可见：未回款、长库龄、负毛利、对账差异和缺失数据自动预警；
- 权限可控：财务、业务、管理层按角色和数据范围访问；
- 结果可复现：任何历史日期均可按当时参数和数据版本重新计算。

## 2. 建设原则

1. **不照搬 Excel 页面**：保留业务口径，重构数据和交互。
2. **明细与指标分离**：原始事实数据不可被报表公式反向修改。
3. **参数集中管理**：费率、系数、分摊规则必须有有效期和版本。
4. **事实可追溯**：每个指标可下钻到业务单据和导入批次。
5. **差异显性化**：不以人工改数“抹平”差异，使用调整单和调节项。
6. **先对账后切换**：历史数据和关键指标未通过核对前不停止旧台账。

## 3. 建设范围

### 3.1 一期范围（建议纳入）

- 项目主数据、组织和业务维度；
- 采购、入库、出库、回款、保证金、费用明细；
- Excel 模板导入及导入校验；
- 资金占用、收益、财务成本、毛利、净利润计算；
- 总览驾驶舱、资金台账、采购库存、出货毛利、差异对账报表；
- 异常待办、审批复核、期间锁定和审计日志；
- Excel/CSV 导出。

一期数据工作的重点为：基于金融助手数据建设报表，并利用 Excel 完成字段覆盖、项目覆盖、数量金额及计算结果核对；任何年度均不得直接用 Excel 覆盖系统数据。

### 3.2 二期范围（条件成熟后）

- 与运营助手、聚水潭、订单、库存、收付款或财务系统接口；
- 银行流水自动匹配；
- 发票、合同和凭证附件管理；
- 预测资金占用和现金流；
- 自助取数、订阅推送和更复杂的归因分析。

### 3.3 非目标

- 一期不建设完整 ERP、WMS 或财务总账；
- 不把单元格级任意公式编辑能力开放给普通用户；
- 不默认迁移无业务价值的格式、图片、空白预留区和历史评论。

## 4. 目标业务架构

建议按四层建设：

| 层级 | 主要内容 | 责任 |
|---|---|---|
| 数据接入层 | Excel 导入、业务系统接口、手工补录、附件 | 获取原始事实并记录来源 |
| 业务数据层 | 项目、采购、入库、出库、收付款、保证金、费用、调整单 | 形成统一业务数据模型 |
| 指标计算层 | 资金占用、周转、收益、财务成本、库存成本、毛利、净利润 | 统一参数和版本化计算 |
| 报表应用层 | 驾驶舱、明细台账、对账、预警、导出、订阅 | 面向财务、业务和管理层使用 |

## 5. 数据模型设计

### 5.1 主数据

| 实体 | 核心字段 | 说明 |
|---|---|---|
| 项目 | project_id、项目编码、项目名称、状态、BU、区域、负责人、起止日期 | 取代项目名称文本关联 |
| 组织/人员 | org_id、BU、区域、负责人、在职状态 | 支持权限和历史归属 |
| 往来单位 | party_id、类型、统一名称、别名、税号 | 客户和供应商统一管理 |
| 商品 | sku_id、品牌、品类、商品名称、规格、标准编码 | 统一 iQOO/iqoo 等写法 |
| 平台 | platform_id、平台名称、业务模式、含税标识、仓储模式 | 拆分当前混合字段 |
| 费用类型 | fee_type_id、费用名称、归集层级、利润影响方式 | 支持额外费用 |

### 5.2 事实数据

| 实体 | 关键字段 | 来源对应 |
|---|---|---|
| 采购单/采购明细 | 单号、项目、供应商、SKU、数量、单价、金额、日期 | 采购明细 |
| 库存流水 | 入库/出库/退货、批次、SKU、数量、成本、日期 | 采购明细及后续接口 |
| 销售单/出货明细 | 单号、项目、客户、SKU、数量、价格、成本、日期 | 出货明细 |
| 资金流水 | 项目、往来单位、款项性质、金额、方向、日期、单据号 | 资金明细 |
| 保证金流水 | 收/付/退/抵扣、金额、日期、关联项目 | 资金明细 |
| 费用明细 | 项目、费用类型、金额、日期、分摊规则、凭证 | 各成本列及额外费用 |
| 调整单 | 调整对象、原值、新值、原因、审批单、影响期间 | 替代直接改单元格 |

### 5.3 参数与版本

建立“规则参数表”，至少包括：

| 参数 | 当前文件值 | 建议配置维度 |
|---|---:|---|
| 公司日资金费率 | 2.5 元/万元/天（待确认） | 项目/平台/日期区间 |
| 财务日成本率 | 2 元/万元/天（待确认） | BU/资金来源/日期区间 |
| 最低提货价系数 | 1.002 | 品类/项目/日期区间 |
| 计息日规则 | 首尾日口径待确认 | 全局或项目 |
| 仓储费规则 | 按数量、单价和月数 | 仓库/品类/日期区间 |

每次参数变更应记录版本号、生效/失效时间、申请人、审批人、变更原因。历史报表必须绑定参数版本，禁止直接覆盖历史口径。

## 6. 指标口径设计

### 6.1 核心指标

| 指标 | 建议系统口径 |
|---|---|
| 日初资金占用 | 前一日已确认日末资金占用 |
| 日末资金占用 | 日初 + 采购付款 + 费用支出 - 保证金影响 - 采购退款 - 销售回款 ± 调整 |
| 资金收益 | 日末资金占用 ÷ 10,000 × 适用日资金费率 |
| 财务成本 | 日末资金占用 ÷ 10,000 × 适用财务成本率 |
| 项目预计毛利 | 资金收益 - 财务成本，或按最终确认口径重命名 |
| 库存数量 | 累计入库 - 累计出库 - 退货/报损 |
| 库存成本 | 按选定成本法计算；一期可沿用数量 × 采购单价 |
| 商品毛利 | 销售金额 - 销售成本 |
| 项目净利润 | 业务收入 - 财务成本 - 仓储成本 - 系统成本 - 税务成本 - 其他费用 |
| 回款周转天数 | 明确按逐笔匹配、加权平均或项目首采至回款计算 |

### 6.2 指标状态

每个业务金额建议同时保留：

- 原始值：来自业务系统或导入文件；
- 调整值：经审批的调节；
- 报表值：原始值 + 生效调整；
- 状态：草稿、待复核、已确认、已锁定、已冲销；
- 数据时间：业务发生时间、入库时间、报表归属日期和系统更新时间。

### 6.3 实际与预测

“对账单”需拆分为实际和预测两个场景：

- 实际：只使用已确认且业务日期不晚于报表日的数据；
- 预测：允许使用计划付款、预计回款和预测参数；
- 页面、导出和接口必须明确显示场景和数据截止时间；
- 未来日期不得自动混入实际累计收益。

## 7. 产品功能设计

### 7.1 报表总览驾驶舱

建议展示：

- 资金占用余额、库存价值、应收未回、保证金余额；
- 本期销售额、毛利额、净利润、资金成本；
- 资金占用趋势、回款趋势、库存趋势；
- 按 BU/区域/负责人/平台的资金占用及利润排行；
- 高风险项目：长账龄、长库龄、负毛利、逾期未回、对账差异；
- 数据状态：最后同步时间、待复核数、失败导入数、未通过校验数。

所有卡片均应支持下钻到项目和原始单据，不只展示汇总数字。

### 7.2 项目资金台账

- 查询条件：日期、项目状态、BU、区域、负责人、平台、客户/供应商；
- 指标：采购付款、收款、保证金、资金占用、周转、各项成本、收入、净利润；
- 项目详情：时间轴展示采购、出货、收付款和调整事件；
- 支持项目关账检查和完结确认。

### 7.3 日资金对账

- 展示期初、当日流入流出、期末、资金收益和财务成本；
- 可切换实际/预测；
- 展示公式口径和参数版本；
- 自动检查前后日滚动、负余额、未来计提和异常波动；
- 支持按日期下钻到构成流水。

### 7.4 采购与库存报表

- 采购、入库、出库、库存、未入库、库龄和库存成本；
- 按项目、SKU、品牌、品类、供应商、负责人分析；
- 未入库、负库存、超长库龄、无商品编码自动预警；
- 今日提货价作为计算指标显示，同时保留计算日期。

### 7.5 出货与毛利报表

- 销售数量、销售额、成本、毛利、毛利率、仓储费；
- 按项目、客户、商品、品牌、品类及负责人分析；
- 负毛利、异常单价、缺订单号形成结构化异常任务；
- 合同和发票状态如一期启用，应采用枚举和流程，而非颜色标记。

### 7.6 对账差异中心

至少内置以下检查：

| 检查 | 预期关系 |
|---|---|
| 出库销售数量 | 采购库存流水出库 = 销售明细数量 |
| 销售金额 | 项目销售订单金额 = 出货销售金额 |
| 销售成本 | 资金明细对应成本 = 出货成本金额 ± 已审批调整 |
| 毛利 | 销售金额 - 销售成本 = 毛利额 |
| 库存数量 | 入库 - 出库 - 退货/报损 = 期末库存 |
| 库存价值 | 库存明细汇总 = 项目级库存价值 |
| 资金滚动 | 本日期初 = 前一日期末 |
| 项目利润 | 各项收入成本之和 = 项目净利润 |

差异记录字段应包括：检查项、日期、项目、差异金额/数量、原因、责任人、状态、处理意见、调整单和完成时间。

### 7.7 数据导入中心

支持现有 Excel 的四类数据模板，但导入时不接收原表公式，只接收业务事实和必要参数：

1. 上传文件并识别模板版本；
2. 预览字段映射；
3. 校验必填、格式、枚举、主数据、重复和跨表关系；
4. 展示新增、更新、跳过和失败记录；
5. 用户确认后入库；
6. 生成批次号、导入人、时间、文件摘要和错误报告；
7. 同一文件/同一业务单据支持幂等防重。

## 8. 权限与流程

### 8.1 角色建议

| 角色 | 主要权限 |
|---|---|
| 报表管理员 | 模板、口径、参数、期间、权限和全量数据管理 |
| 财务录入 | 导入/录入资金、保证金、费用，查看授权范围 |
| 财务复核 | 复核、退回、确认、锁定、调整审批 |
| 业务负责人 | 查看本人/本区域项目，补充业务字段和异常说明 |
| 仓储/运营 | 维护采购、入库、出库和库存信息 |
| 管理层 | 查看汇总驾驶舱和授权范围明细，不直接修改事实数据 |
| 审计/只读 | 查看历史版本、日志、附件和导出记录 |

权限至少支持：功能权限、数据范围、字段权限、导出权限和敏感金额脱敏。利润、财务成本、客户/供应商信息应可独立控制。

### 8.2 业务流程

建议状态流转：

`草稿/待导入 → 校验通过 → 待复核 → 已确认 → 期间锁定`

锁定后不得直接改原记录；需要通过“调整单/冲销单”变更，并保留原值、调整值、原因、附件和审批链。

### 8.3 期间管理

- 支持日、月结算期间；
- 期间锁定前运行完整对账检查；
- 失败项必须处理或经授权豁免；
- 解锁需单独权限和审批，并记录影响报表。

## 9. 数据质量规则

### 9.1 基础校验

- 项目、业务日期、款项性质、金额方向等核心字段必填；
- 金额、数量、日期、比例类型正确；
- 项目、客户、供应商、SKU、负责人必须映射到有效主数据；
- 状态和平台采用枚举，不允许任意文本；
- 业务单号或组合业务键唯一，重复导入可识别；
- 出货日期不得早于采购日期，除非有授权例外；
- 入库、出库和库存数量不得出现无解释的负数；
- 项目完结前必须满足回款、库存、保证金和异常关闭条件。

### 9.2 异常预警

- 资金占用为负或单日异常跳变；
- 超阈值资占天数、回款天数或库龄；
- 负毛利或毛利率超出合理区间；
- 采购金额与付款、销售金额与收款差异；
- 费用缺失、项目状态空白、订单号或 SKU 缺失；
- 费率参数缺失、失效或重复生效；
- 实际报表包含未来业务日期。

阈值应可配置，并支持消息中心、待办或邮件/企业协同工具通知。

## 10. 数据核对与差异处理方案

### 10.1 数据权威与迁移边界

| 数据期间 | 权威来源 | Excel 定位与处理策略 |
|---|---|---|
| 2025 年 | 金融助手及经确认的原始业务单据 | Excel 仅核对历史覆盖；疑似缺失数据须回溯原始单据后在系统正式补录 |
| 2026 年 | 金融助手 | Excel 仅核对，不迁移、不覆盖、不回写 |
| 2027 年未来日期 | 金融助手预测模块（如启用） | Excel 预生成数据不进入实际库，也不直接进入预测库 |

当金融助手与 Excel 不一致时，报表仍以金融助手数据为准。差异仅用于触发核查，不自动更改系统结果。若原始业务单据证实系统数据需修正，应通过金融助手正式补录、调整、审批和审计流程处理。

### 10.2 核对与差异闭环步骤

1. 冻结一份 Excel 核对文件并计算文件摘要，确保核对期间不再变化；
2. 读取金融助手数据，形成唯一报表基线；
3. 对第三方 XLSX 做兼容性读取，但不直接写入金融助手；
4. 建立 Excel 与金融助手的字段、枚举、项目、往来单位和商品映射；
5. 按年度、项目、单据、SKU 分层核对记录数、数量、金额和指标；
6. 将差异分为 Excel 缺失、Excel 多出、口径差异、时间差、系统疑似缺失、系统疑似错误和人工调整；
7. 对系统疑似缺失或错误项回溯合同、订单、流水、发票等原始业务单据；
8. 经业务及财务确认后，在金融助手中通过正式补录、调整或冲销流程处理；
9. 重新生成系统报表并复核差异，保留处理前后结果和审批记录；
10. 完成至少一个结算周期核对后，将第三方文档转为只读归档。

### 10.3 核对原则

- 原 Excel 行号、工作表名和原文件摘要保留在核对记录中，便于追溯；
- 评论不直接丢弃：有业务价值的评论转成异常事项或调整说明；
- “额外费用”空表不产生系统数据；
- 未来日期的 Excel 对账数据不作为实际或预测事实写入系统；
- Excel 公式中的费率和系数仅用于口径核对，不自动生成系统参数；
- 系统补录必须以原始业务单据为依据，保留差异原因和审批记录；
- 金融助手中已确认、已审批或已锁定的记录不得被 Excel 直接覆盖。

### 10.4 系统与 Excel 核对矩阵

| 核对层级 | 核对内容 | 处理要求 |
|---|---|---|
| 数据覆盖 | 项目、采购、出货、资金、保证金、费用记录数 | 列出系统缺失和 Excel 缺失 |
| 主数据 | 项目、客户、供应商、SKU、负责人、平台 | 建立一对一映射及别名规则 |
| 数量 | 采购、入库、出库、库存数量 | 按项目和 SKU 核对，不只核对总量 |
| 金额 | 采购、销售、成本、回款、保证金、各项费用 | 按项目、日期和单据核对 |
| 指标 | 资金占用、周转天数、毛利、净利润 | 对比参数版本和计算日期 |
| 状态 | 项目状态、审批状态、锁定状态 | 系统状态优先，差异需解释 |

核对输出应包含：Excel 值、金融助手值、差异、差异率、原因类型、责任人、处理方案、审批结果和完成时间。

### 10.5 首批重点差异

迁移时应单独建立以下基线差异：

- 对应成本与出货成本差 450.00 元；
- 业务收入与出货毛利差 450.00 元；
- 仓储成本与出货仓储费差 1,085.50 元；
- 库存价值与采购库存成本差 12,550.00 元；
- 采购金额与采购付款/退款差 1,973,560.20 元；
- 采购数量与入库数量差 1,290，但未入库汇总为 0；
- 53 个负资金占用日期；
- 2 条负毛利出货记录。

## 11. 接口与非功能要求

### 11.1 接口原则

- 优先使用稳定业务 ID，不使用项目名称做接口主键；
- 接口记录来源系统、源单据号、源更新时间和同步批次；
- 支持增量同步、失败重试、幂等和对账；
- 来源系统删除数据时采用作废/冲销，不物理删除历史事实；
- 接口数据与手工调整分层保存。

### 11.2 性能

- 常用驾驶舱查询建议在 3 秒内返回；
- 明细查询采用分页，导出采用异步任务；
- 报表按日或按事件增量计算，避免每次扫描全量明细；
- 指标层保留日、项目、SKU 等必要聚合，原始明细仍可下钻。

### 11.3 安全与审计

- 传输和存储加密；
- 登录、查询、导出、修改、审批、参数变更和解锁均记录日志；
- 关键调整需双人复核；
- 导出文件建议带操作者、时间和水印；
- 备份、恢复和数据保留周期符合公司财务数据制度。

## 12. 实施阶段与交付物

### 阶段 0：口径澄清与数据盘点（建议 1–2 周）

交付物：

- 字段字典和业务术语表；
- 指标口径确认单；
- 主数据及来源系统清单；
- 历史差异清单；
- 金融助手 2026 年数据覆盖及质量盘点；
- 一期范围和验收基线。

退出条件：本方案“上线前必须确认的业务口径”全部有责任人和结论。

### 阶段 1：产品与数据设计（建议 2–3 周）

交付物：

- 页面原型、权限矩阵、流程图；

- 指标、参数和对账规则设计；
- 导入模板及接口规范；
- 迁移映射方案。

### 阶段 2：一期开发与单元验证（建议 4–6 周）

交付物：

- 权限、审批、日志和导出；

### 阶段 3：数据核对与试运行（建议 2–4 周）

交付物：

## 13. 测试与验收

### 13.1 功能验收

- 导入、校验、复核、锁定、调整、导出全流程可用；
- 权限按角色、组织和字段正确生效；
- 报表下钻能够定位到来源记录；
- 参数版本切换不影响已锁定历史结果；
- 异常能够生成待办并闭环。

### 13.2 数据验收

建议至少达到：

- 金融助手与 Excel 的差异记录 100% 有分类、责任人和处理结论；
- 只补录经原始业务单据确认的系统缺失记录，不因 Excel 差异直接修改系统；
- 不重复生成金融助手已有业务单据；
- 项目、采购、出货、资金主键无未解释重复；
- 出货数量、销售金额等已勾稽指标与基准文件一致；
- 金额类指标差异为 0，或全部进入已审批调节表；
- 关键维度映射率 100%，空值有“不适用/待补录”状态；
- 随机抽取不少于 30 个项目，逐笔核对采购、出货、回款和利润；
- 至少完成一个完整结算周期双轨运行。

### 13.3 计算验收用例

必须覆盖：

- 同日多笔采购/回款；
- 跨月和跨年占用；
- 部分入库、部分出库、部分回款；
- 采购退款、销售退款、保证金退回；
- 负毛利和负资金占用；
- 费率跨有效期变更；
- 项目完结后补录或冲销；
- 未来预测与实际隔离；
- 历史时点重算结果可复现。

## 14. 上线策略与回退

推荐策略：

1. 正式确认金融助手为唯一权威数据源；
2. 报表直接读取金融助手数据；
3. 完成金融助手与 Excel 的存量核对和差异分类；
4. 对系统疑似缺失或错误项回溯原始业务单据；
5. 只通过金融助手正式流程补录、调整或冲销，不用 Excel 覆盖；
6. 旧在线文档停止新增正式数据，仅作为只读核对材料；
7. 连续一个结算周期稳定后，将旧文档正式归档；
8. 保留核对文件、映射、差异处理表和日志，不删除历史证据。

若出现严重口径或数据问题，可暂停新期间确认，继续使用最近一次已锁定数据和旧台账核对；回退不得覆盖已产生的系统审计记录。

## 15. 项目治理建议

建立由业务、财务、产品、研发、测试和数据负责人组成的小组：

| 事项 | 建议责任方 |
|---|---|
| 费率、利润和资金口径 | 财务负责人 |
| 项目、订单、库存业务规则 | 业务/运营负责人 |
| 主数据及接口 | 数据/系统负责人 |
| 产品范围、流程和权限 | 产品负责人 |
| 迁移对账和验收 | 财务牵头，业务共同签字 |
| 上线与运维 | 研发/运维负责人 |

每个差异和待确认口径均应有责任人、截止日期和决策记录，避免继续依赖聊天或单元格评论。

## 16. 建议立即开展的下一步

1. 召开一次 2 小时口径工作坊，确认费率、计息、保证金、退款、完结和费用分摊；
2. 明确一期数据来源：继续 Excel 导入，还是对接运营助手/聚水潭等系统；
3. 建立项目、往来单位、商品和平台的主数据映射表；
4. 对当前已发现的金额和数量差异完成业务解释；
5. 以 10–20 个代表性项目制作系统计算原型，先验证规则再扩展全量；
6. 确定一个月作为双轨试运行期间，并冻结验收基线。

完成上述事项后，即可进入正式产品原型、数据模型和研发排期阶段。
