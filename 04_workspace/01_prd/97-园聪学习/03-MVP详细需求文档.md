# 园聪学习 MVP 详细需求文档

> 产品版本：v0.4 | 文档状态：iPad横屏第一阶段已实现  
> 日期：2026-08-21

## 1. 版本目标

通过“胡萝卜加减法”验证三件事：孩子是否理解入口和操作、是否能通过实物合并与拿走理解 10 以内加减法、答错后是否愿意继续。MVP 的成功不是题目数量多，而是独立完成率和学习反馈真实可用。

### 1.1 成功指标

| 指标 | 目标 |
|---|---:|
| 首次体验完整完成率 | ≥ 80% |
| 首局中需要家长操作帮助的儿童 | ≤ 40% |
| 答错后继续作答率 | ≥ 80% |
| 单局平均时长 | 3～5 分钟 |
| 语音、画面、算式、答案一致率 | 100% |

## 2. 用户与使用场景

- **孩子**：约 4 岁，识字少，认识少量数字，能完成点击或简单拖拽。
- **家长**：首次帮助设置，之后观察孩子操作并查看简报。
- **典型场景**：晚饭前后，家长陪同打开小程序，孩子独立完成 5 道题，家长查看一句学习建议。

## 3. 核心流程

```text
首次启动 → 家长设置 → 儿童首页 → 开始游戏
→ 题目语音/动画 → 选择答案 → 反馈 → 下一题
→ 5 题完成 → 结算/奖励 → 首页
                         └→ 家长报告
```

非首次启动直接进入儿童首页。未完成的单局在 30 分钟内可继续，超过 30 分钟重新开始且不计为中途失败。

## 4. 页面需求

### 4.1 首次设置页

**目标**：由家长在 1 分钟内完成最小设置。

**页面元素**：

- 标题：“先请爸爸妈妈帮一下”。
- 昵称输入，默认“小聪”，最多 6 个汉字，可跳过。
- 4 个角色头像单选。
- 开启题目语音，默认开启。
- “设置完成”按钮。
- 隐私说明入口：“学习记录只保存在本机”。

**规则**：

- 不请求微信昵称、头像、手机号或位置授权。
- 昵称为空时使用“小朋友”。
- 点击完成写入 `childProfile` 和 `settings`，进入首页。

### 4.2 儿童首页

#### 4.2.1 页面目标

首页是多个学习板块的总入口，定位为“学习乐园地图”，不是课程目录或家长数据看板。4 岁儿童应能依靠图标、位置和语音完成选择，不要求阅读说明。

首页优先级固定为：

```text
今日推荐（唯一主入口）
       ↓
学习乐园（全部板块）
       ↓
我的收获 / 首页 / 家长
```

#### 4.2.2 顶部问候区

- 左侧展示儿童头像和“你好，{昵称}”。
- 右侧只展示累计星星，不展示正确率、排名或连续签到。
- 每日第一次进入首页，在档案已完成设置且语音开启时，延迟约 500ms 播放：“{昵称}，今天想去哪里玩呀？”
- 自动问候日期保存在本机，同一天再次进入不自动播放。

#### 4.2.3 今日推荐卡

今日推荐卡是首页唯一使用主按钮和高视觉权重的区域，占首屏约 30%～35%。

页面内容：

- 标签：“今天玩什么”。
- 推荐标题：“去数字乐园帮助小兔”。
- 辅助信息：“5 个小游戏 · 大约 3 分钟”。
- 场景图形：小兔和胡萝卜。
- 5 个进度圆点，表示一次学习中的5个节点，不使用百分比。
- 主按钮：“开始玩”。

推荐规则：

1. 新用户默认推荐点数练习，遵循“先数量、再分解、后计算”的启蒙顺序。
2. 有30分钟内未完成的学习时，优先继续上次板块。
3. 多板块开放后，优先推荐最近较少学习的可用板块。
4. 已达到每日建议局数时仍允许进入，但推荐文案应提示适当休息。

当前版本点击“开始玩”进入 `/pages/count/count`。

#### 4.2.4 学习乐园板块区

- 标题：“学习乐园”。
- 右侧设置明显的语音按钮，点击播放：“这里是学习乐园，选一个你喜欢的地方吧。”
- 使用两列大卡片网格，不使用横向滑动。
- 每张卡片高度不低于 210rpx，整张卡片都是点击区域。
- 每张卡片包含固定图标、2～4字名称、简短状态、主题色和可选标签。
- 首屏最多完整展示4张板块卡；超过4个时纵向滚动。

当前板块配置：

| ID | 名称 | 图标 | 主题 | 状态 | 状态文字 | 路由/反馈 |
|---|---|---|---|---|---|---|
| `math` | 数字乐园 | 🥕 | 灰紫 | active | 10以内加减法 | `/pages/game/game` |
| `count` | 点数练习 | 🍬 | 柔绿 | active | 一个一个数 | `/pages/count/count` |
| `split` | 积木分一分 | 🧱 | 雾蓝 | active | 数的分解 | `/pages/split/split` |
| `dice` | 骰子游戏 | 🎲 | 暖橙 | active | 点数做加法 | `/pages/dice/dice` |

#### 4.2.5 板块状态

| 状态 | 视觉表现 | 点击行为 |
|---|---|---|
| `active` | 正常饱和度，可显示进度圆点 | 进入配置的板块路由 |
| `new` | 右上角显示“新” | 播放首次介绍后进入板块 |
| `coming` | 降低饱和度，显示“准备中” | 播放准备中语音并显示文字，不跳转 |
| `locked` | 显示锁或家长图形 | 提示找家长开启，不直接进入家长区 |
| `completed` | 显示柔和对勾，不变成禁用灰色 | 允许再次进入，并根据时长提示休息 |

禁止为 coming/locked 状态配置到空白页面的导航。

#### 4.2.6 底部导航

底部固定保留3个入口：

1. **我的收获**：当前版本点击展示累计星星；后续进入星星、贴纸和最近完成内容页。
2. **首页**：显示选中状态，帮助孩子确认当前位置。
3. **长按家长**：长按约1.5秒进入家长中心，触摸取消或移出时取消计时。

底部入口不得增加到3个以上。具体课程入口必须放在对应板块内部，不得堆到总首页底部。

#### 4.2.7 配置化扩展

首页板块由统一数据配置生成，不允许在WXML中逐个写死：

```js
{
  id: 'math',
  name: '数字乐园',
  icon: '🥕',
  theme: 'purple',
  route: '/pages/game/game',
  status: 'active',
  stateText: '10以内加减法',
  badge: '',
  progress: 2,
  total: 5
}
```

新增学习板块至少需要配置唯一ID、名称、图标、主题、状态、状态文字和路由。首页布局应在增加到6个板块时保持两列结构，不需要修改WXML。

#### 4.2.8 视觉与注意力规则

- 使用方案B的暖米色、灰紫、柔绿、雾蓝和暖橙低饱和色板。
- 今日推荐卡之外，不再出现第二个高强调主按钮。
- 同一时间最多一个角色轻微运动，不自动播放多个动画。
- 不使用红点催促、倒计时、排行榜或连续签到清零。
- 板块识别不能只依靠颜色，必须同时有图标和名称语音。
- 页面底部可显示“以后还会有新的学习乐园”，但不得诱导孩子反复点击。

#### 4.2.9 异常和容错

- 找不到板块ID时不跳转、不报错。
- active板块没有route时按准备中处理。
- 首页语音加载失败时显示文字提示，板块点击仍正常工作。
- 快速连续点击同一active卡片时，页面导航不得重复堆叠。
- 切后台时停止首页语音，返回后同一天不重复自动问候。

#### 4.2.10 首页验收标准

| 编号 | 验收项 | 通过标准 |
|---|---|---|
| H01 | 主入口识别 | 4岁儿童在首次介绍后10秒内找到“开始玩” |
| H02 | 板块区分 | 仅凭图标能指出至少3个板块不同 |
| H03 | 点击范围 | 点击卡片任意可见区域均触发对应行为 |
| H04 | active导航 | 数字乐园点击进入加减法游戏 |
| H05 | 四板块导航 | 点数、分解、加减法和骰子均进入正确横屏页面 |
| H06 | 语音频率 | 每日问候只自动播放一次，手动引导可重复播放 |
| H07 | 家长防误触 | 普通点击不进入，长按完成才进入家长区 |
| H08 | 扩展能力 | 配置增加到6个板块后仍按两列纵向滚动 |
| H09 | 导航数量 | 底部固定3项，不出现更多同级入口 |
| H10 | 无障碍表达 | 状态和板块区别均不只依赖颜色 |

### 4.3 游戏页

#### 4.3.1 默认状态

- 顶部左侧退出按钮，中央显示 `第 1 题 / 5`，右侧语音按钮。
- 加法展示两组胡萝卜，以“又送来”表达合并；减法展示初始数量、拿走数量和剩余数量。
- 语音按题型播放：“又送来……现在一共有几根”或“拿走了……现在还剩几根”。
- 动画完成后展示 3 个答案按钮。
- 底部“帮帮我”按钮，默认不突出。

#### 4.3.2 出题规则

- 加法两个加数至少为 1，结果不超过 10；减法被减数为 2～10、减数至少为 1，答案不小于 0。
- 第一题从被操作数和答案均不超过 5 的简单加减法中抽取。
- 第 2～4 题从 10 以内加减法组合中抽取，每局必须同时包含两种运算。
- 第 5 题选择此前已答对的组合或最简单的新组合。
- 同局不出现完全相同的有序加数组合。
- 三个选项为正确答案及相邻数，必须在 0～10 内且随机排序。

#### 4.3.3 语音与动画时序

1. 页面稳定 300ms 后开始播题。
2. 播到第一数量时，对应胡萝卜依次出现。
3. 播到“又送来”时，第二组从右侧移动进入。
4. 播报结束后答案区进入可操作状态。
5. 播放中点击语音按钮，从头重播；动画同步复位后重演。

若设备静音或音频失败，画面仍能完成题意表达，并显示简短文字。

#### 4.3.4 作答状态

**首次答对**：

- 锁定答案区，正确按钮轻微放大并出现星光。
- 每根胡萝卜依次高亮并播报 `1、2、3`。
- 展示 `2 + 1 = 3`，语音解释：“2 个和 1 个合起来，一共是 3 个。”
- 约 1.8 秒后自动进入下一题；同时提供“下一题”避免等待。

**首次答错**：

- 所选按钮轻轻左右摆动，不出现红叉。
- 语音：“差一点，我们看看胡萝卜怎么合起来。”
- 重放合并动画，答案区恢复可选；记录提示级别 1。

**第二次答错**：

- 自动逐个点数全部胡萝卜，正确答案按钮发光。
- 语音说明答案并展示算式；记录提示级别 2 和演示完成。
- 本题不记首次正确，但正常进入下一题且不扣奖励。

**主动求助**：

- 第一次点击“帮帮我”执行合并动画。
- 再次点击逐个点数。
- 使用提示后答对记为“提示后正确”。

#### 4.3.5 退出

- 点击退出后显示大按钮确认层：“休息一下？”
- 选项为“继续游戏”和“退出”。
- 退出保存当前题号和已完成日志，30 分钟内从首页可继续。

### 4.4 结算页

**页面元素**：

- 小兔吃饱的短动画，最长 2 秒且可跳过。
- 主文案：“5 道题完成啦！”
- 获得星星：完成即 +1；5 题均首次答对再 +1 勇气星。
- 用图标展示“自己答对 X 题”“认真数了 X 次”。
- 主按钮“回到首页”，次按钮“再玩一局”。

**规则**：

- 不显示排名、失败、满分压力或红色错题数。
- 结算以 `sessionId` 幂等处理，多次进入不重复加星。
- 连续使用达到 15 分钟时，隐藏“再玩一局”，改为“休息一下”。

### 4.5 家长门与家长页

**家长门**：长按家长图标 3 秒后，显示问题“请按顺序点一下：3、1、2”。数字位置随机。验证成功进入家长页，失败可重试。

**家长页包含**：

- 今日/累计完成局数。
- 最近 20 题首次正确率、提示使用率。
- 一句能力判断和生活陪学建议。
- 设置：语音、音乐、每日建议 1/2/3 局。
- 数据操作：导出暂无；提供“清除本机学习记录”，二次确认。

**能力判断规则**：最近某能力至少 5 题才出结论；不足 5 题显示“再完成几题后生成建议”。

### 4.6 iPad横屏公共规范

#### 4.6.1 技术与方向

- 保持微信原生 WXML、WXSS、JavaScript，不迁移UniApp。
- `app.json` 全局使用 `navigationStyle: custom`。
- 所有页面JSON设置 `pageOrientation: landscape`。
- 页面内容最大宽度为1200px并水平居中，避免iPad大屏无限放大。
- 右上角至少预留约180～220rpx胶囊安全空间，任何儿童按钮不得进入该区域。

#### 4.6.2 竖屏保护

- 公共 `orientation-guard` 组件通过 `wx.getWindowInfo()` 判断宽高。
- `windowHeight > windowWidth` 时显示全屏提示：“请把iPad横过来”。
- 提示层层级高于页面游戏内容，阻止竖屏误操作。
- 监听 `wx.onWindowResize`，转为横屏后自动消失。

#### 4.6.3 触控与视觉

- 主要按钮、答案按钮、可拖拽物体热区不小于120rpx。
- 不使用hover作为必要反馈；所有操作使用tap和touch事件。
- 儿童核心文字建议36～44rpx，数字答案可放大至55rpx以上。
- 一屏只呈现一个主要任务，左右两栏之间保留明确留白。
- 无分数、排名、倒计时、连胜和失败惩罚。

#### 4.6.3.1 手机与iPad自动适配

- 使用 `wx.getWindowInfo()` 获取当前窗口宽高，以短边作为设备布局判定依据。
- 短边 `≥600px` 归类为 `tablet`，使用iPad宽松双栏布局。
- 短边 `<600px` 归类为 `phone`，在横屏下使用紧凑双栏布局。
- CSS使用 `@media (max-height:600px) and (orientation:landscape)` 自动启用手机样式。
- 手机样式缩短顶部、安全间距、装饰图案和非关键文字，不缩小核心答案和点击热区到120rpx以下。
- iPad继续使用基础样式，保持更大的插画、留白和篮子区域。
- 两种设备共用同一套WXML、JavaScript、题库、日志和语音，禁止复制手机专用业务页面。
- 两端内容超出可视高度时均允许纵向滚动；积木拖拽过程只局部拦截页面移动。

#### 4.6.4 10分钟休息管理

- 公共 `rest-overlay` 在所有儿童页面运行。
- 只累计小程序处于前台的实际使用时间，切后台暂停，返回继续。
- 连续累计达到10分钟时显示全屏休息层，不在儿童端显示倒计时。
- 儿童可以选择“今天先玩到这里”，进入锁定状态；重新进入首页仍保持休息层。
- 只有家长长按约1.5秒才能重置本次使用时间并继续。
- 休息层文案不批评孩子，只提示看远处、眨眼和休息。

### 4.7 点数练习

#### 4.7.1 学习目标

帮助孩子建立手口一致数数能力，理解数字1～10与实际数量的对应关系。

#### 4.7.2 页面布局

- 左侧约68%为物品卡片区。
- 右侧约32%为反馈和答案区。
- 顶部显示返回、模块名称和当前第几组，不显示分数。

#### 4.7.3 玩法规则

1. 每组随机生成1～10个糖果、水果、小鱼或花朵。
2. 孩子点击一个物品，该物品缩小并降低透明度，但不完全消失。
3. 每次有效点击按当前已点数量播放1～10的离线数字语音。
4. 已点击物品不可再次点击，避免重复计数。
5. 全部物品点击完成后，右侧显示3个唯一数字选项。
6. 答对后只给予鼓励并进入下一组。
7. 答错提示“再数数看”，随后恢复所有物品，允许重新点数，不直接给答案。
8. 每局5组，完成后主动提示休息或返回学习乐园。

### 4.8 数的分解——积木分一分

#### 4.8.1 学习目标

通过真实拖拽理解5～10可以由两个部分组成，为后续加减法建立数量组成基础。禁止默写分解表。

#### 4.8.2 页面布局

- 顶部显示目标数字和当前组数。
- 上方中央展示与目标数相等的积木。
- 下方左右各一个大篮子，中间显示加号。
- 积木热区约82～92rpx，拖动时提升层级并跟随手指。

#### 4.8.3 拖拽规则

1. 目标数字随机为5～10。
2. 孩子用原生touch事件把积木拖到左篮或右篮。
3. 释放位置位于页面下半部分时，根据左右坐标进入对应篮子；释放在上方则回到起始区。
4. 已进入篮子的积木可以再次拖到另一篮或起始区。
5. 两篮数字实时显示，但不显示“正确/错误”。
6. 当起始区为空时即完成，因为两篮数量天然等于目标数。
7. 完成文案：“A和B合起来是N”。
8. 每局5组，完成后建议拿真实积木继续探索。

### 4.9 骰子游戏

#### 4.9.1 学习目标

通过骰子点数巩固数量识别和10以内加法，强调游戏性，不设置输赢。

#### 4.9.2 玩法规则

1. 页面显示两个大骰子和一个不小于120rpx的“掷骰子”按钮。
2. 每个骰子随机1～5点，和为2～10。
3. 点击后播放约0.7秒滚动动画，不使用快速闪烁。
4. 停止后显示3个唯一答案选项。
5. 答对后鼓励并进入下一组。
6. 答错只提示“再分别数一数两个骰子”，允许重新选择。
7. 不显示积分、连胜、速度或失败次数。
8. 每局5组，完成后返回学习乐园或再玩一组。

### 4.10 横屏加减法改造

- 保留原有十以内加减法题库、语音、帮助、答案校验和会话迁移。
- 页面改为左右两栏：左侧约68%显示实物和算式，右侧显示3个大答案与帮助按钮。
- 左上角放置返回，语音按钮避开右上角微信胶囊。
- 每题仍不计时、不打分；一局5题。
- 结算页改为横屏双栏，不强调累计星星数量。

## 5. 题库与内容

### 5.1 初始题目组合

`1+1、1+2、2+1、1+3、3+1、2+2、1+4、4+1、2+3、3+2`，通过三个场景模板生成至少 15 条表现内容。交换加数用于帮助理解合并关系，但不在同一局相邻出现。

### 5.2 文案原则

- 每条语音不超过 18 个汉字或约 6 秒。
- 使用“一共有几个”，不混用“总共、合计”等词。
- 角色鼓励针对行为：“你认真数完了”，避免空泛或夸张评价。
- 算式只在数量动画之后出现。

## 6. 数据结构

```js
childProfile = { id, nickname, avatar, createdAt }
settings = { voiceOn, musicOn, dailySessions: 1 }
progress = { stars, sessionsCompleted, lastPlayedAt }
questionLog = {
  id, sessionId, questionId, left, right, answer,
  firstChoice, attempts, hintLevel, demonstrated,
  startedAt, completedAt
}
sessionLog = {
  id, startedAt, completedAt, currentIndex,
  questionIds, firstCorrectCount, hintedCount,
  status, rewardGranted
}
```

本地存储分别使用带版本号的 key，例如 `yc_child_profile_v1`。读取失败时保留原始数据并回退默认值，禁止因单条异常导致整个应用无法启动。

## 7. 异常与边界

| 场景 | 处理 |
|---|---|
| 快速连续点击答案 | 首次点击后立即锁定，后续点击忽略 |
| 音频加载失败 | 显示文字并允许继续，记录非阻塞错误 |
| 切到后台 | 暂停音频和动画，回前台恢复当前题默认状态 |
| 进程被关闭 | 30 分钟内恢复未完成局，否则新建一局 |
| 本地数据损坏 | 使用默认配置启动，家长页提示修复 |
| 当日完成多局 | 可继续，但展示温和休息建议 |
| 屏幕较小 | 答案按钮仍完整可见，内容区允许纵向适配 |

## 8. 非功能需求

- 首屏本地资源加载目标 ≤ 1.5 秒。
- 点击反馈在 100ms 内出现。
- 单个非必要动画不超过 2 秒。
- 主要点击区域不小于 88rpx。
- 包体资源需压缩；数字、算式不做图片，避免缩放失真。
- 不联网也能从首页开始、完成并结算一局。
- 所有状态不能只靠颜色表达。

## 10. 原型测试任务
