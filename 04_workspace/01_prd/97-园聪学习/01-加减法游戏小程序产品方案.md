# 园聪学习——加减法游戏小程序产品方案

> 面向约 4 岁、刚开始接触加减法的儿童  
> 产品形态：微信小程序（原生）  
> 文档版本：v1.0  
> 更新日期：2026-08-21

---

## 1. 产品概述

### 1.1 产品定位

「园聪学习」是一款让学龄前儿童通过短时、低压力的小游戏理解加减法的小程序。产品不追求大量刷题，而是先让孩子看见“增加、拿走、合起来、还剩下”的过程，再逐步认识数字和算式。

### 1.2 核心目标

1. 建立 1～10 的数量感，理解数字代表多少。
2. 理解加法是“合起来/变多”，减法是“拿走/变少”。
3. 从实物动画逐步过渡到数字算式。
4. 每天用 5～8 分钟完成一次轻松练习，形成持续学习习惯。
5. 让家长能看懂孩子“会什么、容易错在哪里”，而不是只看到分数。

### 1.3 暂不追求

- 不做排行榜、好友竞争和公开社交。
- 不用连续失败惩罚、倒计时压迫、体力值等机制。
- 不以背口诀或机械刷题作为主要学习方式。
- MVP 不做乘除法、竖式、进位加法和退位减法。

### 1.4 目标用户

| 角色 | 特征 | 核心需求 |
|---|---|---|
| 孩子 | 约 4 岁，识字少，专注时间短，正在建立数量概念 | 看得懂、听得懂、点得准；答错也愿意继续 |
| 家长 | 希望孩子启蒙数学，但不一定懂教学方法 | 控制范围、了解进步、获得陪学建议 |

## 2. 产品设计原则

### 2.1 先理解，再计算

同一道题按“故事动画 → 实物数量 → 数字算式”的顺序呈现。例如：

```text
树上有 3 个苹果，又长出 2 个
        ↓
●●●  +  ●●
        ↓
3 + 2 = ?
```

### 2.2 语音优先

- 题目、按钮含义和反馈均支持语音播报。
- 页面文字只作为家长辅助，不要求孩子识字。
- 进入题目自动播报一次，并始终提供明显的“再听一次”按钮。

### 2.3 一屏只做一件事

- 单屏只展示一道题和一个主要操作。
- 可点击区域不小于约 88rpx，关键按钮使用大图形和高对比色。
- 选项最多 3 个，避免信息过载。

### 2.4 正向纠错

- 答对：即时说明“为什么对”，配轻量庆祝动画。
- 第一次答错：不显示红叉，不扣星星，提示“我们一起数一数”。
- 第二次答错：播放逐个点数动画，让孩子再次选择。
- 第三次仍不会：演示答案并放入稍后复习，不阻塞本局。
- 不使用“太笨了”“失败”等负面表达。

### 2.5 控制屏幕时间

- 每局建议 5 题，约 3～5 分钟。
- 每日建议 1～2 局；连续使用 15 分钟后提醒休息。
- 动画服务于数量变化，不加入难以跳过的长动画。

## 3. 难度体系

儿童端不直接显示“简单/普通/复杂”，改为更轻松的主题名称；家长端保留标准难度名称。

| 家长端 | 儿童端 | 数值范围 | 表现方式 | 主要题型 | 目标 |
|---|---|---:|---|---|---|
| 简单 | 🌱 萌芽岛 | 1～5 | 全程显示实物和变化动画 | 数量匹配、增加 1、拿走 1、5 以内加减 | 理解数量与“变多/变少” |
| 普通 | 🌼 花朵岛 | 1～10 | 实物为主，逐步出现算式 | 10 以内不进位加法、不退位减法、缺图补数 | 能借助数物完成计算 |
| 复杂 | 🚀 星星岛 | 1～20 | 数字为主，可主动查看图示提示 | 20 以内不进位/不退位、简单缺项、混合判断 | 从具象过渡到心算 |

### 3.1 各档题目边界

#### 简单 / 萌芽岛

- 数字范围 1～5，答案允许为 0。
- 初期只练“增加 1”和“拿走 1”，掌握后再扩展到任意 5 以内加减。
- 每个物体均可点击并逐个发声计数。
- 加法和减法分开成局，不在同一局频繁切换。

#### 普通 / 花朵岛

- 数字范围 1～10。
- 加法结果不超过 10；减法被减数不超过 10，且不出现负数。
- 引入 `3 + 2 = ?`，同时保留实物提示按钮。
- 可出现“还差几个凑成 5/10”的补数题。

#### 复杂 / 星星岛

- 数字范围 1～20。
- MVP 阶段不做进位和退位，例如可以出现 `13 + 4`、`18 - 5`，不出现 `8 + 7`、`12 - 5`。
- 可出现 `? + 2 = 5`、`7 - ? = 4` 等缺项题，但每局不超过 1 题。
- 图示提示由默认显示改为孩子主动点击查看。

### 3.2 解锁与自适应规则

- 首次使用从简单档开始，家长也可直接指定可用难度。
- 最近 3 局共至少 15 题，首次作答正确率达到 80%，且使用提示不超过 30%，建议解锁下一档。
- 升级只弹出“发现了新岛屿”，不提示孩子优于或落后于他人。
- 最近 2 局首次正确率低于 50% 时，不自动降级；下一局自动减少数值范围、增加图示，并向家长提示复习建议。
- 错题不原样连续重复，间隔 2～3 题后以不同物品和故事重新出现。

## 4. 核心游戏设计

MVP 建议先做 3 个核心游戏，玩法简单但覆盖“数量—变化—算式”的学习路径。

### 4.1 游戏一：喂饱小动物（加法）

**场景**：小兔面前有 2 根胡萝卜，又送来 1 根，请孩子把正确数量拖进餐盘。

**操作流程**：

1. 语音：“盘子里有 2 根胡萝卜，又送来 1 根，现在有几根？”
2. 动画展示 2 根和新增的 1 根汇合。
3. 孩子从 3 个数字/数量选项中选择答案。
4. 答对后逐个点数，并出现 `2 + 1 = 3`。

**训练能力**：合并数量、加法含义、数字与数量对应。

### 4.2 游戏二：小熊商店（减法）

**场景**：货架有 5 个面包，顾客买走 2 个，请孩子将 2 个面包拖进购物篮，再判断剩余数量。

**操作流程**：

1. 孩子实际执行“拿走”动作。
2. 被拿走的物品移动并变灰，剩余物品保持可数。
3. 选择剩下的数量。
4. 动画回放并出现 `5 - 2 = 3`。

**训练能力**：拿走与剩余、减法含义、动作与符号对应。

### 4.3 游戏三：数字小火车（综合）

**场景**：火车车厢上显示数字或算式，孩子选择正确数量的乘客上车。

**玩法变化**：

- 简单：数字 4 对应 4 只小动物。
- 普通：`3 + 2` 对应 5 只小动物。
- 复杂：补齐 `? + 2 = 6` 的缺失车厢。

**训练能力**：数量匹配、算式识别、从实物向符号过渡。

### 4.4 后续可扩展玩法

| 游戏 | 玩法 | 适用阶段 |
|---|---|---|
| 水果切切乐 | 按答案切中对应数量的水果 | 简单、普通 |
| 池塘钓鱼 | 钓上/放回若干条鱼后回答数量 | 简单、普通 |
| 找朋友凑数字 | 两张数字卡合起来得到目标数 | 普通、复杂 |
| 数字跳格子 | 角色在数轴上向前/向后跳 | 普通、复杂 |
| 小小修理师 | 为缺项算式装上正确零件 | 复杂 |

## 5. 单局学习流程

```text
选择岛屿
   ↓
角色语音说明玩法（首次出现时）
   ↓
热身题 1 道 → 核心题 3 道 → 巩固题 1 道
   ↓
获得星星与贴纸
   ↓
“再玩一局”或“今天先休息”
```

### 5.1 题目结构

每局固定 5 题，系统根据孩子表现动态组题：

| 位置 | 类型 | 目的 |
|---|---|---|
| 第 1 题 | 已掌握的简单题 | 快速进入状态 |
| 第 2～3 题 | 当前学习目标 | 核心练习 |
| 第 4 题 | 当前目标的不同表现形式 | 检查是否真正理解 |
| 第 5 题 | 已掌握题或较简单的新题 | 以成功体验结束 |

### 5.2 反馈文案示例

| 场景 | 语音/文案 |
|---|---|
| 答对 | “答对啦！2 个和 1 个合起来，一共是 3 个。” |
| 首次答错 | “差一点点，我们一起数一数吧。” |
| 使用提示 | “点一个，数一个：1、2、3……” |
| 完成本局 | “你帮助了 5 位小伙伴，获得一颗星星！” |
| 建议休息 | “眼睛要休息啦，明天再来帮助小伙伴吧。” |

## 6. 激励与成长体系

### 6.1 激励原则

- 奖励“认真完成、愿意尝试和学会新方法”，不只奖励全对。
- 不设置全球排行榜和孩子之间的公开比较。
- 不因答错扣除已有奖励。
- 奖励展示短而明确，避免奖励动画反过来干扰学习。

### 6.2 星星和贴纸

- 完成一局获得 1 颗基础星星；独立完成可额外获得 1 颗“勇气星”。
- 每完成 3 局，随机获得一张主题贴纸。
- 重复贴纸可用于装饰自己的小房间，不转化为付费抽卡。
- 连续学习只记录“本周来了几天”，不因中断清零全部成果。

### 6.3 成长地图

三个岛屿分别对应三档难度。每个岛屿设置 6～8 个小节点，每个节点解锁一种场景或角色外观。成长地图展示个人探索进度，不展示班级或好友排名。

## 8. 题库设计

### 8.1 题目数据结构建议

```json
{
  "id": "add_5_story_001",
  "operation": "addition",
  "difficulty": "easy",
  "gameType": "feed_animal",
  "representation": "objects_and_equation",
  "left": 2,
  "right": 1,
  "answer": 3,
  "options": [2, 3, 4],
  "objectType": "carrot",
  "voiceTemplate": "盘子里有{left}根胡萝卜，又送来{right}根，现在有几根？",
  "skillTags": ["quantity_1_5", "addition_as_joining"],
  "hintSteps": ["animate_merge", "count_objects", "show_number_line"]
}
```

### 8.2 自动出题约束

- 答案选项必须互不重复，且不出现负数。
- 干扰项优先使用 `答案 - 1`、`答案 + 1`，但超出当前范围时自动替换。
- 同一局不连续使用完全相同的数字组合和物品。
- 减法必须满足 `被减数 ≥ 减数`。
- 简单档避免连续 3 题答案相同。
- 语音数字必须与画面物品数量一致，生成后应有自动校验。
- 题目日志需记录首次答案和提示次数，不能只记录最终是否答对。

### 8.3 学习标签

建议按能力而非仅按题目记录数据：

- `quantity_1_5`：1～5 数量感
- `quantity_1_10`：1～10 数量感
- `addition_as_joining`：理解加法是合并
- `subtraction_as_taking_away`：理解减法是拿走
- `symbol_plus_minus`：认识 `+`、`-`、`=`
- `number_bonds_5`：5 的组成
- `number_bonds_10`：10 的组成
- `equation_missing_part`：缺项算式

## 9. 家长端学习报告

家长报告以“能力建议”为主，不给 4 岁儿童贴“差/不及格”的标签。

### 9.1 核心指标

| 指标 | 说明 |
|---|---|
| 首次作答正确率 | 不含看过答案后的再次选择，更能反映掌握情况 |
| 提示使用率 | 判断孩子是否仍依赖实物点数 |
| 平均完成时间 | 仅供家长观察，不向孩子强调速度 |
| 能力掌握度 | 按学习标签统计最近 20 题表现 |
| 常见错误 | 数错物品、加减混淆、数字识别、缺项理解等 |

### 9.2 报告文案示例

> 小聪已经能独立完成 5 以内“合起来”的题目；“拿走后还剩多少”有时会重新数全部物品。建议生活中用 3 块积木拿走 1 块，让他先说“拿走”，再数剩余数量。

## 10. 视觉、声音与可用性规范

### 10.1 视觉

- 主色建议使用柔和的蓝绿或橙黄，正确反馈使用绿色但不依赖颜色单独传意。
- 每屏主色不超过 3 种，背景降低饱和度，题目物品保持清晰。
- 数字采用圆润、笔画清楚的字体；核心数字建议不小于 64rpx。
- 加号、减号、等号须有足够间距，避免与装饰元素混淆。
- 不使用快速闪烁、强烈震动或高频粒子特效。

### 10.2 声音

- 配音语速比成人日常语速慢约 15%～20%，句子尽量短。
- 数数时每个数字和对应物体动画同步。
- 背景音乐默认轻柔，语音播报时自动降低音量。
- 家长可一键关闭背景音乐，但题目语音和音效分开控制。

### 10.3 无障碍与容错

- 颜色之外同时使用形状、图标和语音表达状态。
- 拖拽失败时物品自动回位，不产生扣分。
- 关键页面退出前保留当前题目，意外切后台后可继续。
- 网络不可用时，MVP 核心题库和常用语音应支持本地运行。

## 11. MVP 范围

### 11.1 首版必须有（P0）

1. 儿童档案与首次家长设置。
2. 简单、普通、复杂三档难度及锁定/解锁机制。
3. “喂饱小动物”“小熊商店”“数字小火车”3 个游戏。
4. 5 以内和 10 以内加减法；复杂档先支持 20 以内不进退位题。
5. 语音播题、再听一次、分步提示和正向纠错。
6. 每局 5 题、结算页、星星和基础成长地图。
7. 本地学习记录、错题间隔复现和简单自适应组题。
8. 家长设置与基础学习报告。
9. 休息提醒、隐私说明和儿童信息最小化采集。

### 11.2 第二阶段（P1）

- 更多主题皮肤和游戏场景。
- 5/10 的组成、数轴跳格和缺项算式专项练习。
- 多孩子档案与云端同步。
- 周报、家庭陪学任务、贴纸房间装饰。
- 家长录制鼓励语音。

### 11.3 后续探索（P2）

- 进位加法与退位减法，需要单独设计十框/凑十教学。
- 基于能力标签的更精细自适应路径。
- 语音回答与儿童发音容错。
- 平板横屏模式与更多无障碍能力。

## 12. 技术实现建议

### 12.1 首版架构

结合当前目录中的微信小程序原生骨架，建议：

```text
前端：微信小程序原生 WXML + WXSS + JavaScript
数据：首版使用本地 JSON 题库 + wx Storage 学习记录
音频：预置常用数字、指令和鼓励语音，减少联网依赖
动画：WXSS 动画 + Canvas（仅用于轻量数量变化效果）
云端：第二阶段再接入微信云开发进行多端同步和家长周报
```

首版先采用本地优先，可以降低登录、网络、数据库和儿童隐私处理的复杂度，更快验证孩子是否真正喜欢并理解玩法。

## 13. 隐私与儿童安全

- 默认不采集真实姓名、头像照片、手机号和精确位置。
- 首版不需要微信头像昵称授权即可使用。
- 家长区通过成人门槛进入，付费、分享、外链等能力不得出现在儿童游戏流程中。
- 不接入面向儿童的个性化广告，不用分享行为换取奖励。
- 学习记录默认保存在本机；启用云同步时需由家长明确同意并提供删除入口。
- 正式上线前按微信小程序最新规则完善隐私保护指引、儿童个人信息处理说明和监护人同意流程。

## 14. 验收标准

### 14.1 儿童可用性

- 4 岁儿童在家长首次说明后，能独立开始一局并完成点选/拖拽。
- 不识字的孩子可以仅依靠图形和语音理解主要流程。
- 单局 5 题平均在 3～5 分钟完成。
- 答错后能继续操作，不会因弹窗或复杂提示卡住。

### 14.2 学习有效性

- 每道题均能回放数量变化过程，而非只报答案。
- 系统区分首次正确、提示后正确和演示后完成。
- 错题会间隔复现，且以不同场景呈现。
- 难度升级依据正确率和提示率综合判断。

### 14.3 产品质量

- 无网络时可完成至少一个完整游戏局。
- 重启或切后台后，已完成进度不丢失。
- 语音、画面数量、算式和答案四者一致。
- 所有主要按钮均有按下反馈，连续点击不会重复结算。

## 15. 开发路线建议

| 阶段 | 目标 | 主要产出 |
|---|---|---|
| 第 1 阶段：原型验证 | 验证孩子是否看得懂、愿意玩 | 首页 + 1 个加法游戏 + 15 道固定题 + 语音 |
| 第 2 阶段：MVP | 跑通三档难度和学习闭环 | 3 个游戏、自动组题、反馈、成长、家长报告 |
| 第 3 阶段：家庭内测 | 修正交互和难度 | 观察记录、错题分析、语音与动画优化 |
| 第 4 阶段：上线准备 | 满足稳定性与合规要求 | 隐私流程、兼容性测试、资源压缩、体验版审核 |

### 15.1 原型验证重点

先找 3～5 名接近 4 岁的孩子，在家长陪同下观察，而不是询问“喜不喜欢”。重点记录：

- 是否知道从哪里开始。
- 是否理解“又来了”和“拿走了”。
- 会不会误触，拖拽是否困难。
- 第几题开始分心。
- 答错时是否愿意重试。
- 奖励动画是否过长或抢走对题目本身的注意。

## 16. 产品成功指标

首版以内测学习效果和可用性为主，不以日活规模为第一目标。

| 指标 | 建议目标 |
|---|---:|
| 首局完成率 | ≥ 80% |
| 单局中途退出率 | ≤ 15% |
| 首次提示后继续作答率 | ≥ 80% |
| 7 日内再次使用比例 | ≥ 40%（家庭内测参考） |
| 语音重复播放率 | 用于判断题目是否过长，不设越低越好的目标 |
| 简单档连续 3 局掌握率 | 首次正确率 ≥ 80%、提示率 ≤ 30% |

---

## 17. 推荐的第一版体验

第一版不要同时铺开所有功能。建议先实现“萌芽岛—喂饱小兔”：15 道 5 以内加法题、语音播报、实物合并动画、三选一答案、分步提示和本局奖励。让真实孩子试玩并验证交互后，再复用同一套题目引擎开发减法和更高难度，能够显著降低返工风险。
