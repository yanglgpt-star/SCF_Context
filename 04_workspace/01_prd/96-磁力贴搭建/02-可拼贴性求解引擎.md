# 可拼贴性求解引擎 — 技术方案

> 配套：[01-整体方案.md](01-整体方案.md) 的 P0 与 P2 阶段
> 本文回答一个问题：**给定一张草稿图和一套磁力片库存，怎么确定性地算出「能不能拼出来」？**

---

## 一、为什么必须自研求解器

「用 AI 模拟搭建」有两种做法，成本差别极大：

| | 让大模型直接画 | 用求解器算 |
|---|---|---|
| 输出 | 一张看起来像拼贴的图 | 每片的精确坐标、旋转、形状 ID |
| 能否验证 | 不能，人眼都难判断 | 能，覆盖率是可计算指标 |
| 库存约束 | 靠提示词，经常忽略 | 硬约束，超了就无解 |
| 边对不齐 / 有缝隙 | 常见 | 数学上不可能出现 |
| 批量跑 100 张 | 不稳定，风格漂移 | 完全一致 |
| 用于指导实物搭建 | 不可靠，搭到一半发现搭不出 | 可信 |

结论：**求解器是必需品，不是优化项**。大模型的角色退回到它擅长的位置——看图和写文案。

## 二、形状几何建模

### 2.1 标准套装形状参数

以正方形边长为基准单位 `a`（市面常见 6 / 7 / 7.5 cm，**必须用卡尺实测你手上的实物**）：

| 形状 ID | 名称 | 几何参数 | 面积（a²） | 占格数（T 单位） |
|---|---|---|---|---|
| `SQ` | 正方形 | 边长 a | 1.000 | 2 |
| `TRI-R` | 等腰直角三角形 | 直角边 a，斜边 a√2 | 0.500 | 1 |
| `RECT` | 长方形 | 2a × a | 2.000 | 4 |
| `TRI-E` | 等边三角形 | 边长 a | 0.433 | — （60° 族） |
| `SECTOR` | 扇形（1/4 圆） | 半径 a | 0.785 | — （含圆弧） |
| `SEMI` | 半圆 | 半径 a/2 | 0.393 | — （含圆弧） |

### 2.2 关键几何约束：两个角度族不能混拼

这是整个求解器设计的前提，务必先理解：

```
直角族 (45°/90°)                     三角族 (60°/120°)
┌───┬───┐                            ╱╲╱╲╱╲
│   │   │   正方形 90°              ╱  ╲  ╱  ╲
├───┼───┤   等腰直角三角 45°/90°   ╲  ╱╲  ╱
│   │   │   长方形 90°              ╲╱  ╲╱
└───┴───┘   扇形 90°                等边三角 60°
            半圆 180°               六边形 120°

        两族的边方向不重合，在同一平面内
        无法满足「边对边无缝共边」的拼贴要求
```

**工程结论**：
- **平面拼贴只用直角族**（`SQ` / `TRI-R` / `RECT`）
- **等边三角形留给立体搭建**（在立体结构里它是不同朝向的面，不受平面共边约束）
- 扇形/半圆含圆弧，另行处理（见 2.4）

这个结论能砍掉大量复杂度。而且亲子题材（动物、字母、数字、几何图案）绝大多数是方正的，直角族完全够用。

### 2.3 最小单元：单位直角三角形 T

直角族的所有形状都是「单位直角三角形 T」的整数倍：

```
T 的定义：直角边 a、a，斜边 a√2

  SQ    = 2 × T（两个 T 沿斜边对拼）
  TRI-R = 1 × T
  RECT  = 4 × T（2×2 个 T）
```

**这意味着：整个平面拼贴问题可以离散化成一个 T 网格上的精确覆盖问题。** 这是本方案能落地的关键——把连续几何问题变成组合优化问题。

T 网格的坐标表示：

```
格子坐标：(i, j, k)
  i, j = 方格坐标（a 为单位）
  k ∈ {0, 1} = 该方格内的两个三角（0 = 左下三角，1 = 右上三角）

  (i,j,0) 的顶点：(i·a, j·a), ((i+1)·a, j·a), (i·a, (j+1)·a)
  (i,j,1) 的顶点：((i+1)·a, j·a), ((i+1)·a, (j+1)·a), (i·a, (j+1)·a)
```

### 2.4 扇形与半圆的处理

扇形有圆弧边，无法用 T 精确表示。三种处理方式：

| 方案 | 做法 | 建议 |
|---|---|---|
| **一期：不支持** | 平面作品里不出现圆弧形状 | ✅ **推荐**，造型选型时避开弧度 |
| 二期：边界附着 | 扇形占一个 a×a 方格，直边落在网格线上，作为「跨格 tile」注册 | 扩展方案 |
| 三期：混合网格 | 引入圆弧的细分近似 | 复杂度高，非必要不做 |

一期直接砍掉，能省掉大量边界情况处理。

## 三、从草稿图到目标区域

### 3.1 完整管线

```
草稿图 (PNG)
   │
   ├─① 去背景          rembg / SAM → 只留主体
   ├─② 二值化          主体 mask，可做形态学闭运算填补空洞
   ├─③ 轮廓提取        OpenCV findContours → 多边形
   ├─④ 轮廓简化        Douglas-Peucker，控制顶点数到 20-40 个
   ├─⑤ 顶点吸附 ★      snap 到 T 网格顶点（关键步）
   ├─⑥ 边方向吸附 ★    每条边吸附到 0° / 45° / 90° / 135°
   ├─⑦ 区域生成        得到目标格子集合 C = {(i,j,k)}
   │
   └─→ 目标区域 C
```

第 ⑤⑥ 步是**成败关键**。跳过它们，任意曲线轮廓会得到极低的覆盖率；做完吸附，轮廓变成「网格友好」的直角多边形，覆盖率能上 95%。

### 3.2 顶点吸附的具体做法

```
对简化后的每个顶点 p：
    最近网格点 q = round(p / (a/1)) 对齐到方格顶点
    若 |p − q| > 阈值：标注为「高偏差顶点」，在可行性报告里提示

对每条边 e = (p1, p2)：
    计算角度 θ
    吸附到最近的允许方向：0°, 45°, 90°, 135°, 180°, 225°, 270°, 315°
    以两端吸附后的顶点重算边

吸附后可能出现自交或退化 → 用 Shapely 做 buffer(0) 修复
```

### 3.3 网格原点对齐的优化

网格原点的选择会影响覆盖率。做法：

```
枚举 K 个候选原点偏移（如 4×4 = 16 个偏移，各偏移 a/4）
对每个偏移计算吸附后的覆盖率
取覆盖率最高的偏移
```

代价很低（栅格化很快），收益明显。

## 四、求解算法

### 4.1 问题形式化

**输入**
- 目标格子集合 `C`（来自第三章）
- 形状库存 `S = {(形状 i, 数量 nᵢ)}`

**输出**
- 放置集合 `P = {(形状 i, 位置 p, 旋转 θ, 颜色 c)}`，满足：
  1. `⋃ coverage(p) = C`（精确覆盖，无缝隙）
  2. `coverage(p) ∩ coverage(p') = ∅`（无重叠）
  3. `count(i) ≤ nᵢ`（不超库存）

这是经典的**精确覆盖问题（Exact Cover）**，标准解法是 DLX（Dancing Links，Knuth 的 Algorithm X）。

### 4.2 候选放置枚举

```
对每个 T 格 (i, j, k)：
    SQ    在该格有 2 种放置（T(0)+T(1) 的组合，即整个方格）
    TRI-R 在该格有 2 种朝向（k=0 或 k=1）

再对每个 T 格考虑 4 个方格位置（作为形状的锚点）：
    SQ    候选数 ≈ |C| / 2 × 1 = O(|C|)
    TRI-R 候选数 ≈ |C| × 2 = O(|C|)
    RECT  候选数 ≈ |C| / 4 × 2（横竖）= O(|C|)
```

规模估算：一张 20×20 格的作品，`|C| ≈ 800` 个 T 格 → 候选放置约 **2400 个**。

### 4.3 DLX 求解

```
矩阵构造：
  列 = |C| 个格子（每列必须被恰好覆盖一次）+ 每种形状一列（容量 = nᵢ）
  行 = 每个候选放置

求解：DLX 回溯，命中数量约束时剪枝
```

这个规模（2400 行 × 800+ 列）用纯 Python 实现 DLX 完全跑得动，**单次求解毫秒到秒级**。

### 4.4 带优化目标的版本（CP-SAT）

精确覆盖通常有**多个解**，需要择优。用 OR-Tools CP-SAT 表达：

| 目标 | 权重 | 理由 |
|---|---|---|
| 最少片数 | 高 | 省料、搭建快、视频短 |
| 最少形状种类 | 中 | 备料简单，观众易跟做 |
| 最大对称性 | 中 | 对称造型在短视频里更吸睛 |
| 颜色分布均衡 | 低 | 避免出现孤立异色块 |
| 优先用掉库存多的形状 | 低 | 库存周转 |

```python
# 目标函数示意
model.Minimize(
    1.0 * total_pieces +
    0.5 * distinct_shape_kinds +
    0.3 * asymmetry_score +
    0.2 * color_scatter_score
)
```

**建议**：先用 DLX 快速判定「有没有解」，有解再用 CP-SAT 在若干解里择优。两级策略兼顾速度和效果。

### 4.5 求解失败怎么办

失败不要直接判死刑，按梯度降级：

| 级别 | 策略 | 输出 |
|---|---|---|
| L0 | 原轮廓精确覆盖 | 完美方案 |
| L1 | 换网格原点（16 个偏移）重试 | 大概率能救回 |
| L2 | 放宽为「高覆盖率」：允许 ≤5% 格子未覆盖（空洞用背景色处理） | 近似方案 + 覆盖率 |
| L3 | 轮廓简化：减少顶点、拉直凹凸、增强对称 | 新的目标区域 |
| L4 | 回退到 P1，重新生成草稿（提示词加强「方正、大色块、少细节」） | 新草稿 |
| L5 | 标记为「不可拼」，从选题库剔除并记录原因 | 负样本 |

**L5 的负样本很有价值**——积累起来能反过来训练 P1 的选题提示词，形成正循环。

### 4.6 步骤序列生成（流程图和视频的原料）

求解出的是「一堆片的集合」，不是「搭建顺序」。顺序要单独生成，且有约束：

**硬约束：连通性**
每一步新加的片，必须与「已搭建的结构」至少有 1 条边相邻。否则实物搭建时那片会孤立放不住（磁力片没有底座支撑）。

**软约束：符合真人搭建习惯**

| 策略 | 说明 | 适用 |
|---|---|---|
| 中心向外 | 从作品中心开始，逐层扩散 | 对称造型（推荐默认） |
| 从下到上 | 先搭底部轮廓，再往上填 | 有明确上下方向的造型（动物、房子） |
| 按颜色分组 | 先把一个颜色搭完，再加下一个 | 颜色块状分明的造型 |
| 按区域分块 | 先搭左半，再搭右半 | 大作品 |

**实现**：BFS / 贪心 + 连通性检查

```
已搭集合 A = ∅，步骤列表 steps = []
剩余片集合 R = 全部片

while R 非空:
    候选 = {p ∈ R | 与 A 相邻（共享至少一条边）}
    if 候选为空:  # 说明有孤立区域，从 A 里找一个「新起点」
        候选 = R 中按选定的排序策略排在最前的片
    按策略从候选中选一片 p
    steps.append(p); A.add(p); R.remove(p)

输出多套（中心向外 / 从下到上 / 按颜色）让用户挑
```

**输出格式**：每个 step 包含新增的片的列表（可以是多片）、该步的说明文案占位、当前完成度百分比。

多片合并成一步很重要——**60 片分 60 步的视频没人看**，实际要合并到 6-12 步。

## 五、可行性判定标准

把「能不能成功」变成一个可量化的报告：

| 指标 | 定义 | 阈值 |
|---|---|---|
| **覆盖率** | 已覆盖 T 格 / 目标 T 格 | ≥ 95% 判通过，≥ 99% 判优秀 |
| **溢出率** | 超出轮廓的 T 格 / 目标 T 格 | ≤ 5% |
| **库存满足** | 各形状用量 ≤ 库存 | **必须满足**，否则直接判失败 |
| **连通性** | 每一步的增量都与已搭结构相邻 | **必须满足** |
| **对称性分** | 左右/上下镜像重合度 | 0-100，供选题参考 |
| **难度分** | `f(片数, 形状种类, 颜色种类, 对称性)` | 映射到年龄档位 |

**难度分建议公式**（权重可调，先跑起来再校准）：

```
难度 = 0.5 × 片数/30
     + 0.2 × 形状种类/4
     + 0.2 × 颜色种类/5
     + 0.1 × (1 − 对称性分/100)

档位映射：< 0.4 → 启蒙(3-4岁)
          0.4-0.7 → 进阶(5-6岁)
          > 0.7 → 挑战(7-8岁)
```

**求解报告输出示例**：

```json
{
  "solvable": true,
  "coverage": 0.982,
  "overflow": 0.011,
  "stock_ok": true,
  "connectivity_ok": true,
  "total_pieces": 27,
  "shape_usage": { "SQ": 14, "TRI-R": 9, "RECT": 4 },
  "color_usage": { "红色": 8, "黄色": 7, "蓝色": 6, "绿色": 6 },
  "symmetry_score": 82,
  "difficulty": 0.46,
  "age_band": "进阶(5-6岁)",
  "steps_count": 8,
  "fallback_level": "L0"
}
```

## 六、与视觉模型的分工边界

大模型（VLM）在这个引擎里的三个角色，**都只作为辅助，不作为最终判定**：

| 角色 | 输入 | 输出 | 用途 |
|---|---|---|---|
| **热启动** | 草稿图 + 形状库描述 | 建议的形状构成与大致布局（JSON） | 给求解器一个初始倾向，加速收敛 |
| **候选生成** | 草稿图 | 候选拼贴 SVG | 求解器校验并修正（snap、补缺口） |
| **失败归因** | 草稿图 + 失败报告 | 「这个造型不适合拼贴，因为…」 | 给 P1 反馈，改进提示词 |

**混合流程（推荐）**：

```
草稿图 ──→ VLM 输出候选 SVG ──→ 吸附到网格 ──→ 求解器校验/修正
                                                      │
                            校验失败 ←────────────────┘
                                │
                                └─→ 纯求解器从零求解（DLX）
```

VLM 出候选能把求解成功率从 70% 拉到 85% 左右，但**校验和修正必须由求解器做**。这是「快」和「准」的分工。

## 七、工程实现建议

### 7.1 技术栈

| 模块 | 选型 | 备注 |
|---|---|---|
| 图像处理 | Python + OpenCV + Pillow | 管线①-④ |
| 几何运算 | Shapely | 多边形吸附、修复、面积计算 |
| 精确覆盖 | 自研 DLX（约 300 行） | 无重依赖，可控 |
| 约束优化 | OR-Tools CP-SAT | 多解择优 |
| 数据交换 | JSON | 求解器唯一出口格式 |
| 渲染 | TypeScript + SVG | 与求解器解耦，只吃 JSON |

**架构原则**：求解器（Python）与渲染器（TypeScript）**只通过 JSON 通信**。这样算法可以独立迭代，渲染层可以独立迭代，互不影响。

### 7.2 性能预估

| 环节 | 规模 | 耗时 |
|---|---|---|
| 去背景 + 轮廓提取 | 1024×1024 图 | < 2 秒 |
| 轮廓吸附 | 20-40 个顶点 | < 0.1 秒 |
| 候选枚举 | ~2400 个放置 | < 0.5 秒 |
| DLX 求解 | 2400 × 800 | 秒级 |
| CP-SAT 择优 | 同上 + 目标函数 | 10-60 秒 |
| 步骤序列生成 | 全图 BFS | < 0.1 秒 |

**整个 P2 阶段单作品耗时可控在 1 分钟内**（不含 LLM API 调用）。批量跑 100 个作品完全可行。

### 7.3 开发顺序建议

```
Step 1  T 网格与形状定义        → 能画出网格、能放置/渲染单个形状
Step 2  SVG 渲染器              → 能吃 JSON 渲染拼贴图（先做渲染，好调试）
Step 3  DLX 精确覆盖            → 手工给一个矩形轮廓，能求出覆盖
Step 4  轮廓吸附管线            → 从真实草稿图跑到目标区域
Step 5  库存约束 + 求解报告      → 输出第五章的 JSON
Step 6  步骤序列生成            → 输出有序 steps
Step 7  CP-SAT 择优             → 加分项，可后置
```

**先做 Step 2（渲染器）**，因为它让后面每一步的结果都可见，调试效率翻倍。
