# 资产库与内容管线

> 配套：[01-整体方案.md](01-整体方案.md) 的 P4 / P5 / P6 阶段
> 本文回答：**步骤数据怎么存，流程图/视频/小程序怎么从同一份数据里出来？**

---

## 一、核心原则：一份数据，三种输出

```
                    ┌──→ 静态流程图（SVG → PNG 信息图 / 轮播图）
                    │
步骤数据 work.json ──┼──→ 搭建视频（Remotion → MP4，多规格）
                    │
                    └──→ 小程序交互演示（同 SVG 数据 + 交互层）
```

**只有一份数据要维护**。改一个步骤的顺序，三种产物同步更新。这是批量生产的前提——如果流程图、视频、小程序各维护一份数据，做到第 20 条就会崩。

---

## 二、步骤数据 Schema（最关键的一份定义）

放在 `library/works/<workId>/work.json`：

```json
{
  "workId": "W-20260917-001",
  "version": 3,

  "meta": {
    "title": "小黄鸭",
    "theme": "动物",
    "ageBand": "启蒙",
    "difficulty": 0.32,
    "totalPieces": 12,
    "tags": ["动物", "黄色", "入门"],
    "createdAt": "2026-09-17"
  },

  "canvas": {
    "unit": 7.5,
    "cols": 12,
    "rows": 10,
    "padding": 40,
    "background": "#F7F5F0"
  },

  "palette": {
    "黄": "#F5C518",
    "橙": "#F08A24",
    "黑": "#2B2B2B",
    "白": "#FFFFFF"
  },

  "tiles": [
    { "id": "t01", "shape": "SQ",    "i": 3, "j": 4, "rot": 0,   "color": "黄" },
    { "id": "t02", "shape": "SQ",    "i": 4, "j": 4, "rot": 0,   "color": "黄" },
    { "id": "t03", "shape": "TRI-R", "i": 2, "j": 5, "rot": 180, "color": "橙" },
    { "id": "t04", "shape": "RECT",  "i": 3, "j": 6, "rot": 0,   "color": "橙" }
  ],

  "steps": [
    {
      "no": 1,
      "tileIds": ["t01", "t02"],
      "caption": "第 1 步 · 长方形 ×2（共 2 片）",
      "progress": { "done": 2, "total": 4 },
      "camera": { "cx": 4.0, "cy": 4.5, "zoom": 1.6 }
    },
    {
      "no": 2,
      "tileIds": ["t03", "t04"],
      "caption": "第 2 步 · 三角形 ×2（共 2 片）",
      "progress": { "done": 4, "total": 4 },
      "camera": { "cx": 4.0, "cy": 5.5, "zoom": 1.4 }
    }
  ],

  "solution": {
    "coverage": 0.982,
    "symmetryScore": 82,
    "fallbackLevel": "L0",
    "shapeUsage": { "SQ": 6, "TRI-R": 4, "RECT": 2 }
  },

  "assets": {
    "draft": "works/W-20260917-001/draft.png",
    "render": "works/W-20260917-001/render.svg",
    "stepImages": ["works/W-20260917-001/step-01.svg", "works/W-20260917-001/step-02.svg"],
    "photos": ["works/W-20260917-001/photo-front.jpg", "works/W-20260917-001/photo-top.jpg"],
    "video": "works/W-20260917-001/video-9x16.mp4",
    "cover": "works/W-20260917-001/cover.png"
  }
}
```

> **本页示例与代码不一致的三处，一律以代码为准**（M6/M7 实施时确认）：
>
> - **`progress` 存 `{ done, total }`，不是比例。** 比例只能显示成 `17%`，而页面要显示的是
>   「累计 2 / 4 片」。绝对片数在片数变了之后仍然成立，比例不成立。
> - **`assets` 存 library 根相对路径，不是裸文件名。** `raw?path=` 需要完整相对路径；
>   裸名会让 Library 解析资产的方式和 Draft / Steps 不一致。
> - **`tileIds` 是位置派生的 id（如 `RECT-0-3-4`），不是 `t01` 这样的顺序号。**
>   位置派生的 id 让重解后同一处的片 id 不变，锁定片的选中态才不会跳。
>   代价是旋转会改 id，见 `pc/CLAUDE.md`。
>
> 另外 `caption` 由步骤的形状构成 + 序号**确定性生成**，纯文本，**绝不写颜色名** ——
> 颜色是 `assignColors` 第二遍软约束的产物，写进标题就等于让步骤文案依赖配色，改个颜色就得重排文案。

### 字段说明

| 字段 | 作用 | 谁产出 |
|---|---|---|
| `canvas` | 画布规格，所有渲染层的统一基准 | P0 定义，全局共用 |
| `palette` | 颜色映射，改色只需改这里 | P0 定义 |
| `tiles` | 每片的形状/网格坐标/旋转/颜色 | P2 求解器 |
| `steps` | 有序步骤，含分组、文案、镜头 | P2 步骤生成器 + P5 人工润色 |
| `steps[].camera` | 该步的镜头中心与缩放 | 自动算包围盒，可人工微调 |
| `solution` | 可行性报告，用于筛选和归档 | P2 求解器 |
| `assets` | 素材文件引用，相对路径 | 各阶段回填 |

**schema 设计要点**：
- `tiles` 和 `steps` **分离**。片是空间数据，步骤是时间数据，两者解耦——重构步骤顺序不影响片的数据。
- `steps[].tileIds` 是**多片一组**。60 片的作品要合并成 6-12 步，否则视频没法看。
- `camera` 可自动算（该步片的包围盒外扩），也可手调。
- 所有路径**相对 workId 目录**，方便整包搬迁。

## 三、流程图生成

**实现**：从 `work.json` 渲染 SVG，每步一张。

单张步骤图的构成：

```
┌─────────────────────────┐
│  ①  先摆出身体最宽的两块  │  ← 步骤号 + caption
│                         │
│      ▓▓                 │  ← 当前步的片：实色高亮
│    ▓▓▓▓                 │  ← 已完成步的片：70% 透明度
│                         │  ← 未完成的片：不绘制
│                         │
│  ───────────────        │
│  已完成 2/12 片          │  ← 进度条
└─────────────────────────┘
```

**排版**：全部步骤图拼成一张信息图，2×4 或 3×3 网格，带作品标题和用量清单表。

**用途**：
- 小红书图文笔记（首图 + 步骤图轮播）
- 抖音视频的封面
- 小程序详情页
- 打印出来当搭建说明书

## 四、视频生成

### 4.1 为什么不用 AI 视频生成器

| | AI 视频生成器（Sora / 可灵等） | 程序化渲染（Remotion） |
|---|---|---|
| 几何精度 | 会变形，零件会凭空出现/消失 | 100% 准确 |
| 跨帧一致性 | 差，磁力片会"融化" | 完美 |
| 可控性 | 抽卡，改一处要重生成 | 改参数即可 |
| 批量 100 条 | 成本高、不稳定 | 自动化，边际成本近零 |
| 时长/节奏 | 难精确控制 | 逐帧控制 |

搭建过程的本质是**结构化的几何变换**——这正是程序化渲染最擅长、AI 生成最不擅长的。所以主流程用 Remotion，AI 视频只在需要片头氛围空镜时作为补充。

### 4.2 Remotion 实现要点

```tsx
// 每个 tile 一个组件，入场时机由所属 step 决定
const Tile: React.FC<{tile: Tile; stepStart: number}> = ({tile, stepStart}) => {
  const frame = useCurrentFrame();
  const t = interpolate(frame, [stepStart, stepStart + 12], [0, 1], {
    extrapolateLeft: 'clamp', extrapolateRight: 'clamp'
  });
  return (
    <g transform={`translate(${tile.x}, ${tile.y}) rotate(${tile.rot})`}
       opacity={t}                                   // 淡入
       transform-origin="center"
       style={{transform: `scale(${0.85 + 0.15 * t})`}}>  {/* 轻微放大 */}
      <Shape shape={tile.shape} color={tile.color} />
    </g>
  );
};
```

**镜头**：用 `tile.step.camera` 驱动一个外层 `<g>` 的 `translate` + `scale`，用 spring 做平滑过渡，让镜头跟随当前搭建区域。

**节奏建议**（30-60 秒竖屏）：

| 段落 | 时长 | 内容 |
|---|---|---|
| 开场 | 3s | 成品亮相 + 标题 |
| 步骤 | 20-40s | 逐步搭建，每步 2-4s |
| 收尾 | 5s | 成品旋转/缩放 + 引导关注 |

**多规格输出**：同一份数据渲染多个版本号

| 平台 | 规格 | 说明 |
|---|---|---|
| 抖音 | 1080×1920，9:16 | 主战场 |
| 小红书 | 1080×1440，3:4 | 或 1:1 |
| 视频号 | 1080×1920 | 同抖音版本可复用 |

### 4.3 配音与字幕

| 环节 | 方案 |
|---|---|
| 配音 | 火山引擎 TTS / MiniMax（选真人感强的亲子音色） |
| 字幕 | 直接用 `steps[].caption` 文本上屏，无需 ASR 对齐 |
| 背景音乐 | 素材库，注意版权（用平台商用曲库） |

**文案生成**：可以用大模型批量生成每个步骤的口播文案（输入 `steps[].caption` + 目标年龄档，输出口语化、有互动感的句子）。

## 五、小程序

**技术栈**：微信云开发（与仓库里 [99_益智游戏](../../01_prd/99_益智游戏/) 项目同栈，云函数和登录能力可直接复用）。

**一期页面**：

| 页面 | 内容 |
|---|---|
| 首页 | 作品列表（封面图 + 难度标签 + 片数），按年龄档筛选 |
| 详情页 | 步骤播放器（前进/后退/自动播放）+ 用量清单 + 收藏 |
| 我的 | 收藏的作品、已搭完的记录 |

**数据来源**：`work.json` 打到云数据库，步骤播放器直接消费 `steps` 数组——**和视频、流程图吃同一份数据**。

**二期可加**：
- 拍照上传 → 调用差分检测 → 给完成度评分（亲子激励闭环）
- 成就系统、连续打卡
- 套装购买引导（如果做电商）

## 六、发布与数据回流

### 6.1 平台策略

| 平台 | 发布方式 | 备注 |
|---|---|---|
| 抖音 | 人工发布 | 个人主体无开放发布 API，一期不要在这上面投入开发 |
| 小红书 | 人工发布 | 图文笔记用流程图轮播，视频用竖屏版 |
| 微信小程序 | 开发者工具上传 | 走正常审核流程 |

### 6.2 素材规格规范

一次定死，后续所有作品自动按规范导出：

```
output/W-20260917-001/
├── douyin-9x16.mp4       1080×1920  30-60s
├── xhs-cover.png         1080×1440  首图（成品+标题）
├── xhs-steps/            步骤图 × N  3:4
├── wechat-9x16.mp4
└── copy.txt              标题 + 正文 + 话题标签
```

**命名规范必须从第一条内容就定死**，包括：`<平台>-<规格>.<ext>`、步骤图补零 `step-01`。批量生产时这是省事和灾难的区别。

### 6.3 数据回流

发布记录表（可以就是一个 CSV / JSON）：

```json
{
  "workId": "W-20260917-001",
  "publications": [
    {
      "platform": "douyin",
      "url": "...",
      "publishedAt": "2026-09-18",
      "metrics": {
        "d7": { "views": 12400, "likes": 620, "saves": 180, "comments": 43 }
      }
    }
  ]
}
```

**回流用途**：
- 找出高数据的题材特征（哪个主题、哪种难度、哪种颜色组合表现好）
- 反哺 P1 选题库：数据好的题材自动扩产变体
- 淘汰低效题材（比如「复杂动物」普遍数据差 → 降权）

**不要现在建复杂的数据系统**。一期用一个 CSV 手工记录就够，关键是**每一条都记**——积累 30 条之后规律自然会浮现。

│   ├── stock.json             # 库存（P0）

│   ├── topics.json            # 选题库（P1）

## 八、实施顺序

| 顺序 | 事项 | 产出 |
|---|---|---|
| 1 | 定 `work.json` schema v1 | 一份字段定义（本文档第二章） |
| 2 | 定 `shapes.json` / `stock.json` / `palette.json` | P0 的三个基础文件 |
| 3 | 写渲染器（吃 work.json 出手工造的图） | 可视化调试能力 |
| 4 | 写求解器，产出第一份真实 work.json | 端到端打通 |
| 5 | 接 Remotion，出第一条视频 | 一期目标达成 |
| 6 | 跑 3 个作品，观察哪一步最费人工 | 二期提效的输入 |

第 3 步先做渲染器，是为了让后面每一步的产出都能被看见——调试效率会高很多。
