# Spec：货权管理-质押物估值与监控

> **涉及端**：🔧 运营端


## 1. Goal（目标）

平台运营专员通过建立品类差异化质押率配置（3C 70%/白酒80%/食品75%/家电80%）和价格库管理体系，实现质押物7×24小时货值自动监控。系统对接多源价格数据，按核心企业等级加权计算当日参考价，自动批量重算质押率和相对质押率，触发四级预警（正常≤85%/警戒85-100%/超标100-115%/紧急>115%），使质押率超标预警率从70%提升至100%，品类风险预警及时率从75%提升至≥95%。

## 2. Scope（边界）

### 本次包含
- 质押率/相对质押率计算引擎
- 当日参考价加权公式（按核心企业等级差异化权重）
- 品类差异化配置（质押率上限/预警阈值/监控频率/特有监控项）
- 价格库管理（多数据源/更新频率/审核机制/核心企业报价可信度校验）
- 分级预警响应机制（4级）及自动处置（冻结融资/冻结出库/通知）
- 货值监控看板（风险总览/品类分析/相对质押率说明）
- 3C新品发布/促销季动态质押率调整
- 白酒串货监控、食品保质期监控的品类特有规则

### 本次不包含
- AI预测性价格走势分析（需积累历史数据，延后）
- 食品存储条件传感器硬件集成（硬件方案待确认）
- 白酒扫码溯源系统的深度对接（仅接收核心企业推送数据）
- 3C新品发布日历的自动抓取（数据来源待产品+技术+运营确认）
- 价格数据源的爬虫具体技术方案（待技术确认后补充接口定义）

## 3. I/O（输入输出）

### 3.1 质押率/相对质押率计算

**核心公式：**

```
质押率 = 融资本金 ÷ 质押物货值 × 100%
货值 = Σ(各SKU数量 × 当日参考价)
相对质押率 = 当前质押率 ÷ 品类上限 × 100%
```

**输入字段：**

| 字段 | 来源 | 类型 | 说明 | 所属端 |
|-----|------|------|------||------|------|------|------|--------|
| principal | 融资业务系统 | Decimal(16,2) | 融资本金 | | 🔧 运营端 |
| sku_quantity | WMS库存数据 | Integer | 各SKU在库数量 | | 📦 仓储方/WMS |
| reference_price | 价格库 | Decimal(16,2) | 当日参考价 | | 🔧 运营端 |
| category_limit | 品类配置 | Decimal(5,2) | 品类质押率上限 | | 🔧 运营端 |

**计算频率：**
- 价格数据源更新后自动批量重算（每日至少1次）
- WMS库存变化后实时重算
- 促销季/新品发布期：每4小时重算

**输出：**

| 字段 | 类型 | 说明 |
|-----|------|------|
| pledge_ratio | Decimal(5,2) | 当前质押率，保留2位小数 |
| relative_pledge_ratio | Decimal(5,2) | 相对质押率，保留2位小数 |
| warning_level | Enum | 正常/警戒/超标/紧急 |

**异常状态：**
- 价格为0或负数：丢弃该SKU价格，记录异常日志，使用缓存价格
- 价格较前一日变化>50%：标记"异常波动"，等待人工复核
- 多数据源价格差异>15%：取较低价格，保守估值
- 核心企业报价偏离度>阈值：按可信度调整权重（见3.4）

### 3.2 当日参考价加权公式

**按核心企业等级差异化计算：**

| 核心企业等级 | 公式 |
|-------------|------|
| S级 | 核心企业报价×60% + 京东价×25% + 天猫价×15% |
| A/B级 | 核心企业报价×40% + 京东价×35% + 天猫价×15% + 中关村价×10% |
| C级或无核心企业 | 京东价×50% + 天猫价×30% + 中关村价×20% |

**输入字段（每条SKU）：**

| 字段 | 类型 | 必填 | 来源 |
|-----|------|------|------|
| core_enterprise_price | Decimal(16,2) | 条件必填 | 核心企业ERP推送 |
| jd_price | Decimal(16,2) | 条件必填 | 京东API/爬虫 |
| tmall_price | Decimal(16,2) | 条件必填 | 天猫爬虫 |
| zol_price | Decimal(16,2) | 条件必填 | 中关村在线API/爬虫 |
| core_enterprise_level | Enum | 是 | 客户档案：S/A/B/C |

**输出：**

| 场景 | 处理方式 |
|-----|---------|
| 某数据源返回失败 | 使用缓存价格，记录失败日志，剩余数据源重新归一化权重 |
| 所有数据源均失败 | 使用最近一次成功价格，生成"数据源延迟"告警 |
| 价格计算结果≤0 | 标记异常，等待人工复核，该SKU暂不参与货值计算 |

### 3.3 品类差异化配置

**品类基础配置表：**

| 品类 | 质押率上限 | 正常阈值(相对) | 警戒阈值(相对) | 超标阈值(相对) | 紧急阈值(相对) | 价格更新频率 |
|-----|-----------|--------------|--------------|--------------|--------------|------------|
| 3C电子 | 70% | ≤85% | 85-100% | 100-115% | >115% | 每日（促销季每4小时） |
| 食品 | 75% | ≤85% | 85-100% | 100-115% | >115% | 每周 |
| 白酒 | 80% | ≤85% | 85-100% | 100-115% | >115% | 每周 |
| 家电 | 80% | ≤85% | 85-100% | 100-115% | >115% | 每日 |

**绝对质押率阈值换算（示例）：**

| 品类 | 正常 | 警戒 | 超标 | 紧急 |
|-----|------|------|------|------|
| 3C电子(上限70%) | ≤59.5% | 59.5%-70% | 70%-80.5% | >80.5% |
| 食品(上限75%) | ≤63.75% | 63.75%-75% | 75%-86.25% | >86.25% |
| 白酒(上限80%) | ≤68% | 68%-80% | 80%-92% | >92% |
| 家电(上限80%) | ≤68% | 68%-80% | 80%-92% | >92% |

**品类特有监控项配置（JSON格式）：**

| 品类 | 特有监控项 | 配置字段 |
|-----|-----------|---------|
| 3C电子 | 新品发布监控 | brand, model, release_date, ratio_down_adjustment(默认10%) |
| 3C电子 | 促销季监控 | promo_name, start_date, end_date, ratio_down_adjustment(默认5%) |
| 白酒 | 串货监控 | cross_region_ratio_threshold(默认10%), data_source |
| 食品 | 保质期监控 | entry_threshold(剩余>2/3),临近阈值(剩余<90天),处置阈值(剩余<60天) |
| 食品 | 存储条件监控 | temp_max, humidity_max, sensor_data_source |

### 3.4 价格库管理

**价格数据来源配置：**

| 品类 | 数据源 | 优先级 | 获取方式 | 更新频率 |
|-----|--------|--------|---------|---------|
| 3C电子 | 核心企业、中关村在线、京东、天猫 | 核心企业>B2B平台>电商平台 | API+爬虫 | 每日（促销季每4小时） |
| 白酒 | 核心企业、1919、酒仙网 | 核心企业>B2B平台 | API | 每周 |
| 食品 | 核心企业、批发市场、经销商报价 | 核心企业>批发市场>经销商 | 爬虫+人工 | 每周 |
| 家电 | 核心企业、京东、天猫、苏宁 | 核心企业>电商平台 | API+爬虫 | 每日 |

**核心企业报价可信度校验：**

| 历史准确率 | 权重调整 |
|-----------|---------|
| ≥95% | 维持当前权重 |
| 90%-95% | 权重下调10个百分点 |
| <90% | 权重下调至20%以下，重点依赖市场公开价格 |

**价格审核规则：**

| 规则 | 处理方式 |
|-----|---------|
| 系统自动抓取价格 | 定时任务自动抓取 |
| 单日价格波动>10% | 需人工复核，确认非数据抓取错误 |
| 多渠道价差>15% | 取较低价格，保守估值 |
| 价格源返回失败 | 使用缓存价格，记录失败日志，告警通知 |

**价格库数据接口：**

- 查询：GET /api/price/library?sku_code=xxx&date=xxx
- 更新：POST /api/price/library（运营人工录入/系统批量导入）
- 复核：POST /api/price/library/review（人工复核异常价格）

### 3.5 分级预警响应

**预警触发条件及自动处置：**

| 预警等级 | 相对质押率范围 | 颜色 | 响应时效 | 自动处置动作 | 通知对象 |
|---------|--------------|------|---------|------------|---------|
| 正常 | ≤85% | 绿色 | 正常监控 | 无 | — |
| 警戒 | 85%-100% | 黄色 | 24小时内 | 系统消息通知客户经理 | 客户经理+风控专员 |
| 超标 | 100%-115% | 红色 | 4小时内 | 冻结新增融资+出库权限；短信+邮件通知客户 | 风控专员+客户 |
| 紧急 | >115% | 紫色 | 立即 | 冻结所有权限；短信+邮件通知客户；推送风控专员+主管 | 风控专员+主管+客户 |

**预警生成输出：**

| 字段 | 类型 | 说明 |
|-----|------|------|
| warning_id | String(32) | 唯一预警编号 |
| warning_level | Enum | 紧急/超标/警戒/正常 |
| warning_type | Enum | 价格下跌/质押率超标/盘点差异/临期/串货/核心企业推送等 |
| business_no | String(32) | 关联业务编号 |
| customer_id | String(32) | 关联客户 |
| trigger_value | Decimal(5,2) | 触发预警的指标值 |
| threshold_value | Decimal(5,2) | 预警阈值 |
| response_deadline | DateTime | 响应截止时间 |
| status | Enum | 待处理/处理中/已关闭/已升级 |

### 3.6 3C动态质押率调整

**新品发布监控：**

| 阶段 | 触发条件 | 系统动作 |
|-----|---------|---------|
| 发布前30天 | 系统识别某型号新品即将发布 | 1.下调该型号旧款质押率上限10%<br>2.批量重算所有相关业务质押率<br>3.超标业务自动生成预警<br>4.推送客户补充质押物或还款通知 |
| 发布前7天 | — | 加强价格监控频率（每日→每4小时） |
| 发布后 | 新品正式上市 | 观察7天价格走势，旧款价格稳定后恢复正常质押率上限 |

**促销季监控：**

| 阶段 | 系统动作 |
|-----|---------|
| 促销季前15天 | 1.自动下调质押率上限（3C下调5%）<br>2.批量重算所有3C业务质押率<br>3.超标业务自动生成预警<br>4.推送客户补充质押物或还款通知 |
| 促销季期间 | 1.价格监控频率提高至每4小时<br>2.价格跌幅>5%立即预警<br>3.暂停高价值单品（>10万）新增入库 |
| 促销季结束后 | 观察7天价格走势，价格稳定后恢复正常质押率上限，解除入库限制 |

## 4. Constraints（约束）

### 技术约束
- 价格数据缓存在Redis，缓存有效期24小时，支持手动刷新
- 价格批量重算采用异步队列执行，≤10分钟完成全量在库业务重算
- 预警生成延迟≤5分钟
- 页面加载时间≤3秒（货值监控看板）
- 价格源多源备份：主价格源异常时支持切换到备用价格源（【待确认】备用源方案）

### 安全约束
- 价格库修改操作需记录操作日志（操作人、时间、修改前/后价格）
- 价格审核权限仅限运营专员及以上角色
- 敏感价格数据（核心企业B2B报价）脱敏展示
- 货值变更日志留存5年

### 设计约束
- 货值监控看板：风险总览卡片始终显示，品类差异化展示区按品类动态加载（3C突出价格波动/白酒突出串货/食品突出保质期）
- 相对质押率说明区域支持展开/收起计算公式
- 预警列表按"级别降序+触发时间升序"排列

## 6. Non-Goals（非目标）

- ❌ 不实现AI预测性价格走势分析（需积累历史数据，模型训练延后）
- ❌ 不实现食品温湿度传感器的硬件集成和数据采集（传感器硬件方案待技术团队+仓储方确认）
