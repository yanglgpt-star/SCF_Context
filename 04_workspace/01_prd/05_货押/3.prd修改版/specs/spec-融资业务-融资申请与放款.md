# Spec：融资业务-融资申请与放款

> **涉及端**：🔧 运营端、🏪 企业端-融资企业、🏦 银行端


## 1. Goal（目标）

**谁**：经销商（企业端）、平台运营人员（运营端）、财务人员（运营端）、银行系统（服务端）
**怎么做**：通过企业端在线提交融资申请，系统自动校验引擎拦截不合格申请，审批通过后放款流程引擎自动生成放款指令并通过银企直联API推送给银行，财务确认后完成放款
**达成什么**：
- 申请一次通过率从60%提升至≥80%
- 放款成功率从93%提升至≥98%
- 银行对账时效从2-4小时缩短至≤30分钟
- 资料一次性完整率≥90%

---

## 2. Scope（边界）

### 本次包含
- 企业端在线融资申请表单（分步表单：基本信息→质押物信息→资料上传→确认提交）
- 自动校验引擎（额度/货物/黑名单/证照/逾期/核心企业数据）
- 申请状态流转（草稿→校验→审批→放款）
- 放款流程引擎（终审通过→生成立项→财务确认→发送指令→银行处理→结果反馈）
- 银企直联API对接（HTTPS+JSON+RSA签名）
- 放款自动对账（每日，±0.01元误差）
- 放款结果通知（企业端系统消息+短信）

### 本次不包含
- 移动端独立APP（通过H5/小程序覆盖）
- 跨品类组合融资（一笔融资涉及多个品类质押物）
- 动态费率定价（待结算管理模块统一规划）
- 区块链存证（归属货权管理模块）
- 企业端线上直接还款（对接支付通道）【待确认】
- 【待确认】放款金额是否允许财务修改
- 【待确认】融资期限具体范围

## 3. I/O（输入输出）

### 3.1 企业端融资申请提交

**输入（申请表单字段）**：

| 字段名 | 类型 | 必填 | 校验规则 | 所属端 |
|--------|------|------|----------||--------|------|------|----------|--------|
| 申请金额 | Decimal(18,2) | 是 | 必须≤可用授信额度；必须≤质押物货值×质押率上限 | | 📦 仓储方/WMS |
| 融资期限 | Int | 是 | 【待确认】具体范围待业务确认（如7-180天） | | 🔧 运营端 |
| 质押物品类 | Enum | 是 | 必须与系统已入库或预报的品类一致 | | 📦 仓储方/WMS |
| 质押物品牌 | String(100) | 是 | - | | 📦 仓储方/WMS |
| 质押物型号 | String(100) | 是 | - | | 📦 仓储方/WMS |
| 质押物数量 | Int | 是 | 必须>0 | | 📦 仓储方/WMS |
| 质押物货值 | Decimal(18,2) | 是 | 单位：元，基于系统估值 | | 📦 仓储方/WMS |
| 预计入库日期 | Date | 是 | 必须在申请日期+7天内【待确认】 | | 📦 仓储方/WMS |
| 资金用途 | String(500) | 是 | - | | 🔧 运营端 |
| 还款来源 | String(500) | 是 | - | | 🏦 银行端 |
| 关联质押物ID | String(32) | 条件必填 | 如质押物已入库则必填 | | 📦 仓储方/WMS |

**输出**：
- **保存草稿**：状态="草稿"，返回申请编号
- **提交成功**：状态="待校验"，返回申请编号，进入自动校验
- **提交失败（必填项缺失）**：返回缺失字段清单，提交按钮置灰
- **提交失败（格式错误）**：返回具体格式错误提示

### 3.2 自动校验引擎

**输入**：融资申请全量数据 + 客户档案数据 + 质押物数据

**校验规则**：

```
✓ 申请金额 ≤ 可用授信额度
✓ 质押物货值 × 质押率上限 ≥ 申请金额
✓ 质押物品类 = 客户主营品类
✓ 客户状态 = "正常"（非冻结/预警）
✓ 客户证照在有效期内
✓ 无未结清的逾期业务
✓ 申请金额 ≤ 单笔融资上限（按客户等级配置）
✓ 融资期限在允许范围内【待确认】
```

**输出**：

| 结果 | 状态 | 说明 |
|------|------|------|
| 全部通过 | 校验通过 → 待审批 | 自动触发审批流程匹配 |
| 授信额度不足 | 校验驳回 | 返回"可用授信额度不足，当前可用XX万" |
| 质押物货值不足 | 校验驳回 | 返回"质押物可融资金额上限为XX万" |
| 客户状态异常 | 校验驳回 | 返回"客户状态为XX，暂不可申请融资" |
| 证照过期 | 校验驳回 | 返回"XX证照已过期，请先更新" |
| 存在逾期业务 | 校验驳回 | 返回"您有未结清逾期业务，请先处理" |
| 重复申请 | 校验驳回 | 同一客户同一自然日内相同金额、相同品类的申请提示"请勿重复提交" |

**异常处理**：
- 任一校验不通过，系统立即驳回申请
- 向企业端返回具体不通过原因
- 向客户经理推送通知
- 记录校验日志

### 3.3 核心企业数据联动（申请时）

**输入**：客户ID + 核心企业ID

**输出**：
- **正常**：返回经销商最新信用评级（A+/A/B/C，A+视为A级）、近期供货情况
- **核心企业标注风险**：自动触发加强审批流程（5级），在审批页面红色高亮提示
- **核心企业数据获取失败**：系统允许继续申请，但审批页面提示"核心企业数据获取失败，审批时请注意核验"

### 3.4 放款流程引擎

**输入（终审通过触发）**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 业务编号 | String(32) | 融资申请编号 |
| 审批通过金额 | Decimal(18,2) | 终审确定的放款金额 |
| 客户ID | String(32) | - |
| 收款账户名称 | String(100) | 来自客户档案 |
| 收款账号 | String(50) | 来自客户档案 |
| 开户行 | String(100) | 来自客户档案 |
| 联行号 | String(20) | 来自客户档案 |

**放款流程状态流转**：

```
终审通过
  → 待生成（系统自动生成立项）
  → 待财务确认（财务人工确认账户/金额）
  → 待发送指令（财务确认后）
  → 指令处理中（已发送银行）
  → 放款成功（银行反馈成功）/ 放款失败（银行反馈失败）
  → 已撤销（人工撤销）
```

**输出（各阶段）**：

| 状态 | 系统动作 |
|------|----------|
| 待生成 | 系统自动生成立项，推送待办给财务 |
| 待财务确认 | 财务在页面确认收款账户和金额 |
| 待发送指令 | 系统生成放款指令，待推送 |
| 指令处理中 | 已发送银行，轮询查询结果 |
| 放款成功 | 更新业务状态；记录放款时间、银行流水号；通知企业 |
| 放款失败 | 记录失败原因；自动重试（默认3次，间隔15分钟）；超次人工介入 |
| 结果未知/超时 | 标记异常；人工核查；通知财务 |

### 3.5 放款指令内容

**输入（系统生成）**：

| 字段名 | 类型 | 必填 | 说明 | 所属端 |
|--------|------|------|------||--------|------|------|------|--------|
| 业务编号 | String(32) | 是 | 融资申请编号 | | ⚙️ 系统 |
| 收款账户名称 | String(100) | 是 | - | | 🔧 运营端 |
| 收款账号 | String(50) | 是 | - | | 🔧 运营端 |
| 开户行 | String(100) | 是 | - | | 🔧 运营端 |
| 放款金额 | Decimal(18,2) | 是 | 默认=审批通过金额【待确认】是否允许修改 | | 🏦 银行端 / 🔧 运营端 |
| 币种 | String(3) | 是 | 默认CNY | | 🔧 运营端 |
| 用途摘要 | String(200) | 是 | - | | 🔧 运营端 |
| 指令生成时间 | DateTime | 是 | - | | 🔧 运营端 |
| 请求流水号 | String(32) | 是 | 系统唯一幂等键 | | 🏦 银行端 |

**银行接口规范**：

| 规范项 | 确认内容 |
|--------|----------|
| 接口协议 | HTTPS RESTful API |
| 报文格式 | JSON |
| 加密方式 | RSA非对称加密 |
| 签名机制 | RSA-SHA256签名，签名值置于HTTP Header `X-Bank-Signature` |
| 重试与幂等 | 失败自动重试3次（间隔15分钟），每次请求携带唯一幂等键 `Idempotency-Key` |
| 超时时间 | 30秒 |

**输出（银行返回）**：

| 银行返回 | 系统处理 |
|----------|----------|
| 放款成功 | 更新状态="放款成功"；记录放款时间、银行流水号；通知企业 |
| 放款失败 | 记录失败码和原因；自动重试（按配置次数和间隔）；超次通知财务和运营 |
| 处理中 | 轮询查询结果（按配置间隔）；超过最大等待时间（24小时）标记异常 |
| 结果未知/超时 | 标记异常；人工核查；通知财务 |

### 3.6 放款自动对账

**输入**：
- 平台侧：放款申请记录（申请编号、金额、账户、时间）
- 银行侧：银行流水接口返回数据

**匹配规则**：
1. 按金额匹配（允许±0.01元误差）
2. 按时间匹配（±1天内）
3. 按账户匹配

**输出**：
- **匹配成功**：自动更新对账状态="已对账"
- **匹配失败**：自动标注异常，推送待办给财务人员

### 3.7 财务确认页

**输入（展示信息）**：

| 字段名 | 类型 | 可编辑 |
|--------|------|--------|
| 业务编号 | String(32) | 否 |
| 客户名称 | String(100) | 否 |
| 审批通过金额 | Decimal(18,2) | 否 |
| 实际放款金额 | Decimal(18,2) | 【待确认】默认=审批通过金额 |
| 收款账户名称 | String(100) | 否 |
| 收款账号 | String(50) | 否 |
| 开户行 | String(100) | 否 |

**输出（操作结果）**：
- **确认**：状态变更为"待发送指令"，系统推送放款指令给银行
- **退回**：状态回退，退回运营重新核实

## 4. Constraints（约束）

### 4.1 技术约束
- 自动校验响应时间≤1秒
- 银行接口调用超时时间≤30秒
- 高峰期申请提交并发支持≥100笔/分钟
- 放款失败自动重试次数：默认3次，间隔15分钟
- 银行结果轮询间隔：默认5分钟，最大等待24小时
- 对账周期：每日自动执行

### 4.2 安全约束
- 放款指令双重确认：系统生成后需财务人工确认，放款指令发送前需二次确认（弹窗确认）
- 放款指令幂等控制：同一笔业务只允许发送一次放款指令（除非前次明确失败），系统记录指令流水号
- 敏感数据加密存储：银行账户、征信信息AES-256加密
- 操作审计：关键操作（审批、放款确认）记录操作人、时间、IP地址
- 防重放攻击：银行接口实现请求签名和时效校验

### 4.3 设计约束
- 申请金额必须≤可用授信额度，且≤质押物货值×质押率上限
- A+级经销商在平台侧**视为A级**，申请时校验按A级标准
- 重复申请拦截：同一客户同一自然日内相同金额、相同品类的申请系统提示"请勿重复提交"
- 放款金额默认=审批通过金额，【待确认】是否允许财务修改及修改权限
- 融资期限范围【待确认】（如7-180天）

## 5. Acceptance Criteria（验收标准）

### 5.1 企业端在线申请
1. **打开企业端融资申请页面**，某A级客户当前可用额度50万，申请金额输入框旁实时显示"您当前可用授信额度：50万元"
2. **打开企业端融资申请页面**，经销商输入申请金额60万（>可用额度50万），输入框实时红色提示"申请金额超过可用授信额度"
3. **打开企业端融资申请页面**，经销商完成所有必填项并上传必传资料，点击"提交申请"，系统返回申请编号，状态="待校验"
4. **打开企业端融资申请页面**，经销商遗漏必填项（如未填写资金用途），点击"提交申请"，系统提示"请完善必填项：资金用途"，提交按钮置灰
5. **打开企业端融资申请页面**，经销商今日已提交一笔金额为30万、品类为3C电子的申请，再次提交相同金额和品类的申请，系统提示"您已提交相似申请，请勿重复提交"

### 5.2 自动校验引擎
6. **调接口** `/api/v1/financing/apply`，传入申请金额=40万、可用额度=50万、质押物货值×质押率=45万，返回"校验驳回：质押物可融资金额上限为45万"
7. **调接口** `/api/v1/financing/apply`，传入客户状态="冻结"，返回"校验驳回：客户状态为冻结，暂不可申请融资"
8. **调接口** `/api/v1/financing/apply`，传入客户存在未结清逾期业务，返回"校验驳回：您有未结清逾期业务，请先处理"
9. **调接口** `/api/v1/financing/apply`，传入客户证照已过期，返回"校验驳回：营业执照已过期，请先更新"
10. **调接口** `/api/v1/financing/apply`，传入所有校验条件均满足，返回"校验通过"，状态自动流转至"待审批"

### 5.3 核心企业数据联动
11. **调接口** `/api/v1/financing/apply`，核心企业返回经销商信用评级=A+，系统记录为A级，审批流程按A级标准匹配
12. **调接口** `/api/v1/financing/apply`，核心企业标注该经销商存在"串货"风险，系统自动触发加强审批流程（5级），审批页面展示红色风险预警提示
13. **调接口** `/api/v1/financing/apply`，核心企业接口超时，系统允许继续申请，审批页面提示"核心企业数据获取失败"

### 5.4 放款流程
14. **打开运营端财务确认页面**，展示业务编号、客户名称、审批通过金额、收款账户信息，财务点击"确认无误"，状态变更为"待发送指令"
15. **调接口** `/api/v1/disbursement/instruction/send`，系统推送放款指令给银行，返回"指令已发送，处理中"
16. **调接口**（模拟银行回调）银行返回放款成功，系统更新业务状态="放款成功"，记录银行流水号，企业端收到"放款成功"通知
17. **调接口**（模拟银行回调）银行返回放款失败，系统记录失败原因，自动重试（第1次），15分钟后再次发送
18. **调接口**（模拟银行回调）银行连续3次返回失败，系统停止自动重试，推送异常待办给财务人员，通知运营负责人
19. **打开运营端放款记录列表页**，列表展示放款编号、业务编号、客户名称、放款金额、银行名称、放款状态、实际放款时间、银行流水号

### 5.5 放款对账
20. **打开运营端对账管理页面**，系统每日自动执行对账，匹配成功的记录状态="已对账"，匹配失败的记录状态="异常"并推送财务人员待办
21. **调接口** `/api/v1/disbursement/reconcile`，传入平台放款记录和银行流水，金额差0.005元，系统按±0.01元容差判定匹配成功
22. **调接口** `/api/v1/disbursement/reconcile`，传入平台放款记录和银行流水，金额差0.1元，系统判定匹配失败，标注异常

### 5.6 企业端通知
23. **打开企业端消息中心**，放款成功后，经销商收到系统消息+短信，内容包含"您的融资申请已放款成功，放款金额XX万元"
24. **打开企业端消息中心**，放款失败后，经销商收到系统消息+短信，内容包含"您的融资申请放款失败，失败原因：XX，请联系客户经理"

## 6. Non-Goals（非目标）

1. **移动端独立APP融资申请**：本期通过H5/小程序覆盖企业端功能
2. **跨品类组合融资**：一笔融资涉及多个品类质押物的复杂场景，本期不支持
3. **动态费率定价**：基于客户等级的差异化融资费率，待结算管理模块统一规划
4. **区块链存证**：仓单区块链存证在货权管理模块实现
5. **企业端线上直接还款**：是否支持对接支付通道本期【待确认】
6. **放款金额自动修改**：放款金额需财务确认，系统不自动根据任何规则修改金额
7. **AI智能填写申请表单**：不提供AI自动识别合同并填写融资申请功能
