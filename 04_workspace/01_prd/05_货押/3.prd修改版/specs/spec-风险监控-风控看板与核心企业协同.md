# Spec：风险监控-风控看板与核心企业协同

> **涉及端**：🔧 运营端、🏭 企业端-核心企业


## 1. Goal（目标）

平台决策层和管理层通过风控看板实时掌握全平台风险状况（统计卡片区/分布区/趋势区/TOP排行区/地图区），风控专员通过核心企业协同机制接收8字段标准化推送、发起4类协同请求、跟踪协同处置进度，实现核心企业预警响应率从60%提升至100%，并通过分级响应升级机制确保高风险预警不遗漏。

## 2. Scope（边界）

### 本次包含
- 风控看板（统计卡片区：6张卡片/分布区：风险类型+级别/趋势区：30天折线/TOP排行区：3类TOP10/地图区：仓库风险分布）
- 核心企业推送接收（8字段标准化数据+验签+映射+自动评估+自动处置）
- 协同请求推送（4类协同类型：停止供货/催收欠款/核实库存/提供补充信息）
- 分级响应升级机制（超时自动升级+高风险升级+升级记录）
- 核心企业协同看板（推送统计/响应率排行/协同成功率）
- 数据权限控制（决策层/管理层/执行层三级可见范围）

### 本次不包含
- 风控看板的完整UI/UX设计方案（【待确认】设计部门）
- 核心企业预警激励制度的积分/额度规则（【待确认】运营部门）
- 移动端独立APP的看板页面（本期H5/小程序适配）
- 风险地图的完整GIS集成方案（【待确认】是否本期实现）
- 核心企业ERP的8个标准接口之外的定制化对接（按《通用方案》标准接口执行）
- 核心企业推送准确率的自动计算和激励发放（规则待确认）

### 3.2 核心企业推送接收（8接口）

**API接口规范（已确认）：** HTTPS RESTful API + JSON + OAuth 2.0

**推送数据字段（8字段）：**

| 字段名 | 类型 | 必填 | 校验规则 | 所属端 |
|--------|------|------|---------||--------|------|------|----------|--------|
| push_id | String(32) | 是 | 核心企业端唯一推送标识，平台侧幂等去重 | | 🏭 企业端-核心企业 |
| core_enterprise_id | String(32) | 是 | 核心企业在平台的企业编码，须已准入 | | 🏭 企业端-核心企业 |
| dealer_id | String(32) | 是 | 经销商在平台的企业编码，须存在 | | 🏪 企业端-融资企业 |
| warning_type | Enum | 是 | 串货违规/大量退货/信用评级下降/销售额异常下滑/经营地址变更/其他 | | 🔧 运营端 |
| risk_level | Enum | 是 | 高/中/低 | | 🔧 运营端 |
| warning_content | String(512) | 是 | 预警详细描述，最少10字 | | 🔧 运营端 |
| warning_time | DateTime | 是 | 核心企业发现时间，不得晚于当前时间 | | 🏭 企业端-核心企业 |
| attachment_url | String(256) | 否 | 佐证材料URL，须可访问 | | 🔧 运营端 |
| push_time | DateTime | 是 | 推送时间 | | 🔧 运营端 |
| signature | String | 是 | HMAC-SHA256签名，用于验证推送方身份 | | 🔧 运营端 |

**平台接收后处理流程：**

```
1. 验签：验证推送方身份合法性（HMAC-SHA256）
2. 幂等：根据push_id去重，已存在的不再处理
3. 匹配客户：根据dealer_id匹配平台客户档案
4. 生成预警：根据warning_type和risk_level映射为平台预警级别
   - risk_level=高 → 平台预警级别=超标（红色）或紧急（紫色，根据具体内容）
   - risk_level=中 → 平台预警级别=警戒（黄色）
   - risk_level=低 → 平台预警级别=警戒（黄色）
5. 关联业务：自动关联该客户的所有在途业务
6. 自动评估：规则引擎评估风险等级
7. 自动处置：高风险（串货违规）自动冻结新增融资
8. 推送风控：推送给风控人员处理（紫色来源标签高亮，优先级置顶）
```

**核心企业推送预警类型与风险等级映射：**

| 预警类型 | 默认风险等级 | 映射说明 |
|----------|--------------|----------|
| 串货违规 | 高风险 | 直接映射为平台"超标"或"紧急" |
| 大量退货 | 中风险 | 映射为平台"警戒" |
| 信用评级下降 | 中风险 | 映射为平台"警戒" |
| 销售额异常下滑 | 低风险 | 映射为平台"警戒" |
| 经营地址变更 | 低风险 | 映射为平台"警戒" |

**输出：**

| 场景 | HTTP状态 | 返回体 |
|-----|----------|--------|
| 接收成功 | 200 | `{code:200, data:{platform_warning_id:"xxx", status:"PROCESSED"}}` |
| 重复推送 | 200 | `{code:200, data:{platform_warning_id:"xxx", status:"DUPLICATE"}}` |
| 验签失败 | 403 | `{code:403, message:"签名验证失败"}` |
| dealer_id不存在 | 400 | `{code:400, message:"经销商不存在"}` |
| core_enterprise_id未准入 | 400 | `{code:400, message:"核心企业未准入"}` |

**重试机制：** 推送失败时核心企业自动重试3次（间隔5分钟），仍失败后记录异常告警并转人工处理。

### 3.3 协同请求推送

**平台向核心企业推送协同请求的场景：**
- 经销商逾期（M2及以上自动推送）
- 质押物异常（盘点差异>阈值）
- 串货疑似（平台发现但需核心企业确认）

**协同请求数据字段：**

| 字段名 | 类型 | 必填 | 说明 | 所属端 |
|--------|------|------|------||--------|------|------|------|--------|
| request_id | String(32) | 是 | 平台端唯一请求标识 | | ⚙️ 系统 |
| business_id | String(32) | 是 | 关联业务编号 | | ⚙️ 系统 |
| dealer_id | String(32) | 是 | 经销商编码 | | 🏪 企业端-融资企业 |
| collaboration_type | Enum | 是 | 停止供货/催收欠款/核实库存/提供补充信息 | | 📦 仓储方/WMS |
| request_content | String(512) | 是 | 协同请求详细说明 | | 🏭 企业端-核心企业 |
| deadline | Date | 是 | 期望响应截止时间 | | 🔧 运营端 |
| request_time | DateTime | 是 | 请求时间 | | 🔧 运营端 |
| signature | String | 是 | HMAC-SHA256签名 | | 🔧 运营端 |

**核心企业响应后处理：**
- 平台接收核心企业响应（响应结果/处理意见/附件）
- 更新协同状态（待响应→已响应→已处理）
- 记录协同结果
- 根据核心企业反馈决定平台后续处置

### 3.4 分级响应升级机制

**响应时效矩阵（建议，【待确认】运营部门）：**

| 预警级别 | 首次响应时效 | 处置完成时效 | 升级阈值 | 升级对象 |
|----------|-------------|-------------|----------|----------|
| 紧急 | 立即（30分钟内） | 24小时内 | 2小时未响应 | 风控主管 |
| 超标 | 4小时内 | 3天内 | 4小时未响应 | 风控主管 |
| 警戒 | 24小时内 | 7天内 | 24小时未响应 | 部门经理 |
| 正常 | 无需响应 | — | — | — |

**升级机制逻辑：**

```
IF 责任人超时未响应 THEN
    自动升级给上级
    同时通知责任人和上级（系统消息+短信+邮件）
    记录超时情况
    纳入绩效考核
END IF

IF 高风险预警3天仍未解决 THEN
    升级至风控总监
    列入重点跟踪
    每日汇报进展
END IF
```

**升级记录字段：**

| 字段 | 类型 | 说明 |
|-----|------|------|
| upgrade_id | String(32) | 升级记录唯一ID |
| warning_id | String(32) | 关联预警 |
| upgrade_reason | String(256) | 升级原因：超时未响应/高风险未解决 |
| from_user | String(32) | 升级前责任人 |
| to_user | String(32) | 升级后责任人 |
| upgrade_time | DateTime | 升级时间 |
| notify_channels | Array | 通知渠道：系统消息/短信/邮件 |

## 4. Constraints（约束）

### 技术约束
- 看板数据刷新：实时数据每5分钟，趋势数据每小时
- 页面加载时间≤3秒（风控看板首屏）
- 核心企业推送延迟≤5秒（从推送到平台接收并生成预警）
- 内部模块调用采用HTTPS+JSON+服务间认证Token
- 所有接口调用记录完整日志，留存≥180天

### 安全约束
- 核心企业推送数据验签（HMAC-SHA256），验签失败拒绝接收
- 核心企业推送的经销商数据受保密协议约束，不得外泄
- 看板数据权限按角色控制，执行层仅能查看本人负责客户数据
- 冻结/解冻操作需二次确认，解冻需上级审批

### 设计约束
- 统计卡片支持点击下钻到对应明细列表
- 图表支持按时间范围（近7天/近30天/自定义）筛选
- 核心企业推送的预警在列表中用紫色来源标签高亮，优先级置顶
- 协同看板展示各核心企业推送统计（累计/本月/待响应/已处理）

## 5. Acceptance Criteria（验收标准）

### 5.1 风控看板
- ✅ 打开风控看板页面，顶部一行展示6张统计卡片：高风险客户数(15)/在途融资风险敞口(5000万)/今日新增预警数(8)/待处理预警数(23)/核心企业推送待响应(3)/平均响应时效(3.2小时)
- ✅ 点击"高风险客户数"卡片，下钻到预警列表页面，自动筛选级别=紧急或超标的记录
- ✅ 风险分布区左栏饼图展示：质押物监控(40%)/客户监控(20%)/业务监控(25%)/核心企业推送(15%)
- ✅ 风险趋势区折线图展示近30天每日新增预警数，今日新增8条，环比昨日+2条（+33%）
- ✅ 高风险客户TOP10排行，第一条客户A相对质押率125%、在途金额200万、预警数5条，点击客户名可查看客户详情
- ✅ 切换时间范围为"近7天"，所有图表和统计数据重新计算并展示，加载时间≤3秒

### 5.2 核心企业推送接收
- ✅ 核心企业ERP发送推送（push_id=P001，core_enterprise_id=CE001，dealer_id=D001，warning_type="串货违规"，risk_level="高"，warning_content="发现经销商D001大量产品流向非授权区域，涉及金额约30万"），平台5秒内接收并生成紫色紧急预警
- ✅ 推送到达后，系统自动根据dealer_id匹配客户档案，关联该客户所有在途业务（3笔，合计150万）
- ✅ 高风险串货预警自动生成后，系统自动调用POST /api/risk/freeze/financing冻结该客户新增融资，状态变更为"已冻结"
- ✅ 同一push_id再次推送，平台返回`status:"DUPLICATE"`，不生成新预警
- ✅ 推送签名错误，平台返回403，安全日志表新增记录，通知运维人员

### 5.3 协同请求推送
- ✅ 风控专员在预警详情页点击"申请协同"，选择"停止供货"，填写请求内容"客户M2逾期15天，请暂停供货直至还款"，点击发送
- ✅ 系统生成协同请求（request_id=R001）并推送给核心企业ERP，协同状态变更为"待响应"
- ✅ 核心企业响应"已停止供货"，平台接收响应后协同状态变更为"已响应"，记录响应内容
- ✅ 核心企业响应"无法确认库存"，平台记录后风控专员可选择"重新申请协同"或"调整处置方案"
- ✅ 协同请求超过deadline未响应，系统自动发送催办通知给核心企业，同时升级给风控主管

### 5.4 分级响应升级
- ✅ 紧急预警触发后2小时责任人未响应，系统自动升级给风控主管，同时通知原责任人（系统消息+短信+邮件），升级记录表新增记录
- ✅ 超标预警触发后4小时责任人未响应，系统自动升级给风控主管
- ✅ 警戒预警触发后24小时责任人未响应，系统自动升级给部门经理
- ✅ 高风险预警3天仍未解决，系统自动升级至风控总监，列入"重点跟踪"列表，每日发送进展汇报
- ✅ 升级后的预警，新责任人可在预警详情页点击"接管"，状态从"已升级"变更为"处理中"

### 5.5 核心企业协同看板
- ✅ 打开核心企业协同看板，展示各核心企业推送统计：核心企业A累计推送50/本月8/待响应2/已处理48
- ✅ 核心企业响应率排行：核心企业A响应率96%（排名第1）、核心企业B响应率85%（排名第2）
- ✅ 协同处置成功率统计：本月协同请求20/成功处置18/成功率90%
- ✅ 点击某核心企业名称，钻取到该核心企业推送的预警明细列表
- ✅ 核心企业推送准确率排行（【待确认】准确率计算口径），核心企业C准确率95%排名第1

### 5.6 数据权限
- ✅ 决策层账号登录，风控看板展示全平台所有数据，可穿透分析所有客户和业务
- ✅ 管理层（部门经理）账号登录，仅展示本部门负责范围内的数据（【待确认】部门划分规则）

- ✅ 执行层尝试访问其他客户的预警详情，系统返回"无权限查看"
