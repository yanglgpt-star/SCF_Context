# Spec：通用方案——角色权限

> **涉及端**：🔧 运营端、🏭 企业端-核心企业、🏪 企业端-融资企业、🏦 银行端、📦 仓储方/WMS


> **对应PRD**：PRD_通用方案_待确认事项补充.md（章节十三）  
> **适用范围**：供应链金融平台——运营端全部模块

---

## 1. Goal（目标）

平台系统管理员通过预定义的16个角色和7个模块的功能权限矩阵，为不同岗位员工分配最小必要的操作权限和数据可见范围，确保敏感操作（审批、资金划转、参数配置）受控，同时满足审计追踪要求。

---

## 2. Scope（边界）

### 本次包含
- 12个内部运营角色 + 4个外部角色定义
- 7个模块的功能权限矩阵（客户管理/融资业务/货权管理/风险监控/贷后管理/结算管理/系统管理）
- 6类数据权限规则
- 权限变更流程和审计日志

### 本次不包含
- 外部角色（经销商/核心企业/银行/仓储方）的详细权限设计（由各端PRD覆盖）
- SSO单点登录和LDAP/AD域集成
- 动态权限的实时计算引擎（RBAC模型即可满足）
- 权限申请审批的OA系统对接（提供标准接口）
- 各角色对应的UI界面个性化配置（如看板布局）

### 3.5 数据权限规则

| 规则类型 | 数据范围 | 适用角色 |
|----------|----------|----------|
| ALL | 全量数据 | 决策层、管理层、风控主管、管理员 |

| DEPT | 本部门全部人员的数据 | 部门经理 |
| APPROVAL_TASK | 仅处理审批任务时可见 | 审批员 |
| ASSIGNED_TASK | 仅分配给自己的催收任务 | 催收员 |
| FINANCE_ONLY | 仅资金相关数据，客户联系方式脱敏 | 财务人员 |
| AUDIT_READONLY | 全量数据只读，无操作权限 | 审计人员 |

### 3.6 权限变更接口

**请求**：
| 字段名 | 类型 | 长度 | 必填 | 校验规则 | 所属端 |
|--------|------|------|------|----------||--------|------|------|------|----------|--------|
| user_id | string | ≤32 | 是 | 已存在用户 | | ⚙️ 系统 |
| role_codes | array | - | 是 | 至少1个，均为已定义角色 | | ⚙️ 系统 |
| change_reason | string | ≤512 | 是 | 变更原因 | | ⚙️ 系统 |
| effective_time | datetime | - | 否 | 默认立即生效 | | ⚙️ 系统 |

**响应**：
| 场景 | 响应 |
|------|------|
| 成功 | change_log_id + 生效时间 |
| 失败 | 错误码+原因（如包含互斥角色） |
| 敏感权限变更 | 额外通知风控/审计部门 |

## 4. Constraints（约束）

### 技术约束
- 权限校验必须在服务端完成，禁止前端控制权限（防篡改）
- 每个API请求必须携带当前用户身份标识，服务端实时鉴权
- 权限变更记录必须写入不可篡改的审计日志表
- 角色删除时，若该角色下仍有活跃用户，禁止删除

### 安全约束
- 敏感权限（审批权、财务权、系统配置权）变更必须通知风控/审计部门
- 同一用户不可同时拥有互斥角色（如催收员+客户经理）
- 管理员账号必须使用强密码+多因素认证
- 审计人员账号禁止分配任何操作权限（只读）

### 设计约束
- 权限矩阵以"功能点×角色"二维表维护，不支持行级数据权限的复杂表达式
- 数据权限规则优先于功能权限：即使功能权限为✓，数据权限为"仅自己"时也只能看自己的数据
- 外部角色权限独立配置，不与内部角色混用同一套矩阵

## 5. Acceptance Criteria（验收标准）

1. **以客户经理身份登录运营端，打开客户列表页面**：仅展示"客户归属人=当前用户"的客户，其他客户经理名下的客户不可见；页面无"客户冻结"按钮（该功能对客户经理无权限）。
2. **以系统管理员身份登录，进入角色管理页面**：可为某用户同时分配"ROLE_RISK"和"ROLE_APPROVER"；尝试同时分配"ROLE_COLLECTION"和"ROLE_CUSTOMER_MGR"时，系统拦截提示"角色互斥，不可同时分配"。
3. **以财务人员身份登录，打开客户详情页面**：客户联系方式（手机号/邮箱）显示为脱敏格式（如138****1234），但可查看该客户的账单和还款记录。
4. **以审批员身份登录，打开融资申请列表**：仅展示"待审批"状态的融资申请，且只能查看分配给自己的审批任务；已审批完成的申请不可见。
5. **系统管理员将某用户从"ROLE_OPERATOR"调整为"ROLE_FINANCE"**：操作完成后，审计日志页面自动生成一条权限变更记录，包含操作人、变更时间、变更前后角色、变更原因；同时风控部门收到站内通知。
6. **以决策层身份登录，打开贷后管理-核销审批页面**：看到一笔核销金额60万的申请，页面显示"待总经理审批"标签，点击"通过"后审批完成；若金额为30万，则总经理页面上不显示该审批任务（由财务审批即可）。

## 6. Non-Goals（非目标）

- ❌ 不实现基于属性的访问控制（ABAC）和动态策略引擎
- ❌ 不实现权限的临时委托和转授权功能
- ❌ 不实现各角色登录后的个性化Dashboard布局配置
- ❌ 不实现权限变更的邮件/短信实时通知（仅站内信+审计日志）
- ❌ 不实现与HR系统的组织架构自动同步接口
