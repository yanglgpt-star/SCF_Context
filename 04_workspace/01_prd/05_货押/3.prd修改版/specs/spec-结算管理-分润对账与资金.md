# Spec：结算管理——分润对账与资金

> **涉及端**：🔧 运营端、🏭 企业端-核心企业


> **对应PRD**：PRD_结算管理.md — 5.1 分润结算 + 5.4 收款确认 + 资金账户  
> **覆盖范围**：分润计算（推荐首笔0.1%/后续0.05%/催收0.2%/回购1.0%/质量系数S1.5/A1.2/B1.0/C0.8）、月度/季度结算周期、自动对账、资金账户（4个）  
> **版本**：V1.0

---

## 1. Goal（目标）

**财务/运营人员**通过自动分润计算引擎和在线对账机制，实现核心企业分润的精准计算、快速确认和及时支付，达成：
- 分润准确率100%
- 分润确认周期≤2天（从生成分润明细到双方确认）
- 对账时效≤2小时
- 对账准确率100%

---

## 2. Scope（边界）

### 本次包含
- 分润自动计算（推荐佣金/协同催收奖励/回购合作奖励/合作质量奖金）
- 分润明细在线查看（企业端）和确认/异议提交
- 分润争议处理流程（平台财务核查3个工作日）
- 月度/季度结算周期管理（自动生成/推送/截止/支付）
- 银行流水导入（Excel/CSV/API）和自动对账（精确匹配+模糊匹配）
- 差异处理（多付/少付/付款方不一致/重复付款）
- 4个资金账户管理（余额查询/流水/近期变动）
- 分润支付指令生成（含大额审批控制）

### 本次不包含
- 资金池统一调度和计息（延后V3.0）
- 第三方支付自动分润（本期仅生成支付指令，不直接调用支付API）
- 多币种分润结算（延后V3.0）
- 税务自动化申报（延后V2.0）
- 智能合约自动分润（区块链）
- 实时分润（T+0，本期采用月度/季度周期）

### 输出

| 字段 | 类型 | 说明 |
|------|------|------|
| settlement_id | string | 分润结算单编号 |
| total_profit_amount | decimal(18,2) | 总分润金额 |
| referral_commission | decimal(18,2) | 推荐佣金 = Σ(首笔×0.1% + 后续×0.05%) |
| collection_reward | decimal(18,2) | 协同催收奖励 = Σ(催收成功金额×0.2%) |
| repurchase_reward | decimal(18,2) | 回购合作奖励 = Σ(回购货值×1.0%) |
| quality_bonus | decimal(18,2) | 质量奖金 = (前三项之和) × (质量系数 - 1.0) |
| quality_coefficient | decimal(3,1) | 质量系数（S=1.5/A=1.2/B=1.0/C=0.8） |
| settlement_status | enum(待确认/已确认/有异议/已调整/待支付/已支付) | 结算状态 |
| reconciliation_result | enum(精确匹配/模糊匹配/无法匹配) | 对账结果 |
| account_balance | object | 4个账户实时余额 |
| payment_order_id | string | 支付指令编号 |

### 异常状态全覆盖

| 异常场景 | 系统行为 | 处理方式 |
|----------|----------|----------|
| 核心企业提出异议（5个工作日内） | 暂停支付流程，创建异议工单，推送财务核查 | 财务3个工作日内完成核查 |
| 核查确认分润计算错误 | 调整分润金额，重新推送确认 | 核心企业重新确认后进入支付 |
| 核查确认分润无误 | 记录说明，与核心企业协商解决 | 协商达成一致后进入支付 |
| 异议超期未处理（>5个工作日） | 自动视为"确认无误"，进入支付流程 | 自动流转 |
| 银行流水与账单金额完全一致+付款方一致 | 自动标记"精确匹配"，更新账单状态为"已付款" | 自动处理 |
| 银行流水金额相近（±5%）+付款方一致 | 标记"模糊匹配"，推荐关联，需人工确认 | 人工确认后更新 |
| 付款方与账单企业不一致 | 标记"付款方异常"，需人工核实是否为代付 | 人工核实后关联 |
| 多付款（金额>账单） | 确认后标记"预付款"，差额挂账可抵扣未来账单 | 人工确认后挂账 |
| 少付款（金额<账单） | 标记"部分收款"，剩余金额继续催收 | 自动更新账单状态 |
| 重复付款 | 标记"重复"，联系企业核实后退款或预存 | 人工处理 |
| 分润计算误差>0.01% | 系统告警，阻断结算流程，触发人工复核 | 人工核查后修复 |
| 核心企业等级变更 | 下季度分润自动按新系数计算，已结算分润不受影响 | 自动隔离 |
| 大额支付(>10万) | 系统拦截，需财务总监审批后才可生成支付指令 | 审批通过后继续 |

## 4. Constraints（约束）

### 技术约束
- 单月全部分润计算响应≤30秒
- 报表查询响应≤3秒
- 批量导出1000条数据≤10秒
- 分润计算结果与手工抽样核对误差率<0.01%
- 月末/季末结算高峰期支持弹性扩容
- 结算系统可用性≥99.9%

### 安全约束
- 所有收款必须进入平台监管账户，禁止员工个人账户代收
- 分润支付需双人复核，大额支付（>10万）需财务总监审批
- 支付操作需短信验证码+数字证书双重验证
- 每日收款与银行流水自动核对，差异超阈值自动告警
- 敏感财务数据（银行账户、交易金额）传输加密
- 防重放攻击：所有支付请求需包含唯一请求ID
- 账单和分润明细保留不少于10年

### 业务约束
- 推荐佣金率：首笔0.1%、后续0.05%、年度≥500万额外0.5%
- 协同催收奖励：协同催收成功金额×0.2%
- 回购合作奖励：回购货值×1.0%
- 质量系数：S=1.5、A=1.2、B=1.0、C=0.8
- 月度结算：每月5日系统自动生成分润明细，12日截止确认，15日支付
- 季度结算：季后首月10日生成质量奖金明细，20日截止确认，25日支付
- 异议时效：核心企业需在明细推送后5个工作日内提出异议
- 核查时效：平台财务需在收到异议后3个工作日内完成核查
- 对账匹配：精确匹配（金额+付款方一致）+ 模糊匹配（±5%）+ 时间窗口≤30天
- 资金账户：融资资金监管户 + 平台运营收入户 + 分润支付专用户 + 风险准备金户
- 风险准备金：服务费收入5%计提，最低余额为在途余额1%

### 跨模块约束
- **与贷后管理数据流**：催收回收金额、回购完成金额、核销金额需在每月4日前同步至结算模块
- **与融资业务管理**：融资金额、首笔/后续标志用于推荐佣金计算
- **与客户管理**：核心企业等级变化影响下季度分润质量系数
- **与银行核心系统**：银企直联API为主，网银文件导入为备选

## 5. Acceptance Criteria（验收标准）

| 编号 | 验收标准 | 验证方式 |
|------|----------|----------|
| AC-1 | 打开分润明细页（企业端），核心企业可见本期总分润金额及4类构成明细（推荐佣金/协同奖励/回购奖励/质量奖金），与上期对比显示环比增长率 | 打开页面验证展示字段和计算逻辑 |
| AC-2 | 调接口 `GET /api/settlement/detail?core_enterprise_id=xxx&period=2026-03`，返回某核心企业上月分润明细，每笔分润可追溯至原始业务编号和计算过程 | 调接口验证字段完整性和可追溯性 |
| AC-3 | 核心企业点击"确认无误"后，分润状态从"待确认"变为"已确认"，系统生成支付指令进入待支付队列 | 操作后验证状态变更和支付指令生成 |
| AC-4 | 打开收款确认页，导入银行流水Excel后，系统自动按"金额+付款方"匹配账单，精确匹配的记录自动标记"已收款"，模糊匹配(±5%)的记录标注"待人工确认" | 导入后验证匹配结果分类 |
| AC-5 | 调接口 `POST /api/reconciliation/auto-match`，返回精确匹配、模糊匹配(±5%)、无法匹配三类结果及各自数量 | 调接口验证对账逻辑和分类 |
| AC-6 | 打开资金账户看板，可见4个账户（融资监管户/运营收入户/分润支付户/风险准备金户）的实时余额、近期流水、收入/支出汇总 | 打开页面验证4个账户展示 |
| AC-7 | 每月5日0点系统自动生成分润明细并推送核心企业；逾期至12日24点未确认的，系统自动视为"确认无误"并进入支付流程 | 定时任务验证自动生成和逾期自动确认 |

## 6. Non-Goals（非目标）

以下功能是AI/技术最容易顺手做的，但本期明确排除：

1. **智能合约自动分润**：不使用区块链技术实现分润的自动执行和不可篡改
2. **多币种分润结算**：本期仅支持人民币分润结算
3. **实时分润（T+0）**：不实现融资业务完成后实时计算并支付分润，采用月度/季度周期
4. **基于区块链的分润存证**：不对分润计算和支付过程做区块链存证
5. **自动对接第三方支付API自动打款**：本期仅生成支付指令，不直接调用支付宝/微信/银联API执行转账
6. **AI智能预测核心企业分润趋势**：不基于历史数据预测未来分润金额
7. **自动对接央行征信获取企业信用数据**：不从央行征信系统获取数据用于分润风控
8. **动态质量系数调整算法**：不基于实时业务数据动态调整质量系数（按季度评估调整）
