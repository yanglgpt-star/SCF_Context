# Spec：货权管理-入库库存与仓单

> **涉及端**：🔧 运营端、🏪 企业端-融资企业、📦 仓储方/WMS


## 1. Goal（目标）

平台运营端通过接收WMS入库数据并与企业预报自动比对（品类/数量±5%/仓库/时间±3天），实现入库确认或异常预警，入库完成后自动触发仓单开立。提供库存总览5维度视图（品类/仓库/客户/核心企业/风险）和盘点计划管理（按价值分层频率），支持仓单全生命周期（开立→质押→变更→解押→注销）管理，使盘点差异率从3%降至≤2%，入库异常及时拦截率100%。

## 2. Scope（边界）

### 本次包含
- 入库预报（企业端填写）与WMS入库数据自动比对
- 库存总览5维度统计与地图化展示
- 盘点计划自动生成（高价值周盘/普通月盘/高风险加密盘）
- 盘点差异处理（≤2%记录/2%-5%复盘/>5%冻结+核查）
- 仓单全生命周期管理（开立→质押→变更→解押→注销）
- 仓单与货物联动规则（入库增/出库减/价格更新/盘点调整/结清解押）
- WMS接口对接（入库inbound/库存inventory/盘点stocktaking）

### 本次不包含
- 企业端入库预报的移动端独立页面（本期H5/小程序适配）
- 仓单区块链存证的完整技术实现（区块链平台选择待技术+法务确认，本期预留接口）
- 跨平台仓单互认（行业标准未统一）
- 物联网传感器实时监控（硬件方案待确认）
- 库存地图化展示的UI/UX完整设计（【待确认】设计部门）

## 3. I/O（输入输出）

### 3.1 入库预报

**输入（企业端提交）：**

| 字段 | 类型 | 必填 | 校验规则 |
|-----|------|------|---------|
| business_no | String(32) | 是 | 已审批通过的融资业务编号 |
| forecast_goods | Array | 是 | [{sku_code, sku_name, category, brand, model, quantity, unit, batch_no}] |
| warehouse_id | String(32) | 是 | 已准入仓库 |
| forecast_inbound_date | Date | 是 | 预计入库日期 |
| remark | String(256) | 否 | — |

**输出：**

| 场景 | 返回体 | 说明 |
|-----|--------|------|
| 提交成功 | `{code:200, data:{forecast_id:"xxx", status:"PENDING"}}` | 入库预报入库，等待WMS实际入库数据 |
| 业务编号不存在 | `{code:400, message:"业务编号不存在或状态不正确"}` | — |
| 仓库未准入 | `{code:400, message:"仓库未准入"}` | — |

### 3.2 WMS入库数据推送与自动比对

**输入：POST /api/wms/inbound**

| 字段 | 类型 | 必填 | 说明 | 所属端 |
|-----|------|------|------||------|------|------|------|--------|
| warehouse_id | String(32) | 是 | WMS仓库编号 | | 📦 仓储方/WMS |
| inbound_no | String(32) | 是 | 入库单号 | | 📦 仓储方/WMS |
| inbound_time | DateTime | 是 | 实际入库时间 | | 📦 仓储方/WMS |
| business_no | String(32) | 是 | 平台业务编号 | | ⚙️ 系统 |
| goods_list | Array | 是 | [{sku_code, sku_name, category, brand, model, quantity, unit, batch_no, production_date, expiry_date, photos}] | | 🔧 运营端 |
| operator | String(32) | 否 | 仓库操作员 | | 📦 仓储方/WMS |
| sign | String | 是 | 数据签名 | | 🔧 运营端 |

**自动比对规则：**

| 比对项 | 允许误差 | 不一致处理 |
|-------|---------|-----------|
| 货物品类 | 必须完全一致 | 标记异常 |
| 品牌 | 必须完全一致 | 标记异常 |
| 型号 | 必须完全一致 | 标记异常 |
| 数量 | ±5% | 超过阈值标记异常 |
| 入库仓库 | 必须完全一致 | 标记异常 |
| 入库时间 | 预计入库日期±3天 | 超过范围标记异常 |

**输出：**

| 场景 | 返回体 | 后续动作 |
|-----|--------|---------|
| 比对通过 | `{code:200, data:{check_result:"PASS", platform_inbound_id:"xxx"}}` | 自动确认入库→触发放款流程/仓单开立 |
| 比对异常 | `{code:200, data:{check_result:"EXCEPTION", exception_reason:"xxx"}}` | 标记异常→暂停放款→推送异常通知→人工核实 |
| 签名失败 | `{code:403, message:"签名验证失败"}` | 记录安全日志 |
| 业务编号不存在 | `{code:400, message:"业务编号不存在"}` | 记录异常数据，标记"待关联" |

**异常处理流程：**
1. 系统标记异常后，自动暂停放款流程
2. 推送异常通知给客户经理和风控人员
3. 客户经理联系企业和仓储方核实原因
4. 核实后：确认无误可手动确认入库；确认有问题则要求企业补充或更换货物

### 3.3 库存总览

**5维度统计：**

| 维度 | 统计内容 | 展示形式 | 数据来源 |
|-----|---------|---------|---------|
| 品类维度 | 各品类在库数量、货值、平均质押率 | 表格+柱状图 | 库存表+品类配置 |
| 仓库维度 | 各仓库在库数量、货值、占比 | 表格+饼图 | 库存表+仓库表 |
| 客户维度 | 各客户在库数量、货值、质押率 | 表格 | 库存表+客户表 |
| 核心企业维度 | 各核心企业推荐客户在库情况 | 表格 | 库存表+客户表 |
| 风险维度 | 各风险等级（正常/警戒/超标/紧急）业务占比 | 条形图+卡片 | 预警表+库存表 |

**地图化展示：**

| 元素 | 说明 |
|-----|------|
| 仓库位置标记 | 地图上标记各仓库地理位置 |
| 仓库信息气泡 | 点击标记显示仓库名称、在库货值、预警数量 |
| 仓库状态颜色 | 正常（绿色）/有预警（黄色）/有超标（红色） |
| 货值热力图 | 可选按区域展示货值分布密度 |

**数据刷新：** 每5分钟自动刷新

**钻取路径：** 品类→客户→单笔业务→货物明细

**导出：** 支持Excel/PDF导出

### 3.4 盘点计划管理

**盘点频率规则：**

| 货物类型 | 盘点频率 | 说明 |
|---------|---------|------|
| 高价值货物（单价>5000元） | 每周盘点 | — |
| 普通货物 | 每月盘点 | — |
| 促销季/新品发布期 | 加密盘点（每3天） | 针对3C等高风险品类 |

**盘点计划生成：**
1. 系统按上述规则自动生成盘点计划
2. 推送盘点任务给对应仓库管理员
3. 仓库管理员执行盘点后，WMS推送盘点结果到平台

**输入：POST /api/wms/stocktaking**

| 字段 | 类型 | 必填 | 说明 | 所属端 |
|-----|------|------|------||------|------|------|------|--------|
| warehouse_id | String(32) | 是 | WMS仓库编号 | | 📦 仓储方/WMS |
| check_no | String(32) | 是 | 盘点单号 | | 📦 仓储方/WMS |
| check_time | DateTime | 是 | 盘点时间 | | 📦 仓储方/WMS |
| business_no | String(32) | 是 | 平台业务编号 | | ⚙️ 系统 |
| check_items | Array | 是 | [{sku_code, book_quantity, actual_quantity, difference, difference_rate}] | | 🔧 运营端 |
| photos | Array | 否 | 盘点照片URL | | 📦 仓储方/WMS |

**差异处理规则：**

```
差异率 = |实盘数量 - 账面数量| ÷ 账面数量 × 100%

IF 差异率 ≤ 2% THEN
    记录差异，列入下次重点核查
ELSE IF 差异率 > 2% AND ≤ 5% THEN
    触发人工复盘 → 核查原因 → 记录处理结果
ELSE IF 差异率 > 5% THEN
    冻结客户融资
    实地核查
    追究仓储方责任
END IF
```

### 3.5 仓单全生命周期管理

**仓单状态流转：**

```
待开立 → 已开立 → 已质押 → 已解押 → 已注销
              ↑______|
         （质押物变更：补充/部分出库后更新货物明细，状态仍为"已质押"）
```

**仓单要素：**

| 字段 | 类型 | 必填 | 说明 | 所属端 |
|-----|------|------|------||------|------|------|------|--------|
| receipt_no | String(32) | 是 | 唯一编码，系统生成 | | ⚙️ 系统 |
| warehouse_name | String(64) | 是 | 仓储方名称 | | 📦 仓储方/WMS |
| warehouse_address | String(256) | 是 | 详细地址 | | 📦 仓储方/WMS |
| depositor | String(64) | 是 | 融资企业名称 | | 🏪 企业端-融资企业 |
| goods_detail | JSON | 是 | SKU列表（品名/规格/数量/单价/货值） | | 🔧 运营端 |
| inventory_value | Decimal(16,2) | 是 | 当前货物总价值 | | 📦 仓储方/WMS |
| pledge_amount | Decimal(16,2) | 是 | 融资本金 | | 🔧 运营端 |
| pledge_ratio | Decimal(5,2) | 是 | 当前质押率 | | 🔧 运营端 |
| pledgee | String(64) | 是 | 银行名称 | | 🏦 银行端 |
| status | Enum | 是 | 待开立/已开立/已质押/已解押/已注销 | | 🔧 运营端 |
| e_signature | String | 是 | 平台+仓储方+客户三方电子签章 | | 📦 仓储方/WMS |
| blockchain_hash | String(64) | 否 | 上链存证哈希值（本期预留字段） | | 🔧 运营端 |
| create_time | DateTime | 是 | — | | 🔧 运营端 |
| update_time | DateTime | 是 | — | | 🔧 运营端 |

**仓单与货物联动规则：**

| 货物变动 | 仓单联动 | 触发条件 |
|---------|---------|---------|
| 新货物入库 | 仓单货物明细增加 | 入库确认完成 |
| 部分出库 | 仓单货物明细减少 | 出库审批通过并完成 |
| 价格更新导致货值变化 | 仓单在库货值更新 | 价格库批量重算完成 |
| 盘点差异调整 | 仓单货物明细调整 | 差异处理完成 |
| 融资结清 | 仓单状态变更为"已解押" | 还款确认完成 |

**仓单操作接口：**

| 操作 | 方法 | 路径 | 说明 |
|-----|------|------|------|
| 开立仓单 | POST | /api/receipt/create | 入库确认后自动触发 |
| 查询仓单 | GET | /api/receipt/{receipt_no} | — |
| 更新仓单 | POST | /api/receipt/{receipt_no}/update | 货物变动后自动触发 |
| 解押仓单 | POST | /api/receipt/{receipt_no}/release | 还款确认后自动触发 |
| 注销仓单 | POST | /api/receipt/{receipt_no}/cancel | 解押后归档 |

## 4. Constraints（约束）

### 技术约束
- WMS接口路径统一为 `/api/wms/*`（inbound/inventory/stocktaking）
- 库存数据同步每5分钟批量增量同步
- 入库/盘点数据采用Webhook实时推送
- 页面加载时间≤3秒（库存总览）
- 系统并发≥500同时在线用户

### 安全约束
- 仓单操作日志留存10年（涉及法律权属）
- WMS数据签名验证失败拒绝接收，记录安全日志
- 敏感库存数据（客户名称、货值）脱敏展示
- 仓单电子签章采用法大大为主供应商，e签宝为备用

### 设计约束
- 库存总览支持从汇总直接钻取到明细（品类→客户→单笔业务→货物明细）
- 入库验证页面展示预报vs实际对比表，差异项标红
- 盘点监控页面差异项标红，差异率>2%显示"触发核查"按钮
- 仓库地图气泡需展示仓库名称、在库货值、预警数量

## 5. Acceptance Criteria（验收标准）

### 5.1 入库预报与比对
- ✅ 企业端提交入库预报（business_no=B001，品类3C，数量100台，仓库W01，预计2026-05-01），系统返回forecast_id，状态"PENDING"
- ✅ WMS推送实际入库数据（business_no=B001，品类3C，数量98台，仓库W01，时间2026-05-02），数量差异2%（≤5%），其他一致，系统返回check_result="PASS"，自动确认入库，触发放款流程
- ✅ WMS推送实际入库数据（business_no=B002，品类3C，数量90台，仓库W01），数量差异10%（>5%），系统返回check_result="EXCEPTION"，exception_reason="数量差异超过阈值"，放款流程自动暂停，客户经理收到异常通知
- ✅ WMS推送实际入库数据（business_no=B003，品类食品，仓库W02，时间2026-05-10），预计入库日期2026-05-01，时间差异9天（>3天），系统标记"入库时间异常"
- ✅ WMS推送business_no不存在的入库数据，系统返回"业务编号不存在"，记录异常数据表，标记"待关联"

### 5.2 库存总览
- ✅ 打开库存总览页面，顶部展示5个统计卡片：在库总货值、总在库数量、平均质押率、预警业务数、仓库数量
- ✅ 点击"品类维度"标签，展示各品类在库数量/货值/平均质押率表格，3C品类平均质押率72%显示黄色高亮（>70%上限）
- ✅ 点击3C品类行，钻取到该品类下所有客户列表，显示各客户在库货值和质押率
- ✅ 点击某客户，钻取到该客户所有在途业务列表，点击业务可查看货物明细（SKU/数量/货值/质押率）
- ✅ 点击"导出"按钮，导出当前筛选条件下的库存数据为Excel，包含品类/仓库/客户/核心企业/风险等级全字段

### 5.3 盘点计划与差异处理
- ✅ 系统每周一自动生成高价值货物（单价>5000元）的盘点计划，每月1日生成普通货物的盘点计划，3C品类在促销季自动生成每3天的加密盘点计划
- ✅ 盘点计划列表展示：盘点单号/仓库/业务编号/计划时间/状态（待执行/已执行/有差异），支持按状态筛选
- ✅ WMS推送盘点结果（book_quantity=100, actual_quantity=98, difference_rate=2%），系统标记"差异率≤2%，列入下次重点核查"
- ✅ WMS推送盘点结果（book_quantity=100, actual_quantity=94, difference_rate=6%），系统标记"差异率>5%"，自动调用POST /api/risk/freeze/financing冻结该客户融资，生成"实地核查"待处理任务
- ✅ 盘点差异率>2%时，盘点监控页面显示"触发核查"按钮，点击后生成核查任务并推送给责任人

### 5.4 仓单全生命周期
- ✅ 入库确认完成后，系统自动生成仓单，receipt_no格式为"ZD"+年月日+6位流水号，状态"已开立"
- ✅ 仓单"已开立"后自动流转至"已质押"状态，记录质权人（银行名称）和质押金额
- ✅ 部分出库后（出库审批通过），仓单货物明细自动减少对应SKU数量，在库货值和质押率自动更新
- ✅ 价格库批量重算完成后，仓单在库货值字段自动更新，质押率自动重算
- ✅ 融资结清（还款确认完成）后，仓单状态自动变更为"已解押"，支持查看解押记录（解押时间/操作人/还款金额）
- ✅ 仓单详情页展示完整信息：仓单编号/仓储方/仓库地址/存货人/货物明细/在库货值/质押金额/质押率/质权人/状态/电子签章/创建时间/更新时间

### 5.5 WMS数据同步
- ✅ WMS推送库存数据（POST /api/wms/inventory），系统5分钟内完成库存数据更新，库存总览页面数据与WMS一致
- ✅ WMS服务不可用超过10分钟，平台使用最近一次成功同步的数据继续监控，同时显示"数据源延迟"告警提示
- ✅ 库存数据与平台账面数据差异>5%，系统自动生成"库存差异"预警，触发人工复盘
- ✅ 入库照片随WMS数据推送，入库验证页面可点击查看大图

## 6. Non-Goals（非目标）

- ❌ 不实现区块链存证的完整技术实现（区块链平台选择待技术+法务确认，本期预留字段和接口）
- ❌ 不实现跨平台仓单互认（行业标准未统一，生态不成熟）
- ❌ 不实现物联网传感器实时监控（温湿度等硬件方案待确认）
- ❌ 不实现库存地图化展示的完整UI设计（地图展示方案【待确认】设计部门）
- ❌ 不实现全自动仓储方责任追偿扣款（合同条款待法务确认，系统仅记录和预警）
- ❌ 不实现企业端入库预报的独立APP页面（本期仅H5/小程序适配）
