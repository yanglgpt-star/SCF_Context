# Spec：客户管理-企业档案与推荐

> **涉及端**：🔧 运营端、🏭 企业端-核心企业


## 1. Goal（目标）

**谁**：平台运营人员（运营端）、核心企业（企业端）
**怎么做**：通过统一的客户档案管理平台，实现客户A/B/C分级管理、授信额度维护、证照有效期自动监控、核心企业推荐质量评估
**达成什么**：
- 客户全生命周期信息统一管理，信息分散问题解决
- 证照到期预警及时率100%
- 核心企业推荐质量可量化评估，差异化合作政策落地
- 优质客户占比提升至≥60%

---

## 2. Scope（边界）

### 本次包含
- 企业客户档案管理（基本信息、联系人、资质证照、银行账户）
- 客户A/B/C三级分级管理（A+视为A级）
- 授信额度管理（额度分配、占用、释放、调整）
- 证照有效期自动监控（提前30天预警）
- 风险标签管理（白名单/黑名单/预警/冻结）
- 核心企业档案与分级（S/A/B/C）
- 推荐质量得分自动计算（通过率/首贷率/逾期率加权）
- 核心企业推荐激励机制（质量奖金/协同催收奖励框架）

### 本次不包含
- 客户自助修改档案信息（档案变更需经平台审核，本期延后）
- 推荐佣金计算与发放（归属结算管理模块）
- 客户画像AI预测模型
- 与CRM系统的双向同步
- 客户行为分析漏斗模型

---

**输出（查询）**：
- **成功**：返回客户完整档案信息，含历史变更记录
- **无权限**：返回"无权查看该客户信息"
- **客户不存在**：返回"客户不存在或已删除"

### 3.2 证照管理

**输入（证照录入/更新）**：

| 字段名 | 类型 | 必填 | 说明 | 所属端 |
|--------|------|------|------||--------|------|------|------|--------|
| 证照ID | String(32) | 是 | 系统生成 | | ⚙️ 系统 |
| 客户ID | String(32) | 是 | 关联客户 | | 🏪 企业端-融资企业 |
| 证照类型 | Enum | 是 | 营业执照/法人身份证/开户许可证等 | | 🔧 运营端 |
| 证照编号 | String(100) | 是 | 证照上的编号 | | ⚙️ 系统 |
| 证照影像 | File | 是 | 扫描件/照片 | | 🔧 运营端 |
| 发证日期 | Date | 条件必填 | 证照上的发证日期 | | 🔧 运营端 |
| 有效期至 | Date | 条件必填 | 证照到期日 | | 🔧 运营端 |
| 是否长期有效 | Boolean | 否 | 如营业执照长期有效 | | 🔧 运营端 |
| 预警状态 | Enum | 是 | 正常/即将过期/已过期 | | ⚙️ 系统 |

**输出（证照查询/预警）**：
- **正常**：有效期>30天，无预警
- **即将过期**：有效期≤30天且>0天，系统推送预警通知给客户经理和企业联系人
- **已过期**：有效期<0天，系统推送紧急通知，冻结新增融资申请
- **预警列表**：运营端可查看全部即将过期证照，支持按到期时间排序

### 3.3 授信额度管理

**输入（额度调整）**：

| 字段名 | 类型 | 必填 | 说明 | 所属端 |
|--------|------|------|------||--------|------|------|------|--------|
| 客户ID | String(32) | 是 | - | | 🏪 企业端-融资企业 |
| 调整类型 | Enum | 是 | 初始授予/额度上调/额度下调/临时调额/冻结/解冻 | | 🔧 运营端 |
| 调整金额 | Decimal(18,2) | 是 | 正数=增加，负数=减少 | | 🔧 运营端 |
| 调整后总额度 | Decimal(18,2) | 是 | 系统校验 | | 🔧 运营端 |
| 调整原因 | String(500) | 是 | - | | 🔧 运营端 |
| 审批人 | String(50) | 是 | - | | 🔧 运营端 |

**输出（额度查询）**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 总额度 | Decimal(18,2) | 当前授信总额度 |
| 已占用额度 | Decimal(18,2) | 所有在途业务占用额度之和 |
| 可用额度 | Decimal(18,2) | 总额度-已占用额度 |
| 冻结额度 | Decimal(18,2) | 因特殊原因冻结的额度 |

**额度占用/释放规则**：
- 融资申请审批通过时：占用额度（额度状态="已占用"）
- 业务结清时：释放额度（额度状态="已释放"）
- 业务逾期时：额度不释放，客户状态变更为"冻结"
- 客户状态="冻结"时：禁止新增额度占用

### 3.4 核心企业推荐质量评估

**输入（评估参数）**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 核心企业ID | String(32) | - |
| 统计周期 | Enum | 季度（默认）/月度 |
| 推荐总数 | Int | 该周期内推荐客户总数 |
| 准入通过数 | Int | 推荐客户中通过准入的数量 |
| 首贷成功数 | Int | 推荐客户中首次成功融资的数量 |
| 逾期笔数 | Int | 推荐客户中发生逾期的融资笔数 |
| M3+逾期笔数 | Int | 推荐客户中逾期90天以上的笔数 |

**输出（推荐质量得分）**：

```
推荐质量得分 = 
  准入通过率 × 30% + 
  首贷率 × 30% + 
  (1 - 逾期率) × 25% + 
  (1 - M3+逾期率) × 15%
```

**评分结果及等级映射**：

| 得分区间 | 推荐质量等级 | 合作政策 |
|----------|-------------|----------|
| ≥90分 | 优秀 | 授信额度上浮20%，推荐码有效期延长 |
| 70-89分 | 良好 | 标准合作政策 |
| 50-69分 | 一般 | 限制单月推荐数量，加强审核 |
| <50分 | 较差 | 暂停推荐资格，连续2季度<50分自动降级 |

**核心企业等级自动评估规则**：
- S级：得分≥90分，年融资规模≥5000万，合作年限≥3年
- A级：得分70-89分
- B级：得分50-69分
- C级：得分<50分，或连续2季度<50分

### 3.5 核心企业推荐激励机制

**输入（奖励计算参数）**：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 核心企业ID | String(32) | - |
| 推荐客户融资总额 | Decimal(18,2) | 季度统计 |
| 推荐质量得分 | Int | 季度评估得分 |
| 协同催收次数 | Int | 响应平台协同催收请求的次数 |

**输出（激励结果）**：【待确认】具体激励金额和计算公式待运营部编制《核心企业推荐激励制度》后确认

- **推荐佣金**：按推荐客户实际融资金额的一定比例计算
- **质量奖金**：推荐质量得分≥90分时发放
- **协同催收奖励**：响应协同催收请求时发放

## 4. Constraints（约束）

### 4.1 技术约束
- 客户档案数据存储期限：永久（已注销客户档案保留，标记状态）
- 证照影像存储：对象存储，支持CDN加速访问
- 授信额度实时计算延迟：≤500ms
- 推荐质量评估周期：每季度自动评估，支持手动触发
- 证照预警定时任务：每日凌晨2:00执行扫描

### 4.2 安全约束
- 客户档案敏感字段（银行账户、法人身份证、征信报告）AES-256加密存储
- 运营端查看客户档案需RBAC权限校验
- 客户档案变更记录完整审计日志（谁、何时、改了什么字段、原值/新值）
- 黑名单数据同步来源需多重校验，防止误伤

### 4.3 设计约束
- A+级经销商在平台侧**视为A级**，档案中等级字段存储为"A"，原A+标识保留在"核心企业评级"字段
- 客户等级调整需审批流程支持，不允许运营人员直接修改
- 证照到期前默认30天预警，可配置，最小7天
- 核心企业等级每季度自动评估，运营人员可人工复核调整
- 核心企业allow_referral=false时，无法生成新推荐码，但已生成的有效推荐码仍可使用

## 5. Acceptance Criteria（验收标准）

### 5.1 客户档案管理
1. **打开运营端客户管理列表页**，列表展示客户名称、客户类型、客户等级（A/B/C标签色区分）、授信额度、客户状态，支持按客户等级/状态/类型筛选
2. **打开运营端客户详情页**，点击某客户"查看详情"，页面展示客户完整档案信息（基本信息、联系人、资质证照、银行账户、授信记录、风险标签）
3. **打开运营端客户详情页**，运营人员点击"编辑档案"，修改客户联系电话后保存，系统记录变更日志（操作人、时间、字段、原值、新值）
4. **调接口** `/api/v1/customer/{id}`，传入不存在的客户ID，返回HTTP 404，错误信息"客户不存在"
5. **打开运营端客户管理列表页**，客户经理角色登录，列表仅展示其负责的客户数据，不可查看其他客户经理的客户

### 5.2 客户分级与授信额度
6. **打开运营端客户详情页**，某A级客户当前总额度100万、已占用30万，页面展示"总额度：100万，已占用：30万，可用额度：70万"
7. **打开运营端授信额度调整页面**，运营人员为某客户上调额度20万，填写调整原因并提交，系统校验调整后总额度≤品类上限，通过后更新额度并记录日志
8. **调接口** `/api/v1/customer/{id}/credit-limit`，查询某客户额度信息，返回总额度、已占用、可用额度、冻结额度四个字段
9. **打开运营端客户管理列表页**，运营人员将某客户等级从B级调整为A级，系统提示"等级调整需经审批流程"，提交后进入审批
10. **打开企业端客户中心**，经销商查看自身档案，显示客户等级=A级（如核心企业评定为A+，则展示"平台等级：A级（核心企业评级：A+）"）

### 5.3 证照有效期监控
11. **打开运营端证照预警列表**，系统展示所有30天内到期的证照，按到期时间升序排列，每条记录显示客户名称、证照类型、到期日、剩余天数
12. **调接口** `/api/v1/certificate/warning`，返回即将过期证照列表，字段包含客户ID、证照类型、有效期至、剩余天数
13. **打开运营端消息中心**，某客户营业执照距到期日30天，系统推送预警通知给客户经理，通知内容包含"XX客户营业执照将于X月X日到期，请及时提醒更新"
14. **打开运营端客户详情页**，某客户营业执照已过期，客户状态自动变更为"预警"，新增融资申请被禁止
15. **打开企业端消息中心**，证照即将过期时，企业联系人收到短信+系统消息提醒，内容包含证照类型和到期日

### 5.4 核心企业推荐质量评估
16. **打开运营端核心企业管理页面**，某核心企业本季度推荐质量得分88分，页面展示得分及四个子维度得分（准入通过率/首贷率/逾期率/M3+逾期率）
17. **打开运营端核心企业管理页面**，季度评估日（每季度首日），系统自动生成所有核心企业的推荐质量评估报告，运营人员可下载PDF报告
18. **调接口** `/api/v1/core-enterprise/{id}/quality-score`，传入核心企业ID，返回推荐质量得分及各项子指标
19. **打开运营端核心企业分级配置页面**，某核心企业连续2季度得分<50分，系统自动将其等级降级为C级，allow_referral自动设为false
20. **打开运营端核心企业管理页面**，核心企业等级为S级时，页面展示"授信额度上浮20%"标识，推荐码有效期显示为60天

### 5.5 推荐激励机制
21. **打开运营端激励统计页面**，展示核心企业本季度推荐佣金、质量奖金、协同催收奖励的汇总数据（【待确认】具体金额待激励制度确认后验证）
22. **打开核心企业端激励中心**，核心企业可查看本季度推荐质量得分、各项奖励明细和发放状态
23. **调接口** `/api/v1/core-enterprise/{id}/incentive-summary`，返回推荐佣金、质量奖金、协同催收奖励三个字段的汇总金额

## 6. Non-Goals（非目标）

1. **客户自助修改档案信息**：本期客户档案变更需经平台审核，不支持客户自助修改
2. **客户画像AI预测模型**：本期基于规则引擎评估客户资质，不构建AI客户画像
3. **推荐佣金自动发放**：激励金额计算后需财务人工确认发放，本期不自动打款
4. **与外部CRM系统双向同步**：本期仅平台内部管理，不与其他CRM系统对接
5. **客户社交网络分析**：不分析客户之间的关联关系和网络图谱
6. **实时征信监控**：征信数据在准入和融资申请时查询，不做7×24小时实时监控
7. **自动额度调整**：额度调整需运营人员发起或审批触发，系统不自动根据数据调整额度
