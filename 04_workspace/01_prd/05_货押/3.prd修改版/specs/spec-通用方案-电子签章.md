# Spec：通用方案——电子签章

> **涉及端**：🔄 跨端（平台/企业/仓储方/银行）


> **对应PRD**：PRD_通用方案_待确认事项补充.md（章节十二）  
> **适用范围**：供应链金融平台——客户准入、融资业务、货权管理、贷后管理模块

---

## 1. Goal（目标）

平台业务人员通过多供应商电子签章系统（法大大/e签宝/CFCA），在融资合同、仓单、质押合同、回购协议等6类业务场景中发起在线签署，实现实名认证、在线签字、时间戳固化、区块链存证的全流程数字化，确保签署文件具备司法效力。

---

## 2. Scope（边界）

### 本次包含
- 3家签章供应商的优先级配置和自动切换策略
- 6类业务场景的签署流程定义
- 签署流程的核心接口规范
- 区块链存证、时间戳、司法鉴定报告生成
- 5类异常场景的处理策略

### 本次不包含
- 签章供应商的合同谈判和商务采购
- 电子签章供应商的SDK/SDK接入层的底层封装（复用现有接入组件）
- 与互联网法院/仲裁机构的系统直连对接
- 线下纸质合同的邮寄和归档
- 合同模板的法律条款起草（由法务提供模板）

### 3.3 核心接口

#### 发起签署流程

**请求**：
| 字段名 | 类型 | 长度 | 必填 | 校验规则 | 所属端 |
|--------|------|------|------|----------||--------|------|------|------|----------|--------|
| scene_code | string | ≤32 | 是 | 已定义场景 | | ⚙️ 系统 |
| biz_no | string | ≤32 | 是 | 关联业务单号 | | ⚙️ 系统 |
| signatories | array | - | 是 | 每方包含：role、name、id_card_no、mobile、email | | ⚙️ 系统 |
| template_params | object | - | 否 | 模板填充变量 | | ⚙️ 系统 |
| callback_url | string | ≤512 | 是 | HTTPS URL | | ⚙️ 系统 |

**成功响应**：
| 字段名 | 类型 | 说明 |
|--------|------|------|
| flow_id | string | 签署流程ID |
| sign_url | string | 签署链接（各签署方独立） |

**失败响应**：
| 字段名 | 类型 | 说明 |
|--------|------|------|
| code | string | 错误码 |
| message | string | 如"模板不存在""实名信息不匹配" |

#### 查询签署状态

**响应**：
| 字段名 | 类型 | 长度 | 说明 |

| signatories_status | array | - | 各方签署状态 |
| signed_file_url | string | ≤512 | 签署完成后PDF下载地址 |
| blockchain_tx_hash | string | ≤128 | 区块链存证哈希 |
| timestamp_service_sn | string | ≤128 | 时间戳序列号 |

#### 签署完成回调（供应商→平台）

| 字段名 | 类型 | 长度 | 必填 | 校验规则 | 所属端 |
|--------|------|------|------|----------||--------|------|------|------|----------|--------|
| flow_id | string | ≤32 | 是 | - | | ⚙️ 系统 |
| status | string | ≤16 | 是 | COMPLETED/REJECTED/EXPIRED | | ⚙️ 系统 |
| sign_time | datetime | - | 是 | 最后签署时间 | | ⚙️ 系统 |
| signed_file_id | string | ≤64 | 是 | 文件ID | | ⚙️ 系统 |
| blockchain_tx_hash | string | ≤128 | 否 | 存证哈希 | | ⚙️ 系统 |
| signature | string | ≤512 | 是 | RSA签名，平台验签 | | ⚙️ 系统 |

### 3.4 异常处理

| 异常场景 | 系统响应 | 业务处理 |
|----------|----------|----------|
| 签署方拒绝 | status=REJECTED | 记录拒绝原因，通知业务方，可重新发起 |
| 签署超时（7天） | status=EXPIRED | 自动过期，可重新发起 |
| 实名认证失败 | status=AUTH_FAILED | 引导更换认证方式，3次失败后转人工 |
| 签章服务商故障 | 自动切换备用供应商（e签宝） | 新流程自动走备选供应商 |
| 合同内容争议 | 调取区块链存证，比对哈希值 | 确认文件完整性 |

### 3.5 状态覆盖矩阵

| 场景 | 成功 | 失败 | 网络异常 | 空状态 |
|------|------|------|----------|--------|
| 发起签署 | flow_id+sign_url | 返回错误码+message | 重试3次后标记"待人工处理" | 模板参数缺失时前置校验 |
| 签署回调 | 更新业务单签署状态 | 验签失败则丢弃+告警 | 入消息队列定时消费 | 回调body为空时拒收 |
| 文件下载 | 返回PDF二进制流 | 返回404+记录日志 | 重试后仍失败则标记"文件待补" | 流程未结束时返回"尚未完成" |

## 4. Constraints（约束）

### 技术约束
- 签章供应商接口协议：HTTPS RESTful API，AppID + AppSecret + RSA签名
- 回调接口必须支持RSA签名验签，否则视为非法请求丢弃
- 签署文件PDF必须包含国家授时中心可信时间戳
- 区块链存证支持蚂蚁链和至信链，哈希值永久保存

### 安全约束
- 签署链接必须通过实名认证后才能访问，不可直接分享绕过
- 各方身份信息（姓名、身份证号、手机号）在传输和存储时加密
- 签署完成后的PDF文件在平台侧保存至少15年
- 签章供应商的AppSecret必须加密存储，禁止明文落库

### 设计约束
- 多供应商切换对业务方透明，业务代码不感知具体供应商
- 每份合同必须生成唯一的签署流程ID，与业务单号一对一映射
- 签署状态变更必须同步更新关联业务单状态（如融资合同签署完成→待放款）

## 5. Acceptance Criteria（验收标准）

1. **在融资申请页面点击"发起合同签署"**：系统调用法大大接口创建签署流程，返回flow_id和经销商签署链接；经销商打开链接完成实名认证和签字后，平台收到回调，融资单状态自动变为"合同已签署"。
2. **法大大服务故障时发起仓单签署**：系统检测到法大大接口连续3次超时，自动切换至e签宝创建签署流程，业务人员无感知，签署链接正常生成。
3. **查看已完成的质押合同**：页面显示"区块链存证"按钮，点击后展示蚂蚁链交易哈希、区块高度、时间戳序列号；点击"下载合同"可获取带时间戳的PDF文件。
4. **经销商在签署页面点击"拒绝签署"**：平台收到REJECTED回调，融资单状态变为"合同签署拒绝"，页面显示拒绝原因（如"对利率条款有异议"），业务人员可重新发起签署流程。
5. **签署流程超过7天未完结**：系统自动将flow状态更新为EXPIRED，关联业务单显示"签署已过期"，业务人员点击"重新发起"可创建新流程。
6. **实名认证连续失败3次**：第3次失败后页面提示"认证失败次数超限，请联系客户经理处理"，系统自动生成人工处理工单，不再允许该用户继续尝试。

---

## 6. Non-Goals（非目标）

- ❌ 不实现手写签名笔迹的动态采集和笔迹鉴定功能
- ❌ 不实现合同条款的AI智能审核（由法务人工审核）
- ❌ 不实现签署过程的全程录屏和视频存证
- ❌ 不实现与互联网法院的在线立案直连对接（仅提供证据包下载）
- ❌ 不实现多方同时在线会签的实时协同编辑功能（按顺序签署）
