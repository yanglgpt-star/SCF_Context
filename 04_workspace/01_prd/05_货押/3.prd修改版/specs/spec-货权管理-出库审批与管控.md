# Spec：货权管理-出库审批与管控

> **涉及端**：🔧 运营端、🏦 银行端、🏪 企业端-融资企业、📦 仓储方/WMS


## 1. Goal（目标）

平台货权监控员通过接收银行出库授权，经三重自动校验引擎和智能审批策略（≤5万且质押率≤80%自动通过、>100%自动拒绝），在2小时内完成出库审批决策并下发出库指令，使出库审批时效从12小时降至≤2小时，自动审批覆盖率达50%。同时，系统7×24小时监控异常出库行为（未经审批/数量不符/频繁出库/非营业时间），确保货权异常率≤2%。

## 2. Scope（边界）

### 本次包含
- 银行出库授权接收接口（POST /api/bank/release_auth）及去重/过期/金额异常处理
- 三重校验引擎（授权有效性/剩余货值充足性/质押率安全性）
- 智能审批策略（≤5万自动通过、>100%自动拒绝、中间地带转人工）
- 出库审批页面（银行授权状态/倒计时/质押率进度条/校验结果/审批按钮）
- 出库指令下发（POST /api/wms/release）
- 异常出库监控（未经审批出库/数量不符/频繁出库/非营业时间/循环出入库）
- 3C品类动态阈值调整（新品发布期/促销季）

### 本次不包含
- 全自动货物处置（无人审批）——涉及资金安全和法律合规，保持人工审批
- 与物流TMS/DMS系统的深度集成——非核心集成，延后二期
- 仓储方合同条款及责任追溯的系统落地——【待确认】法务+运营
- 银行授权通过邮件/传真备用通道的完整自动化——过渡期保留人工

## 3. I/O（输入输出）

### 3.1 银行出库授权接收

**输入：POST /api/bank/release_auth**

| 字段 | 类型 | 必填 | 校验规则 |
|-----|------|------|---------|
| bank_code | String(16) | 是 | 已准入银行编码 |
| auth_no | String(32) | 是 | 银行唯一授权编号，平台侧去重 |
| business_no | String(32) | 是 | 平台融资业务编号，须存在且状态为"在库监管" |
| repayment_amount | Decimal(16,2) | 是 | >0 |
| release_value | Decimal(16,2) | 是 | >0，与repayment_amount差异>5%标记"金额异常" |
| expire_time | DateTime | 是 | 通常为接收后24小时，过期后不可用 |
| operator | String(32) | 否 | 银行操作员工号 |
| auth_time | DateTime | 是 | 银行发送时间 |
| sign | String | 是 | HMAC-SHA256签名验证 |

**输出：**

| 场景 | HTTP状态 | 返回体 | 说明 |
|-----|----------|--------|------|
| 成功接收 | 200 | `{code:200, data:{platform_auth_id:"xxx", status:"RECEIVED"}}` | 新授权入库 |
| 重复授权 | 200 | `{code:200, data:{platform_auth_id:"xxx", status:"DUPLICATE"}}` | 根据auth_no去重，返回已存在记录 |
| 签名失败 | 403 | `{code:403, message:"签名验证失败"}` | 记录安全日志 |
| 业务编号不存在 | 400 | `{code:400, message:"业务编号不存在"}` | 记录异常数据，标记"待关联" |
| 金额异常（差异>5%） | 200 | `{code:200, data:{status:"AMOUNT_EXCEPTION"}}` | 授权入库但标记异常，转人工核实 |
| 银行服务不可用 | — | — | 记录异常，切换邮件/传真备用通道（过渡期） |

### 3.2 三重校验引擎

**输入：** 出库审批请求（由系统内部触发或前端人工审批时调用）

| 字段 | 来源 | 说明 |
|-----|------|------|
| auth_no | 银行授权记录 | — |
| business_no | 银行授权记录 | — |
| apply_release_value | 申请出库货值 | 企业端提交或银行授权金额 |
| current_inventory_value | 货权管理-库存数据 | 当前在库货值 |
| current_principal | 融资业务系统 | 剩余融资本金 |
| category_pledge_ratio_limit | 品类配置 | 3C:70%, 食品:75%, 白酒:80%, 家电:80% |

**校验逻辑：**

| 校验项 | 校验逻辑 | 通过条件 | 失败处理 |
|-------|---------|---------|---------|
| 校验1：授权有效性 | auth_no存在且未过期；release_value>0 | 当前时间<expire_time | 直接拒绝，提示"授权无效或已过期" |
| 校验2：剩余货值充足性 | current_inventory_value - apply_release_value ≥ 0 | 剩余货值≥0 | 直接拒绝，提示"在库货值不足" |
| 校验3：质押率安全性 | after_ratio = current_principal / (current_inventory_value - apply_release_value) × 100% | after_ratio ≤ 100%（自动拒绝阈值） | 自动拒绝，提示"出库后质押率超标，需还款或补充质押物" |

> 重要原则：三项全部通过才允许审批，任一不通过直接拒绝。

**输出：**

| 场景 | 校验结果 | 后续动作 |
|-----|---------|---------|
| 三项全通过 | `{check1:"PASS", check2:"PASS", check3:"PASS", after_ratio:72.2}` | 进入智能审批策略 |
| 任一失败 | 对应项为"FAIL"，附失败原因 | 直接拒绝，记录拒绝原因 |

### 3.3 智能审批策略

**输入：** 三重校验通过后的上下文数据

**审批规则：**

```
IF apply_release_value ≤ 50000 AND after_ratio ≤ 80% THEN
    自动审批通过 → 实时下发POST /api/wms/release
ELSE IF after_ratio > 100% THEN
    自动拒绝 → 冻结该客户出库权限 → 提示需还款或补充质押物
ELSE
    转人工审批 → 推送至货权监控员待办
END IF
```

**3C品类动态阈值调整：**

| 时期 | 自动通过阈值 | 自动拒绝阈值 | 人工审批区间 |
|-----|------------|------------|------------|
| 正常期 | ≤80% | >100% | 80%-100% |
| 新品发布期（发布前30天） | ≤70% | >90% | 70%-90% |
| 促销季（双11等，季前15天） | ≤75% | >95% | 75%-95% |

**输出：**

| 审批结果 | 状态值 | 触发动作 |
|---------|--------|---------|
| 自动通过 | AUTO_PASS | 下发出库指令，通知银行端+企业端 |
| 自动拒绝 | AUTO_REJECT | 冻结出库权限，生成待处理任务 |
| 待人工审批 | PENDING | 推送待办给货权监控员，倒计时显示 |
| 人工通过 | MANUAL_PASS | 下发出库指令，记录审批人+时间+依据 |
| 人工驳回 | MANUAL_REJECT | 记录驳回原因，通知企业端 |

### 3.4 出库指令下发

**输入：POST /api/wms/release**

| 字段 | 类型 | 必填 | 说明 | 所属端 |
|-----|------|------|------||------|------|------|------|--------|
| auth_no | String(32) | 是 | 平台授权编号 | | 🏦 银行端 |
| business_no | String(32) | 是 | 平台业务编号 | | ⚙️ 系统 |
| warehouse_id | String(32) | 是 | WMS仓库编号 | | 📦 仓储方/WMS |
| allow_goods_list | Array | 是 | [{sku_code, allow_quantity, batch_no}] | | 🔧 运营端 |
| expire_time | DateTime | 是 | 指令有效期 | | 🔧 运营端 |
| sign | String | 是 | 数据签名 | | 🔧 运营端 |

**输出：**

| 场景 | HTTP状态 | 返回体 |
|-----|----------|--------|
| WMS接受 | 200 | `{code:200, data:{wms_auth_no:"xxx", status:"ACCEPTED", accept_time:"xxx"}}` |
| WMS拒绝 | 400 | `{code:400, message:"WMS拒绝原因"}` |
| WMS超时（>30秒） | 504 | 重试3次，仍失败记录异常日志通知运维 |

### 3.5 异常出库监控（WMS推送数据自动比对）

**输入：** WMS推送出库数据 POST /api/wms/outbound

| 异常类型 | 判定规则 | 触发处理 |
|---------|---------|---------|
| 未经审批出库 | WMS推送出库数据但平台无对应审批记录 | 立即预警→冻结该仓库所有客户出库权限→通知风控→联系仓储方核实 |
| 出库数量与审批不符 | 实际出库数量与审批数量差异超过±5% | 立即预警→记录差异→暂停该客户后续出库→人工核实 |
| 短时间内频繁出库 | 同一客户1天内出库次数>3次 | 预警提示→转人工审批该客户后续出库 |
| 非营业时间出库 | 出库时间在22:00-8:00之间 | 预警提示→要求仓储方说明原因 |
| 同一批次货物反复出入库 | 同一批次30天内出入库循环>2次 | 预警提示→标记为可疑操作→风控核查 |

## 4. Constraints（约束）

### 技术约束
- WMS接口路径统一为 `/api/wms/*`（inbound/outbound/inventory/stocktaking/release）
- 银行接口采用HTTPS+JSON+OAuth 2.0或数字证书认证
- 关键接口（银行授权、出库指令）采用HMAC-SHA256数据签名防篡改
- 出库审批响应≤1秒（自动审批场景）
- WMS数据同步延迟≤5分钟

### 安全约束
- 出库审批日志留存5年（含自动审批和人工审批）
- 敏感数据（客户信息、金额）前端展示脱敏
- 关键操作（审批、冻结、解押）完整记录操作人、时间、IP
- 人工审批需登录态验证，审批按钮权限控制

### 设计约束
- 出库审批页面需展示授权有效期倒计时（实时，过期标红）
- 质押率进度条颜色规则：绿色(<80%)/蓝色(80-90%)/黄色(90-100%)/红色(>100%)
- 审批页面状态变体：自动通过/自动拒绝/待人工审批/授权已过期（审批按钮禁用）

## 5. Acceptance Criteria（验收标准）

### 5.1 银行授权接收
- ✅ 打开银行端模拟器，发送出库授权（auth_no=AUTH001，business_no=B001，release_value=50000），平台返回`status:"RECEIVED"`，数据库授权表新增记录，status=RECEIVED
- ✅ 再次发送相同auth_no的授权，平台返回`status:"DUPLICATE"`，数据库不新增记录
- ✅ 发送release_value与repayment_amount差异>5%的授权，平台返回`status:"AMOUNT_EXCEPTION"`，同时生成"金额异常"待处理任务
- ✅ 发送expire_time为当前时间-1小时的授权，平台返回`status:"AUTH_EXPIRED"`（或校验失败提示）
- ✅ 发送签名错误的授权，平台返回403，安全日志表新增记录

### 5.2 三重校验引擎
- ✅ 打开出库审批页面，当前在库货值100万，融资本金65万，申请出库10万，三重校验结果均显示"✓通过"，出库后质押率显示72.2%
- ✅ 当前在库货值80万，融资本金70万，申请出库15万，三重校验中"质押率安全性"显示"✗不通过"，系统提示"出库后质押率超标(107.7%)，需还款或补充质押物"
- ✅ 当前在库货值10万，申请出库15万，三重校验中"剩余货值充足性"显示"✗不通过"
- ✅ 使用已过期的授权编号发起审批，三重校验中"授权有效性"显示"✗不通过"
- ✅ 调接口直接请求三重校验API（内部接口），输入异常参数，返回明确的校验失败原因字段

### 5.3 智能审批策略
- ✅ 申请出库货值4万，出库后质押率72%，系统5秒内自动审批通过，生成出库指令并推送WMS
- ✅ 申请出库货值20万，出库后质押率107%，系统5秒内自动拒绝，客户出库权限状态变更为"冻结"
- ✅ 申请出库货值8万，出库后质押率88%，系统标记"待人工审批"，货权监控员待办列表新增一条记录
- ✅ 3C品类处于新品发布期（发布前30天内），申请出库货值4万，出库后质押率73%，系统转人工审批（因正常期阈值80%下调至70%）
- ✅ 自动审批通过的任务，出库审批统计表中"自动审批"字段+1，审批时效字段记录实际耗时

### 5.4 异常出库监控
- ✅ WMS推送一条无对应审批记录的出库数据（business_no=B002，outbound_no=OUT999），系统15分钟内生成"未经审批出库"紧急预警，该仓库所有客户出库权限状态变更为"冻结"
- ✅ WMS推送出库数量50，但审批数量为100，差异率50%>5%，系统生成"出库数量不符"预警，该客户后续出库申请自动转人工审批
- ✅ 同一客户1天内第4次出库，系统生成"频繁出库"预警，并标记该客户后续出库为"需人工审批"
- ✅ WMS推送出库时间为23:00的数据，系统生成"非营业时间出库"预警
- ✅ 未经审批出库预警触发后，风控人员可在系统中查看该仓库近30天所有出库记录

### 5.5 出库审批页面
- ✅ 打开出库审批页面，授权有效期倒计时实时递减，过期后倒计时变红，审批按钮禁用，提示"授权已过期，请联系银行重新授权"
- ✅ 页面顶部展示银行授权状态区块，点击可展开查看授权详情（授权编号/金额/已用/剩余/有效期）
- ✅ 质押率进度条颜色与当前质押率/预测质押率匹配（绿色<80%/蓝色80-90%/黄色90-100%/红色>100%）
- ✅ 人工审批状态下，审批通过按钮和审批驳回按钮可用，点击驳回弹出输入框要求填写驳回原因（必填，最少10字）
- ✅ 历史出库记录区域展示该业务近30天所有出库记录，点击单条可查看详情

## 6. Non-Goals（非目标）

- ❌ 不实现全自动无人审批（>5万或高风险场景必须保留人工决策环节）
- ❌ 不实现仓储方物联网传感器实时监控（温湿度等硬件方案待确认，本期不做）
- ❌ 不实现跨平台仓单互认（行业标准未统一，生态不成熟）
- ❌ 不实现AI预测性风险识别（需积累历史数据，模型训练延后）
- ❌ 不实现仓储方责任追偿的自动扣款/法律诉讼流程（合同条款待法务确认，系统仅记录和预警）
- ❌ 不实现银行授权的邮件/传真通道的完全自动化（过渡期保留人工录入备用通道）
