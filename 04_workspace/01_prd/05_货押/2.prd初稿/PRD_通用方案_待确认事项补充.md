## 平台整体架构

### 参与方与端定义

供应链金融平台（货押模式）包含 **1 个后台管理端 + 2 个前台端 + 1 个外部监管方系统**，共五方协同：

| 端/参与方 | 类型 | 定位 | 面向用户 |
|-----------|------|------|----------|
| **运营端** | 后台管理 | 平台业务管理与决策中枢 | 平台内部运营人员（客户经理、风控专员、货权监控员、财务人员等） |
| **企业端 — 核心企业** | 前台 | 链主企业信用背书与供应链协同 | 核心企业用户（推荐经销商、订单确认、风险协同、协同催收、货物回购、分润查询） |
| **企业端 — 融资企业** | 前台 | 资金需求方自助服务 | 经销商/融资企业用户（准入申请、融资申请、资料上传、仓单查看、还款管理） |
| **银行端** | 前台 | 资金方协同平台 | 合作银行用户（业务审批、放款管理、出库授权、还款确认、业务监控、资金对账） |
| **仓储方/WMS** | 外部监管系统 | 质押物实际监管与数据同步 | 仓储合作方（入库、出库、库存、盘点数据实时推送，异常上报） |

> **说明**：
> - 企业端内部通过**双角色登录与功能分区**区分核心企业与融资企业，两者权限、数据范围、功能菜单完全隔离。
> - 仓储方作为货权管控的核心执行方，通过 WMS 系统与平台实时对接，承担货物监管责任和异常上报义务。

## 一、核心企业ERP接口规范

### 1.1 接口协议

| 项目 | 规范 |
|------|------|
| 协议 | HTTPS RESTful API |
| 数据格式 | JSON (UTF-8编码) |
| 认证方式 | OAuth 2.0 Client Credentials Grant + JWT Token |
| Token有效期 | 2小时 |
| 签名算法 | HMAC-SHA256，密钥由平台与核心企业双向预置 |
| 超时时间 | 连接超时5秒，读取超时10秒 |
| 重试策略 | 失败重试3次，间隔2秒、4秒、8秒（指数退避） |
| 幂等性 | 所有写入接口需携带`idempotency_key`（UUID），防重复处理 |

### 1.2 接口清单

| 接口 | 方法 | 路径 | 用途 | 调用方 |
|------|------|------|------|--------|
| 推荐码验证 | GET | `/api/v1/dealer/verify` | 准入时验证推荐关系 | 平台 |
| 经销商数据查询 | GET | `/api/v1/dealer/{credit_code}` | 获取经销商主数据 | 平台 |
| 风险预警推送 | POST | `/api/v1/risk/alert` | 核心企业推送经销商异常 | 核心企业 |
| 数据变更通知 | POST | `/api/v1/data/change` | 经销商数据变更时主动通知 | 核心企业 |
| 协同催收响应 | POST | `/api/v1/collection/response` | 核心企业反馈协同催收结果 | 核心企业 |
| 回购邀请响应 | POST | `/api/v1/repurchase/response` | 核心企业反馈回购意向 | 核心企业 |
| 分润明细查询 | GET | `/api/v1/settlement/detail` | 核心企业查询分润明细 | 核心企业 |
| 分润确认 | POST | `/api/v1/settlement/confirm` | 核心企业确认或异议 | 核心企业 |

### 1.3 通用请求/响应格式

**请求头**：
```json
{
  "Authorization": "Bearer {jwt_token}",
  "Content-Type": "application/json",
  "X-Request-ID": "uuid",
  "X-Idempotency-Key": "uuid",
  "X-Timestamp": "1699123456"
}
```

**成功响应**：
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "request_id": "uuid"
}
```

**错误响应**：
```json
{
  "code": 40001,
  "message": "推荐码无效",
  "data": null,
  "request_id": "uuid"
}
```

### 1.4 错误码定义

| 错误码 | 含义 | 处理策略 |
|--------|------|----------|
| 200 | 成功 | - |
| 40001 | 推荐码无效 | 提示经销商联系核心企业获取新推荐码 |
| 40002 | 经销商不存在 | 驳回申请，提示核实企业信息 |
| 40003 | 请求参数错误 | 记录日志，提示技术排查 |
| 40101 | Token过期 | 自动刷新Token后重试 |
| 40102 | 签名验证失败 | 记录日志，触发告警，人工排查 |
| 40301 | 无权限访问 | 记录日志，联系核心企业确认权限配置 |
| 42901 | 请求频率超限 | 等待后重试 |
| 50001 | 核心企业系统内部错误 | 标记"待人工确认"，通知核心企业技术 |
| 50301 | 核心企业系统维护中 | 提示"系统维护"，降级为人工处理 |

### 1.5 降级方案

当核心企业ERP接口不可用时：
1. **准入场景**：标记"推荐待人工确认"，由客户经理电话/邮件联系核心企业核实，核实通过后人工录入确认结果
2. **数据同步场景**：使用最近一次成功同步的缓存数据，有效期7天，超期后标记"数据过期"
3. **预警推送场景**：核心企业仍可通过平台运营端Web页面手动录入预警信息

## 二、征信系统供应商方案

### 2.1 供应商选择

采用**双源征信策略**，主备冗余：

| 供应商 | 用途 | 优先级 | 成本 |
|--------|------|--------|------|
| **企查查** | 主数据源，企业征信、涉诉、失信、股权穿透 | 主 | 按查询次数计费，约0.5-2元/次 |
| **天眼查** | 备用数据源，主数据源异常时切换 | 备 | 按查询次数计费，约0.5-2元/次 |

### 2.2 查询策略

| 场景 | 查询内容 | 查询时机 | 结果有效期 |
|------|----------|----------|-----------|
| 客户准入 | 企业工商信息、司法风险、经营异常、股权结构 | 初审通过后自动查询 | 30天 |
| 客户准入 | 法人个人征信（如涉及连带责任担保） | 终审前 | 30天 |
| 风险监控 | 新增涉诉、失信、被执行人 | 每日自动扫描 | 实时 |
| 授信复核 | 企业工商变更、股权变更 | 季度复核时 | 实时 |

### 2.3 风控阈值

| 风险项 | 阈值 | 处置措施 |
|--------|------|----------|
| 涉诉金额 > 年营收20% | 高风险 | 冻结新增融资 |
| 失信被执行 | 高风险 | 自动驳回准入/冻结融资 |
| 经营异常名录 | 中风险 | 加强审核/降低额度 |
| 法人个人征信逾期>3次 | 中风险 | 降低授信额度 |
| 股权冻结 | 中风险 | 暂停新增融资，核实原因 |

## 三、品类质押率上限方案

### 3.1 最终数值

| 品类 | 质押率上限 | 相对质押率警戒阈值 | 相对质押率超标阈值 | 新品发布期调整 |
|------|-----------|-------------------|-------------------|--------------|
| 3C电子 | **70%** | 100%（即70%） | 115%（即80.5%） | 上限降至60%，自动审批阈值降至70% |
| 白酒 | **80%** | 100%（即80%） | 115%（即92%） | 促销季视情况降5% |
| 食品 | **75%** | 100%（即75%） | 115%（即86.25%） | 临期前降质押率 |
| 家电 | **80%** | 100%（即80%） | 115%（即92%） | 大促前视情况降5% |

### 3.2 推导逻辑（已保留在各PRD中）

```
质押率上限 = 100% - 预期最大跌幅 - 安全边际

3C电子：100% - 20%(新品发布+促销) - 10%(安全边际) = 70%
食品：100% - 10%(季节波动) - 10%(保质期风险) - 5%(安全边际) = 75%
白酒：100% - 10%(市场波动) - 10%(安全边际) = 80%
家电：100% - 15%(技术迭代+促销) - 5%(安全边际) = 80%
```

## 七、逾期利率和宽限期方案

### 7.1 逾期利率

| 逾期阶段 | 逾期利率 | 计算基数 |
|----------|----------|----------|
| M0（1-3天） | **0%**（宽限期不计逾期利息） | 逾期本金 |
| M1（4-30天） | **日利率0.03%**（年化10.95%） | 逾期本金 |
| M2（31-60天） | **日利率0.04%**（年化14.6%） | 逾期本金+已产生逾期利息 |
| M3+（>60天） | **日利率0.04%**（年化14.6%） | 逾期本金+已产生逾期利息 |

> **合规说明**：
> - 上述利率均不超过法律保护的民间借贷利率上限（LPR的4倍，当前约14.8%年化）。
> - M1阶段日利率0.03%（年化10.95%），M2/M3+阶段日利率0.04%（年化14.6%），均在LPR 4倍范围内，符合法律规定。
> - 如监管政策调整，系统支持参数化配置，运营人员可在配置中心调整各阶段利率（上限受系统校验，不得超过LPR 4倍）。

### 7.2 宽限期

| 项目 | 设置 |
|------|------|
| 还款宽限期 | **3天**（即M0阶段不收取逾期利息，仅自动提醒） |
| 宽限期内计息 | 不计逾期利息，按正常利率计息 |
| 宽限期后 | 从第4天起按M1利率计收逾期利息 |

### 7.3 逾期利息计算示例

```
融资本金：100万
正常到期日：2026-03-01
实际还款日：2026-03-20（逾期19天）

逾期利息计算：
- M0宽限期（3月1日-3月3日，3天）：不计逾期利息
- M1阶段（3月4日-3月18日，15天）：100万 × 0.03% × 15 = 4,500元
- M2阶段（3月19日-3月20日，2天）：100万 × 0.04% × 2 = 800元

总逾期利息：5,300元
```

## 九、税务处理方案

### 9.1 服务费收入税务

| 项目 | 处理方式 |
|------|----------|
| 增值税 | 按"直接收费金融服务"或"经纪代理服务"缴纳，税率**6%** |
| 计税基数 | 含税服务费收入 ÷ (1+6%) |
| 销项税额 | 计税基数 × 6% |
| 开票方式 | 向融资企业开具6%增值税专用发票/普通发票 |
| 纳税义务发生时间 | 融资服务完成（放款成功）当日 |

### 9.2 分润支出税务

| 项目 | 处理方式 |
|------|----------|
| 增值税 | 分润支出属于平台成本，核心企业向平台开具发票 |
| 核心企业开票 | 核心企业向平台开具6%增值税发票（服务费/经纪代理） |
| 代扣代缴 | 如核心企业为个人/小规模纳税人，平台按税法规定代扣代缴 |
| 企业所得税 | 分润支出作为成本费用税前扣除 |

### 9.3 系统税务支持

| 功能 | 说明 |
|------|------|
| 自动计税 | 服务费计算时自动分离不含税金额和税额 |

## 十、资金账户体系方案

### 10.1 账户架构

采用**监管账户模式**，确保资金安全与合规：

```
┌─────────────────────────────────────────────────────────────┐
│                      平台监管账户体系                        │
│                                                             │
│  ┌─────────────────┐    ┌─────────────────┐                │
│  │  融资资金监管户  │    │  平台运营收入户  │                │
│  │  （银行共管）    │    │                 │                │
│  │                 │    │  · 服务费收入    │                │
│  │  · 银行放款入账  │    │  · 其他收入      │                │
│  │  · 企业还款入账  │    │                 │                │
│  │  · 质押物处置回款│    │                 │                │
│  └────────┬────────┘    └────────┬────────┘                │
│           │                      │                          │
│           │    ┌─────────────────┘                          │
│           │    ▼                                            │
│           │  ┌─────────────────┐                            │
│           └──▶│  分润支付专用户  │                            │
│               │                 │                            │
│               │  · 核心企业分润  │                            │
│               │  · 仓储方费用    │                            │
│               │  · 银行利息支出  │                            │
│               └─────────────────┘                            │
│                                                             │
│  备注：融资资金监管户由平台和银行共同监管，                  │
│        平台无权单方面划转资金。                              │
└─────────────────────────────────────────────────────────────┘
```

### 10.2 账户明细

| 账户名称 | 开户主体 | 用途 | 资金流入 | 资金流出 | 监管要求 |
|----------|----------|------|----------|----------|----------|
| 融资资金监管户 | 平台（银行共管） | 专项用于融资业务资金流转 | 银行放款、企业还款、处置回款 | 银行扣款（还款给银行） | 银行+平台双签 |
| 平台运营收入户 | 平台 | 平台服务费收入 | 企业支付的服务费 | 税费、运营成本、利润提取 | 平台自主管理 |
| 分润支付专用户 | 平台 | 专项用于分润支付 | 从运营收入户划拨 | 核心企业分润、合作方费用 | 平台自主管理 |
| 风险准备金户 | 平台 | 风险准备金计提 | 按收入比例计提 | 核销损失补偿 | 专款专用 |

### 10.3 资金流转规则

| 业务场景 | 资金流转路径 | 说明 |
|----------|-------------|------|
| 银行放款 | 银行→融资资金监管户→经销商账户 | 平台不触碰资金 |
| 企业还款 | 经销商账户→融资资金监管户→银行 | 平台自动对账确认 |
| 服务费收取 | 经销商账户→平台运营收入户 | 账单到期后收取 |
| 分润支付 | 平台运营收入户→分润支付专用户→核心企业 | 按月/季度结算 |
| 货物处置回款 | 买方账户→融资资金监管户 | 优先偿还银行本金 |
| 风险准备金计提 | 平台运营收入户→风险准备金户 | 按收入的5%计提 |

### 10.4 风险准备金

| 项目 | 设置 |
|------|------|
| 计提比例 | 服务费收入的**5%** |
| 计提时机 | 每月末根据当月服务费收入自动计提 |
| 使用条件 | 资产核销时，用于弥补损失 |
| 最低余额 | 不低于在途融资余额的**1%** |
| 不足补足 | 低于最低余额时，次月加倍计提 |

## 十二、电子签章系统方案

### 12.1 供应商选型

采用**多供应商备选策略**：

| 供应商 | 定位 | 优先级 | 适用场景 | 特点 |
|--------|------|--------|----------|------|
| **法大大** | 主供应商 | 首选 | 仓单签署、回购协议、融资合同 | 市占率高，司法认可度高，API完善 |
| **e签宝** | 备用供应商 | 备选 | 主供应商异常时切换 | 阿里生态，稳定性好，价格有竞争力 |
| **CFCA** | 合规备选 | 监管要求场景 | 银行端强合规场景 | 金融级安全认证，监管认可度高 |

### 12.2 应用场景

| 业务场景 | 签署方 | 签署文件 | 法律效力 |
|----------|--------|----------|----------|
| 融资合同签署 | 平台、经销商 | 融资服务协议 | 高 |
| 仓单开立 | 平台、仓储方、经销商 | 电子仓单 | 高 |
| 仓单质押登记 | 平台、经销商、银行 | 质押合同 | 高 |
| 回购协议 | 平台、核心企业 | 货物回购协议 | 高 |
| 核心企业合作协议 | 平台、核心企业 | 战略合作框架协议 | 高 |
| 对账单确认 | 平台、经销商/核心企业 | 月度对账单 | 中 |

### 12.3 技术对接方案

**接口协议**：HTTPS RESTful API，AppID + AppSecret + RSA签名，JSON格式

**核心接口**：

```
POST /api/v1/sign/flow/create    // 发起签署流程
GET  /api/v1/sign/flow/{id}/status // 查询签署状态
POST /api/scf/sign/callback       // 签署完成回调（供应商→平台）
GET  /api/v1/contract/{id}/download // 下载签署后合同
```

### 12.4 签署流程

```
平台发起签署 → 系统自动填充模板 → 推送签署通知
→ 各方实名认证 → 各方在线签署 → 生成带时间戳PDF
→ 区块链存证 → 归档关联业务单据
```

### 12.5 存证与司法保障

| 保障措施 | 说明 |
|----------|------|
| 区块链存证 | 签署全过程哈希上链（蚂蚁链/至信链） |
| 时间戳服务 | 国家授时中心可信时间戳 |
| 司法鉴定报告 | 支持一键生成完整证据包 |
| 诉讼绿色通道 | 与互联网法院/仲裁机构系统对接 |

### 12.6 异常处理

| 异常场景 | 处理策略 |
|----------|----------|
| 签署方拒绝 | 记录原因，通知业务方，可重新发起 |
| 签署超时（7天） | 自动过期，可重新发起 |
| 实名认证失败 | 引导更换认证方式，3次失败后转人工 |
| 签章服务商故障 | 自动切换备用供应商（e签宝） |
| 合同内容争议 | 调取区块链存证，比对哈希值确认完整性 |
