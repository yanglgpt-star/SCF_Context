## 三、需求背景

### 3.1 问题现状

#### 用户/业务侧痛点
1. **服务费计算复杂易出错**：计算规则复杂（按融资金额比例、按天计息、不同客户等级不同费率），缺乏标准化的计费规则文档，约5%的账单存在计算错误需重新开具。
2. **账单生成效率低**：账单生成依赖手工制作Excel或Word，格式不统一，账单发送需打印盖章扫描发邮件，流程繁琐。
3. **分润计算争议多**：分润计算涉及多方（推荐佣金、协同催收奖励、回购奖励、质量奖金），计算规则复杂，约10%的分润存在争议需重新核对。
4. **对账效率低**：收款后需手工核对账单和银行流水，每日对账耗时2-4小时，易出现遗漏或重复。

#### 系统侧痛点
1. **无自动化计费**：服务费手工计算工作量大，财务人员每笔融资业务完成后需手动计算。
2. **无在线对账**：缺乏自动化的分润计算和在线确认机制，分润确认周期平均7天。
3. **信息不透明**：核心企业无法实时查看分润明细，分润金额需手工计算并通知各合作方沟通确认。

### 3.2 需求目标

| 目标项 | 现状 | 目标值 | 衡量方式 |
|--------|------|--------|----------|
| 账单准确率 | 95% | 100% | 正确账单数/总账单数 |
| 服务费收缴率 | 92% | ≥98% | 实收服务费/应收服务费 |
| 分润准确率 | 90% | 100% | 正确分润笔数/总分润笔数 |
| 分润确认周期 | 7天 | ≤2天 | 从生成分润明细到双方确认的平均天数 |
| 对账时效 | 2-4小时 | ≤2小时 | 每日对账耗时 |
| 对账准确率 | 95% | 100% | 对账一致笔数/总对账笔数 |

## 五、需求详情

### 5.1 分润结算（重点功能）

#### 5.1.1 解决的核⼼问题
1. 分润计算涉及多方，计算规则复杂，约10%的分润存在争议
2. 分润金额需手工计算并通知各合作方沟通确认，工作量大
3. 核心企业无法实时查看分润明细，信息不透明
4. 分润确认周期平均7天，效率低下

#### 5.1.2 分润模型设计（服务端需求）

**核心企业总分润构成**：
```
核心企业总分润 = 推荐佣金 + 协同催收奖励 + 回购合作奖励 + 合作质量奖金
```

**1. 推荐佣金（基础分润）**：
```
推荐佣金 = Σ(推荐经销商融资额 × 推荐佣金率)

推荐佣金率：
- 推荐经销商首笔融资：0.1%
- 推荐经销商后续融资：0.05%
- 年度融资额≥500万：年度总额的0.5%（年度一次性结算）
```

**2. 协同催收奖励**：
```
协同催收奖励 = Σ(协同催收成功金额 × 0.2%)

触发条件：
- 逾期≥15天
- 核心企业协助催收
- 最终成功回款
```

**3. 回购合作奖励**：
```
回购合作奖励 = Σ(回购货值 × 1%)

触发条件：
- 核心企业接受回购
- 完成货物交接和付款
```

**4. 合作质量奖金（季度结算）**：
```
合作质量奖金 = 基础分润 × 质量系数

质量系数：
- S级核心企业：1.5倍
- A级核心企业：1.2倍
- B级核心企业：1.0倍
- C级核心企业：0.8倍
```

**计算示例**：
```
某S级核心企业Q1数据：
- 推荐经销商融资总额：8500万
  - 首笔融资（5家）：2200万
  - 后续融资（23家）：6300万
- 协同催收成功金额：520万
- 回购货值：1600万

计算：
1. 推荐佣金：
   首笔：2200万 × 0.1% = 2.2万
   后续：6300万 × 0.05% = 3.15万
   小计：5.35万

2. 协同催收奖励：
   520万 × 0.2% = 1.04万

3. 回购合作奖励：
   1600万 × 1% = 16万

4. 合作质量奖金（S级，1.5倍）：
   (5.35 + 1.04 + 16) × (1.5 - 1.0) = 11.2万

季度总分润：5.35 + 1.04 + 16 + 11.2 = 33.59万
```

#### 5.1.3 分润与评级联动（服务端需求）

**联动机制**：
```
每季度评估推荐质量得分
    ↓
质量得分变化 → 等级调整
    ↓
等级调整 → 质量系数变化
    ↓
下季度分润自动按新系数计算
```

**示例**：
```
某核心企业从A级升至S级：
质量系数：1.2 → 1.5
季度基础分润：100万
质量奖金：100 × (1.5 - 1.0) = 50万
vs 原A级：100 × (1.2 - 1.0) = 20万
增加30万奖金（+150%）
```

#### 5.1.4 分润在线确认（前端需求）

**【分润明细页】（企业端）**

页面元素：
1. **分润总览卡片**：
   - 本期总分润金额
   - 各项分润构成（推荐佣金/协同奖励/回购奖励/质量奖金）
   - 与上期对比（金额变化、环比增长率）

2. **分润明细表格**：
   - 字段：业务编号、经销商名称、融资额、分润类型、分润金额、计算时间
   - 筛选：按分润类型、时间范围筛选
   - 排序：默认按计算时间降序
   - 导出：支持导出Excel

3. **确认操作区**：
   - "确认无误"按钮：确认后进入支付流程
   - "提出异议"按钮：弹出异议表单

**【异议处理页】（运营端）**

页面元素：
1. **异议列表**：核心企业提出的所有异议
2. **异议详情**：
   - 异议内容、证据附件
   - 涉及的业务编号、分润类型、争议金额
3. **核查结果录入**：
   - 核查结论（确认错误/核查无误）
   - 调整金额（如确认错误）
   - 说明原因
4. **协商记录**：双方沟通记录时间轴

#### 5.1.5 对账与争议处理机制（后台需求）

**对账流程**：
```
每月5日前：
→ 系统自动生成分润明细
→ 推送给核心企业确认

核心企业5个工作日内：
→ 在线查看明细
→ 确认无误 → 进入支付流程
→ 提出异议 → 进入争议处理

争议处理：
→ 提交异议说明和证据
→ 平台财务核查（3个工作日）
→ 确认错误：调整分润
→ 无误：说明情况，协商解决
→ 双方确认：进入支付流程
```

**争议处理时效要求**：
- 核心企业提出异议：需在分润明细推送后5个工作日内
- 平台财务核查：收到异议后3个工作日内完成
- 双方协商：核查完成后2个工作日内达成一致
- 整体周期：从推送明细到最终确认不超过15个工作日

   - 示例：A级客户，融资100万，期限60天，3C电子
   - 计算结果预览

4. **版本管理**：
   - 保存为新版本
   - 查看历史版本
   - 回滚到历史版本
   - 版本对比

#### 5.2.2 服务费计算公式（服务端需求）

**模式1：按融资金额比例**
```
服务费 = 融资金额 × 服务费率 × (融资天数 / 360)

示例：
融资金额 = 100万
服务费率 = 年化3%
融资天数 = 60天
服务费 = 100万 × 3% × (60/360) = 5000元
```

**模式2：按天计息**
```
服务费 = 融资金额 × 日服务费率 × 融资天数

日服务费率 = 年化服务费率 / 360
```

**模式3：固定费用**
```
服务费 = 固定金额（如每笔500元）
```

**模式4：分段计费**
```
≤50万：3.5%
50-100万：3%
>100万：2.5%

示例：融资120万
服务费 = 50万×3.5% + 50万×3% + 20万×2.5% = 1.75万 + 1.5万 + 0.5万 = 3.75万
```

**催缴流程**：
```
账单到期前7天：
→ 系统自动发送提醒（短信+邮件）

账单到期前3天：
→ 再次提醒 + 推送给客户经理

账单到期当天：
→ 未付款标记"逾期"

逾期7天：
→ 升级催缴（客户经理电话跟进）

逾期15天：
→ 财务经理介入

```

**催缴效果跟踪**：

   - 支持银行API自动同步（如有）
   - 导入预览：展示导入数据的校验结果

2. **自动匹配结果**：
   - 精确匹配：金额完全一致，自动关联账单
   - 模糊匹配：金额相近（±5%），推荐关联，需人工确认
   - 无法匹配：标注待人工确认

3. **手动匹配区**：
   - 未匹配的流水列表
   - 未收款的账单列表
   - 拖拽或选择进行手动匹配

#### 5.4.2 自动对账规则（服务端需求）

**匹配规则**：
```
导入银行流水
    ↓
系统自动识别：
- 付款方（企业名称/账户）
- 金额
- 时间
    ↓
匹配待收款账单：
- 精确匹配：金额完全一致 + 付款方一致
- 模糊匹配：金额相近（±5%）+ 付款方一致
- 时间窗口：付款日期与账单日期相差≤30天
    ↓
自动更新账单状态
    ↓
无法匹配 → 人工确认
```

**差异处理**：

| 差异类型 | 处理方案 |
|----------|----------|
| 多付款 | 确认后标记为"预付款"，可用于抵扣未来账单 |
| 少付款 | 标记为"部分收款"，剩余金额继续催收 |
| 付款方不一致 | 人工核实是否为代付，确认后关联 |
| 重复付款 | 标记为"重复"，联系企业核实后退款或预存 |
| 无法识别付款方 | 标记为"待确认"，财务人工核实 |

## 七、系统集成

### 7.1 与支付系统的集成

**集成目的**：实现服务费收款和分润支付的自动化。

**集成数据**：
- 支付请求（收款/付款）

```

POST /api/payment/collect
Request:
  - bill_id: string

分润支付接口：
POST /api/payment/disburse
Request:
  - settle_id: string
  - amount: decimal
  - payee_account: string
  - payee_name: string
  - channel: enum (银行转账/支付宝/微信)
```

**集成方式**：
- 银行网银流水导出后导入平台

## 十、风控

### 10.1 资金安全防护
- 所有收款必须进入平台监管账户，禁止员工个人账户代收
- 分润支付需双人复核，大额支付（>10万）需财务总监审批
- 支付操作需短信验证码+数字证书双重验证
- 每日收款与银行流水自动核对，差异超阈值自动告警

### 10.2 分润计算准确性校验
- 分润计算结果需与手工抽样核对，误差率<0.01%
- 分润明细中每笔分润需可追溯至原始业务单据
- 核心企业等级变化时，系统自动重新计算未结算分润
- 分润计算公式变更时，保留历史版本，已确认分润不受影响

### 10.3 审计与合规
- 所有计费、分润、收付款操作记录完整审计日志
- 账单和分润明细保留不少于10年
- 支持按时间、客户、核心企业等维度全量导出
- 定期（每季度）由财务部门进行内部审计

### 10.4 税务合规
- 服务费收入按适用税率计算增值税
- 分润支出按"经纪代理服务"或"其他现代服务"代扣代缴增值税（如适用）
- 系统支持生成税务申报所需的汇总数据
