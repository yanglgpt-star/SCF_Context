## 三、需求背景

### 3.1 问题现状

#### 3.1.1 决策层痛点

- **缺乏品类风险穿透分析能力**：各品类质押率上限不同（3C电子70%、白酒80%），但决策层查看汇总数据时无法直接判断风险优先级——3C电子65%实际已接近红线，白酒65%仍在安全区间，但报表中显示相同。整体不良率从2.1%上升至4.8%，3个月后才发现3C电子品类不良率高达7.2%。
- **缺乏实时风控决策依据**：缺乏各品类质押率分布、货值波动趋势、出库审批时效等数据的实时穿透分析，无法快速调整风控策略。

#### 3.1.2 管理层痛点

- **货值监控与质押率管理失控**：
  - 管理问题：质押率设定未考虑品类特性（3C产品新品发布后月跌幅10-15%），缺乏分级预警响应制度，质押率超标后平均5天才处置；缺乏价格库管理规范，货值评估与市场价格脱节。
  - 协作问题：仓储方信息报送依赖邮件或电话，滞后且准确性难保证；某业务质押物实际已出库，平台3天后才发现。
  - 系统问题：缺乏与市场价格的动态联动机制，货值下跌后未及时重估；盘点依赖仓储方反馈，平台无法验证真实性，盘点差异率约3%。
  - 结果：质押率超标预警率仅70%，货权异常率达5%。例如某3C电子产品单月跌价15%，平台未及时发现，质押率从65%上升至76%。

- **出库审批效率低下**：
  - 管理问题：缺乏分级审批授权，所有出库都需人工审批，审批人员工作量大；缺乏异常出库监控和仓储方责任追溯机制。
  - 协作问题：银行出库授权通过邮件或传真发送，信息传递滞后；部分业务还款后银行未及时发送授权。
  - 系统问题：审批时需手工查询银行授权、剩余货值、质押率等多系统信息，人工汇总耗时4-12小时。
  - 结果：出库审批时效从4小时延长至12小时，货物处置周期平均60天。

- **品类差异化监控缺失**：
  - 管理问题：不同品类风险特性差异大（3C价格波动、白酒串货、食品保质期），但采用统一监控规则，约25%的品类风险未及时发现。
  - 协作问题：核心企业发现经销商异常（串货、违规等）需电话或邮件通知平台，信息传递延迟1-3天。
  - 系统问题：缺乏品类特有风险的自动监控能力（新品发布周期、串货流向、保质期临期等）。
  - 结果：品类风险预警及时率仅75%。

#### 3.1.3 执行层痛点

- 每天需向仓储方询问货物状态，获取信息慢且无法验证真实性。
- 处理出库申请时需手工查询多个系统信息，难以快速判断是否满足放货条件。
- 货值变化后不知道哪些业务质押率超标，需逐笔核查。
- 不同品类商品关注点不同，容易遗漏关键风险点。

### 3.2 需求目标

| 目标指标 | 当前值 | 目标值 | 衡量方式 |
|---------|--------|--------|---------|
| 质押率超标预警率 | 70% | 100% | 系统预警覆盖的在库业务占比 |
| 货权异常率 | 5% | ≤2% | 月度异常业务数/总在库业务数 |
| 出库审批时效 | 12小时 | ≤2小时 | 从接收银行授权到下发WMS指令的平均时长 |
| 盘点差异率 | 3% | ≤2% | 盘点差异笔数/总盘点笔数 |

## 五、需求详情

### 5.1 出库审批决策（重点功能）

#### 5.1.1 业务说明

出库审批是货权管理的核心控制环节。银行确认企业还款到账后向平台发送出库授权，平台接收授权后自动执行三重校验，根据校验结果决定自动审批通过、自动拒绝或转人工审批。平台通过出库审批机制掌握货物流转的最终决策权。

#### 5.1.2 业务流程（服务端需求）

```
企业端申请还款并提货
    │
    ▼
银行端确认还款到账 → 发送出库授权（授权释放XX价值质押物）
    │
    ▼
平台系统自动接收银行授权
    │
    ▼
【三重自动校验】
    │    │
    │    ├── 校验1：银行授权有效性
    │    │   - 银行是否已确认还款
    │    │   - 授权出库数量/金额
    │    │   - 授权是否在有效期内（24小时）
    │    │
    │    ├── 校验2：剩余货值充足性
    │    │   - 当前在库货值
    │    │   - 申请出库货值
    │    │   - 剩余货值 = 在库货值 - 出库货值
    │    │
    │    └── 校验3：质押率安全性
    │        - 剩余融资本金
    │        - 出库后剩余货值
    │        - 出库后质押率 = 剩余本金 / (剩余货值 × 质押率)
    │        - 判断：出库后质押率 ≤ 100%
    │
    ▼
【智能审批策略】
    │    │
    │    ├── IF 出库货值 ≤ 5万 AND 出库后质押率 ≤ 80%
    │    │   THEN → 【自动审批通过】→ 下发出库指令
    │    │
    │    ├── ELSE IF 出库后质押率 > 100%
    │    │   THEN → 【自动拒绝】→ 提示需还款或补充质押物
    │    │
    │    └── ELSE → 【转人工审批】→ 审批人决策
    │            │
    │            ├── 审批通过 → 下发出库指令
    │            └── 审批驳回 → 驳回通知
    │
    ▼
WMS系统接收出库指令 → 允许提货 → 出库完成反馈
    │
    ▼
平台自动更新质押物数据 → 触发仓单状态变更
    │
    ▼
通知出库完成（银行端/企业端）
```

#### 5.1.3 银行出库授权接收（服务端需求）

**接收内容**：

| 字段 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| 授权编号 | String(32) | 是 | 银行生成的唯一授权编号 |
| 业务编号 | String(32) | 是 | 关联的平台融资业务编号 |
| 还款金额 | Decimal(16,2) | 是 | 企业实际还款金额（元） |
| 可释放质押物价值 | Decimal(16,2) | 是 | 银行计算的可释放货值（元） |
| 授权有效期 | DateTime | 是 | 授权截止时间，通常为接收后24小时 |
| 银行操作员 | String(32) | 否 | 发起授权的银行操作人员 |
| 授权时间 | DateTime | 是 | 银行发送授权的时间 |

**异常处理**：
- 授权超过24小时未使用：系统自动标记为"已过期"，不再允许用于出库审批。
- 重复授权接收：系统根据授权编号去重，已存在的授权编号不再重复创建。
- 授权金额与系统记录差异>5%：系统标记为"金额异常"，转人工核实。

#### 5.1.4 三重自动校验逻辑（服务端需求）

**校验规则表**：

| 校验项 | 校验逻辑 | 通过条件 | 失败处理 |
|-------|---------|---------|---------|
| 校验1：授权有效性 | 检查授权编号存在且未过期；检查授权金额>0 | 授权在有效期内且金额有效 | 直接拒绝，提示"授权无效或已过期" |
| 校验2：剩余货值充足性 | 当前在库货值 - 申请出库货值 ≥ 0 | 剩余货值≥0 | 直接拒绝，提示"在库货值不足" |
| 校验3：质押率安全性 | 出库后质押率 = 剩余本金 / 剩余货值 × 100% | 出库后质押率 ≤ 100%（自动拒绝阈值） | 自动拒绝，提示"出库后质押率超标，需还款或补充质押物" |

> **重要原则**：三项全部通过才允许审批，任一不通过直接拒绝。

**计算公式验算示例**：

```
示例场景：
- 当前在库货值：100万元
- 融资本金：65万元
- 当前质押率：65%
- 申请出库货值：10万元

计算过程：
1. 剩余货值 = 100万 - 10万 = 90万元
2. 出库后质押率 = 65万 / 90万 × 100% = 72.2%
3. 判断：72.2% ≤ 80%（自动通过阈值）
4. 结果：若出库货值≤5万且出库后质押率≤80%，自动审批通过

示例场景2（高风险）：
- 当前在库货值：80万元
- 融资本金：70万元
- 当前质押率：87.5%
- 申请出库货值：15万元

计算过程：
1. 剩余货值 = 80万 - 15万 = 65万元
2. 出库后质押率 = 70万 / 65万 × 100% = 107.7%
3. 判断：107.7% > 100%
4. 结果：自动拒绝
```

#### 5.1.5 智能审批策略（服务端需求）

**审批策略规则**：

```
IF 出库货值 ≤ 5万 AND 出库后质押率 ≤ 80% THEN
    自动审批通过 → 实时下发出库指令
ELSE IF 出库后质押率 > 100% THEN
    自动拒绝 → 提示需还款或补充质押物 → 冻结该客户出库权限
ELSE
    转人工审批 → 推送至货权监控员待办
END IF
```

**5万元金额门槛设定依据**（来自原始素材）：
- 历史数据分析显示，单笔出库≤5万的申请占总量的65%，但金额占比仅18%。
- 小额出库多为经销商日常周转提货，业务场景稳定，风险可控。
- 5万元约为单件3C产品（如iPhone）的2-3倍价值，覆盖常见的零散提货需求。
- 即使出现问题，5万元的风险敞口在可接受范围内，不影响整体资产安全。

**80%质押率"安全线"设定依据**（来自原始素材）：
- 质押率 = 融资余额 ÷ 质押物货值 × 100%
- 80%意味着质押物货值仍有20%的安全缓冲空间。
- 以3C电子70%的质押率上限为例，80%质押率时：货值下跌空间 = (100%-80%) ÷ 80% = 25%
- 历史数据显示，3C产品单月最大跌幅约15%，25%的缓冲可覆盖1.5个月的极端下跌。
- 行业对标：京东供应链金融的自动审批阈值为75%，平安银行为80%，平台取值与行业主流一致。

#### 5.1.6 质押率分级标准及处置措施

**标准品类审批阈值**（3C新品发布期/促销季除外）：

| 等级 | 条件 | 处理方式 | 响应时效 |
|-----|------|---------|---------|

| 关注（人工审批） | 出库后质押率在80%-100%之间 | 转人工审批，货权监控员综合判断 | ≤2小时 |
| 危险（自动拒绝） | 出库后质押率>100% | 系统自动拒绝，提示需还款或补充质押物 | 实时 |

**触发100%超标的常见场景及占比**（来自原始素材）：

### 5.2 货值监控与预警（重点功能）

#### 5.2.1 业务说明

系统对接市场价格数据源，7×24小时自动监控质押物的货值波动和质押率变化，达到预警阈值时自动推送通知。系统支持品类差异化监控配置，针对不同品类设置专属监控规则。采用"相对质押率"统一度量跨品类风险，让决策层无需记忆各品类上限即可快速识别高风险业务。

#### 5.2.2 核心计算公式（服务端需求）

**公式1：质押率**

```
质押率 = 融资本金 ÷ 质押物货值 × 100%
```

**公式2：货值**

```
货值 = Σ(各SKU数量 × 当日参考价)
```

**公式3：相对质押率（跨品类统一度量）**

```
相对质押率 = 当前质押率 ÷ 品类上限 × 100%
```

> 相对质押率说明：质押率上限是该品类的红线，相对质押率超过100%即触发"超标"预警。

**公式4：当日参考价（3C电子品类示例）**

S级核心企业推荐：
```
当日参考价 = 核心企业报价×60% + 京东价×25% + 天猫价×15%
```

A/B级核心企业推荐：
```
当日参考价 = 核心企业报价×40% + 京东价×35% + 天猫价×15% + 中关村价×10%
```

C级核心企业或无核心企业推荐：
```
当日参考价 = 京东价×50% + 天猫价×30% + 中关村价×20%
```

**验算示例**（来自原始素材）：

```
示例：S级核心企业推荐的iPhone 15 Pro

数据来源：
- 核心企业报价：7,200元（B2B批发价）
- 京东价：7,999元（B2C零售价）
- 天猫价：7,899元

计算：
当日参考价 = 7200×60% + 7999×25% + 7899×15%
           = 4320 + 1999.75 + 1184.85
           = 7504.6 ≈ 7505元

对比分析：
- 如果仅用京东价（7,999元），货值会被高估约7%
- 采用核心企业报价为主（7,505元），更接近实际出货价和回购价
- 当质押物需要处置时，核心企业回购价通常在7,000-7,300元，与加权参考价更匹配
```

### 5.3 入库监控

#### 5.3.1 业务说明

实时监控质押物入库，系统自动接收WMS入库数据并校验货物信息与融资申请的一致性，支持远程查看入库照片核验货物真实性。入库完成后自动触发仓单开立流程。

#### 5.3.2 入库流程（服务端需求）

```
企业端提交融资申请 → 填写入库预报（品类/数量/仓库/预计时间）
    │
    ▼
货物送达仓库 → WMS执行入库操作
    │
    ▼
WMS推送入库数据到平台
    │
    ▼
【自动比对】
    │    │
    │    ├── 货物品类、品牌、型号 → 与预报一致？
    │    ├── 数量 → 与预报差异≤±5%？
    │    ├── 入库仓库 → 与预报一致？
    │    └── 入库时间 → 在预计入库日期±3天内？
    │
    ▼
比对结果：
    │    │
    │    ├── 全部一致 → 【确认入库】→ 触发放款流程/仓单开立
    │    └── 任一不一致 → 【标记异常】→ 暂停放款 → 人工核实
```

#### 5.3.3 入库监控配置（服务端/运营需求）

**自动比对规则**：

| 比对项 | 允许误差 | 不一致处理 |
|-------|---------|-----------|
| 货物品类 | 必须完全一致 | 标记异常 |
| 品牌 | 必须完全一致 | 标记异常 |
| 型号 | 必须完全一致 | 标记异常 |
| 数量 | ±5% | 超过阈值标记异常 |
| 入库仓库 | 必须完全一致 | 标记异常 |
| 入库时间 | 预计入库日期±3天 | 超过范围标记异常 |

**异常处理流程**：
1. 系统标记异常后，自动暂停放款流程。
2. 推送异常通知给客户经理和风控人员。
3. 客户经理联系企业和仓储方核实原因。
4. 核实后：确认无误可手动确认入库；确认有问题则要求企业补充或更换货物。

#### 5.3.4 入库验证（前端需求）

| 元素 | 展示条件 | 数据来源 | 交互行为 |
|-----|---------|---------|---------|
| 入库照片查看 | 有照片时显示 | WMS推送 | 点击查看大图 |
| 照片审核按钮 | 待审核时显示 | — | 点击标记"照片审核通过/不通过" |
| 入库信息卡片 | 始终显示 | WMS数据 | 展开/收起详情 |
| 预报vs实际对比表 | 始终显示 | 系统对比 | 差异项标红 |

### 5.5 盘点监控

#### 5.5.1 业务说明

系统对接WMS盘点数据，自动比对账面与实盘差异，生成差异明细和异常预警。支持远程查看盘点照片，对差异超过阈值的情况自动触发实地核查流程。盘点结果与仓单信息实时同步。

#### 5.5.2 盘点计划管理（服务端/运营需求）

**盘点频率规则**：

| 货物类型 | 盘点频率 | 说明 |
|---------|---------|------|
| 高价值货物（单价>5000元） | 每周盘点 | — |
| 普通货物 | 每月盘点 | — |
| 促销季/新品发布期 | 加密盘点（每3天） | 针对3C等高风险品类 |

**盘点计划生成逻辑**：
1. 系统按上述规则自动生成盘点计划。
2. 推送盘点任务给对应仓库管理员。
3. 仓库管理员执行盘点后，WMS推送盘点结果到平台。

#### 5.5.3 差异处理规则（服务端需求）

```
IF 差异率 ≤ 2% THEN
    记录差异，列入下次重点核查
ELSE IF 差异率 > 2% AND ≤ 5% THEN
    触发人工复盘 → 核查原因 → 记录处理结果
ELSE IF 差异率 > 5% THEN
    冻结客户融资
    实地核查
    追究仓储方责任
END IF
```

> 差异率计算公式：差异率 = |实盘数量 - 账面数量| ÷ 账面数量 × 100%

#### 5.5.4 盘点监控页面（前端需求）

| 元素 | 展示条件 | 数据来源 | 交互行为 |
|-----|---------|---------|---------|
| 盘点计划列表 | 始终显示 | 盘点计划表 | 点击可查看详情 |
| 盘点状态筛选 | 始终显示 | — | 筛选：待执行/已执行/有差异 |
| 差异对比表 | 有差异时显示 | 盘点结果 | 差异项标红 |
| 盘点照片查看 | 有照片时显示 | WMS推送 | 点击查看大图 |
| 触发核查按钮 | 差异率>2%时显示 | — | 点击生成核查任务 |

### 5.6 仓单管理

#### 5.6.1 业务说明

提供电子仓单的全生命周期管理，包括仓单开立、质押登记、质押物变更、解押管理和仓单查询与流转。系统采用唯一编码和电子签章技术，支持与区块链或电子存证平台对接。仓单状态与货物监控数据实时联动。

#### 5.6.2 仓单生命周期状态流转（服务端需求）

```
【待开立】→ 货物入库确认后
    │

    │

【已质押】→ 质押登记完成（记录质权人/质押金额）

    │
    ▼
【已解押】→ 融资结清后解除质押
    │
    ▼
【已注销】→ 仓单注销归档
```

| 质押金额 | Decimal(16,2) | 是 | 融资本金 |
| 质押率 | Decimal(5,2) | 是 | 当前质押率 |

#### 5.6.4 仓单与货物联动规则（服务端需求）

### 6.2 3C电子监控规则

#### 6.2.1 新品发布监控机制

**数据来源**：
- 品牌官网发布日历（苹果、华为、小米等主流品牌）
- 核心企业推送（核心企业提前获知供应商发布计划）
- 行业资讯平台（中关村在线、IT之家等）

**监控规则**：

| 阶段 | 触发条件 | 系统动作 |
|-----|---------|---------|
| 发布前30天 | 系统识别到某型号新品即将发布 | 1.下调该型号旧款质押率上限10%<br>2.批量重算所有相关业务质押率<br>3.超标业务自动生成预警<br>4.推送客户补充质押物或还款通知 |
| 发布前7天 | — | 加强价格监控频率（每日→每4小时） |
| 发布后 | 新品正式上市 | 1.观察7天价格走势<br>2.旧款价格稳定后恢复正常质押率上限 |

**客户通知示例**：
```
"您质押的iPhone15 Pro受新品发布影响，质押率上限已从70%调整为60%，
当前质押率62%，已超标。请在3个工作日内选择以下方式处理：
方案A：补充质押物约8万元，使质押率降至55%以下
方案B：部分还款约5万元，使质押率降至55%以下"
```

#### 6.2.2 促销季监控机制

**监控周期**：双11、618、品牌大促等。

**执行流程**：

| 阶段 | 系统动作 |
|-----|---------|
| 促销季前15天 | 1.系统自动下调质押率上限（3C下调5%）<br>2.批量重算所有3C业务质押率<br>3.超标业务自动生成预警<br>4.推送客户补充质押物或还款通知 |
| 促销季期间 | 1.价格监控频率提高至每4小时<br>2.价格跌幅>5%立即预警<br>3.暂停高价值单品（>10万）新增入库 |
| 促销季结束后 | 1.观察7天价格走势<br>2.价格稳定后恢复正常质押率上限<br>3.解除入库限制 |

### 6.3 白酒串货监控

**数据来源**：
- 核心企业推送（经销商跨区销售数据）
- 扫码溯源系统（产品流向追踪）
- 平台出库记录（出库区域与销售区域比对）

**监控规则**：

| 指标 | 阈值 | 预警等级 |
|-----|------|---------|
| 跨区销售比例 | >10% | 超标预警（红色） |

**处置流程**：

```
触发：核心企业推送"XX经销商跨区串货"

执行流程：
1. 系统立即冻结该客户新增融资
2. 系统自动关联该客户所有在途业务
3. 推送紧急预警给风控人员
4. 风控人员2小时内联系核心企业了解详情：
   - 串货数量、金额、流向区域
   - 核心企业处置意见（停止供货？扣除保证金？）
5. 根据核心企业反馈决定平台处置：
   - 轻微（金额<5万）：警告 + 保持冻结30天
   - 严重（金额>5万）：要求提前还款 + 降低授信额度
   - 恶意（屡次发生）：终止合作 + 启动货物处置
```

### 6.4 食品保质期监控

**入库规则**：

| 条件 | 规则 |
|-----|------|
| 剩余保质期比例 | 必须 > 2/3（即入库时保质期已消耗<1/3） |
| 不满足条件 | 系统拒绝入库，通知客户更换货物 |

**在库监控规则**：

| 剩余保质期 | 系统动作 |
|-----------|---------|
| <90天 | 质押率上限降低（从75%降至50%） |
| <60天 | 启动处置流程，发送出库或还款通知 |
| <30天 | 强制出库或平台协助处置 |

**处置流程示例**：
```
触发：某食品质押物剩余保质期58天

执行流程：
1. 系统自动将该批货物质押率上限从75%降至50%
2. 重算质押率（如原58% → 新相对质押率116%，超标）
3. 发送通知：
   "您质押的XX食品剩余保质期58天，质押率上限已调整为50%，
   当前质押率58%，已超标。请在5个工作日内处置：
   方案A：申请出库销售（推荐）
   方案B：部分还款使质押率降至45%以下
   方案C：平台协助处置（回收率约60-70%）"
4. 客户响应：
   - 申请出库 → 加急审批（当日完成）
   - 部分还款 → 质押率恢复 → 继续监控
   - 平台处置 → 联系处置渠道 → 回款抵扣本金
```

### 6.5 补充质押物管理制度

**触发条件**：
- 货值下跌导致相对质押率超过100%（即超过品类上限）
- 客户主动申请增加融资额度
- 部分出库后相对质押率接近100%

**补充流程**：

```
系统发出补充质押物通知
    │
    ▼
客户在[3]个工作日内响应（待运营确认具体天数）
    │
    ▼
选择处置方式：
    │    │
    │    ├── 1) 补充质押物 → 新货物入库 → 重新评估货值
    │    ├── 2) 部分还款 → 降低本金 → 质押率恢复正常
    │    └── 3) 无法补充 → 进入风险处置流程
```

## 十、风控

### 10.1 风险识别

| 风险类型 | 风险描述 | 发生场景 |
|---------|---------|---------|
| 货值下跌风险 | 市场价格下跌导致质押率超标 | 3C新品发布、促销季、市场波动 |
| 未经审批出库风险 | 仓储方未经平台审批直接放货 | 仓储方操作失误或恶意行为 |
| 出库数量不符风险 | 实际出库与审批数量不一致 | 仓储方操作失误 |
| 虚假入库风险 | 实际货物与申报不一致 | 企业欺诈、仓储方配合造假 |
| 串货风险 | 经销商跨区域销售 | 白酒等渠道管控严格品类 |
| 保质期风险 | 食品临期导致货值贬值 | 食品品类 |
| 价格数据异常风险 | 数据源价格异常导致货值计算错误 | 数据源故障、反爬机制变化 |
| 系统对接风险 | WMS/银行接口故障导致数据不同步 | 第三方系统故障 |

### 10.2 风控措施

| 风险 | 防控措施 |
|-----|---------|
| 货值下跌 | 7×24小时价格监控；分级预警+自动冻结；品类差异化质押率；新品发布/促销季动态调整 |
| 未经审批出库 | WMS实时同步+自动比对；异常出库15分钟内预警；自动冻结仓库出库权限；仓储方责任追溯 |
| 出库数量不符 | 出库后WMS反馈比对；差异超±5%自动预警；暂停后续出库 |
| 虚假入库 | 入库自动比对（品类/数量/仓库/时间）；远程照片核验；异常暂停放款 |
| 串货 | 核心企业推送+扫码溯源；跨区销售比例>10%预警；自动冻结融资 |
| 保质期 | 入库门槛（剩余>2/3）；临期自动降低质押率；<60天启动处置 |
| 价格数据异常 | 单日波动>10%人工复核；多渠道价差>15%取低值；核心企业报价偏离度校验 |
| 系统对接故障 | 重试机制+备用通道；日终对账确保一致性；异常自动告警 |
