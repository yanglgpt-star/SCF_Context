## 三、需求背景

### 3.1 问题现状

#### 3.1.1 用户/业务侧

1. **审批效率瓶颈**：业务量从月均200笔增长至500笔，但审批人员未增加。缺乏分级授权机制，所有业务都需人工审批，审批时效从1天延长至2.5天，审批积压严重，客户频繁询问进度。
2. **申请一次通过率低**：缺乏标准化的申请资料清单和填报规范，约40%申请因资料不完整需补充，平均沟通2-3轮，申请一次通过率仅60%。
3. **放款/还款数据协同差**：银行出库授权通过邮件或传真发送，信息传递慢且易出错；放款、还款数据需手工录入和对账，每日耗时2-4小时，信息同步滞后0.5-1天，放款成功率仅93%。
4. **缺乏全局业务视图**：缺乏各环节审批时效、积压量、一次通过率等运营效率数据的实时穿透分析，资产周转率从6.5次/年下降至5.2次/年，平均融资周期从50天延长至70天，3个月后才发现瓶颈在审批环节。

#### 3.1.2 系统侧

1. **审批系统分散**：审批需在多系统间切换查询（客户信息、授信额度、在途业务、质押物等），无集成化审批工作台。
2. **缺乏自动化校验**：申请表单缺乏前置校验，资料不完整无法自动拦截；审批流程无法根据业务风险智能匹配。
3. **银行对接缺失**：放款、还款、出库授权数据未与银行系统打通，全部依赖手工操作。
4. **缺乏业务看板**：无实时监控看板，管理层无法及时定位流程瓶颈。

#### 3.1.3 竞品对比

| 维度 | 本平台现状 | 京东供应链金融 | 平安银行存货融资 |
|------|-----------|--------------|----------------|
| 小额快速审批 | 无，全部人工 | 有，≤30万快速通道 | 有，≤100万标准流程 |
| 审批时效 | 2.5天 | 约0.5天 | 约1天 |
| 银行对接 | 手工对账 | 系统直连 | 系统直连 |
| 一次通过率 | 60% | 约85% | 约80% |

### 3.2 需求目标

1. **审批时效**：从2.5天缩短至1天以内，A级客户30万以下申请4小时内完成。
2. **申请一次通过率**：从60%提升至80%以上。
3. **放款成功率**：从93%提升至98%。
4. **资产周转率**：从5.2次/年恢复至6.5次/年。
5. **银行对账时效**：从2-4小时缩短至30分钟。
6. **审批通过后逾期率**：从3.2%降至1.5%。

## 五、需求详情

### 5.1 审批流转（重点功能）

#### 5.1.1 功能概述

提供可配置的审批流程引擎，支持多级审批、并行审批、会签等多种模式。系统根据融资金额、客户等级、核心企业风险标注等条件智能匹配差异化审批流程。审批页面采用集成化设计，所有决策信息在一页展示，支持一键审批。

#### 5.1.2 后台/运营需求

#### 5.1.3 服务端需求

**5.1.3.1 智能流程匹配**

系统根据以下规则自动匹配审批流程：

```
IF 融资金额 ≤ 30万 AND 客户等级 = A级 THEN
  流程 = "初审 → 终审"（2级）
ELSE IF 融资金额 ≤ 100万 THEN
  流程 = "初审 → 风控审批 → 终审"（3级）
ELSE IF 融资金额 > 100万 OR 核心企业标注风险 THEN
  流程 = "初审 → 实地核查 → 风控审批 → 高管审批 → 终审"（5级）
END IF
```

**快速通道（2级审批）适用条件详解：**
- 融资金额≤30万
- 客户等级为A级
- 历史数据显示：A级客户30万以下融资逾期率仅0.8%，显著低于整体平均水平2.5%
- 30万约为A级经销商平均单笔融资额（28.6万）的105%，覆盖其80%以上的融资需求

**标准流程（3级审批）适用条件详解：**
- 融资金额≤100万（不满足快速通道条件）
- 100万是中小经销商单笔融资的常见上限，覆盖约85%的融资申请
- 行业对标：京东供应链金融、平安银行存货融资的标准审批流程上限均在80-120万区间

**加强流程（5级审批）适用条件详解：**
- 融资金额>100万
- 或核心企业标注风险
- 100万以上融资占比约15%，但金额占比达40%，单笔风险敞口大
- 历史数据显示，100万以上融资逾期率为3.2%，高于整体平均水平

**5.1.3.2 综合风险评分模型**

评分维度及权重：

| 维度 | 权重 | 具体指标 | 数据来源 |
|------|------|----------|----------|
| 客户资质 | 20% | 征信评级、经营年限、注册资本 | 征信系统/客户档案 |
| 核心企业背书 | 25% | 推荐等级、推荐质量、经销商信用评级 | 核心企业接口/客户档案 |
| 历史表现 | 25% | 历史融资笔数、累计金额、逾期率 | 平台历史数据 |
| 质押物评估 | 20% | 品类风险、质押率、货值稳定性 | 货权管理模块 |
| 市场风险 | 10% | 品类价格波动率、新品发布周期 | 市场价格数据源 |

评分计算公式（示例）：

```
综合风险评分 = 
  客户资质得分 × 20% + 
  核心企业背书得分 × 25% + 
  历史表现得分 × 25% + 
  质押物评估得分 × 20% + 
  市场风险得分 × 10%
```

各子维度得分由业务规则引擎根据具体指标计算，满分100分。

**评分结果及系统建议：**

| 分数区间 | 风险等级 | 系统建议 | 审批通道 |
|----------|----------|----------|----------|
| 85-100分 | 低风险 | 建议通过，可适用快速审批通道 | 快速通道/标准流程 |
| 70-84分 | 中风险 | 建议通过，需审批人确认风险点 | 标准流程 |
| 60-69分 | 较高风险 | 建议谨慎，需上级复核 | 加强流程 |
| <60分 | 高风险 | 建议驳回，如需通过须风控总监审批 | 加强流程+特批 |

**5.1.3.3 核心企业数据联动**

申请提交时系统自动执行：
1. 从核心企业获取经销商最新信用评级、近期供货情况
2. 若核心企业标注风险（串货、销售下滑、付款异常等），自动触发加强审批流程
3. 审批页面突出展示核心企业评价，作为重要决策依据
4. 核心企业信息占决策权重约40%（历史数据显示，S级核心企业推荐的A+经销商逾期率仅0.8%，而C级核心企业推荐的B级经销商逾期率达6.2%）

**5.1.3.4 智能分配规则**

系统根据以下条件自动分配审批人：
1. 审批人员的业务负载（当前待办数量）
2. 专业领域匹配（按品类归属/按客户归属/按核心企业归属，待运营确认具体策略）
3. 支持轮询、按客户归属、按品类归属等多种分配策略（待运营确认优先级）

**5.1.3.5 审批状态流转**

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| 待初审 | 系统校验通过后进入初审队列 | 自动校验全部通过 |
| 初审中 | 初审员已认领/系统分配 | 自动分配或人工认领 |
| 初审通过 | 初审员审批通过 | 初审员点击"通过" |
| 初审驳回 | 初审员审批驳回 | 初审员点击"驳回" |
| 待实地核查 | 加强流程需实地核查 | 初审通过后触发 |
| 待风控审批 | 需风控专员复核 | 初审/实地核查通过后触发 |
| 待高管审批 | 加强流程需高管审批 | 风控审批通过后触发 |
| 待终审 | 进入终审节点 | 前置节点全部通过 |
| 终审通过 | 终审员审批通过 | 终审员点击"通过" |
| 终审驳回 | 终审员审批驳回 | 终审员点击"驳回" |
| 审批完成 | 放款申请已生成 | 终审通过后自动生成 |

**异常处理：**
- 超时未审批：系统自动升级给上级，同时通知原审批人和上级，记录超时情况纳入绩效考核
- 审批人离职/请假：系统自动转交给同角色其他人员，待办任务不丢失
- 核心企业预警在审批过程中到达：系统实时推送，当前审批页面红色高亮提示，如为快速通道业务则自动阻断自动审批转人工

| 逾期金额 | SUM(逾期未还本金) | 全部 |
| 逾期率 | 逾期金额 ÷ 在途融资金额 × 100% | 全部 |
| 资产周转率 | 年度累计放款金额 ÷ 平均在途余额 | 决策层 |

#### 5.3.3 服务端需求

**5.3.3.1 自动校验规则**

系统对每笔融资申请执行以下自动校验：

```
校验项：
✓ 申请金额 ≤ 可用授信额度
✓ 质押物货值 × 质押率 ≥ 申请金额
✓ 质押物品类 = 客户主营品类
✓ 客户状态 = "正常"（非冻结/预警）
✓ 客户证照在有效期内
✓ 无未结清的逾期业务

不通过校验 → 自动驳回 + 说明原因
```

**校验失败处理：**
- 任一校验不通过，系统立即驳回申请
- 向企业端返回具体不通过原因（如"可用授信额度不足，当前可用XX万"）
- 向客户经理推送通知
- 记录校验日志

**5.3.3.2 申请状态流转**

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| 草稿 | 企业暂存未提交 | 企业保存草稿 |
| 待校验 | 已提交待系统校验 | 企业点击提交 |

| 校验通过 | 系统校验全部通过 | 全部校验规则通过 |
| 校验驳回 | 系统校验未通过 | 任一校验规则不通过 |
| 待审批 | 进入审批流程 | 校验通过后自动触发 |
| 审批中 | 审批流程进行中 | 进入首个审批节点 |
| 审批通过 | 终审通过 | 终审节点通过 |
| 审批驳回 | 任一节点驳回 | 任一审批节点驳回 |
| 放款中 | 放款指令已发送 | 终审通过后自动生成放款申请 |
| 放款成功 | 银行反馈放款成功 | 银行接口返回成功 |
| 放款失败 | 银行反馈放款失败 | 银行接口返回失败 |

```
  3. 按账户匹配

匹配结果：

  - 匹配失败：自动标注异常，推送待办给财务人员
```

### 5.5 还款管理

#### 5.5.1 功能概述

支持还款计划的自动生成和维护、还款提醒的自动发送、还款数据的实时记录和对账。到期前3天自动提醒，到期当天自动检查还款状态，未还款则标记逾期并触发贷后管理流程。

|--------|----------|------|

| 还款日规则 | 枚举 | 固定日/放款日对应日/月末 |
| 宽限期 | 数字（天） | 到期后宽限天数（待运营确认，如0天或3天） |
| 逾期利率 | 百分比 | 逾期后适用的利率（待运营确认） |

**5.5.2.2 提醒规则配置**

| 提醒节点 | 提醒方式 | 提醒对象 | 内容模板 |
|----------|----------|----------|----------|
| 到期前3天 | 短信+系统消息 | 企业联系人 | 提醒即将到期，需准备还款资金 |
| 到期前1天 | 短信+系统消息 | 企业联系人+客户经理 | 提醒次日到期 |
| 到期当天（未还） | 短信+系统消息 | 企业联系人+客户经理+风控 | 通知已逾期，需立即还款 |
| 逾期3天 | 短信+系统消息 | 企业联系人+客户经理+催收员 | 催收提醒 |

#### 5.5.3 服务端需求

**5.5.3.1 还款计划生成规则**

系统根据融资业务数据自动生成还款计划：

```
输入：
  - 融资本金
  - 融资期限（天）
  - 利率（年化）
  - 计息方式（待运营确认）
  - 放款日期

输出：
  - 还款计划表（期数/应还日期/应还本金/应还利息/应还总额）
  - 总利息
  - 到期日
```

**待运营确认：具体计息方式和还款计划计算公式**

**5.5.3.2 自动提醒机制**

```
还款到期前3天：
→ 发送短信提醒给企业
→ 推送提醒给客户经理

还款到期当天：
→ 系统自动检查还款状态
→ 若未还款 → 标记"逾期"
→ 自动触发贷后管理流程
→ 通知风控部门和客户经理
→ 冻结客户新增融资
```

**5.5.3.3 还款数据接收与对账**

还款数据来源：
1. 银行接口自动推送（主推方式）
2. 企业端主动确认还款（辅助方式，需财务复核）
3. 财务手工录入（兜底方式）

自动对账规则：
```
平台还款计划 vs 银行流水：
  按金额匹配（±0.01元）
  按日期匹配（±1天）
  按业务编号匹配（银行备注中包含业务编号时）

匹配成功：
  更新还款计划状态为"已还"
  更新业务在途余额
  如为最后一期，更新业务状态为"已结清"

匹配失败：
  标注异常，推送财务人员待办
```

**5.5.3.4 逾期处理规则**

| 逾期天数 | 等级 | 系统动作 |
|----------|------|----------|
| 1-3天 | M0 | 自动短信+IVR提醒；每日1次 |
| 4-15天 | M1 | 自动生成催收任务，分配给初级催收员；每2天1次电话 |
| 16-30天 | M2 | 升级高级催收员；自动推送核心企业协同催收 |
| 31-90天 | M3 | 催收经理介入；同步启动货物处置评估；法律诉讼准备 |
| >90天 | M4 | 法务部接管；资产核销评估 |

**核心企业协同催收触发条件：**
```
IF (逾期天数 ≥ 15天 OR 逾期金额 ≥ 30万) THEN
  自动推送核心企业协同催收

IF (客户等级 = A级 AND 逾期天数 ≥ 7天) THEN
  建议推送（需人工确认）

IF (核心企业推荐时承诺协同催收) THEN
  任何逾期立即推送

IF (核心企业标注为重点客户) THEN
  逾期3天推送（给核心企业留充足时间）
END IF
```

## 九、风控

### 9.1 涉及资金变动的风控

1. **放款指令双重确认**：
   - 系统生成放款申请后，需财务人员在页面人工确认收款账户和金额
   - 放款金额必须与审批通过的金额一致（如不一致需说明原因，待运营确认修改权限）
   - 放款指令发送前需二次确认（弹窗确认）

2. **放款指令幂等控制**：
   - 同一笔业务只允许发送一次放款指令（除非前次明确失败）
   - 系统记录指令流水号，银行返回结果与流水号绑定

3. **还款到账核验**：
   - 优先以银行流水为准，企业端主动确认的还款需财务复核
   - 还款金额与应还金额差异>0.01元时标记异常

### 9.2 涉及用户隐私的风控

1. 客户征信数据、银行账户信息加密存储
2. 审批页面敏感信息脱敏展示（如银行账户中间位隐藏）
3. 核心企业推送的经销商数据仅限审批相关角色查看

### 9.3 重复申请/操作防护

1. **重复申请拦截**：同一客户同一自然日内提交相同金额、相同品类的融资申请，系统提示"您已提交相似申请，请勿重复提交"
2. **重复放款拦截**：同一笔业务终审通过后只能生成一笔放款申请，状态为"放款成功"后禁止再次发起
3. **重复审批拦截**：同一审批节点同一审批人只能审批一次，审批后按钮置灰

### 9.4 日志留存要求

1. 所有审批操作（通过/驳回/退回/转交）必须记录完整日志：操作人、操作时间、操作内容、审批意见
2. 所有放款指令发送记录永久留存：指令内容、发送时间、银行返回结果
3. 所有还款记录永久留存：还款时间、还款金额、还款来源
4. 所有核心企业数据交互记录留存至少5年
5. 日志不可删除、不可修改，支持审计追溯

## 十、非功能性需求

### 10.1 性能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 页面加载时间 | ≤3秒 | 集成化审批页完整加载 |
| 列表查询响应 | ≤2秒 | 待办列表、申请列表查询 |
| 自动校验响应 | ≤1秒 | 融资申请自动校验完成 |
| 看板数据刷新 | ≤5秒 | 看板数据更新延迟 |
| 银行接口超时 | ≤30秒 | 银行接口调用超时时间 |
| 并发申请支持 | ≥100笔/分钟 | 高峰期申请提交并发 |
| 报表生成 | ≤30秒 | 月度报表导出 |

### 10.2 安全需求

1. **数据传输安全**：与银行、核心企业的接口通信采用HTTPS/TLS加密传输
2. **数据存储安全**：敏感数据（银行账户、征信信息）采用AES-256加密存储
3. **访问控制**：基于角色的权限控制（RBAC），审批操作需登录态验证
4. **操作审计**：关键操作（审批、放款确认）记录操作人、时间、IP地址
5. **防重放攻击**：银行接口、核心企业接口需实现请求签名和时效校验

### 10.3 可用性需求

1. **系统可用性**：核心业务系统可用性≥99.9%（年停机时间<8.76小时）
2. **故障降级**：银行接口故障时，支持人工录入作为兜底，业务不中断
3. **数据备份**：核心业务数据每日全量备份，保留30天
4. **灾难恢复**：RPO≤1小时，RTO≤4小时

### 10.4 兼容性需求

1. **浏览器兼容**：支持Chrome、Firefox、Safari、Edge最新两个主版本
2. **企业端兼容**：支持PC端和H5移动端（待确认是否需独立APP）

### 10.5 可扩展性需求

1. **审批流程配置化**：新增审批节点、调整流程分支无需改代码
2. **评分模型可配置**：评分维度权重可通过配置调整（需管理员权限）
3. **银行接口可扩展**：新增合作银行时，只需配置接口参数，无需修改核心代码
