# PRD精简_风险监控

## 一、背景与目标

### 1.1 为什么做

- **业务侧**：风险识别依赖人工查看报表，监控频率低，约30%风险未被及时识别；响应时效平均8小时，错过最佳处置时机；处置经验未沉淀，新员工培训成本高。
- **系统侧**：
  - 风险数据分散在不同系统，缺乏统一视图
  - 预警规则固化在代码中，调整需提IT需求
  - 品类差异化缺失，25%品类风险未及时发现
  - 核心企业信息延迟1-3天，串货发现时平台已新增放款50万
- **执行层**：每天手工查看多报表逐项检查异常，预警信息不穿透，通知渠道单一，处置记录繁琐。

### 1.2 目标指标

| 目标指标 | 当前值 | 目标值 | 衡量方式 |
|---------|--------|--------|---------|
| 风险识别覆盖率 | 70% | ≥90% | 系统成功识别的风险事件 ÷ 实际风险事件总数 |
| 预警准确率 | 60% | ≥80% | 有效预警数 ÷ 总预警数 |
| 预警响应时效 | 平均8小时 | ≤4小时 | 预警触发到责任人首次处理的时间 |
| 核心企业预警响应率 | 约60% | 100% | 规定时间内响应的核心企业预警 ÷ 总推送数 |
| 品类风险预警及时率 | 75% | ≥95% | 品类特有风险在规定时间内被预警的比例 |

### 1.3 业务价值目标

- 建立统一风险监控工作台，实现7×24小时自动监控
- 建立品类差异化监控规则和核心企业风险联动机制，推动风险识别覆盖率从70%提升至90%
- 通过可配置的风控规则引擎，实现预警规则快速调整，响应周期从"提IT需求"缩短至"运营自助配置"
- 通过多渠道预警推送和移动端支持，确保责任人随时随地接收和处理预警

## 二、范围决策

### 2.1 本期做（P0-P2）

| 优先级 | 模块 | 内容 |
|-------|------|------|
| P0 | 实时预警（含分层预警机制） | 多维度数据整合、分层预警（4级）、来源分类处理、优先级排序 |
| P0 | 风控规则配置（含品类差异化模板） | 可视化规则配置（CRUD/22字段）、品类差异化模板、阈值分层、规则热加载 |
| P1 | 风控看板 | 风险概览、分布、趋势、TOP排行、地图 |
| P1 | 预警处理 | 接收、分配、调查、处置、关闭（7状态流转），知识库沉淀 |
| P1 | 风险指标监控 | 客户/业务/质押物/市场/渠道风险指标实时监控和趋势分析 |
| P1 | 核心企业风险联动 | 推送接收（8字段）、协同处置请求推送、激励机制 |
| P1 | 分级响应与升级机制 | 超时升级、高风险升级、响应时效矩阵 |
| P2 | 报表与埋点 | 风险统计报表、处置效率报表、核心操作埋点 |
| P2 | 风险知识库 | 案例沉淀、方案库、识别模型（仅预留接口） |

### 2.2 本期不做（延后）

| 事项 | 原因 | 计划处理方式 |
|-----|------|------------|
| 机器学习风险预测模型 | 需积累历史预警处置数据后方可训练 | 本期仅预留数据接口和模型接入框架，模型训练延后 |
| 区块链存证（风险事件） | 原始素材在仓单管理中提及区块链，风险事件区块链存证延后 | 延后 |
| 移动端独立APP | 本期仅支持H5/小程序适配的移动端页面 | 延后 |
| 外部征信系统直连（人行征信等） | 客户涉诉信息、经营异常等通过第三方数据服务商接入 | 延后 |
| 智能客服/机器人处置 | 预警处置仍需人工介入 | 延后 |

## 三、关键决策记录

| 决策 | 内容 | 原因 |
|-----|------|------|
| 【决策】预警四级分层 | 紧急(>115%/立即响应)、超标(100-115%/4小时)、警戒(85-100%/24小时)、正常(≤85%) | 基于相对质押率统一度量跨品类风险，已确认 |
| 【决策】预警来源优先级 | 级别优先→来源优先（核心企业>业务>客户>质押物）→金额降序→时间升序 | 原始素材定义，核心企业推送风险最高 |
| 【决策】阈值覆盖优先级 | 客户级 > 核心企业级 > 品类级 > 全局默认级 | 精细化风控，高信用客户可适度放宽 |
| 【决策】规则引擎热加载 | 规则变更无需重启服务即可生效 | 运营自助配置，快速响应市场变化 |
| 【决策】模块边界划分（风险监控↔贷后） | M0-M1早期提醒由风险监控负责，M2-M4催收执行由贷后管理负责 | M1第7天自动升级为紧急预警并触发协同催收 |
| 【决策】核心企业推送协议 | HTTPS RESTful API + JSON + OAuth 2.0，8个标准接口 | 《通用方案》第一章已确认 |
| 【决策】跨模块联动接口 | 冻结融资POST /api/risk/freeze/financing、冻结出库POST /api/risk/freeze/outbound等6个 | 内部模块间调用采用HTTPS+JSON+服务间认证Token |
| 【决策】冻结/解冻双重确认 | 冻结需二次确认，解冻需上级审批 | 资金安全，操作留痕 |
