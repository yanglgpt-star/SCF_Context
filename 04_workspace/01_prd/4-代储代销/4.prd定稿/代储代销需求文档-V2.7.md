## 一、文档概述

### 1.1 愿景及目标

#### 1.1.1 业务现状与痛点

当前供应链金融平台中，供应商面临"先货后款"的资金周转压力，传统销售模式存在以下痛点：

| 序号 | 痛点 | 说明 |
|------|------|------|
| 1 | 资金占用 | 供应商货物入库后需等待销售回款，资金周转周期长 |
| 2 | 货物监管难 | 缺乏从入库到出库的全流程货物监管手段 |
| 3 | 销售渠道窄 | 供应商缺乏高效的分销渠道，销售效率低 |
| 4 | 结算复杂 | 多方参与（供应商、平台、采购商、仓储方）的清分结算繁琐 |
| 5 | 协同效率低 | 供应商、采购商、平台、仓储方之间缺乏高效的业务协同工具 |

#### 1.1.2 系统建设目标

构建代储代销业务系统，为供应商提供"先入库、后销售"的供应链金融服务，实现以下目标：

| 目标 | 说明 |
|------|------|
| 资金提前回笼 | 通过支付履约保证金（最高70%），帮助供应商在销售前获得资金支持 |
| 货物全程监管 | 从入库到出库的全流程货物监管，降低平台风险 |
| 平台挂牌销售 | 支持定向销售模式，对接市场助手等销售渠道 |
| 自动清分结算 | 销售完成后自动按比例扣回保证金、服务费、仓储费 |
| 多方业务协同 | 供应商、采购商、平台（金融助手）、仓储方多方协同 |

#### 1.1.3 涉众分析

| 角色 | 期望与利益 | 优先级 |
|------|-----------|--------|
| 供应商（无仓平台） | 快速获得资金支持，货物安全监管，高效销售回款 | P0 |
| 采购商（市场助手） | 通过平台购买代储代销货物，确保货源质量和交付 | P0 |
| 金融助手 | 管理代储代销全流程业务，控制风险，获取服务费收入 | P0 |
| 仓储方 | 提供货物仓储服务，执行入库出库操作 | P1 |

#### 2.1.2 核心业务流程闭环

1. **准入阶段**：供应商提交申请 → 平台审核定价 → 生成代储订单
2. **入库阶段**：仓库实物验收 → 生成入库清单 → 金融助手生成电子仓单
3. **融资阶段**：金融助手确认入库 → 支付保证金（70%）至供应商平安钱包
4. **销售阶段**：金融助手在代储订单管理中创建定向销售订单 → 采购商下单支付
5. **履约阶段**：货款到账 → 发布出库指令 → 仓库发货 → 自动分账结算

#### 3.1.5 事件流 - 主要路径

| 步骤 | 角色+操作 | 系统响应 |
|------|----------|---------|
| 1 | 审核员点击"审核"按钮 | 系统打开审核定价弹窗（1200px宽） |
| 2 | 系统 | 加载申请信息：申请编号、批次编号、供应商、申请时间 |
| 3 | 系统 | 加载货物明细：品牌、商品、SKU、SKU编码、数量、申请单价、申请总价、行情单价、行情总价、评估单价（默认等于行情单价）、评估总价 |
| 4 | 系统 | 加载终审定价区域：货物总评估价（只读）、保证金比例（默认70%）、保证金金额（自动计算）、服务费率、评估有效期、入库仓库、仓储费、出资类型、业务归属人、审核意见 |
| 5 | 审核员 | 调整评估单价（如有必要），系统实时重新计算评估总价和货物总评估价 |
| 6 | 审核员 | 填写终审定价信息，输入审核意见 |
| 7 | 审核员 | 点击"审核通过"按钮 |
| 8 | 系统 | 校验所有必填字段和业务规则，通过后更新申请状态为"已通过"，自动生成代储订单（订单编号规则：DC+年月日+4位流水号）和批次编号（DCPC+年月日+4位流水号） |
| 9 | 系统 | 弹出审核通过提示，关闭弹窗 |

#### 3.1.6 事件流 - 替代路径

| 步骤 | 触发条件 | 操作 | 系统响应 |
|------|---------|------|---------|
| 2.1 | 审核员认为需修改 | 点击"驳回修改" | 更新状态为"已驳回"，供应商可重新编辑后提交 |
| 2.2 | 审核员认为不合格 | 点击"拒绝" | 更新状态为"已拒绝"，流程终止 |
| 5.1 | 评估单价超出范围 | 输入低于成本价或高于行情单价 | 前端标红提示，后端校验拦截 |

#### 3.1.7 业务规则

| 编号 | 规则 | 说明 |
|------|------|------|
| R-AUDIT-001 | 评估单价限制 | 上限：不高于行情单价；下限：不低于成本价（从采购系统获取，字段名：cost_price） |
| R-AUDIT-002 | 评估单价联动 | 修改评估单价后实时计算：评估总价=评估单价×数量；货物总评估价=∑所有货物评估总价（自动汇总，不可人工修改） |
| R-AUDIT-003 | 保证金比例 | 默认70%，最高不超过70%，修改后重新计算保证金金额 |
| R-AUDIT-004 | 保证金金额 | 保证金金额=货物总评估价×保证金比例（自动计算，只读） |
| R-AUDIT-005 | 行情单价来源 | 优先级：运营助手市场行情价 > 无仓行情价 > 空缺 |
| R-AUDIT-006 | 评估有效期 | 必须≥当前日期，过期后需重新评估定价 |
| R-AUDIT-007 | 审核页面必填项 | 所有终审定价字段均为必填（红色星号标记） |

#### 3.7.5 分账计算规则

| 计算项 | 公式 | 说明 |
|--------|------|------|
| 扣回保证金 | 评估总价 × 保证金比例（70%） | 按比例扣回代储保证金 |
| 服务费 | 评估总价 × 服务费率（1%） | 平台撮合服务费 |
| 仓储费 | 仓储单价 × 实际仓储天数 × 销售数量 | 10元/台/天的标准费率 |
| 供应商实收 | 销售总额 - 扣回保证金 - 服务费 - 仓储费 | 结算给供应商的最终款项 |

**分账明细表格（6行）颜色规范**：

| 行项目 | 颜色 |
|--------|------|
| 销售总额、评估总价 | 蓝色 #1890ff |
| 扣回保证金、服务费、仓储费 | 红色 #cf1322 |
| 供应商实收 | 绿色 #52c41a + 淡绿色背景 #f6ffed + 加粗 |

#### 3.7.6 触发条件

满足任一条件即触发分账：
1. 采购商点击"确认收货"
2. 物流自动签收（签收后72小时自动触发）

#### 3.7.7 分账状态流转

```
待分账 → 分账中 → 已完成
```

#### 3.7.8 接口调用

分账触发后 POST /api/settlement/split，异步处理，回调更新状态。分账失败时记录失败原因，支持人工重新分账。

#### 4.1.2 计算规则

| 计算项 | 公式 | 说明 |

| 申请总价 | 申请单价 × 数量 | 供应商申请总价值 |
| 行情总价 | 行情单价 × 数量 | 行情系统获取的实时价格总和 |

| 服务费 | 评估总价 × 服务费率（%） | 如：评估总价 × 1% |
| 仓储费 | 元/台/天 × 存储天数 × 货物数量 | 如：10元/天/台 × 5天 × 10台 |
| 供应商实收 | 销售总额 - 扣回保证金 - 服务费 - 仓储费 | 供应商最终收到金额 |

## 五、风险分析

| 风险 | 可能性 | 严重性 | 应对策略 | 可应对性 |
|------|-------|-------|---------|---------|
| 行情价格波动导致质押物减值 | 中 | 高 | 设置预警机制，当质押物市价下跌超阈值时触发预警；要求供应商补充质押物或部分还款 | 高 |
| 供应商货物质量问题 | 低 | 高 | 审核环节增加实物审核和品牌授权校验；入库时WMS核实验收 | 高 |
| 采购商逾期付款 | 中 | 中 | 信用评分机制；逾期催收流程；保证金覆盖部分风险 | 中 |
| 分账系统异常导致结算失败 | 低 | 高 | 异步处理+回调机制；失败记录+人工重新分账 | 高 |
| 平安钱包支付接口异常 | 低 | 中 | 支付状态轮询+超时重试；人工对账机制 | 中 |

|-----|------|---------|------|
