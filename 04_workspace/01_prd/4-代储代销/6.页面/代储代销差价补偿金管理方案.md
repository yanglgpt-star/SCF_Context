# 代储代销差价补偿金管理方案

> 版本：V1.0（最终确认稿）  
> 日期：2026-07-29  
> 涉及端：金融助手后台、市场助手小程序、无仓平台 PC 端、平安钱包/支付通道

## 1. 方案背景

现有代储代销流程中，平台在货物入库、仓单生效后向供应商拨付保证金。为覆盖货物价格波动及未售风险，新增“代储代销差价补偿金”能力：金融助手生成供应商应缴的差价补偿金应收单，供应商通过市场助手小程序或无仓平台 PC 端完成支付；业务结束后，根据货物处置结果执行原路退回或划转平台。

本方案中的两类资金必须严格区分：

| 资金类型 | 付款方 | 收款方 | 现有/新增 | 用途 |
|---|---|---|---|---|
| 保证金拨付 | 平台 | 供应商 | 现有 | 平台按入库货值和比例向供应商拨款 |
| 差价补偿金 | 供应商 | 平台担保账户 | 新增 | 覆盖价格波动、未售或处置风险 |

本文后续所称“补偿金”均指“代储代销差价补偿金”。

## 2. 建设目标

1. 金融助手支持人工创建补偿金应收单、人工审核/发布、收取跟踪和实收核对；本期不建设自动生成。
2. 市场助手小程序和无仓平台 PC 端向供应商提供统一的待缴账单、详情、支付和结果查询入口。
3. 企业供应商使用平安钱包余额付款；个人供应商通过银行转账进入专属临时账户，再自动归集至担保账户。
4. 货物销售完成时，将对应补偿金退回企业平安钱包或个人银行卡；货物未销售并经平台处置确认后，将对应补偿金划转至平台平安钱包。
5. 应收、支付、实收、退回/划转全链路可追溯、可对账、可审计，避免重复收款和重复退回。

## 3. 范围与角色

### 3.1 本期范围

- 金融助手新增一级菜单“保证金管理”，下设：
  - 差价补偿金应收
  - 收取记录
  - 实收信息
- 金融助手支持人工创建、人工审核、作废、催缴、支付结果跟踪、实收认领、差异处理、退款/划转处理。
- 市场助手小程序和无仓平台 PC 端增加供应商缴纳入口。
- 对接平安钱包余额支付、个人临时账户入账、担保账户归集、企业退款、个人银行卡退款和平台钱包划转结果。
- 消息通知、超期提醒、操作日志和导出。

### 3.2 暂不纳入本期

- 补偿金收益计息。
- 供应商主动部分提现。
- 多币种。
- 补偿金应收凭证/发票处理；如财务确认需要，再接入现有“票据中心”。
- 应收单自动生成、自动计算和定期重估。
- 按 SKU 或销售数量同比例部分退回补偿金。

### 3.3 角色与权限

| 角色 | 核心权限 |
|---|---|
| 业务运营 | 查看应收、手动生成、提交发布、催缴、发起退款/划转申请 |
| 财务人员 | 复核应收、实收认领、差异处理、退款/划转复核、导出对账 |
| 风控/管理员 | 配置权限和审核流程，查看全量数据 |
| 供应商（企业） | 查看本人账单、使用平安钱包余额支付、查看企业钱包退款结果 |
| 供应商（个人） | 查看本人账单、获取专属临时账户、银行转账、维护/确认退款银行卡 |

关键资金动作建议采用经办、复核分离；操作人不能复核本人发起的退款或划转。

## 4. 总体业务流程

```text
代储订单/风险事件
        │
运营人工创建并填写应收信息 → 生成应收草稿 → 提交人工审核 → 审核通过并发布待缴
                                                  │
                              ┌───────────────────┴───────────────────┐
                              │                                       │
                         企业供应商                              个人供应商
                    平安钱包余额直接支付                    银行转账至专属临时账户
                              │                                       │
                              └────────→ 进入/归集担保账户 ←──────────┘
                                                │
                                         实收匹配、核销
                                                │
                         ┌──────────────────────┴──────────────────────┐
                         │                                             │
                    对应货物已销售                               货物未销售且平台处置
                         │                                             │
             企业退平安钱包/个人退银行卡                    转入平台平安钱包
                         │                                             │
                    应收单已退回                                  应收单已划转
```

### 4.1 主流程

1. 运营在金融助手人工创建补偿金应收草稿，并手动填写相关业务及金额信息。
2. 系统校验供应商、代储订单、仓单、在库货物、已拨保证金及是否存在重复有效应收。
3. 复核通过后发布应收单，状态变为“待缴纳”，同步至市场助手和无仓平台，并通知供应商。
4. 企业供应商使用平安钱包余额直接付款；个人供应商按照账单展示的专属临时账户进行银行转账。
5. 支付通道回调后生成收取记录；资金实际进入担保账户后生成实收信息，并按账单号/附言/虚拟账号自动匹配应收单。
6. 足额到账后应收单更新为“已缴清”；部分到账为“部分缴纳”；无法自动匹配的资金进入“待认领”。
7. 关联代储订单清结算完成后，系统生成整单退款任务：企业退至原平安钱包，个人退至已核验银行卡。本期不按 SKU 或已售数量部分退回。
8. 货物未销售时不由系统自动判断或触发处置。平台工作人员在金融助手中人工发起处置，手动填写处置原因、依据和划转金额，审核通过后将对应补偿金从担保账户划转至平台平安钱包。
9. 退款或划转成功后回写应收单，完成资金闭环。

## 5. 应收单生成方案

### 5.1 应收粒度

建议“一张应收单绑定一个供应商 + 一个代储订单编码 + 一次补缴情形”。同一代储订单可以因多次业务需要生成多张应收单，但同一业务事件只能存在一张有效应收单。

本期应收单按代储订单维度管理，可记录仓单及货物说明，但不按 SKU 拆分补偿金，也不按 SKU 执行部分退款。

### 5.2 本期生成方式

本期仅支持人工创建，不建设自动生成任务、自动触发规则或定期重估。运营选择供应商及代储订单后，手动填写补偿金金额、生成原因、缴款说明等信息，提交有权审核人员审核；审核通过后才可发布给供应商。

### 5.3 金额计算

由于当前尚未明确差价补偿金的最终计算口径，本期不由系统自动计算。以下口径仅作为运营填写金额时的业务参考，不作为系统校验公式：

```text
风险覆盖目标 = 当前剩余在库数量 × 基准单价 × 目标覆盖比例
当前可覆盖金额 = 与剩余货物对应的有效保证金/已缴补偿金（按业务定义取值）
本次应收金额 = max(风险覆盖目标 - 当前可覆盖金额, 0)
```

若业务采用纯价差方式，可配置为：

```text
本次应收金额 = max(上次有效评估单价 - 最新评估单价, 0)
              × 剩余在库数量 × 补偿比例
              - 未释放的历史补偿金
```

系统仅校验金额大于 0 且保留两位小数。最终计算公式、取整方式及业务上限由业务、财务和法务另行确认。

### 5.4 手动生成

操作路径：金融助手 → 保证金管理 → 差价补偿金应收 → 新增应收单。

必填项：供应商、代储订单编码、关联仓单、货物说明、生成原因、应收金额、缴款期限。选填项：涉及数量、计算依据、参考评估单价、附件、备注。

系统自动带出供应商类型、联系方式、已拨保证金、剩余库存、历史应收/实收/未退金额。创建人手动填写应收金额和生成原因，所有应收单均必须提交人工审核，不设置免审金额。

### 5.5 防重和金额校验

- 同一业务事件唯一号只能生成一张有效应收单。
- 手工单生成时提示同一代储订单下未完结应收，不允许无说明重复补收。
- 应收金额必须大于 0，不能超过规则计算的风险敞口上限；越权调整走审批。
- 已发布且已有收款的应收单不得直接修改金额，只能通过追加应收或退款/冲销单调整。
- 作废仅限未收款账单；已有实收必须先处理退款或转入异常流程。

## 6. 金融助手后台设计

### 6.1 菜单调整

现有一级菜单“保证金拨付”建议并入新一级菜单“保证金管理”：

```text
保证金管理
├── 保证金拨付（现有）
├── 差价补偿金应收（新增）
├── 收取记录（新增）
└── 实收信息（新增）
```

这样既保留平台向供应商的拨付管理，又统一承载供应商向平台缴存的补偿金业务。

### 6.2 差价补偿金应收

#### 列表查询

查询条件：应收单号、供应商、供应商类型、代储订单编码、仓单编号、应收状态、逾期状态、创建/到期时间。

列表核心字段：

| 字段 | 说明 |
|---|---|
| 应收单号 | 建议规则：BCAR + YYYYMMDD + 4 位流水 |
| 供应商 | 企业名称或个人姓名，敏感信息脱敏 |
| 代储订单/仓单 | 可跳转现有订单及仓单详情 |
| 生成方式 | 本期固定为“人工创建” |
| 应收金额 | 本单应缴金额 |
| 已收金额/未收金额 | 由有效实收核销结果汇总 |
| 缴款期限 | 超期自动标识 |
| 应收状态 | 草稿、待复核、待缴纳、部分缴纳、已缴清等 |
| 资金处置状态 | 待处置、退款中、已退回、划转中、已划转 |
| 操作 | 详情、编辑、提交/发布、催缴、作废、退款/划转 |

详情页按“应收信息—计算依据—货物明细—收取记录—实收核销—退款/划转—操作日志”分区展示。

### 6.3 收取记录

“收取记录”记录每次支付行为和通道交互，一次应收单可以对应多次收取尝试。

核心字段：收取记录号、应收单号、供应商、支付端（小程序/PC）、付款方式、发起金额、通道流水号、支付状态、发起时间、支付完成时间、失败原因。

支付状态：待支付、处理中、支付成功、支付失败、已关闭。该状态表示支付动作结果，不等同于资金已进入担保账户。

### 6.4 实收信息

“实收信息”以银行/钱包实际入账流水为准，是财务核销和退款/划转的唯一资金依据。

核心字段：实收流水号、银行流水号、到账账户、付款户名/账号、到账金额、到账时间、匹配应收单号、核销金额、未认领金额、匹配状态、对账状态、退款/划转状态。

匹配状态：待认领、自动匹配、人工匹配、部分核销、已核销、已冲销。支持按虚拟账户、账单号、付款附言、付款人和金额组合匹配；人工认领需记录操作人和原因。

### 6.5 退款/划转处理

- 退款条件：关联代储订单已完成清结算；对应资金已实收、已核销、未退款且未划转；退款金额不得超过可退余额。
- 企业退款：优先原平安钱包原路退回；原账户异常时进入人工异常流程，不自动改付其他账户。
- 个人退款：退至供应商实名认证且已核验的银行卡；银行卡换卡后必须重新完成校验并经复核。
- 平台划转条件：由平台工作人员人工确认货物未销售并创建处置单，手动填写处置原因、依据和划转金额；处置单审核生效，且资金可用、未退款、未划转。
- 划转目标：预配置的平台平安钱包，页面展示脱敏账号；禁止经办人临时输入任意收款账户。
- 本期不支持按 SKU、已售数量或货物比例部分退款。未完成整单清结算前不触发退款。
- 本期不建设未售自动识别、自动生成处置单或自动触发平台划转。处置及异常结果均由平台人员在后台人工处理并留存操作记录。

## 7. 供应商端设计

### 7.1 市场助手小程序

推荐入口：服务 → 我的申请摘要新增“待缴补偿金”；同时在“我的/订单”区域提供“差价补偿金”入口。存在待缴账单时展示红点和待缴金额。

页面结构：

1. 补偿金账单列表：待缴纳、缴纳中、已缴清、已逾期、已退回/已划转。
2. 账单详情：应收单号、关联订单/货物、生成原因、金额计算说明、应缴/已缴/未缴、截止时间、资金去向说明、协议/附件。
3. 支付页：按供应商类型展示企业钱包支付或个人银行转账指引。
4. 结果页：支付处理中/成功/失败；个人转账显示“等待银行到账确认”，不直接提示缴纳成功。
5. 退款/处置结果：展示退款金额、退款渠道、时间和状态；平台划转时展示处置依据摘要。

### 7.2 无仓平台 PC 端

推荐在顶部“申请记录”旁新增“补偿金账单”，并在代储订单详情增加“差价补偿金”卡片及“去支付”按钮。不要复用现有“保证金拨付管理”页面，以免供应商误解资金方向。

PC 端页面字段与小程序保持一致，并增加筛选、批量导出和支付凭证下载。企业供应商可勾选多张待缴账单合并支付，但后台仍按账单逐笔分摊、核销。

### 7.3 企业支付

1. 供应商点击“立即支付”，系统校验账单有效性和未缴金额。
2. 展示应付金额、平安钱包脱敏账号和可用余额。
3. 供应商完成身份验证并确认支付。
4. 平安钱包扣减企业钱包余额，资金进入担保账户。
5. 支付回调生成成功收取记录；入账流水对账成功后生成实收并核销账单。
6. 余额不足时提示充值或稍后支付，不允许将账单误标为成功。

### 7.4 个人支付

1. 供应商点击“获取转账账户”，系统按照“一张应收单一个临时账户”原则，为该应收单返回专属临时账户/虚拟子账户及唯一附言。
2. 页面展示收款户名、开户行、账号、应转金额、附言、有效期及复制按钮。
3. 个人从本人银行卡转账至临时账户。
4. 到账后系统按虚拟账户优先匹配，随后自动归集至担保账户。
5. 临时账户到账但归集失败时，账单状态显示“到账处理中”，进入后台异常队列。
6. 少付进入“部分缴纳”；多付的超额部分进入待处理资金，不自动计入其他账单。

## 8. 状态设计

### 8.1 应收状态

| 状态 | 说明 | 可执行动作 |
|---|---|---|
| 草稿 | 已生成但未提交 | 编辑、提交、删除草稿 |
| 待复核 | 等待有权人员复核 | 通过、驳回 |
| 待缴纳 | 已发布，尚无有效实收 | 支付、催缴、作废 |
| 部分缴纳 | 实收小于应收 | 继续支付、催缴 |
| 已缴清 | 实收核销金额等于应收 | 等待退款/划转 |
| 已逾期 | 到期仍未缴清，作为附加标识 | 催缴、风险处置 |
| 已作废 | 未收款账单被取消 | 查看 |
| 已关闭 | 通过冲销等方式关闭 | 查看 |

“已逾期”建议作为待缴纳/部分缴纳上的逾期标识，而不是互斥主状态。

### 8.2 资金处置状态

```text
待处置
├── 退款申请中 → 退款中 → 已退回
└── 划转申请中 → 划转中 → 部分划转/已划转

退款中/划转中 → 处理失败 → 重新处理或人工介入
```

### 8.3 支付与实收分离

- 支付成功：平安通道确认付款动作成功。
- 已到账：银行/钱包确认资金入账。
- 已核销：到账资金已匹配到具体应收单。
- 已缴清：应收单累计有效核销金额达到应收金额。

页面不得用“支付成功”替代“已缴清”，尤其是个人银行转账场景。

## 9. 核心数据对象

| 对象 | 关键关联及用途 |
|---|---|
| 补偿金应收单 | 关联供应商、代储订单、仓单、业务事件和规则版本 |
| 应收货物信息 | 记录关联仓单、货物说明和数量，本期不按 SKU 分摊应收及退款 |
| 收取记录 | 记录端内支付尝试、支付渠道及通道结果 |
| 实收流水 | 记录真实到账、归集、匹配及核销情况 |
| 核销明细 | 建立实收流水与应收单的多对多金额关系 |
| 资金处置单 | 记录退款或平台划转申请、审批、通道及结果 |
| 规则配置 | 记录触发条件、公式参数、阈值、适用对象及版本 |
| 操作日志 | 记录生成、修改、复核、催缴、认领、退款、划转等操作 |

所有金额字段使用高精度十进制；所有通道请求需包含业务唯一号和幂等号。

## 10. 系统交互与接口建议

| 交互 | 方向 | 关键内容 |
|---|---|---|
| 应收发布同步 | 金融助手 → 供应商端 | 账单、关联订单、金额、期限、状态 |
| 钱包支付下单 | 供应商端 → 金融助手/支付网关 | 应收单号、付款方、金额、幂等号 |
| 支付结果回调 | 平安 → 金融助手 | 通道流水、状态、金额、时间、签名 |
| 临时账户分配 | 金融助手 → 平安 | 供应商、应收单号、金额、有效期 |
| 入账/归集通知 | 平安 → 金融助手 | 银行流水、临时账户、担保账户、金额 |
| 清结算结果 | 清结算中心 → 金融助手 | 代储订单、清结算状态、完成时间 |
| 退款指令 | 金融助手 → 平安 | 原交易/实收、退款账户、金额、原因 |
| 平台划转指令 | 金融助手 → 平安 | 担保账户、平台钱包、金额、处置单号 |
| 结果状态同步 | 金融助手 → 供应商端 | 缴纳、退款、划转及失败状态 |

接口须验签、防重放、幂等；回调先落原始报文再处理。通道超时按“处理中”处理，通过主动查询确认最终状态，不可直接判失败并重复发起。

## 11. 对账与异常处理

### 11.1 日常对账

- 每日对平安钱包支付订单、临时账户入账、担保账户流水、退款流水和平台划转流水。
- 对账维度：业务单号、通道流水号、付款人、收款账户、金额、时间、状态。
- 差异类型：平台单边、通道单边、金额不一致、状态不一致、重复流水、到账未匹配。
- 差异进入实收信息异常队列，处理完成保留前后值和凭证。

### 11.2 重点异常

| 异常 | 处理建议 |
|---|---|
| 企业钱包余额不足 | 支付失败，不锁死账单，允许重新支付 |
| 重复点击支付 | 幂等号拦截，仅保留一个有效支付请求 |
| 个人少付 | 部分核销，保留未缴余额 |
| 个人多付 | 应收额内核销，超额进入待处理，不跨单自动抵扣 |
| 个人付款人不一致 | 进入待认领/合规复核 |
| 临时账户过期后到账 | 入账挂账，人工确认后认领或退回 |
| 回调丢失 | 定时主动查询并补偿处理 |
| 归集失败 | 保持“到账处理中”，自动重试并告警 |
| 退款失败 | 不减少可退余额，查明原因后使用原任务重试 |
| 销售与处置情况并存 | 本期不自动按货物数量拆分，由平台人员进入人工处置流程 |

## 12. 通知与催缴

- 应收发布：站内信/小程序订阅消息/短信（按现有能力）。
- 到期提醒：建议到期前 3 天、前 1 天、到期日提醒。
- 逾期提醒：到期后每日或按配置提醒，并同步金融助手待办。
- 支付到账、缴清、退款成功、划转完成和异常失败均通知供应商。
- 通知内容包含账单号、金额、期限/结果，不展示完整银行卡号或钱包账号。

## 13. 安全、合规与审计

- 担保账户、临时账户、平台钱包及退款卡必须由受控账户库选择，页面脱敏展示。
- 支付、退款、划转前进行登录态、供应商身份、账单归属、金额和状态校验。
- 企业支付需平安钱包侧完成授权/验证；个人退款银行卡需实名认证和一致性校验。
- 退款、平台划转、人工认领、金额调整均记录不可篡改的操作日志。
- 个人姓名、银行卡号、手机号按最小权限展示和加密存储。
- 差价补偿金的法律性质、担保账户监管方式、未售货物处置及资金划转授权，需在代储代销服务协议中明确并经法务确认。
- 供应商企业/个人身份由其他业务系统判定并同步，本系统使用该结果选择支付及退款路径，不提供人工修改入口。
- 本方案所称担保账户，是平台在平安体系下开立的担保账户；与平台日常平安钱包分账管理。

## 15. 验收要点

1. 人工创建应收单时能发现并提示潜在重复，且未经人工审核不得发布。
2. 企业钱包支付成功后，收取记录、实收流水和应收核销状态正确且可追溯。
3. 个人转账到账、归集、自动匹配成功；少付、多付、付款人不一致可正确处理。
4. 支付成功但尚未实收入账时，账单不得提前标记为已缴清。
5. 同一实收金额不能重复核销、重复退款或同时退款和划转。
6. 只有代储订单清结算完成后才允许整单退款；本期不能按 SKU 或已售数量部分退款。
7. 企业退款进入原平安钱包，个人退款进入已核验银行卡；失败可安全重试。
8. 未售货物由平台人员人工创建处置单、填写原因和金额，审核完成后才能划转至预配置平台钱包；系统不得自动发起。
9. 所有金额调整、人工认领、退款和划转均有权限控制、复核及审计日志。
10. 小程序、PC 和金融助手的账单金额及状态最终一致，通道异常可通过对账修复。

## 16. 上线建议

### 本期：人工账单与收款闭环

- 人工创建并填写应收单，提交人工审核后发布。
- 企业钱包支付、个人临时账户转账。
- 收取记录、实收匹配、基础对账。
- 清结算完成后整单退款；未售货物由平台人员人工创建并审核处置单后划转。
- 暂不因补偿金逾期限制新申请；新申请仍按既有流程独立审核。

### 后续可选：自动化与精细化处置

- 自动生成规则、定期重估和自动催缴。
- 按 SKU/数量部分退款、部分划转。
- 自动对账、异常告警和审批流完善。

### 第三阶段：风险运营

- 补偿金风险看板、逾期分析、规则效果分析。
- 根据价格、库存和销售进度动态调整补偿金。

## 17. 已确认业务口径

1. 本期仅支持人工创建应收单，相关信息和应收金额由经办人手动填写。
2. 本期不考虑自动生成、自动触发和定期重估。
3. 所有应收单必须经过人工审核后才能发布。
4. 补偿金逾期暂不限制供应商发起新申请，新申请继续执行既有审核流程。
5. 货物销售后的退款触发点为关联代储订单“清结算完成”。
6. 本期不按 SKU 或已售数量同比例退回，清结算完成后按应收单整单处理退款。
7. 个人临时账户采用“一单一户”，每张应收单对应一个专属临时账户。
8. 个人更换退款银行卡后必须重新校验。
9. 本期不考虑补偿金收据、发票或其他票据能力。
10. 企业/个人供应商身份由其他系统判断并同步至本系统。
11. 担保账户为平台在平安体系下开立的担保账户。
12. 未销售的平台处置采用手工处理：平台人员人工确认、人工创建处置单并填写处置信息，审核后执行划转；本期不做自动识别和自动处置。

## 18. 实施约束

1. 差价补偿金金额及其计算依据由经办人在创建应收单时手工填写，系统不执行公式计算。
2. 一单一户的临时账户有效期、过期入账和归集结果以平安接口实际返回为准，异常进入人工处理。
3. 企业钱包退款、个人银行卡退款及平台钱包划转按平安通道实际限额和到账结果执行，超限或失败进入人工处理。
4. 本方案业务口径已全部确认，不再保留待确认事项。

---

本方案建立“人工创建—人工审核—应收—收取—实收—核销—整单退款/人工平台处置划转”的资金台账闭环，并作为后续页面原型、字段级 PRD、接口及测试设计的确认基线。
