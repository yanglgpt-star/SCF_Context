# 代储代销风险处置（转售）设计方案

> 版本：V1.0（讨论稿）
> 日期：2026-10-08
> 载体：金融助手 - 代储代销（`金融助手-代储代销-整合版-2.8.html`）
> 关联文档：《代储代销需求文档-V2.7》《代储代销差价补偿金管理方案》《批量销售设计方案（形态二专项）》

---

## 1. 方案背景

### 1.1 现有业务与资金链路

代储代销当前闭环（见 V2.7 第 2.1 节）：

```
供应商申请 → 平台审核定价 → 入库生成电子仓单 → 平台拨付保证金（≤ 评估货值 70%）
→ 平台代销（定向销售 / 批量销售）→ 采购商支付 → 出库 → 清分结算 → 供应商实收
```

清分结算口径（现有）：销售回款扣回 **保证金（deposit_amount）**、**服务费（service_fee）**、**仓储费（storage_fee）** 后，余款退回供应商。

### 1.2 风险敞口在哪

平台在货物入库后即**先行垫付 70% 保证金**，回款却完全依赖后续销售。若销售不畅，已拨付的保证金将无法收回：

| 风险情形 | 表现 | 敞口 |
|---|---|---|
| 到期未售完 | 代储期限届满，`stock_quantity > 0` | 剩余在库货物对应的已拨保证金 |
| 货值大幅下跌 | 最新评估货值低于入库评估货值，触发价差补偿 | 保证金额度可能高于货物实际可变现价值 |

### 1.3 已有能力与缺口

| 侧别 | 已有能力 | 状态 |
|---|---|---|
| **资金侧** | 差价补偿金应收（BCAR）/ 收取记录 / 实收信息 | ✅ 已建（`代储代销差价补偿金管理方案`） |
| **货物侧** | 无。货物卖不动时，系统内没有任何"处置货物"的动作 | ❌ **本次补齐** |

差价补偿金解决的是"**找供应商要钱**"，本次风险处置解决的是"**把货卖掉**"——两条腿缺一不可。

---

## 2. 建设目标

1. 让系统能**认出风险订单**：到期未售完、货值大幅下跌两类情形在代储订单管理列表中可视化、可筛选。
2. 提供**处置动作的登记与审批入口**：运营在代储订单上发起风险处置单，登记处置方式（定向转售 / 线下渠道处置）、数量、价格、凭证，经人工审核后生效。
3. 让转售后**回款重新回到既有资金链路**：货权不变、单据不变，回款仍走原清分结算，与差价补偿金自然衔接。

### 3.1 本期范围（轻量方案）

| # | 内容 |
|---|---|

| 3 | 新增「风险处置单」弹窗：登记 + 提交审核 |

| 5 | 处置方式一「定向转售」：审核通过后调既有 `POST /api/sale/create` 生成销售订单 |
| 6 | 处置方式二「线下渠道处置」：仅登记处置与回款信息，出库与回款沿用既有链路 |

**本次不做**：独立的风险台账与看板、自动触发处置、货权过户、自动定价模型。

### 3.2 入口设计（关键：不新增一级菜单）

延续差价补偿金"并入既有菜单"的思路，风险处置挂在既有「代储订单管理」下：

```text
代储订单管理（现有）
├── 订单列表（现有）          ← 新增「风险状态」列 + 「风险处置」操作入口
├── 风险处置单（新增二级入口）  ← 处置单列表、审核、详情
└── 定向销售 / 批量销售（现有）
```

> 备选：若后续处置单量增大，再升级为一级菜单「风险处理」，届时把风险台账、预警看板一并纳入。

## 4. 现状与边界

### 4.1 与差价补偿金的分工（重要）

| 维度 | 差价补偿金应收 | 风险处置（本次） |
|---|---|---|
| 解决什么 | 供应商**补钱** | 货物**怎么卖** |
| 单据 | 应收单 BCAR | 处置单（本次新增） |
| 触发 | 人工创建 | 风险标签提示 + 人工发起 |
| 结束状态 | 已退回 / 已划转 | 已结案 |

**衔接点**：转售成交价低于最低销售单价时，仍按现规则生成差价补偿金应收单，由既有模块收款。风险处置不做资金收付，只做货物处置登记。

### 4.2 与定向销售 / 批量销售的关系

「定向转售」**复用**定向销售的链路与接口，不新造单据，只多一个来源标识：

- 销售订单新增 `source_type`（来源类型）：`normal` 普通销售 / `risk_resale` 风险转售
- 校验差异：普通销售**禁止**低于最低销售单价；风险转售**允许**低于（见 9.2）

### 4.3 货权口径（已确认）

**本期不取得货权**，转售仍以供应商名义代销。理由与含义：

- 无需过户登记与中登网变更，规避《强制回购条款》的合同执行成本
- 回款天然走原清分结算链路，不需要为"平台自营销售"另建一套结算规则
- ⚠️ 法律上这是"扩大代销渠道"，不是"平台买断"。若供应商拒不配合处置，仍需回到《强制回购条款》兜底——**本次不建设该分支**（见 11.6）

### 4.4 数据缺口（阻断项）

| 缺口 | 说明 | 影响 |
|---|---|---|
| **代储到期日** | `fa_storage_order` 表**无**到期日/代储期限字段 | 「到期未售完」无法自动识别，**必须在本次补齐字段** |
| 货值重估留痕 | `actual_stock_amount` 被直接 UPDATE 覆盖（见 `货值更新.sql`），无历史版本 | 跌幅计算只能拿"最新值 vs 入库值"，无法看曲线（可接受） |

## 5. 风险识别模型

本期为**标签式识别**：系统打标 + 列表可筛选，不生成独立风险事件单据。

### 5.1 触发条件一：到期未售完（`EXPIRED_UNSOLD`）

```
风险成立条件：代储到期日（storage_end_date）≤ 当日
             且 可售库存（stock_quantity）> 0
             且 拨付状态 = 已拨付
```

### 5.2 触发条件二：货值大幅下跌（`VALUE_DROP`）

```text
入库评估货值 = evaluate_price × stock_in_quantity
最新评估货值 = actual_stock_amount（由货值重估写入）
跌幅 = 1 − 最新评估货值 ÷ 入库评估货值
风险成立条件：跌幅 ≥ 阈值（建议 10%，可配置）
```

### 5.3 风险标识呈现

| 标识 | 颜色 | 与处置单的关系 |
|---|---|---|
| 到期未售完 | 红 | 未处置 → 「待处置」；已有通过审核的处置单 → 「处置中」；处置单结案 → 「已处置」 |
| 货值下跌 | 橙 | 同上 |
| 两类同时成立 | 红 + 橙双标签 | 同上 |
| 无风险 | 灰色「正常」 | — |

> 风险标签**只做提示**，不阻断「销售」「批量销售」等既有操作——运营仍可正常继续卖货，处置是并行手段。

## 6. 处置单模型

### 6.1 粒度

**一张处置单 = 一个代储订单（storage_order_no） + 一次处置动作。**

同一代储订单可以分多次处置（例如先转售一半、再线下处理剩余），但同一时刻只能存在一张**未结案**的处置单。

### 6.2 编号规则

沿用既有编号体系（V2.7 名词定义）：

| 单据 | 格式 | 示例 |
|---|---|---|
| 风险处置单 | `FX` + YYYYMMDD + 4 位流水号 | `FX202610080001` |

> FX = 风险（Feng Xian）。销售订单仍用 `XS`，处置单只承载"处置决策"，转售产生的销售单独立编号。

### 6.3 处置方式（两种）

| 处置方式 | 编码 | 动作 | 是否生成销售订单 |
|---|---|---|---|
| 定向转售 | `DIRECT_RESALE` | 指定买家与成交价，审核通过后生成销售订单，走既有定向销售链路 | ✅ 生成（来源标识 `risk_resale`） |
| 线下渠道处置 | `OFFLINE_DISPOSAL` | 线下找渠道卖出，回系统登记成交价、买家/渠道、凭证、回款 | ❌ 不生成 |

### 6.4 处置单状态机

```text
草稿 → 待审核 → ┬─ 已通过 → 处置中 → 已结案
                └─ 已驳回 →（可修改后重新提交）
                              └─ 已作废
```

- 经办与复核**分离**：操作人不得审核自己发起的处置单（与差价补偿金一致）
- 「已通过」是操作生效点：定向转售在此刻调用创建销售订单接口；线下渠道处置在此刻解冻后续登记

| # | 规则 |
|---|---|
| 1 | 同一代储订单**只能存在一张未结案**处置单，重复发起时提示既有单号 |
| 2 | 处置数量 ≤ 剩余可售库存（`stock_quantity`） |

| 6 | 已通过且已生成销售订单的处置单**不可编辑**，只能作废后重发 |

## 9. 资金与清算口径

### 9.1 转售回款路径（货权不变的核心结论）

```text
定向转售：处置单审核通过 → 生成销售订单（source_type=risk_resale）
        → 采购商支付 → 出库指令 → 清分结算（扣回保证金/服务费/仓储费）→ 余款退供应商

线下处置：线下成交 → 回系统登记处置与回款
        → 出库仍走出库指令 → 回款在清结算中心登记 → 冲减代储订单剩余库存与货值
```

**结论：转售不新增任何资金收付规则，完全复用既有清分结算。** 这是选择"不取得货权"换来的最大简化。

### 9.2 低于最低销售单价的豁免

这是风险处置区别于普通销售的关键点：

| 销售类型 | 最低销售单价校验 |
|---|---|
| 普通销售（normal） | 前端校验 + 后端拦截，**不得低于** |
| 风险转售（risk_resale） | **允许低于**，但需满足：① 处置单已审核通过；② 已填写降价说明；③ 差额按 9.3 处理 |

### 9.3 差额处理

转售成交价与最低销售单价的差额，**不新增资金动作**，按现有规则转为差价补偿金应收：

```text
应补差额 = Σ(最低销售单价 − 实际处置单价) × 处置数量
→ 生成差价补偿金应收单（BCAR），走既有收取/核销/退款链路
```

## 11. 待决策事项

### 11.1 代储到期日从哪来（阻断项，需优先拍板）

`fa_storage_order` 现无该字段。三种取法：

| 方案 | 说明 |
|---|---|
| A. 审核定价时人工填写 | 一单一议，灵活，但依赖运营输入 |
| B. 按固定代储期限推算 | 入库日 + N 天，需确定 N 谁定、可否按品类/供应商差异化 |
| C. 两者结合 | 默认推算出日期，审核时允许人工修正（**建议**） |

### 11.2 货值下跌阈值与取值口径

- 阈值建议 10%，**是否配置化**、按谁配置（全局 / 品类 / 供应商）
- 取数是**整单口径**还是按 SKU 口径（现表按代储订单 SKU 粒度，整单更自然）

### 11.3 低于最低销售单价的审批层级

- 是否所有降价都必须走更高层级审批？还是允许一定幅度内运营自主？
- 建议：设置降价幅度带（如 ≤ 5% 运营审批、≤ 15% 风控审批、> 15% 管理层审批）

### 11.4 线下渠道处置的回款入口

- 回款是否走清结算中心登记？还是走差价补偿金的"实收信息"？
- 建议走清结算中心（货物侧回款归清结算，资金侧补款归差价补偿金）

### 11.5 与差价补偿金的防重

- 转售降价差额生成的 BCAR，如何与运营手工创建的 BCAR 防重（复用现有"同一业务事件唯一号"机制，需定义转售的事件号生成规则）

### 11.6 供应商拒不配合时的兜底

- 本次不取得货权；若供应商拒不配合转售/提货，是否启用《强制回购条款》？
- 建议本期**只提示**，兜底动作走线下与法务，系统不建设

### 11.7 风险标签是否可人工干预

- 自动打标 vs 运营可手工标记/取消（如运营判断该单实际无风险）

## 13. 验收要点

1. 到期未售完 / 货值下跌的订单在列表中能被正确打标，筛选结果与打标一致。
2. 无风险订单不出现「风险处置」入口；已有未结案处置单的订单入口置灰并提示单号。
3. 处置单必填校验、数量校验（≤ 剩余可售库存）、单价校验全部生效。
4. 经办人无法审核本人发起的处置单。
5. 定向转售审核通过后正确生成销售订单，来源标识为 `risk_resale`，且**低于最低销售单价时不拦截**。
6. 线下渠道处置不生成销售订单，登记信息完整可查。
7. 转售回款正确进入清分结算，保证金/服务费/仓储费扣回口径与普通销售一致。
8. 转售降价差额正确生成差价补偿金应收单，且与手工创建的应收单不重复。
9. 处置单结案后，对应代储订单风险状态变为「已处置」。
