## 一、先说清楚一个前提：单价不属于 SKU

用户要的是「一条数据 = 一个 SKU 的波动折线」。但本项目里**均价的所有者是核算单元**，不是 SKU：

| 对象 | 键 | 谁拥有均价 |
|---|---|---|
| 核算单元（均价池） | 商品 × 仓库 × 一级货主 | **均价、成本层、凭证、跌价基数都归它** |
| 库存维度 | 商品 × 仓库 × 批次 × 一级货主 | 余额表主键 |

（原文 `§一.5.2` `:138`–`:145`；`fin-valuation` 判据树）

所以同一个 M0001 在 WH01 / OWN-A 和 WH02 / OWN-B 是**两个独立均价池**，各有一条价格曲线。把两条合成一条 SKU 曲线只有两种做法，都不干净：

- 跨池加权：加权平均下勉强成立，但**先入先出法、个别计价没有「池均价」这个概念**，混进同一列就是口径混算；
- 取简单平均：直接错。

**结论：折线图的每一行，粒度和 `prev_unit_cost` / `curr_unit_cost` 的粒度必须一致，即「商品 × 仓库 × 一级货主」。** 这不是实现细节，是这张表能不能对账的前提。

## 二、三个方案对比

| | 方案一（**推荐**） | 方案二 | 方案三 |
|---|---|---|---|
| 行粒度 | **核算单元**：SKU × 一级货主 × 仓库 | SKU（跨池合并） | SKU 为父行，可展开到核算单元 |
| 折线含义 | 该均价池的均价走势 | 跨池加权均价 | 父行合并曲线 + 子行各池曲线 |
| 口径正确性 | ✅ 与 `prev`/`curr` 完全一致 | ❌ 三法混算、互相抵消 | ✅（子行正确，父行仍有方案二的问题） |
| 能否发现异常 | ✅ 池级异常不会被别的池抹平 | ❌ 两个池反向波动会**对消**，恰好看不见 | ⚠️ 默认视图反而掩盖 |
| 实现成本 | 低 | 低 | 高（两级展开、两套曲线） |
| 适用前提 | 无 | 只有「每个 SKU 只在一个池」才成立 | 跨仓铺货极多的品类 |

**推荐方案一。** 如果业务上确实存在「同一个 SKU 铺多个仓」且老板要从 SKU 视角看，方案三可作为二期增强（父行只做数量加权数量列 + 一个「展开」箭头，父行不画曲线、只显示子行曲线的叠加，避免加权口径争议）。

## 三、方案一的具体形态

### 3.1 列表（一行 = 一个均价池）

**12 列**（现 15 列）：

`商品 SKU`（可点）/ `商品名称` / `一级货主` / `仓库` / `当前均价` / `窗口起点均价` / `窗口涨跌幅` / `窗口内最大幅度` / `30 天走势`（折线）/ `预警级别`（窗口内最高）/ `待复核条数` / `操作`

**去掉的列**：变动流水号、业务单号、单据类型、变动前均价、变动后均价、单价变动绝对值、产权人、发生时间——这些都是**事件级**字段，全部下沉到抽屉的流水表。

**产权人为什么去**：二级产权人不是均价池的键（`fin-owner-pricing`），同一核算单元下多个二级产权人共享同一个均价。放在行上会误导「这个价属于这个二级」。抽屉里可以显示涉及到的二级产权人集合，但**不能作为行维度**。

### 3.2 折线口径（必须先定死，否则三个人画出三条线）

| 项 | 口径 |
|---|---|
| 数据源 | 成本波动日志 `inv_cost_fluctuation_log`：一笔日志给 `prev_unit_cost` → `curr_unit_cost` 一对 |
| 窗口 | 默认 **30 天**（与原文 `[复核审批]` 的「30 天走势图」一致），可选 7 / 30 / 90 天 |
| 取点 | **日末值** = 当日最后一笔日志的 `curr_unit_cost`；无日志的日子**沿用前值** |
| 画法 | **阶梯线**（step-after），因为均价只在事件发生时跳变，不是连续变化 |
| 起点值 | 窗口首日之前最近一笔的 `curr_unit_cost`；窗口内完全无日志 → 画一条水平线并在末列标「窗口内无波动」 |
| Y 轴 | 平均单价，货币 **4 位小数**（与 `§三.11` 字段格式 `¥#,##0.0000` 一致） |
| 颜色 | **红涨绿跌**（与本页既有 `is-bad` 红 / `is-good` 绿一致），与 A 股/中文财务习惯一致 |
| 预警点 | 日志 `alert_level` 为黄色预警 / 红色阻断的点，在折线上打黄点 / 红点 |
| 个别计价、先入先出法 | 折线上的「均价」是**结存单位成本的派生值**（结存金额 ÷ 结存数量），仅用于展示，**不参与计价**——权威成本在成本层 `t_inventory_layer.layer_unit_cost`（`fin-valuation` §三.4） |

> ⚠️ **数据前提**：原文 `alert_level` 含 `NONE`（无预警），说明日志记**全量变动**、不只记预警。若生产上只写 WARN 及以上，折线会在无预警区间失真——届时需要 `t_inventory_balance_unit` 的日均价快照兜底。**这一条要在实施前跟后端确认。**

## 四、原型落地细节（单文件、无外部依赖）

原型目前**没有任何 SVG / 图表代码**（全文 `svg` / `canvas` / `polyline` 计数为 0），单文件也不引外部库。所以折线用**内联 SVG + 少量原生 JS** 自绘：

1. **表格**：重写 `<table data-tab="11">` 表头与 8 行样例。
2. **折线列**：
   ```html
   <td class="spark" data-series="0.0,0.0,3.1,12.4,12.4,18.0" data-trend="up" data-alerts="2,4">
   </td>
   ```
   JS 在 boot 时扫描 `[data-series]`，生成 `<svg viewBox="0 0 120 28" preserveAspectRatio="none">` + 一条 `<path>` + 黄/红 `<circle>`。
   **注意命名禁令**：SVG 里不放任何文字，`data-*` 旁的英文码只能进 `title`。
3. **点击 SKU**：现有 `[data-drawer]` 处理器是 `screen.querySelector('[data-dw]')` 取**第一个**抽屉，不能直接用。做法：给 SKU 链接加 `data-skuflow="M0002|OWN-B|WH02"`，新增一个独立处理器按属性找 `[data-dw="11b"]`。
4. **新增抽屉** `<div class="dwrap" data-dw="11b" hidden>`，内含 `.dpane`（走势 + 流水表）与 `.dpane`（字段说明）。
5. **筛选下拉的坑**：`fillSelects()` 用「该页第一张表该列的实际取值」重建 options，**列没了就退回静态占位「选项一/选项二」**。行粒度改造后 `单据类型`、`预警级别`、`复核状态` 三列都不在列表里了，必须在筛选条里**写死真实 option**（10 类单据类型 / 三级预警 / 三种复核状态），否则下拉会显示占位垃圾。
6. **样式**：沿用账簿绿格令牌，新增 `.spark{width:120px;height:28px}`；全局定死一态、不写 `prefers-color-scheme`（`CLAUDE.md §四`）。
7. **说明书**：`…原型说明_v1.0.md` P11 段按新列表 + 新抽屉重写；`build_proto_doc.py` 重新生成 HTML，连跑两次 md5 一致。
