1.1

三个金额：谁参与对平，谁不参与

一、怎么读这份示例 → 三个金额：谁参与对平，谁不参与

二级层的引擎出口是一个数量、三个金额，而三个金额「能不能加总回一级层」各不相同——这是读一切二级数字的前提。

金额 定义 能不能加总回一级层 差额去哪
alloc_amount（二级分摊金额）数量 × 所在核算单元的一级层均价能分摊金额求和恒等于一级层金额（V3 ／ 出口硬校验①）
internal_amount（二级内部结算金额）按内部结算价（internal_price）累计不能差额进二级内部损益（internal_pl），管理口径、不出凭证
own_amount（自有结存金额）二级自有均价池逐笔结转：入池按实际成本、出池按该二级当期自有均价、二级重分配同额平移不能与一级层金额之差就是池化差异 D（自有金额求和 + D = 一级层金额，即 M1）

报表上只看得到两个。 二级维度并排展示 alloc_amount 与 own_amount 两列，外加一列算出来的自有均价（own_unit_price = 自有结存金额 ÷ 数量）。internal_amount 不展示——它既不进列表、也不参与 V1 / V2 / V3 任何一个等式。本文的发生额表仍然把它列出来，因为「一行三个金额」是引擎出口的原始形态，开发要照着对。

二级重分配不出凭证。 单据类型是二级重分配（OWNER_REASSIGN），与一级货权转移（OWNER_TRANSFER）复用同一张货权变更单，但它是非会计事件（is_accounting_event = 0）——一级余额不动、凭证不出，只有二级分摊账上两行数量换了归属；自有池同额平移，D 不变。

1.5

三个金额什么时候分叉

一、怎么读这份示例 → 三个金额什么时候分叉

第二章的示例都是单个核算单元的一条线，所以三个金额会不会分叉，只取决于两件事：

  1. internal_amount 只在二级重分配时与 alloc_amount 分叉。 它是内部结算价（internal_price）的产物，而只有二级重分配（OWNER_REASSIGN）才带这个价。第二章有重分配的只有「销售出库 · 情形二」两个小节。
  2. own_amount 只在「会计结转口径 ≠ 自有池出池价」时与 alloc_amount 分叉。 会计按核算单元或成本层结转，自有池按该二级当期自有均价出池：
  • 移动加权平均 → 二级自有均价 = 单元均价（入池价就是建层价），D = 0.00；
  • 个别计价 → 会计按被点名序列号（SN）的层成本逐件结转，自有池按均价出池，只要出库或转出，D ≠ 0.00；
  • 先入先出法 → 会计逐层结转，自有池按均价出池，同样 D ≠ 0.00。
  1. 二级重分配本身不产生 D。 自有池是同额平移：转出方按自有均价出、转入方同额进，两行相抵。重分配也不出凭证（is_accounting_event = 0），一级余额一动不动。

于是第二章按小节分成三类：

小节 D 为什么
移动加权平均的 10 个小节0.00二级自有均价 = 单元均价，自有池与一级池同进同出
个别计价的入库小节（无出库／转出）0.00只有入池，且入池价 = 层成本
个别计价的出库小节（有出库／转出）≠ 0.00会计逐件按层成本、自有池按均价 —— 见 §2.3 各节末尾
2.4 先入先出法算例+50.00会计逐层（结存 600.00）、自有池按均价（结存 550.00）

真正让三个金额同时长出来的形态，在 §3.6（同一个核算单元里两个二级的进货价不一样）与 §4（逐笔过账与校验）。D 的定义式始终是：

D = 一级层金额 − ∑ 自有结存金额

一句提醒。 D ≠ 0 不是出错，是已经接受下来的代价——会计口径必须逐件 / 逐层如实结转，管理口径要的是一个能滚动的池价，两者本来就不可能同时成立。E-13 校的是「自有池有没有按它自己那口价如实走」，不是「D 必须等于 0」。

2.1

三种计价方法的算法

二、出入库计算示例 → 三种计价方法的算法

移动加权平均法

定义：系统会给每一个核算单元（就是把「商品、仓库、一级货主」这三样绑在一起的那个组合）维护一个「移动平均均价池」。只要进了一笔货，就按「（原来的金额 + 这一笔入账金额）÷（原来的数量 + 这一笔数量）」把均价重算一遍；出库的时候按当下的均价把金额结转出去、不重算均价。均价池只建在一级货主这一层，二级产权人和批次都不进会计均价池（规则 R3）——二级产权人另有一本管理口径的二级自有均价池（见分册 §二）。

适用场景：通用标品，也就是不要求一件件追溯成本的品类。它是一期默认启用的计价法（全局默认）。

入库怎么算（F1）

new_qty    = old_qty + base_qty
new_amount = old_amount + (不含税金额 + 本行分摊费用)        ← in_amount 定义见 F5a
new_price  = round(new_amount / new_qty, 6)

变量说明：采购行成本公式（F5a） · 基本单位数量（base_qty） · 入库金额（in_amount） · 结存金额（new_amount） · 结存单价（new_price） · 结存数量（new_qty） · 原金额（old_amount） · 原数量（old_qty） · 四舍五入函数（round）

  • 基本单位数量（base_qty）一律取基本单位的数量（业务单位只用来展示，不做核算）；入库金额（in_amount）走的是不含税口径，税额只进「应交税费 - 应交增值税（进项税额）」这一科，绝不进成本（规则 F5b）。
  • 入库只对单价做四舍五入、不回头改金额：入库金额是已经定死的入账数（不含税金额 + 分摊费用）；要是回头去改它抹平尾差，等于凭空调整入库金额，会把金额守恒（期初 + 入 − 出 = 期末）给破坏掉。
  • 边界情况：old_qty = 0 时，new_price = round(in_amount / in_qty, 6)（结存单价 = 入库金额 ÷ 入库数量，四舍五入保留 6 位）；new_qty = 0 时禁止入库（系统会直接拒绝）。

出库怎么算（F2 / F3）

F2  out_amount = round(out_qty × current_price, 2)      ← current_price 取核算单元当前均价
    new_qty    = old_qty − out_qty
    new_amount = old_amount − out_amount
    new_price  = current_price                          ← 出库不重算单价
F3  rounding_diff = out_amount − out_qty × current_price

变量说明：出库结转公式（F2） · 出库舍入差异（F3） · 当前均价（current_price） · 结存金额（new_amount） · 结存单价（new_price） · 结存数量（new_qty） · 原金额（old_amount） · 原数量（old_qty） · 出库金额（out_amount） · 出库数量（out_qty） · 四舍五入函数（round） · 舍入差异（rounding_diff）

  • 出库不重算单价：出库只是把核算单元里已经有的均价花掉，不改写它——移动加权平均（MA）和先入先出法（FIFO）/ 个别计价（SI）在「谁能改均价」这件事上的根本分界，就在这里。
  • 舍入差异只在出库这一头产生：入库金额是定死的入账数；出库金额是算出来的（数量 × 6 位单价），落到 2 位小数上必然有尾差。每一笔的尾差都累加进舍入差异累计（rounding_diff_acc），月末由一张单独的凭证把它结转掉（用模板 8.1.7）。

出清处理（F4）

F4  若出库后 new_qty = 0 且 new_amount ≠ 0，
    将剩余金额全额结转（或转入舍入差异账户）并把余额清零

变量说明：出清处理（F4） · 结存金额（new_amount） · 结存数量（new_qty）

一期是否启用：启用——它是一期默认启用的计价法（全局默认）。均价池、余额、凭证、跌价基数全都建在核算单元上；同一个核算单元里，单价（unit_price）是个派生值（结存金额 ÷ 结存数量），它是 F1 / F2 算价时的输入，是本单元唯一说了算的口径。

个别计价法

定义：按业务上指定的批次 / 序列号（SN），一件一件（或一批一批）把成本结转出去——成本跟着被点名的那一件走，件和件之间不互相拉平。

适用场景：3C 高值整机、二手数码这类「一机一价、必须逐台追溯成本」的品类（一期启用，3C 整机按序列号（SN）单台结转的优先级最高）。

入库怎么算（F1）：不并进均价池，而是按这一件（这一批）的实际成本单独建一个成本层 / 资产档案——同一个商品、不同的序列号（SN）各自带着自己的成本，互不平均。入库金额的口径仍然按 F5a 来（不含税金额 + 分摊费用）。

出库怎么算（F2 / F3）：不取核算单元的均价，而是取拣货回传（或业务上指定）的序列号（SN）/ 批次对应的成本，加起来结转；舍入差异和移动加权平均同源，还是在出库这一头产生。

一期硬要求：出库单据的行上必须出现序列号（SN）——这是个别计价按序列号（SN）单台结转成本的前提。序列号（SN）管理的品类（比如 3C 整机），出库单据行少了序列号（SN）就是校验不过。

出清处理（F4）：结存里只剩下那些没被指定出库的批次 / 序列号（SN）成本层；数量清零的时候如果还有残留金额，按 F4 全额结转掉。

一期是否启用：启用（个别计价（SI），出入库对照 v1.0 §2.0 已经定了）。

先入先出法

定义：按入库的先后顺序形成一层层的成本层（每层带自己的数量 + 层单价），出库的时候从最早的那一层开始一层层消耗，一层出完了才轮到下一层。

适用场景：有保质期 / 时效性要求的，或者希望出库成本贴近最早那批采购价的品类（一期启用）。

入库怎么算（F1）：每一笔入库都形成一个新的成本层，不跟别人拉平；入库金额还是按 F5a 定，单价四舍五入到 6 位。

出库怎么算（F2 / F3）：出库成本 = Σ 各层被消耗数量 × 各层单价，一层一层接着结转；移动加权平均那套「核算单元均价」在这里不参与结转。舍入差异同样是在出库这头产生。

出清处理（F4）：一层一层消耗，最后一层消耗完，结存就清零了；要是数量已经清零却还有残留金额，按 F4 全额结转。

一期是否启用：启用（先入先出法（FIFO））。走先入先出法（FIFO）的单元，商品一律按批次 / 入库层来管（每次入库就是一层），不然成本层跟批次余额表对不上。

三法对照（同一批单据、同样出 150 台）

三、三个维度的结存计算示例 → 「一个数量、三个金额」：引擎出口 vs 报表展示

引擎出口的二级结果是一个数量、三个金额（见《财务库存中心（一期）需求文档 1.0（通俗版）.md》§四.1 销售出库那一行）：

项 定义 能不能加总回一级层
数量增量（delta_qty）二级层的量变动，带正负号—（V1 用它）
二级分摊金额（alloc_amount）数量 × 所在单元的一级均价能——分摊金额求和恒等于一级层金额（V3 / 出口硬校验①）
二级内部结算金额（internal_amount）按内部结算价（internal_price，来自带生效期的价目表）累计不能——差额就是二级内部未实现毛利（管理口径）
自有结存金额（own_amount）新增：二级自有均价池逐笔结转——入池按实际成本、出池按该二级当期自有均价、二级重分配同额平移不能——与一级层金额之差就是池化差异 D（自有金额求和 + D = 一级层金额，也就是 M1）

本例第 3 单按内部结算价 11.000000 作价：A-2 那一行的二级内部结算金额 = 20 × 11.000000 = 220.00，而它的二级分摊金额 = 20 × 10.000000 = 200.00，差 20.00 进二级内部损益（internal_pl）。

⚠️ 二级内部结算金额在结存报表上看不到。 二级维度不展示内部结算口径——它既不进列表、也不参与 V1 / V2 / V3 任何一个等式（见《财务库存中心（一期）需求文档 1.0（通俗版）.md》§一.5.2）。它是管理口径：价来自政策数据（内部结算价），不影响会计、不出凭证（R5）。

自有结存金额是另一回事——它是展示的：二级维度并排给出两列金额（会计口径的二级分摊金额、自有口径的自有结存金额），外加一列算出来的自有均价。两列不相等是正常的，差就是池化差异；二级内部结算金额则始终不展示。三者的关系：二级分摊金额对会计、二级内部结算金额对内部结算考核、自有结存金额对「该二级自己这本账」。

二级重分配的会计侧什么都不动——一级余额不变、凭证不出，只有二级分摊账上两行数量换了个归属；二级自有池则同额平移（转出方按自有均价出、转入方同额进，D 不变）。

二级重分配用的单据类型是二级重分配（OWNER_REASSIGN），和一级货权转移（OWNER_TRANSFER）复用同一张货权变更单、同一套字段，但是非会计事件（is_accounting_event = 0）——这就是「不出凭证」在数据上的落点。

个别计价下的差异

三、三个维度的结存计算示例 → 个别计价下的差异

同一套流水，如果三个核算单元配的是个别计价（逐个序列号 + 成本层）：

  • 出库不按均价结转，而是按单据行上点名的序列号取成本层逐台结转。第 4 单出 30 台、第 6 单出 10 台，都必须写明出的是哪几台。
  • 一级均价仍然是算出来的值（结存金额 ÷ 结存数量），仍然要满足批次行均价一致性（引擎侧校验项 E-02：同一个核算单元里所有批次行的单价（unit_price）必须相等）——它是给对账和展示用的，不是计价依据；计价依据是成本层（t_inventory_layer）。
  • 二级维度的「会计均价」在个别计价下不展示：当前结存均价（current_unit_cost，一级层均价）按核算单元的方法分流展示，个别计价单元显示 --（见《财务库存中心（一期）需求文档 1.0（通俗版）.md》§一.5.2）——一级那个价在个别计价下不是一个能对外说话的价。但自有均价（own_unit_price，二级）照常展示：它由自有池实算（自有结存金额 ÷ 数量），和批次行的移动平均单价（unit_price）的既有处置一样，标注「算出来的 · 非计价依据」。
  • 个别计价 / 先入先出法下的 D 会更大：会计侧逐件 / 逐层按实际成本结转，自有池却按自有均价出池，两者差可能明显大于移动加权平均。这是已知并接受的（口径不变的代价），细节见《二级产权人自有均价池设计方案_v1.0.md》§十.1。
  • ★ 差异落在出库行的二级分摊金额上。移动加权平均下，分摊金额可以走「数量 × 一级均价」这条短路；个别计价下不能——它必须等于这一行实际结转的一级层成本（逐个序列号归集），否则出口硬校验①当场不平：
某个核算单元 4 台，成本层分别是 12,000.00 / 13,000.00 / 11,500.00 / 12,500.00
结存金额 = 49,000.00，结存数量 = 4，算出来的均价 = round(49,000.00 / 4, 6) = 12,250.000000

出库 1 台，点名 SN-0003（实际成本 11,500.00）
  分摊金额增量取实际结转            = 11,500.00   ← 正确
  如果误按「数量 × 算出来的均价」算 = 12,250.00   ← 和一级层金额增量 11,500.00 差 750.00
  → 出口硬校验①不平 → 整单回滚 + 告警，错误数据不落库

一句话：二级分摊金额的定义是「能加总回一级层」，不是「数量 × 均价」。「数量 × 均价」只是移动加权平均下让前者成立的一条快捷算法；个别计价下这条捷径失效，必须逐个序列号归集实际结转成本。

先入先出法也一样要小心——它按层序号逐层结转，实际结转金额同样不等于「数量 × 算出来的均价」，分摊金额增量一样要取实际结转值。

R2 / R5：二级重分配必按内部结算价作价，差额进二级内部损益，不出凭证、不影响会计；单据类型是二级重分配（OWNER_REASSIGN），非会计事件（is_accounting_event = 0）——一级余额和凭证一动不动。 6. 二级结果是「一个数量、三个金额」：二级分摊金额（会计分摊）能加总回一级层（V3 / 硬校验①）；二级内部结算金额（内部结算）不能（差额就是内部未实现毛利）；自有结存金额（自有成本）不能（差额就是池化差异 D，对平式 M1）。报表上并排展示两列金额（二级分摊金额 + 自有结存金额）和一列算出来的自有均价，内部结算金额不展示、不参与任何一个等式。 7. 个别计价 / 先入先出法下，分摊金额按实际结转逐笔归集，不能走「数量 × 均价」；移动平均单价（unit_price）在这两种单元里仍然是算出来的值，成本层单价（layer_unit_cost）才是计价依据——这正是 P16 余额管理报表的批次余额页签上单价和成本层单价两列并存的原因。批次行均价一致性（E-02）管的是「批次行」，不含二级产权人行——二级行有自己的自有均价，不受这条等式约束。 8. 二级结存是分摊账的物化投影：二级产权人结存表（t_owner_balance_l2）和二级产权人分摊账（t_owner_allocation）逐行一致，日结校验 E-12（二级结存投影不一致）。自有口径同样要能重放——二级产权人结存表的自有结存金额由分摊账的自有金额求和重建，日结校验 E-13（二级自有池结转不一致）。分摊账的数量带正负号，二级重分配展开成两行（转出行取负 / 转入行取正），所以 SUM(qty) 直接就是结存数量；负值的含义是「超分摊」（分摊出去的量超过了它持有的量），跟仓库 / 一级层的负库存不是一回事——标签文案要区分开。

4.9

E-13：什么时候抓得到、什么时候抓不到

四、二级自有均价池：逐笔过账与校验 → E-13：什么时候抓得到、什么时候抓不到

反例一：出池行写错价。

把第 3 单的出池价误用成一级层均价 15.000000：

  • 行上 own_amount_delta 记成 −round(50 × 15.000000, 2) = −750.00，而该二级当期自有均价是 20.000000，应记 −1,000.00。
  • ✅ M2 当场抓住：−750.00 ≠ −50 × 20.000000 = −1,000.00。
  • ❌ M1 抓不到：D 就是「一级层金额 − ∑ 自有金额」的定义式。自有金额少记 250.00，D 就跟着多算 250.00，等式照样成立。M1 是恒等式，不是校验。
  • ❌ M3 也抓不到：A-1 差 −500.00、A-2 差 +500.00，两边相抵 = 0.00 = -D，同样恒成立。M3 也是恒等式。
  • ❌ E-13 的第二条判据也抓不到：因为这个错同时写进了分摊账和结存表，两处一致地错——重放对得上。
  • ⚠️ 真正的伤害：D 被算成一个错的值（A@WH01 真实值是 +175.00），而且错价会进入 A-2 的自有均价——从 20.000000 变成 25.000000——污染它后面每一笔出池（第 5 单的调拨出池会跟着错）。

结论：M1 / M3 是恒等式，M2 和 E-13 才是真校验。「对平了」不等于「对了」——这条要记住，否则会以为报表上两列能对上就没问题。

反例二：只改结存表，改不动分摊账。

分摊账是逐笔发生额，结存表是它的物化投影。若有人直接更新 t_owner_balance_l2 里 A-2 @ A@WH01 的自有结存金额（比如改成 1,300.00），而分摊账重放出来的 ∑ own_amount 还是 975.00——

  • ✅ E-13 第二条判据当场抓住：t_owner_balance_l2.own_amount ≠ 从 t_owner_allocation 重放的 ∑ own_amount。

这也正是自有金额必须逐笔落在分摊账上（own_unit_price / own_amount 两列）而不能只存一个结存总额的原因——只有一个总额，就没有「重放」可以比。

4.10

要点

四、二级自有均价池：逐笔过账与校验 → 要点

1. 四类动作在自有池上的写法各不相同：入库同额、出库按该二级自己的均价、二级重分配同额平移、跨核算单元动作按作价（一级货权转移转入）/ 同额（调拨与转入方）。唯一出处是分册 §二 2.1 那张规则表，本节只是把它走了一遍。 2. own_amount_delta ≠ alloc_amount_delta 只发生在「自有出池价 ≠ 一级层出账价」的行上（第 3、4、5、6 单）。这个差不是损益，它是池化差异 D 的来源。 3. 逐行看差没有意义，要看 ∑：4a / 4b 两行相抵为 0，重分配不动 D；会计侧同样相抵为 0，所以一级层一动不动。 4. D 逐核算单元算、带符号、可以跨单元相加：A@WH01 +175.00、A@WH02 −25.00、B@WH01 0.00，全局 +150.00。为负是正常现象。 5. 自有均价是逐核算单元滚的，和一级层均价一个粒度；同一个二级在多个核算单元里各有自己的自有均价。调拨的「同额平移」会让两边暂时相同，别把它当成恒等关系。 6. internal_amount 全程没出现在本节：内部结算口径（重分配按内部结算价 12.000000 作价、差额进二级内部损益）既不进会计等式、也不进自有池，报表上不展示。 7. M1 / M3 是恒等式，M2 / E-13 才是校验——M2 管逐事件的出池价一致（重分配转入行例外），E-13 管余额层投影能重放。 8. 自有池既不出凭证、也不进存货总额（R4 / R5）：本节所有 own_* 数字都不影响 V1 / V2 / V3、不影响跌价基数、不影响凭证。

要点

六、全单据类型整体算例 → 要点

1. 三个「情况」是前置结存状态，不是三种算法。 同一类单据在三种状态下走的是同一条公式，差别只在起点——所以 10 行里只有两个方向的数。 2. 出库单价是取出来的，不是填出来的。 正结存取当期均价，零 / 负结存取暂估价 P_est；P_est 必须来自不读结存的价（最近采购价 / 基准价）。 3. 正结存出到 0 是干净出清，负结存进货到 0 是冲平和差价两件事。 前者 F4 只在余差 ≠ 0 时补结转；后者必须先按 P_est 冲平、再按实际成本入池，剩余为 0 就一点不入池。 4. 入池的只有「冲平之后的剩余量」。 把入库金额整笔加到负余额上会同时算错数量和均价（§5.1 第 2 条读法）。 5. 10 类里只有调拨和货权转移是两条腿。 调拨两腿同额，集团净额 0；货权转移两腿两个价——转出按本层成本、转入按作价，差额是转出方已实现毛利。 6. 三张表互相对得上：总表反推发生额（§6.3）、流水逐笔滚动（§6.5）、钱的账汇总（§6.5 末），每一格都能用 附录 B 的 F1 / F2 / F4 复算。
