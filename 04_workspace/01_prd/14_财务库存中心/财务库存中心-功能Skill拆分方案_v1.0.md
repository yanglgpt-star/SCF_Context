# 财务库存中心 · 功能 Skill 拆分方案 v1.0

> **本文是什么**：把财务库存中心的**产品功能**（不是文档工作流——那是另一份方案）拆成 Claude Code Skill 的方案。**只做分析、不落地**。
>
> **一句话结论**：22 个功能里，**只有 4–5 个值得独立成 skill**——判据是**规则密度**，不是页面数。**其余 12 个是「展示层」，价值在列定义与取数口径，应合成一张共享口径表，而不是 12 个 skill。**

## 二、判据：什么样的**功能**适合做成 skill

上一份方案拆的是「**我要做的工作流**」；这一份拆的是「**产品的一项能力**」。判据不同：

| 判据 | 说明 |
|---|---|
| **规则密度高** | 大量非显然的规则 / 公式 / 分支，不看就会做错 |
| **术语陷阱多** | 领域词容易被误用（三个金额、二级产权人、三法） |
| **可被独立触发** | 有人会单独问「负库存怎么处理」，而不是「整个系统怎么设计」 |
| **知识分散** | 规则散在原文 / 详细设计 / PRD / 算例多处 |
| **有判据树** | 存在「如果…则…」的判定链 |

**反判据（这几类做了就是白做）**：

- **纯展示层**——列表 + 筛选 + 详情 + 列定义。它的价值在**列字典**，不在规则；做成 skill 只是把文档目录抄一遍。
- **纯 CRUD**。
- **接口约定**。

## 三、强烈建议成 skill（4 个）

### S1 `fin-valuation` — 存货计价方法（SR03_F02）

- **触发**：「三种计价方法」「移动加权平均 / 个别计价 / 先入先出法」「成本层」「均价怎么算」「批次进不进均价池」
- **内容**：三法定义与差异；成本层 `t_inventory_layer`；**移动加权平均下批次不进均价池**（只影响库龄与跌价），**个别计价 / 先入先出法下批次即成本单元**；按核算单元配置、缺失回落全局默认并告警
- **为什么**：**三法是全系统的心脏**，且三法之间**差异最容易讲错**

### S2 `fin-owner-pricing` — 货主分层与两级作价（SR03_F03）

- **触发**：「货主分层」「一级货主 / 二级产权人」「一级货权转移价」「内部结算价」「自有均价池」「池化差异」「三个金额」
- **内容**：一级货主 = 法人主体（与账套同概念）、二级产权人 = 内部管理维度（**不进存货总额**）；一级 `transfer_price` 是**交易数据**（只取价 + 校验、不定价）、二级 `internal_price` 是**政策数据**（带生效期的价目表）；**二级自有均价池**；**一个数量、三个金额**里谁参与对平；**内部结算价只给转入方定价、转出方按自己账面口径扣**
- **为什么**：**全项目术语陷阱最多、口径最绕的一处**——「二级货主」是废弃称谓、`own_amount` 绝不加总进存货、`internal_amount` 不参与对平

### S3 `fin-negative-stock` — 负库存与跨期（SR03_F04 + SR01_F02）

- **触发**：「负库存」「挂账」「缺口上限」「最长挂账天数」「两阶段闭环」「锁账」「跨期补录」
- **内容**：**两阶段闭环**（`P_est` 锁定 → 冲平 → 入池）；三个配置项（允许负库存 / 缺口上限件数 / 最长挂账天数）与引擎行为的耦合；锁账与跨期的四条路；补录按当期口径、凭证日期 = 记账期间首日
- **为什么**：**分支最多、算例驱动**——规则与配置强耦合，是"配置改了引擎行为怎么变"的典型

### S4 `fin-provision` — 跌价准备（SR07_F01）

- **触发**：「跌价准备」「库龄法」「3C 上市周期法」「孰高」「双轨」
- **内容**：**库龄法 + 3C 上市周期法双轨、取孰高**（按商品类别配置）；**计提范围仅 `is_internal = 1`**；双轨分列
- **为什么**：规则**独立且反直觉**——"取孰高"和"仅内部"这两条最容易被漏

## 四、建议成 skill（2 个，可并入上面）

### S5 `fin-period-close` — 期间与锁账（SR07 期间部分）

日结**只校验**、月结**锁账**；反结账**须走审批并留痕**；跨期补记走**当期补录单**。
**可独立，也可并入 S3**（跨期本就是它的下游）。

### S6 `fin-data-intake` — 数据接入与校验（SR02 全部 + SR03_F01）

**两条通道（API / Excel·CSV）共用同一套字段 / 校验 / 幂等 / 错误回执**；**11 类单据**；错误码 `E-11` / `E-12` / `E-13` 等。
规则是「校验与幂等」，跨文档分散——**独立有价值，但比 S1–S4 薄**。

## 五、⚠️ 不建议做成 skill 的 12 个功能（本方案最重要的判断）

**它们全部是「展示层」**——价值在**列定义 + 取数口径**，不在业务规则：

| 功能 | 为什么不做 skill |
|---|---|
| SR01_F01 计价模型配置 | 是 S1 的**配置界面**，规则在 S1 |
| SR02_F01 业务源单据管理 / F02 原始数据处理 | CRUD |
| SR04_F01/F02/F03 结存流水 / 实时余额 / 余额管理报表 | 查询视图 |
| SR05_F01/F02/F03 三个台账 | 明细查询 |
| SR06_F01/F02/F03 核对表 / 成本波动表 / 负库存挂账表 | 监控报表 |
| SR07_F02 进销存周期表 | 报表 |
| SR08_F01/F02 凭证生成导出 / 价值回传 | 产出与接口，规则浅 |

### 但它们的「取数口径」值得一张共享表，而不是 12 个 skill

**页面一行是什么粒度、取哪张表、关键列是什么——这才是最容易搞错的地方。**

→ 建议 **一个薄的 `fin-report-specs`**，或**直接写进底座 `CLAUDE.md` 的附录**：

| 页 | 一行粒度 | 取数来源 | 备注 |
|---|---|---|---|
| P06 存货实时余额 | 二级产权人 × 一级货主 × 仓库 × 商品 × 资产类型 | 二级货主结存表 `t_owner_balance_l2` | 一级层均价与计价方法从核算单元继承；**与 P16 二级产权人页签逐列同序** |
| P16 余额管理报表 | 4 页签各异 | 见各页签 | 批次 17 / 仓库 10 / 一级货主 11 / 二级产权人 14 列 |
| … | | | |

## 六、数量建议

| 档 | 几个 | 组成 |
|---|---|---|
| **最小集** | **3** | 计价方法 · 货主分层两级作价 · 负库存与跨期 |
| **推荐** | **4–5** | + 跌价准备（+ 期间与锁账） |
| **上限** | **6** | + 数据接入 |

**超过 6 个就退化了**——那就是「把 22 个功能抄一遍」，成了文档目录，不是能力包。

---

## 七、与上一轮 5 个 skill 的关系

**两族正交**：

- 上一轮（`fin-consistency-audit` / `fin-cross-doc-sync` / `fin-prototype-edit` / `fin-calc-example` / `fin-doc-localize`）管 **「文档怎么改」**
- 这一轮（`fin-valuation` / `fin-owner-pricing` / …）管 **「产品是什么规则」**

⚠️ **触发词必须划清，否则互相抢**：

| 易混对 | 划法 |
|---|---|
| `fin-calc-example`（写算例） vs `fin-valuation`（讲计价规则） | 前者产出**逐笔推导**，后者产出**规则说明** |
| `fin-consistency-audit`（核对文档） vs `fin-report-specs`（查报表口径） | 前者**比两份文档**，后者**查一张表** |

## 八、落地顺序

1. **S1 `fin-valuation` + S2 `fin-owner-pricing`**——心脏 + 最绕，收益最大
2. **S3 `fin-negative-stock`**——分支最多
3. **S4 `fin-provision`** + **S5 `fin-period-close`**
4. **`fin-report-specs`**（薄，也可直接并入底座）
5. 可选：**S6 `fin-data-intake`**

---

## 九、要你拍板的 4 件事

1. **粒度**：按**规则簇**（推荐，4–5 个）／按 **SR 分组**（8 个）／按**页面**（16 个）？
2. **`fin-report-specs`** 单独成一个 skill，还是把口径表**直接塞进底座 `CLAUDE.md` 附录**？
3. **知识来源深度**：skill 里放**规则摘要 + 原文指针**（推荐），还是**尽量抄全文**？
   - 原文 **405 KB**，塞进 skill 不现实。skill 应该是**索引 + 易错点 + 判据树**，细节回原文（这也与「原文是唯一权威」的底座规则一致）。
4. **是否落地**：确认后我按 §八 顺序做，**每做完一个给你验一个**。
