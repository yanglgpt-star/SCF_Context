### 2.13 负库存全流程出图轮（2026-10-16）

**用户原话**：`负库存的流程考虑库存为0，没有加权平均价的，输出负库存的全流程，用mermaid输出`。

**交付**：新建 `财务库存中心（一期）负库存全流程_v1.0.md`（400 行 / 4 张图），既有文件零改动。

**★ 用户点名的边界，是原文的一处隐含缺口**

原文 `:4012` 写 `amount_delta = round(out_qty × 当前均价, 2)`——这个式子的前提是「当前均价存在」。但结存数量为 0 时，均价 = 金额 ÷ 数量**分母为 0、无定义**（原文 `:163` 显示 `—`）。

⇒ 若暂估单价来源配成 `MOVING_AVG_PRICE`（当前移动平均价），**在零态下必然取不到值**。本文的建议是回退到不读结存的来源：`LATEST_PO_PRICE`（最近采购订单价）→ `BENCHMARK_PRICE`（基准供货价）。**这是本文的建议，不是原口径。**

**另外两个本轮确认的判据**

1. **「库存为 0」分两种**：**干净零**（数量 0 且金额 0.00，核算单元真正清零）/ **脏零**（数量 0 但金额 ≠ 0，钱悬空）。安全前提靠 `F4`（出清处理）保证——**只判数量不判金额是不够的**。
2. **阶段二必须两步**（冲平缺口 + 剩余入池），并成一步会算错均价（算例里 13.500000 → 13.750000 的差别）。

**核心里程碑**：一期默认**禁止**负库存（负库存容差参数默认 0）；容差 > 0 才进两阶段闭环：阶段一按暂估单价 `P_est` 记负数量负金额、均价强制锁定、挂账 `OPEN`（挂账中·未冲平）；阶段二冲平后按实际入库成本重算。

### 2.14 重算逻辑出图轮（2026-10-16）

**用户原话**：`给出重算的逻辑`。

**交付**：新建 `财务库存中心（一期）重算逻辑_v1.0.md`（422 行 / 18,213 字符 / 5 张图），既有文件零改动。

**★ 本轮的起点判断：本项目「重算」指两个不同动作**

| | **动作 A · 重试计量** | **动作 B · 冲销后重放** |
|---|---|---|
| 作用对象 | **从未入账**的行（`cost_status`（核算状态）= `ROLLED_BACK`（已回滚）） | **已入账**的行（`cost_status` = `CALCULATED`（已核算）） |
| 有没有「已落的过账」要冲 | **没有** | **有**——必须先追加反向事件 |
| 入口 | P04 `[执行计算]` / `[批量执行计算]` / `[重新计算]` | 改单通知 / 作废清单 / 反结账审批 |

原文把两者写在了**同一张危险动作表**里，且两处描述互斥（§四.1 第 1 条）。

**组织轴 = 两个开关 → 五条路**

- 开关一：这笔账**记了没有** → `cost_status`（核算状态）三值 `PENDING`（待处理·挂起）/ `CALCULATED`（已核算）/ `ROLLED_BACK`（已回滚）。
- 开关二：那个期间**锁了没有** → `t_period.is_closed`（会计期间表·是否已锁账）。

| 路 | 触发 | 对象状态 | 动作 |
|---|---|---|---|
| **A** | 校验失败 / 数据修好 | `PENDING` / `ROLLED_BACK` | 重新触发计量，无历史要冲 |
| **1 改单** | 业务推改单通知 | `CALCULATED` + **期间未锁** | 追加反向事件 + 新正向事件（版本号 +1 / +1） |
| **2 作废红冲** | 业务推作废清单 | `CALCULATED` + **期间未锁** | 追加反向事件 + 红字凭证 + 红冲标记置 1 |
| **3 反结账** | 月结后发现**结错了** | **已锁账** | 十一步：申请 → 审批 → 开期间 → 锁单元 → 定位 → 追加修正事件 → **重放受影响区间** → 校验 → 快照版本 + 1 → 重建凭证 → 重新锁账 |
| **4 当期补录单** | 已锁账期间**漏了一笔** | **已锁账** | 必审，一律按当期口径量价，原业务日期仅供追溯 |

**四条铁律**：不物理删除（用红冲标记 / 红冲关联单号 / 版本号留痕）；凭证先红冲再重算；任何反向调整都写入 `t_calc_log`（计算过程留痕表）；已锁账期间禁止任何重算。

**总原则**：`t_calc_log` 是**只增不删的事件流、是真相源**；余额 / 报表 / 快照只是**投影**。**「事务回滚 ≠ 事件回滚」**——前者是技术手段且必须存在，后者已删除。⇒ 重算三段式 = **定位 → 追加 → 重放**，不是「还原 → 改数 → 重存」。

**重算之后必须重跑「重算 ≡ 投影」自检**（详细设计 `§9.5`）：重算只读事件流，**不读余额表**；同一维度键下数量、金额、均价逐项相等，不等即报错 + 告警。这是唯一能发现「余额与事件流已分叉、而两边外部对账各自都过」的校验。

**遗留**：§八 **8 条留白 / 冲突** + §8.1 **1 条派生落后**，见 §四.1。
