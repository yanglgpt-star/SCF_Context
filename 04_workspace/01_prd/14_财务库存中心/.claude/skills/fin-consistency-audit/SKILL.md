# 财务库存中心 · 多文档一致性核对

## 工作原则

1. **只读**：本 skill **绝不修改任何文件**。核对产出的是**分歧清单**，不是补丁。
2. **先定权威**：任何比对前，先确认「以谁为准」——见下节。**不得凭直觉选"看起来更全的那份"**。
3. **给行号**：每条分歧必须带 `文件:行`，否则用户无法核验。
4. **区分三类**：`真分歧`（口径冲突）／`派生落后`（派生件没跟上原文）／`已知待授权`（已在「已报未改」清单里）——**第三类不要重复上报为"新发现"**。
5. **前置读取**：开工前先读 `04_workspace/01_prd/14_财务库存中心/CLAUDE.md`，遵守其中的权威层级与三道门禁。

---

## 权威层级

```
财务库存中心（一期）需求文档 1.0（原型页面与核算引擎）.md   ← 唯一权威规格
        │
        ├── 通俗版 / 计算逻辑分册 / 计算示例        （派生）
        ├── 详细设计文档                          （schema 权威来源之一）
        ├── 整体PRD_v1.0.md / -原文件.md /（表与字段中文版）.md （派生）
        └── 原型页面.html / 原型说明_v1.0.md        （实现层）
```

冲突一律**以原文为准**。派生物之间冲突 → 都回到原文裁定。

---

## 核对流程

```
1. 明确范围 → 哪几份比对？是否含原型 HTML？
2. 读 CLAUDE.md → 载入权威层级与不动清单
3. 逐维度扫描（见下表）→ 记录 文件:行 + 现值
4. 回到原文取应然值
5. 分类（真分歧 / 派生落后 / 已知待授权）
6. 输出分歧清单，按严重度排序
7. 报告末尾附一句：「改动需单独授权」并列出可执行的传播动作
```

## 易分歧点清单（本项目的"老地方"）

| 维度 | 具体检查什么 |
|---|---|
| **金额口径** | 二级层是否「一个数量、三个金额」（`alloc_amount` / `internal_amount` / `own_amount`）；有没有哪份还停在**两金额** |
| **小数位** | 货币 4dp vs 6dp——**全项目并不存在单一小数位口径**，各文档对齐**它自己那页原型**；勿强行统一 |
| **单据号前缀** | 二级重分配：原文是 `OT-202603-0001`、PRD 曾写 `AL-202603-0001` |
| **维度名** | 一级货主 / 二级产权人；有没有残留已废弃的「二级货主」（**对象名除外**） |
| **页签与列数** | P16「余额管理报表」4 页签（批次 17 / 仓库 10 / 一级货主 11 / 二级产权人 14）；P06 与 P16 二级页签是否逐列同序 |
| **字段层级** | 字段分 L0–L4 五层；字段层默认冻结，被解冻的 3 组是哪几列 |
| **计价方法写法** | 正文有无裸 `MA` / `SI` / `FIFO` |
| **原型 `td` 英文码** | `tbody td` 里有无英文码（码只准进 `title`） |
| **示例一致性** | 合并均价是**加权**不是算术平均；`WH01` 10.250000 vs 10.750000 |

## 输出格式

```markdown

## 分歧清单

### 🔴 真分歧（口径冲突）
| # | 位置 | 现值 | 应然值 | 依据 |
|---|---|---|---|---|
| 1 | `B.md:1234` | … | … | 原文 `:567` |

### 🟡 派生落后
| # | 位置 | 现值 | 应然值 | 依据 |
|---|---|---|---|---|

### ⚪ 已知待授权（不重复上报）
| 项 | 位置 | 状态 |
|---|---|---|

## 建议的传播动作（**需单独授权**）
1. …
```

## 禁止操作

1. **不得顺手改文件**——哪怕改动"很明显"。改文件是 `fin-cross-doc-sync` 的事，且**必须先拿到单独授权**。
2. **不得把「已知待授权」项当成新发现**反复上报。
3. **不得强行统一小数位**——那条口径本来就不唯一。
4. **不得改「不动清单」里的东西**（changelog / 历史决策表 / markdownlint 告警）。
