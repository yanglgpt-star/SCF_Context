# 财务库存中心 · 跨文档口径同步

> ⚠️ **这是本项目风险最高的操作**：一次性批量改多份文档。**没有单独授权，一步都不许动。**

## 工作原则

1. **授权前置**：本 skill 的**第一步永远是"停下来要授权"**，不是"开始改"。
2. **授权一次性、不继承**：上个月同意传播 X ≠ 这次 Y 也可以。**每次都要重新拿**。
3. **备份先行**：本目录大半**未纳入 git**，动手前**必须**先备份（`tar` 或逐份 `.bak`）。
4. **零外溢**：改完必须用 `git status` + 文件计数证明**只有预期的那几份变了**。
5. **前置读取**：先读 `04_workspace/01_prd/14_财务库存中心/CLAUDE.md`——权威层级、三道门禁、不动清单都在那里。

---

## 强制流程（顺序不得颠倒）

```
① 出变更清单          不改文件。列：改什么、改哪几份、每份改几处、依据是什么
        ↓
② 停下，请求单独授权    ★ 这一步是整个 skill 的核心。用户没明确说"改"，
                         就停在这里，把清单交出去
        ↓
③ 备份                  tar 打包 或 逐份 .bak（本目录无 git 安全网）
        ↓
④ 逐份执行             按权威层级改：先改权威源，再改派生件
        ↓
⑤ 校验零外溢           git status --porcelain + 各文件行数/处数前后对比
        ↓
⑥ 报告                 改了哪几份、各几处、备份在哪、校验结果
```

## 本项目的"传播面"经验

一次口径改动通常要**同时**落到这几处（**逐份确认，不要漏也不要多**）：

- 原型 HTML（`财务库存中心（一期）原型页面.html`）
- 原文 `§三.x`（权威源，**先改这份**）
- 通俗版 对应小节
- `整体PRD_v1.0.md` **与** `整体PRD_v1.0-原文件.md`（**早一版，需与前者同步改**）
- 详细设计与分册的**活引用**（不含 changelog）

## 校验（第 ⑤ 步，必做）

```bash
cd "04_workspace/01_prd/14_财务库存中心"        # 或仓库根

# 1) 只应看到预期文件变化
git status --porcelain

# 2) 处数前后对比：改前记数、改后复count
grep -c "<旧串>" <文件>     # 应归 0
grep -c "<新串>" <文件>     # 应等于预期处数

# 3) 权威源与派生件同项一致
for f in <改了的那几份>; do grep -n "<新串>" "$f"; done
```

## 禁止操作

1. **未获单独授权就动手**——本 skill 存在的唯一理由就是拦住这件事。
2. **跳过备份**。
3. **改「故意不动」清单里的东西**。
4. **只改一半**（改了原文没改派生件，或漏掉 `-原文件.md`）。
5. **提交 commit**。
