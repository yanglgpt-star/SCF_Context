## 1. 概述

### 1.1 *系统的目标及概述

**一句话目标**：把**存货资产、货权与核算**从物理仓储作业里解耦出来，做成一本**可查、可对、可追溯**的账。

**为什么必须解耦。** 传统体系中，仓储物理作业（库位管理、拣货打包、批次移动）与逻辑资产核算（法定纳税主体、内部产权人毛利、单品移动均价）长期强耦合在同一套 WMS 里，由此产生四类矛盾：

| 矛盾 | 具体表现 |
|---|---|
| 权责与货位绑定 | 多法人实体、多内部产权人团队共用仓库时，实物移位频繁导致账面货权错乱 |
| 成本与毛利失真 | 数码 3C（计算机、通信、消费电子）价格波动剧烈、二手商品「一机一况一价」、车架号溯源强监管，传统加权平均无法反映单机真实利润 |
| 跨法人财税合规风险 | 跨公司调拨、代售在物理出库时未及时生成合规交易流水与开票依据，引发税务合规隐患 |
| 系统架构已达承载上限 | 实物作业高并发与财务核算强一致性相互制约，月结关账时无法阻断动态作业，历史报表无法定格 |

**解耦后的四层分工**（「作业、可用量、资产、凭证」彻底分离）：

| 系统层级 | 关注核心 | 系统职责与核心能力 | 关键数据指标 |
|---|---|---|---|
| 物理仓储中心（WMS） | 实物位置与作业效率 | 库位分配、波次拣货、实物盘点、SN / IMEI 扫描采集、交接装车 | 物理在架量、货位占用率 |
| 业务库存中心（IMS） | 销售调度与可用量控制 | 可用量计算、渠道配额切分、销售预占锁定、履约寻仓路由 | 业务可用量、预占量、在途量 |
| **财务库存中心（本系统）** | **存货资产、货权与核算** | **法人与内部管理账户、移动加权核算、负库存补差、内部转价、月结关账** | **账面结存量、结存均价、结存总金额、内部毛利** |
| 财务总账系统（金蝶） | 法定总账与报表凭证 | 接收本系统导出的标准凭证底稿、总账科目汇总、出具法定资产负债表与利润表 | 会计科目借贷余额、总账资产 |

> **口径界定**：财务库存中心的核心定位是**存货核算**。业务库存中心管**实物**，财务库存中心管**价值**，二者职责分离、同步建设；金蝶（ERP）现有存货核算功能无法满足精细化成本管理需求，本系统**不依赖**它。

**四条设计主线**（全文的功能需求都从这四条派生）：

| # | 主线 | 落点 |
|---|---|---|
| **① 货主分层** | 一级货主 = **法人主体**（与账套同一概念），二级货主 = **二级产权人** = 内部管理维度（可为个人 / 部门 / 事业部 / 代采项目）。均价池只在一级层建；**二级层另开一本管理口径的自有均价池** | `2.3` SR03_F03 |
| **② 三种计价并发** | 移动加权平均（全局默认） / 个别计价 / 先入先出法，按**核算单元** `(商品, 仓库, 一级货主)` 配置 | `2.3` SR03_F02 |
| **③ 期间与锁账** | 引入会计期间；**日结只校验、月结锁账**；反结账须审批留痕；跨期遗漏走当期补录单 | `2.3` SR03_F04 |
| **④ 价值回传** | 成本单价 / 库存金额 / 库龄 / 跌价准备按口径标注后回传业务侧，**两个金额口径并列** | `2.8` SR08_F02 |

### 1.3 约束条件

> 本节是全文的公共约定，各系统需求章节不再重复。**与本节冲突的表述以本节为准。**

#### 1.3.1 精度与舍入

| 字段类型 | 精度 | 处理 |
|---|---|---|
| 金额 | 2 位小数 | 每笔出库按 `round(数量 × 单价, 2)` 计算，差额进舍入差异 |
| 均价 | 6 位小数 | 入库后 `round(金额 ÷ 数量, 6)`，出库**不重算** |

**舍入差异只在出库产生**，由专门科目归集，月结时统一结转（模板见 `2.8` SR08_F01 的「舍入差异结转」）。

#### 1.3.2 维度与核算单元

| 概念 | 定义 | 用途 |
|---|---|---|
| 库存维度（四轴） | `(商品, 仓库, 批次, 一级货主)` | 余额表主键 |
| 存货核算单元 | `(商品, 仓库, 一级货主)` | **计价方法的作用粒度**（均价池 / 成本层 / 凭证 / 跌价基数的所有者） |

> 批次在移动加权平均下只影响库龄与跌价，**一期不进均价池**；在个别计价 / 先入先出法下，批次 / 成本层即成本单元。

**结存流水页的三个维度不是三套算法**，而是**同一批数据的三种分组**——数据同源、只有聚合键不同。三者共用同一套查询条件，切换维度只换分组键，**不换数据集、不换取数口径**。

| 维度 tab | 聚合键（分组键） | 取数表 | 跨货主行为 |
|---|---|---|---|
| 仓库维度 | `(仓库, 商品, 资产类型)` | `t_inventory_balance_unit`（核算单元层库存余额表·均价表） | **跨货主合并**——同仓、同商品下**所有**核算单元（各一级货主）合并为一行；**二级产权人不进核算单元**，不参与本维度合并 |
| 一级货主维度 | `(一级货主, 仓库, 商品, 资产类型)` | `t_inventory_balance_unit`（核算单元层库存余额表·均价表） | 不合并——**一个核算单元一行** |
| 二级产权人维度 | `(二级产权人, 一级货主, 仓库, 商品, 资产类型)` | `t_owner_balance_l2`（二级货主结存表） | 不合并——二级不建核算单元，一行 = 一个二级产权人 × 一级货主 × 仓库 × 商品 × 资产类型 |

**仓库维度的跨货主合并规则**（合并行必须可拆回，否则不可审计）：

| 列 | 合并算法 |
|---|---|
| `current_qty`（当前结存数量） | Σ 各核算单元数量，**直接求和** |
| `current_total_cost`（当前结存总额） | Σ 各核算单元金额，**直接求和** |
| `current_unit_cost`（当前结存均价） | 金额之和 ÷ 数量之和——**加权平均，不是各单元均价的算术平均**；分母为 0 时显示 `—` |
| `pricing_method`（计价模式） | 合并行内各核算单元方法**全同** → 显示该方法；**不同** → 显示 `混合`（灰底 Tag） |
| `has_negative`（负库存标记） | **任一**子单元为负即置位 |
| `updated_at`（最后更新时间） | 取子单元中的**最大值** |

**合并行的均价展示按方法分流**（混合行取更保守的一档）：

| 合并行内的方法 | `current_unit_cost`（当前结存均价）展示 |
|---|---|
| 全移动加权平均 | 派生均价 |
| 全先入先出法 | 派生均价 + 标注「派生 · 非计价依据」 |
| 全个别计价 | `--` |
| 混合、**不含**个别计价（移动加权平均 + 先入先出法） | 派生均价 + 标注「派生 · 混合口径」 |
| 混合、**含**个别计价 | **`--`** + Tag「混合口径 · 拆回货主看明细」 |

> **为什么含个别计价就压成 `--`**：合并行里个别计价单元的量会被一个加权均价掩盖，这正是「个别计价不显示均价」要避免的误导。宁可少给一个数，也不给一个会被读成「这批货就值这个单价」的数。

> **合并行必须可拆回**：仓库维度的 `[查看]` 行详情弹窗除当前行字段外，须列出**构成该行的核算单元明细**（一级货主 / 二级产权人 × 数量 / 金额 / 均价 / 计价模式）。没有这个出口，「跨货主合并」在审计上就是一笔糊涂账。

**维度间对平关系**（三个维度必须能互相验算，不平即数据有问题）：

| # | 等式 | 性质 |
|---|---|---|
| **V1** | Σ 仓库维度数量 = Σ 一级货主维度数量 = Σ 二级产权人维度数量 | **数量守恒**，同一查询范围下三者恒等 |
| **V2** | Σ 仓库维度金额 = Σ 一级货主维度金额 | **一级层金额守恒** |
| **V3** | Σ 二级维度金额（即 Σ `alloc_amount` 二级分摊金额）= 一级层金额 | **二级分摊可加总 · 会计口径**——引擎出口硬校验①，不平**整单回滚**。对平的是 `alloc_amount`（会计分摊），**不是** `own_amount`（自有成本） |
| **M1** | Σ 二级 `own_amount` + `D` = 一级层金额 | **管理口径**：池化差异 `D` 的定义式，**逐核算单元**；**日结校验**；与 V3 **并列成立**，不是它的替代 |
| **M3** | 对每个 (核算单元, 二级产权人)：`own_amount − alloc_amount` = 该二级分摊到的池化差异 | **管理口径 · 并排对账**（余额层）。两列**不相等是正常的**，差必须能解释；Σ 该差 = `−D` |

> **V1 的前提是「同一查询范围」**：仓库维度跨货主合并，一级 / 二级维度不合并，只有当三者命中**同一批核算单元**时等式才成立。**不要跨查询范围对平**。
>
> **V3 对平的是 `alloc_amount` 口径，不是存货总额口径**：V3 右侧是一级层**全部**金额（含外部法人 `is_internal = 0` 的部分）；而**存货总额**只累加一级层中 `is_internal = 1` 的金额，**二级层绝不相加**。`internal_amount`（二级内部结算金额）**不在任何维度展示**，也不参与上述任一等式——它按内部结算价累计，天然加总不回去，差额 = 二级内部未实现毛利（管理口径）。

**维度间的口径差异**（同一列名在不同维度下含义不同，必须按维度读）：

| 列 | 仓库维度 | 一级货主维度 | 二级产权人维度 |
|---|---|---|---|
| `current_unit_cost`（当前结存均价 · **会计口径**） | 合并行加权均价；**含个别计价则 `--`** | 核算单元的**权威均价**（移动加权平均单价即此值） | **不独立建会计均价池，继承所属一级层核算单元**；该单元为个别计价时**同样继承 `--`** |
| `current_total_cost`（当前结存总额 · **会计口径**） | 各核算单元金额**直接求和** | 核算单元金额（**权威**） | **派生值**：数量 × 所属核算单元当期**一级层均价**（不落库、不建会计均价池） |
| **`own_unit_price`（二级自有均价）** | **无此列** | **无此列** | **管理口径**：**该二级自己的**移动加权平均 = `own_amount ÷ qty`（派生 · **非计价依据**）。**与左侧一级层均价可以不同** |
| **`own_amount`（二级自有结存金额）** | **无此列** | **无此列** | **管理口径 · 落库**：二级自有均价池的结存金额。**与 `current_total_cost` 之差 = 该二级分摊到的池化差异** |
| `legal_owner_id`（一级货主） | **无此列**（已合并掉） | 分组键 | 归属一级货主 |
| `amiba_owner_id`（二级产权人） | **无此列**（已合并掉） | 无此列 | 分组键 |
| `batch_no`（批次号） | 恒为 `—` | 恒为 `—` | 恒为 `—` |

> **批次号在结存余额口径下三个维度都恒为 `—`**：核算单元是三轴聚合，批次不属于聚合键，强行展示会打散聚合。**仅记账流水口径**该列有值；批次层的现时存量另有专页承载（`2.4` SR04_F03 余额管理报表的**批次余额**页签）。

> ⚠️ **「数量 × 一级层均价」不是 `alloc_amount` 的通用算式——它只是「结存一侧」的派生写法，「发生额一侧」必须取实际结转额。两侧要分开读**：
> - **结存（报表展示这一侧）**：`current_total_cost` = 数量 × 该核算单元当期**一级层均价**。这里「一级层均价」的定义就是**结存金额 ÷ 结存数量**，所以这条等式**对三种方法都由构造成立**。
> - **发生额（引擎逐单过账这一侧）**：`alloc_amount_delta`（二级分摊金额增量）**必须取该行实际结转的一级层成本**。移动加权平均下两种写法等价；**个别计价 / 先入先出法下不等价**——一级层金额是各成本层的**和**，派生均价只是它的**商**，用 `数量增量 × 均价` 会算错，出口硬校验①当场不平、**整单回滚**。
> - 一句话：**结存看派生、发生额看实际。** 把结存一侧的派生写法搬去算发生额，是个别计价 / 先入先出法下最容易犯的错。

#### 1.3.3 货主分层硬约束（R1–R5）

| # | 规则 |
|---|---|
| **R1** | 一级货权转移**必作价、必出凭证、必产生会计损益** |
| **R2** | 二级重分配**必按内部结算价作价**，差额进二级内部损益（**管理口径**）；**不出会计凭证** |
| **R3** | **会计口径的存货均价池只在一级货主层建立**；二级层另维护内部结算价，并可另建**管理口径**的**二级自有均价池**（`own_amount` / `own_unit_price`） |
| **R4** | 存货总额 = Σ 一级层中 `is_internal = 1` 的金额（**二级层绝不相加**——**含二级自有均价池 `own_amount`**） |
| **R5** | **二级内部结算价与二级自有均价池都不影响会计**——一级层成本、存货总额、凭证、跌价基数均与其无关 |

> **`owner_l2`（二级产权人）必填，但它不是维度轴**：二级货主**每行必填**（缺失即 `E-OWNER-L2-MISSING`：二级货主缺失、行级拒绝），**R3 / R4 / R5 不变**——它**不进四轴** `(商品, 仓库, 批次, 一级货主)`、**不进核算单元键** `(商品, 仓库, 一级货主)`、**不进会计均价池、不进存货总额**。它回答「这笔货归谁经营」，不回答「这笔货值多少钱」——同一核算单元内多个二级货主**在会计口径上共用同一个均价**；而**管理口径上各有其价**，两者分开读、互不干扰。
>
> **注意区分两种「必填」**：本条说的是**数据行上的必填**（业务系统必须在每行推二级产权人）；各原型页面「搜索条件」表里二级产权人的「非必填」是**查询语义**（不填 = 不按二级过滤），**两者不冲突，不要改**。

**二级层「一个数量、三个金额」**：

| 金额 | 字段 | 算法 | 能否加总 | 用途 |
|---|---|---|---|---|
| 二级分摊金额 | `alloc_amount`（二级分摊金额） | **结存**：数量 × 一级均价（派生）；**发生额**：该行**实际结转的一级层成本**（⚠️ 个别计价 / 先入先出法不能走派生短路） | **能**——Σ `alloc_amount` = 一级层金额（引擎出口硬校验，不平整单回滚） | 二级数量与金额的成本还原（**会计口径**） |
| 二级内部结算金额 | `internal_amount`（二级内部结算金额） | 按 `internal_price`（内部结算价）逐笔累计 | **不能**——差额 = 内部未实现毛利，**不做等式校验** | 二级内部考核、内部结算损益（**管理口径**） |
| **二级自有结存金额** | **`own_amount`（二级自有结存金额）** | 二级自有均价池逐笔结转——入池按**实际成本**、出池按**该二级当期自有均价**、二级重分配**同额平移** | **不能**——与一级层金额之差 = **池化差异 `D`**（Σ `own_amount` + `D` = 一级层金额） | **该二级自己的**成本还原与考核（**管理口径**，**不进存货总额、不出凭证**） |

**二级自有均价池（管理口径）**

**要回答的问题**：二级产权人也该有**自己单独的均价**（「我名下这批货值多少钱」），而不是永远借所属核算单元的价。

**为什么不能做在会计口径上**：二级产权人**可为个人 / 部门 / 事业部 / 代采项目**，**不是法人、不是会计主体**。把均价池做在会计层，等于要求**个人持有会计级存货余额**，并且**存货总额**要在「一级层 Σ」与「二级层 Σ」之间二选一——与 R3 / R4 正面冲突。**所以会计侧一点不动**（出口硬校验 / V3 / 存货总额 / 凭证 / 跌价原样保留），二级层**另开一本管理口径的账**。

**入池 / 出池规则**（**按实际成本入池**）：

| 事件 | 一级层（会计） | 二级自有池（管理口径） |
|---|---|---|
| 采购入库 / 其他入库（挂二级 `i`） | `+A`（实际成本） | `own_amount: +A`（**同额**） |
| 销售出库 / 其他出库（挂二级 `i`） | −（数量 × 一级层当期池均价） | `own_amount: −`（数量 × 二级 `i` 当期自有均价） |
| **二级重分配（`i → j`）** | `0`（不出凭证、不动一级余额） | `i`：−（数量 × 自有均价`_i`）、`j`：+（数量 × 自有均价`_i`）（**同额平移**） |
| 调拨（同法人跨仓） | 调出 `−`、调入 `+同额` | 跟随：调出方二级 `−`、调入方二级 `+` |
| 一级货权转移（跨法人） | 转出 −（数量 × 池均价）；转入 **+（数量 × `transfer_price` 一级货权转移价）** | 转出方二级 −（数量 × 自有均价）；转入方二级 **+（数量 × 一级货权转移价）** |

三条概括：**① 入池额 = 该笔进入本核算单元一级层时的实际成本额；② 出池额 = 出池数量 × 该二级当期自有移动加权均价；③ 二级重分配是唯一例外——转入额直接取转出方的出池额**（保证本核算单元内的差异不因重分配而变动）。

**池化差异 `D`**（**核算单元级**，恒等式、派生、**不落库**）：

```
D = 一级层金额 − Σ(各二级 own_amount)
```

`D` **只在「二级自有出池价 ≠ 一级层对这一笔的出账价」时变动**（出库、跨核算单元动作），**二级重分配不动 `D`**。`D` **不进存货总额（R4）、不进跌价基数、不出凭证（R5）**——它是**管理口径的解释项**，回答「为什么二级加起来不等于一级」。

**对平式**：会计侧原样（V3 / 出口硬校验①）；管理侧新增 `M1`（Σ `own_amount` + `D` = 一级层金额，逐核算单元）与 `M3`（并排对账）。**两本账并排展示、互不加总**——`own_amount` 与 `alloc_amount` 的差就是该二级分摊到的池化差异。

> ⚠️ **个别计价 / 先入先出法单元下 `D` 更大**：一级层出池按**成本层逐件**结转，二级自有池按**自有均价**出池，两者的差在这些单元里可能明显大于移动加权平均单元。自有均价仍按 `own_amount ÷ qty` 实算，并标注「**派生 · 非计价依据**」——**它不是计价依据**，只用于二级考核与解释差异。
>
> ⚠️ **`M1` / `M3` 是恒等式，不是校验**：`D` 是「一级层金额 − Σ 自有金额」的**定义式重排**，自有数字怎么错，等式都成立。真正抓错的是**逐事件的出池价一致（`M2`）**与**余额层投影能重放（`E-13`：二级自有池结转不一致）**。详见 `2.3.1.6` 举例演练。

**口径标注**：库存金额标注`（存货口径·一级货主层·is_internal=1）`；库存数量标注`（权属口径·一级货主层）`或`（物理口径·仓库）`；内部结算损益与二级自有均价标注`（管理口径·非会计损益）`。**任何对外分发的报表与指标必须带口径标注。**

#### 1.3.4 取价三条铁律

**按业务日期取价** → **取到即快照**（写进单据行与 `t_calc_log` 计算过程留痕表）→ **调价不追溯**（历史单据不重算）。

> 五种价格类型（`price_type`，价格类型）全域：`biz_price`（业务价，业务侧原始报价）/ `cost_price`（存货成本价，本系统算出的均价，唯一真层）/ `transfer_price`（一级货权转移作价，交易数据，**财务只取价 + 校验，不定价**）/ `internal_price`（二级内部结算价，政策数据，带生效期价目表）/ `financing_fee`（资金占用 / 服务费，**一期未落地**）。

#### 1.3.5 过账顺序与幂等

| 机制 | 约定 |
|---|---|
| **排序键** | `(biz_date, seq_in_day)`（业务日期，当日序号），**全流程唯一决定「谁先谁后」的地方**；同日**入库优先**、同类型按单号；`doc_no`（业务单号）**不可**作排序键 |
| **传输幂等** | `batch_id + doc_no + line_no`（批次号 + 业务单号 + 单据行号）——防**同一条报文重推**（网络重试），由适配层负责 |
| **事件幂等** | `(doc_type, doc_no, version_no)`（单据类型 + 业务单号 + 版本号）——防**同一版本的同一单据被算两次**，由引擎负责 |
| **结果幂等** | 无键（**纯函数**）——只要输入相同，输出必相同，由计量函数本身负责 |

> **为什么必须三条都有**：只有传输幂等 → 业务侧从**两批**推出同一张单，重复入账；只有事件幂等 → 网络重试把一行推成两行，`line_no`（单据行号）相同但 `batch_id` 不同时仍会重复；两者都有但计量函数不纯 → 重放结果与当前余额不一致。

#### 1.3.7 期间与锁账

- **日结只校验，月结锁账**；
- 锁账后的三条路**不可互换**：**改单**（未锁账）、**反结账**（已锁账、结错了）、**当期补录单 `PERIOD_ADJUST`（跨期补录单）**（已锁账、漏一笔，一律按当期口径量价）；
- 反结账权限独立，危险动作须**二次确认 + 填写原因 + 审计日志**。

#### 1.3.8 危险动作与统一要求

**危险动作 = 执行后无法用「再执行一次」抵消的动作**：删除、撤销、启用期初、批量重算。这类动作**一律**走同一套流程，各页按钮表不再逐一重复：

| 要求 | 内容 |
|---|---|
| **二次确认** | 弹窗须列出**操作摘要**与**影响范围**（涉及多少行、影响哪些期间 / 核算单元），不允许只有一句「确定要删除吗」 |
| **填写原因** | **原因必填**，随操作写入审计日志 |
| **勾选确认项** | 弹窗内须有一个**必勾的确认项**（如「我已确认删除该规则，操作不可撤销」）；未勾选不可提交 |
| **审计日志** | 记录操作人 / 操作时间 / 原因 / 影响范围。**反结账另须独立权限** |

**一期危险动作清单**（新增危险动作须同步登记本表）：

| 页 | 动作 | 不可逆之处 |
|---|---|---|
| P01 计价模型配置 | `[删除 (仅未生效)]` | 删除后只能重建；且删除会改变 `priority`（优先级）序列 |
| P03 业务源单据管理 | `[批量重试记账]` | 批量重放记账，失败行的原记账结果被覆盖 |
| P04 原始数据处理 | `[批量执行计算]` / `[重新计算]` | 重算**先回滚已落的过账再重算**，产生新的 `journal_no`（记账流水号） |
| P12 库存表 | `[重新执行库龄推导 (异步任务)]` / `[生成跌价计提凭证建议]` | 异步重算覆盖当期推导结果 |
| P14 期初数据维护 | `[启用期初]` / `[删除]` | 启用后该期间**锁定**，只能靠反向单修正；删除按 `import_batch_id`（导入批次号）**整批撤销**，不做逐行恢复 |

> **`[反结账]` 同属危险动作**，但它在 `1.3.7` 已有完整定义（须审批留痕，记录谁 / 何时 / 因何 / 重开哪个月），**一期不设页面按钮**。
>
> **删除类动作必须重排序列**：删除落在**有序键**上的记录后，须按列表顺序重排剩余记录，**不允许留下断号**（如 `1, 2, 4, 5`）。`priority`（优先级）是路由排序键（数值越小越优先），断号会让排序比较失去确定含义。

##### 2.1.1.2 SR01_F01：〈计价模型配置〉

**2.1.1.2.1 *功能访问路径**

**导航路径**：`财务库存中心` → `配置管理` → `计价模型配置`

**后端菜单注册**：· 在 backend 中添加：「配置管理」>「计价模型配置」中的功能。

**前置条件**：当前用户具备**财务管理员**角色。**无前置数据依赖**——本页是全局配置的入口，可先于任何业务数据配置。

**页面定义**：〔图〕见原文 `§三.1 计价模型配置`（搜索条件 6 项 · 按钮 10 个 · 字段 12 项）。

**2.1.1.2.2 *功能描述**

**要解决的问题**：同一套库存里，不同品类的成本流转规律完全不同——标品手机可以按移动加权平均滚，二手「一机一况一价」必须逐台盯成本，快消与易腐品要按先来后到结转。**计价方法不能全局一刀切，必须能按核算单元分别配。**

**计价模型的作用粒度 = 核算单元**（`商品, 仓库, 一级货主`）。**不是商品、不是仓库、不是法人**单独一层，而是三者的组合。这是本系统最重要的一个粒度约定：均价池、成本层、凭证、跌价基数**全部**挂在这个粒度上。

**规则的四个作用域维度**（按优先级从细到粗）：

| 作用域 | 含义 | 举例 |
|---|---|---|
| 商品 | 精确到单个 SKU（商品编码） | 指定 `M0001` 用个别计价 |
| 一级货主 | 精确到法人主体 | 某法人主体下所有商品一律先入先出法 |
| 仓库 | 精确到仓库 | 海外仓一律先入先出法 |
| 商品类目 | 按商品类目粗配 | 「二手 3C」类目一律个别计价 |

**匹配规则（自上而下，命中即停）**：

| 顺序 | 规则 |
|---|---|
| 1 | 按 `priority`（优先级，**数值越小越优先**）升序逐条尝试匹配 |
| 2 | 一条规则最多在 1 个作用域维度上取值；**本页保存时不允许作用域维度的取值互相包含或冲突**（如「商品 `M0001`」与「商品类目 = 二手 3C」同时命中"二手 3C 下的 `M0001`"）——**命中冲突直接拒绝保存，提示冲突的两条规则** |
| 3 | **同一 `priority` 上不允许两条规则的作用域完全相同**——**保存即拒绝** |
| 4 | **全部规则都未命中**时，回落**全局默认 = 移动加权平均**，**并在 P03 / P04 的核算状态上给出「已回落全局默认」告警标记** |

> **为什么冲突要拒绝保存、而不是给一条隐式优先级**：计价方法决定钱怎么算。两条规则同时命中时，系统替用户"挑一条"，用户永远不知道自己配的哪条生效了。**宁可保存失败，也不给一个静默的选择。**

**三种计价方法的核心差异**：

| 计价方法 | 枚举值 | 入库定价 | 出库结转 | 均价展示 |
|---|---|---|---|---|
| **移动加权平均** | `MOVING_AVG` | 并入核算单元均价池，**重算均价** | 数量 × 当期均价 | **权威均价**（唯一真层） |
| **个别计价** | `INDIVIDUAL` | 按行上指定 SN 逐台建**成本层** | **按 SN 指定的成本层逐台结转** | `--`（**不显示均价**） |
| **先入先出法** | `FIFO` | 按批次建**成本层**，先入者在前 | 按成本层**先进先出**逐层结转 | 派生均价 + 标注「派生 · 非计价依据」 |

> **个别计价为什么必须隐藏均价**：个别计价的本质是「每台的成本就是它自己的成本」。给一个加权平均数，会被读成「这批货就值这个价」——那是移动加权平均的语义，不是个别计价的语义。**宁可少给一个数，也不给一个会被误读的数。**

**成本层**：个别计价 / 先入先出法启用**库存成本层表**（`t_inventory_layer`）承载批次 / SN 级成本。**关键约束：余额与全部报表口径不变**——成本层只是把「均价」这一层拆成「多层」，对外的数量、金额、报表形态与移动加权平均**完全一致**。

**生效期间与版本**：

| 规则 | 说明 |
|---|---|
| 生效期间不可重叠 | 同一作用域下两条规则的生效期间**不允许重叠**（重叠即拒绝保存） |
| 调价不追溯 | 修改计价方法**不回算历史单据**（`1.3.4` 取价三条铁律）；已核算的历史行按当时的方法定格 |
| 已生效规则的修改 | 只能「停用 + 新建」，**不允许就地改方法**——就地改会让同一 `rule_id` 在不同期间有两种含义，审计上不可解释 |
| 状态取值 | 未生效 / 生效中 / 已停用；同一作用域同一时刻**至多一条「生效中」** |

**危险动作**：

| 按钮 | 交互 |
|---|---|
| `[删除 (仅未生效)]` | 仅「未生效」规则可删；已生效规则**只能停用**。删除走 `1.3.8` 统一危险动作流程（二次确认 + 填原因 + 勾选确认项 + 审计日志）。**删除后须按列表顺序重排 `priority`，不留断号** |

##### 2.1.1.3 SR01_F02：〈负库存管理配置〉

**2.1.1.3.1 *功能访问路径**

**导航路径**：`财务库存中心` → `配置管理` → `负库存管理配置`

**后端菜单注册**：· 在 backend 中添加：「配置管理」>「负库存管理配置」中的功能。

**前置条件**：**财务管理员**角色。

**页面定义**：〔图〕见原文 `§三.2 负库存管理配置`（搜索条件 4 项 · 按钮 7 个 · 字段 10 项）。

**2.1.1.3.2 *功能描述**

**要解决的问题**：负库存是**真实存在**的——先出后入（先发货、后到票）在业务上无法避免。但负库存同时是**存货核算最危险的入口**：账面负数意味着均价池被除零或反向污染，一旦扩散，整个核算单元的数字不可信。

**因此本系统的负库存策略不是「禁止」，而是「受控允许 + 全部挂账 + 两阶段闭环」**：

| 阶段 | 动作 |
|---|---|
| **第一阶段（允许）** | 出库时账面不足，按配置**允许过账**，但必须：① 生成**负库存挂账记录**（落 `2.6` SR06_F03 负库存挂账表）；② 该核算单元的余额与均价标记为**待修正**；③ 触发告警 |
| **第二阶段（补正）** | 后续入库到达时，**自动按配置的补差策略**回填：先冲销挂账、再按实际入库成本重算均价，**挂账记录闭环关闭** |

**配置项**（四个维度）：

| 配置 | 取值 | 影响 |
|---|---|---|
| **允许负库存** | 允许 / 不允许 | 「不允许」时，账面不足的出库**直接拒绝**并回执 `E-NEGATIVE-QTY`（负数量错误），单据停在待处理 |
| **允许范围** | 按核算单元 / 按仓库 / 按一级货主 / 全局 | 决定这条配置的**作用粒度**；粒度越细越安全（推荐按核算单元） |
| **告警阈值** | 数量阈值 / 金额阈值 / 账龄天数 | 达到任一阈值即升级告警级别 |
| **补差策略** | 自动补差 / 手工补差 | 「自动补差」在入库时自动回填；「手工补差」须财务在 P04 或 P15 上手工执行 |

**关键约束**：

- **负库存期间该核算单元的均价不可用于任何对外报表**——报表必须显示 `—` 并附「该核算单元存在未平负库存」标注。用一个受污染的数当权威均价，比不给数危害大得多。
- **负库存挂账与 `E-NEGATIVE-QTY`（负数量错误）是两条不同的路**：配置为「允许」时走挂账（不报错、但留痕），配置为「不允许」时走错误码（拒单）。**两者不叠加**。
- 负库存记录**只增不删**——补正后关闭状态，记录本身留存（审计要求）。

**危险动作**：本页无删除类动作（配置变更即停用旧配置 + 新建）。

**2.2.1.2.2 *功能描述**

**要解决的问题**：业务侧推来的每一张单，财务侧必须能回答四个问题——**收没收到、能不能算、算没算、算错了怎么办**。本页就是这四个问题的落点。

**接入的两种通道（共用一套契约）**：

| 通道 | 用途 | 适配器 | 优先级 |

> **两条通道必须共用同一套字段 / 校验 / 幂等 / 错误回执**。否则同一张单走不同通道会得到不同的结果，差异无从排查。**协议层（REST / MQ / 文件、鉴权、调度、重试）尚未定型，但这不影响本页**——字段层已冻结，协议定型后只补映射、不改字段（见 `1.2` 应对）。

**报文信封（一个信封，五类内容）**：

| 信封字段 | 中文名 | 说明 |
|---|---|---|
| `batch_id` | 批次号 | **传输幂等键的组成部分** |
| `source_system` | 来源系统 | 推送方标识 |
| `schema_version` | 契约版本号 | 与本地不一致时回执 `E-SCHEMA-VERSION`（契约版本不符） |
| `object` | 内容类别 | 见下表五类 |
| `push_time` | 推送时间 | 推送方发出的时间 |

**五类 `object`（内容类别）**：

| `object` | 中文名 | 承载内容 |
|---|---|---|

**接入侧的校验（不通过即拒绝整条记录并回执）**：

| 校验类别 | 错误码 | 中文说明 |
|---|---|---|

| 主数据 | `E-MASTER-MISSING` | 主数据缺失（商品 / 仓库未登记） |
| 主数据 | `E-OWNER-L1-MISSING` | 一级货主缺失 |
| 主数据 | `E-OWNER-L2-MISSING` | **二级货主缺失（行级拒绝）** |
| 主数据 | `E-OWNER-L2-ORPHAN` | 二级货主未挂到任何一级货主 |
| 枚举 / 换算 | `E-ENUM-INVALID` | 枚举值非法（单据类型 / 资产类型等不在取值域内） |
| 枚举 / 换算 | `E-UNIT-CONV-MISSING` | 单位换算缺失 |
| 数量 / 金额 | `E-QTY-MISMATCH` | 数量不符（行数量与合计不符等） |
| 数量 / 金额 | `E-PRICE-MISSING` | 价格缺失（该取价口径下取不到价） |
| 数量 / 金额 | `E-NEGATIVE-QTY` | 负数量（配置为「不允许负库存」时） |
| 业务合法性 | `E-CROSS-LEGAL-ENTITY` | **跨法人**——业务推 `TRANSFER`（调拨）但两端属**不同**一级货主；**必须改推 `OWNER_TRANSFER`（一级货权转移）** |
| 业务合法性 | `E-SRC-DOC-MISSING` | 源单缺失（引用不到对应的原始单据） |
| 期间 | `E-PERIOD-CLOSED` | 期间已锁账 |

> **`E-CROSS-LEGAL-ENTITY` 是最容易踩的一个**：业务系统看到的只是"货从一个仓挪到另一个仓"，但在存货核算上，**跨法人的移动是销售 + 采购，不是移库**。业务推错了单据类型，系统**必须拒绝**并告诉它改推 `OWNER_TRANSFER`——**不能替它改成货权转移**，因为那等于系统替业务确认了一笔交易。

| 按接入状态筛选 | 接入状态（已接收 / 校验失败 / 已入账 / 记账失败）× 核算状态（待处理 / 已核算 / 已回滚）双状态筛选 |
| 查看回执 | 失败行展示**错误码 + 中文说明 + 出错字段** |
| **重试记账** | 单条重试 / `[批量重试记账]`；仅对「记账失败」行生效 |
| 穿透 | 从单据穿透到 `t_calc_log`（计算过程留痕表），看这一单当时取到了什么价、走了哪条规则 |

##### 2.2.1.3 SR02_F02：〈原始数据处理〉

**2.2.1.3.1 *功能访问路径**

**导航路径**：`财务库存中心` → `数据接入` → `原始数据处理`

**后端菜单注册**：· 在 backend 中添加：「数据接入」>「原始数据处理」中的功能。

**前置条件**：SR02_F01 已接入单据且校验通过。

**页面定义**：〔图〕见原文 `§三.4 原始数据处理`（搜索条件 14 项 · 按钮 10 个 · 字段 31 项）。

**2.2.1.3.2 *功能描述**

**要解决的问题**：接入的是**原始报文**（业务侧的表达），引擎要的是**事件**（本系统的表达）。中间这一步就是**标准化**——把报文翻译成引擎可重放、可排序、可幂等的事件流。

**标准化要产出的事件四要素**：

| 要素 | 说明 |
|---|---|
| **主体** | 核算单元 `(商品, 仓库, 一级货主)` + 资产类型 + 批次 + 二级产权人 |
| **方向与数量** | 带符号的数量增量 `delta_qty` |
| **取价依据** | 按 `1.3.4` 三条铁律在**业务日期**取价、**取到即快照** |
| **顺序键** | `(biz_date, seq_in_day)`（业务日期, 当日序号）——**全流程唯一决定谁先谁后的地方** |

> **`doc_no`（业务单号）绝不能用作排序键**：单号是字符串，长度与格式由业务侧决定，既不能保证同日同类型的有序，也不能保证跨日可比。用单号排序，等于把核算顺序交给业务侧的编号规则。

**本页是本系统的"作业台"**：财务操作员每天在这里看**待计算队列**、执行计算、处理失败行。

| 能力 | 说明 |
|---|---|
| 待计算队列 | 按 `(biz_date, seq_in_day)` 排序展示待计算事件 |
| `[批量执行计算]` | 执行选中的事件，走 `2.3` 核算引擎 |
| 单条执行 | 逐条执行，便于定位问题 |
| `[重新计算]` | **先回滚已落的过账再重算**，产生新的 `journal_no`（记账流水号） |
| 核算状态 | 待处理 `PENDING` / 已核算 `CALCULATED` / 已回滚 `ROLLED_BACK` |
| 计算过程查看 | 展示 `t_calc_log`（计算过程留痕表）：取价、命中规则、公式、舍入、结果 |

**危险动作**：

| 按钮 | 交互 |
|---|---|
| `[批量执行计算]` | **危险动作**（`1.3.8`）：批量过账，影响面大。二次确认须列出**涉及单据数 / 涉及核算单元数 / 影响期间** |
| `[重新计算]` | **危险动作**（`1.3.8`）：**先回滚再重算，产生新的 `journal_no`，原流水号作废**。原因必填 |

**必守的边界**：

- **重算不是"改一个数"**：它是**回滚 + 重放**，原过账结果被替换。因此重算后必须**重跑「重算 ≡ 投影」自检**（见 `2.6` SR06_F01），确认余额与事件流仍然一致。
- **已锁账期间的事件不可在此过账**，一律回执 `E-PERIOD-CLOSED`；跨期遗漏必须走**当期补录单 `PERIOD_ADJUST`**（见 `2.3` SR03_F04）。

##### 2.2.1.4 SR02_F03：〈期初数据维护〉

**2.2.1.4.1 *功能访问路径**

**导航路径**：`财务库存中心` → `数据接入` → `期初数据维护`

**后端菜单注册**：· 在 backend 中添加：「数据接入」>「期初数据维护」中的功能。

**前置条件**：**财务管理员**角色；期初期间尚未启用。

**页面定义**：〔图〕见原文 `§三.14 期初数据维护`（搜索条件 5 项 · 按钮 9 个 · 字段 17 项）。

**2.2.1.4.2 *功能描述**

**要解决的问题**：系统上线时，账面不是空的——存量商品、在途、货主归属都要有个起点。**期初不是"导入一批数据"，而是"给会计期间定一个由来"。**

**期初数据的内容**：按**四轴**（商品 / 仓库 / 批次 / 一级货主）+ 资产类型 + 二级产权人给出的**期初数量与期初金额**；金额同时要能给到二级分摊口径（`alloc_amount`）与管理口径（`own_amount`）两条线（口径见 `1.3.3`）。

**导入与校验流程**：

| 步骤 | 动作 | 校验 |
|---|---|---|
| 1 | 下载模板 / 导入文件 | 模板列与实际文件列不一致即整批拒绝 |
| 2 | 结构性校验 | 主数据存在（`E-MASTER-MISSING`）、货主完整（`E-OWNER-L1-MISSING` / `E-OWNER-L2-MISSING` / `E-OWNER-L2-ORPHAN`）、枚举合法（`E-ENUM-INVALID`） |
| 3 | 数值校验 | 数量 / 金额自洽（数量 × 单价 ≈ 金额）、**凭证不平不接受**（Σ借 ≠ Σ贷） |
| 4 | **试算** | 展示期初汇总：按一级货主 / 仓库 / 商品类目分组的数量与金额合计，供财务对照上期报表 |
| 5 | `[启用期初]` | **启用后该期间锁定** |
| 6 | 生成期初凭证 | 按 `2.8` SR08_F01，凭证日期 = **记账期间首日** |

**危险动作**：

| 按钮 | 交互 |
|---|---|
| `[启用期初]` | **危险动作**（`1.3.8`）：**启用后该期间锁定**，只能靠反向单修正。二次确认须展示**期初汇总数**（涉及多少核算单元 / 多少数量 / 多少金额），确认项须勾选 |
| `[删除]` | **危险动作**（`1.3.8`）：按 `import_batch_id`（导入批次号）**整批撤销**，**不做逐行恢复**。原因必填 |

> **为什么删除是整批撤销而不是挑行删**：期初是一组**同时生效**的余额，抽掉其中几行会让期间起点变成一个从未在现实中存在过的状态。**要么整批作废重新导，要么就是启用后的反向单修正。**

##### 2.2.1.5 举例演练

**场景**：某法人主体的一批二手手机，要按「个别计价」核算；业务侧推来的调拨单两端分属两个法人。

| 步 | 操作 | 系统行为 |
|---|---|---|
| 1 | 在 P01 配规则：作用域 = 商品类目「二手 3C」，计价方法 = 个别计价，`priority = 10` | 保存成功；`resolveMethod` 对该类目下任何 SKU 返回 `INDIVIDUAL` |
| 2 | 再配一条：作用域 = 商品 `M0001`，计价方法 = 先入先出法，`priority = 5` | 保存成功；`M0001` 命中 `priority=5` 的先入先出法（**更细 + 更优先**） |
| 3 | 试图再配：作用域 = 商品类目「二手 3C」，`priority = 10` | **拒绝保存**，提示与既有规则**作用域完全相同** |
| 4 | 业务侧推 `TRANSFER`（调拨），两端一级货主分别是 `OWN-A` / `OWN-B` | **整条记录拒绝**，回执 `E-CROSS-LEGAL-ENTITY`，提示改推 `OWNER_TRANSFER` |
| 5 | 业务侧改推 `OWNER_TRANSFER`，作价 18.000000 | 校验通过；转入方 `B@WH01` **按作价建成本层**（不是按转出方均价） |
| 6 | 在 P04 点 `[批量执行计算]` | 按 `(biz_date, seq_in_day)` 顺序过账；个别计价单元**按 SN 逐台结转**；每日结跑「重算 ≡ 投影」自检 |

**演练要点**：

1. **优先级数值越小越优先**，且**作用域越细越优先**——两条规则同时命中时按此择一；**范围完全相同才报冲突**。
2. **跨法人调拨是核算上的红线**：系统只拒绝、不代改。
3. **转入方按作价建层**：跨法人转移是**交易**，不是移库——转入方拿到的是**交易价**，不是转出方的账面成本。这一条决定了集团未实现损益的存在（见 `2.8` SR08_F01）。
4. 计算完成后**必须跑自检**——批量过账是本系统里影响面最大的动作。

##### 2.3.1.1 *系统功能需求列表

##### 2.3.1.2 SR03_F01：〈事件、顺序与幂等〉

**2.3.1.2.1 *功能访问路径**

**调用路径**：**非页面功能**——由 SR02_F02 的 `[批量执行计算]` / 单条执行触发，或由业务侧报文直接触发。**无独立页面**。

**后端菜单注册**：无需注册菜单。**引擎是后台服务**，仅通过 SR02_F02「原始数据处理」与本系统各报表间接使用。

**前置条件**：事件已由 SR02_F02 标准化产出且校验通过。

**2.3.1.2.2 *功能描述**

**引擎四层结构**（一个事件从进入到落账，走四层，各层各管一件事）：

| 层 | 名称 | 职责 | 关键约束 |
|---|---|---|---|
| **①** | **事件层** | 接收标准化事件，按 `(biz_date, seq_in_day)` 排序 | 事件**只增不删**（append-only） |
| **②** | **计量层** | 按计价方法算数量增量与金额增量 | 计量函数必须**纯**（结果幂等） |
| **③** | **记账层** | 落 `t_calc_log`（计算过程留痕表）与余额投影 | Σ借 = Σ贷；按法人分账 |
| **④** | **投影层** | 生成各报表口径的物化视图 | 投影必须能由事件流**重放**得到 |

**三条不变量**（贯穿四层，任何一条被破坏都是 P0）：

| # | 不变量 | 含义 | 破坏后果 |
|---|---|---|---|
| **①** | **事件是真相源，余额是投影** | `t_calc_log` 只增不删；余额表是它的物化结果 | 若把 `t_calc_log` 当"操作日志"，就会出现"改单 = 删旧行"→ **历史成本不可追溯** |
| **②** | **数量守恒** | 任一核算单元的期初 + Σ增量 = 期末 | 数量对不上意味着事件丢了或重复了 |
| **③** | **金额可还原** | 一级层金额 = Σ 成本层金额 = Σ 二级 `alloc_amount` | 金额对不上意味着取价或分摊出错 |

**事件"只增不删"下的三条路由**（这是本系统最容易被误解的一处）：

| 情形 | 路由 | 机制 | 不是 |
|---|---|---|---|
| **未锁账期间要改一张单** | **改单** | **追加两组事件**（reverse 反向 + new positive 新增正向），`version_no +1` | **不是**删了重来 |
| **已锁账、上次结错了** | **反结账** | 走审批 + 留痕（记录谁 / 何时 / 因何 / 重开哪个月），重开期间后按改单处理 | **不是**绕过锁账 |
| **已锁账、漏了一笔** | **当期补录单 `PERIOD_ADJUST`** | 一律按**当期口径**的量价补记（**不回填历史期间**） | **不是**反结账 |

> **改单为什么必须是"追加反向事件 + 追加正向事件"，而不是 UPDATE 原行**：
> 若直接改原行，**历史成本就不可追溯了**——三个月后有人问"这批货在 6 月 15 日那天账面值多少"，系统答不出当时的数，因为那一行已经被改过。**追加反向事件**的写法下，6 月 15 日的余额仍然是可重放的，**反向事件本身带着"何时被冲销、为何被冲销"的信息**。
>
> **反结账与当期补录单是两条路，不能互换**：反结账的前提是"上次结账这个动作错了"（结账本身的错），补录单的前提是"结账没问题，只是漏了一笔业务"。用补录单去修结账错误，等于用一个业务单据去掩盖一个程序性错误。

**排序与幂等**：排序键 `(biz_date, seq_in_day)`、三条幂等（传输 / 事件 / 结果）的完整定义见 `1.3.5`，此处不重复。**引擎额外承担的是"事件幂等"这一层**（`(doc_type, doc_no, version_no)`）——**同一版本的同一单据被算两次时必须被拦住**。

**迟到单据的处理**：按业务日期**插入历史位置重算**（不是追加到当天）。**已锁账期间 → 回执 `E-PERIOD-CLOSED`（期间已锁账）**，改走当期补录单。

**引擎侧错误码**（与 `2.2.1.2.2` 的 14 个**接入**错误码**是两套**，不要混用）：

| 错误码 | 中文说明 |
|---|---|
| `E-01` | 同日排序规则违反（同日未按"入库优先、同类型按单号"） |
| `E-02` | **批次行校验不平**（作用域限定为**批次行**）：批次行金额之和 ≠ 该核算单元均价行金额 |
| `E-03` | 期间状态非法（对该期间执行了不允许的操作） |
| `E-05` | 迟到单据插入失败 |
| `E-06` | 事件流被删改（重放结果与余额不一致） |
| `E-07` | 已锁账期间被写入 |
| `E-09` | 反结账未按审批留痕流程执行 |
| `E-11` | 负库存挂账未闭环 |
| `E-12` | 二级结存投影不一致 |
| `E-13` | **二级自有池结转不一致**（逐事件出池价写入错误 / 投影无法重放） |

> **`E-02` 的作用域是"批次行"**，不是"整个核算单元"——这一点在个别计价 / 先入先出法下尤其重要：一个核算单元内多个批次各自对平，才对得上"批次行金额之和 = 均价行金额"。

##### 2.3.1.3 SR03_F02：〈三种计价方法〉

**2.3.1.3.1 *功能访问路径**

**调用路径**：**非页面功能**。配置入口在 `2.1` SR01_F01「计价模型配置」；结果呈现在 `2.4`–`2.7` 的全部报表与台账页。

**后端菜单注册**：无需注册菜单。

**前置条件**：该核算单元的计价方法已由 SR01_F01 解析得到（`resolveMethod`）。

**2.3.1.3.2 *功能描述**

#### 一、入库定价

**移动加权平均**的入库定价（**F1 公式**）：

```
新均价 = round( (原结存金额 + 本次入库金额) ÷ (原结存数量 + 本次入库数量), 6 )
```

| 规则 | 说明 |
|---|---|
| **原结存数量 = 0** | 均价 = `round(本次入库金额 ÷ 本次入库数量, 6)`；**入库不回改金额** |
| **原结存金额为负**（负库存未平） | **不允许并入均价池**——该核算单元的入库先进挂账补正流程（`2.3` SR03_F04），补正后才重算均价 |
| 数量精度 | 4 位小数，直接参与计算，不额外舍入 |
| 金额精度 | 2 位小数 |
| 单价精度 | **6 位小数**，入库后算出 |

**含税口径（红线）**：

| 项 | 处理 |
|---|---|
| 入库成本的入账口径 | **不含税成本**（价税分离）。采购入库时按价税分离后的**不含税金额**入成本 |
| 进项税额 | **单列进项税科目**，不进存货成本 |
| 为什么是红线 | 若误把含税金额计入成本，**存货虚增、进项税少计**，而**总账仍然平**（借贷都变大），**月末根本查不出来**——只能靠口径写死在这里来防 |

**三种方法的入库差异**：

| 方法 | 入库动作 |
|---|---|
| 移动加权平均 | 并入均价池，重算均价（F1） |
| 个别计价 | 按行上**指定的 SN** 逐台建**成本层**，各层成本互不影响 |
| 先入先出法 | 按**批次**建成本层，先入库的层排在前面 |

**暂估与到票（采购入库的两个阶段）**：采购入库先按**暂估成本**入账、后按**到票实际成本**调整差额。调整**只动差额**，不动已结转的出库成本（**调价不追溯**，见 `1.3.4`）。

#### 二、出库结转

| 方法 | 出库金额 | 舍入 |
|---|---|---|
| **移动加权平均** | `round(出库数量 × 当期均价, 2)` | 差额进**舍入差异** |
| **个别计价** | **按行上指定 SN 对应的成本层**逐台结转（**不按均价**） | 逐台取层，无均价舍入 |
| **先入先出法** | 按成本层**先进先出**逐层结转，跨层时按各层成本分拆 | 逐层取层，无均价舍入 |

**舍入差异**：

- **只在出库产生**（入库不回改金额，所以入库不产生）；
- 由**专门科目**归集；
- **月结时统一结转**（凭证模板见 `2.8` SR08_F01 的「舍入差异结转」）；
- **均价出库后不重算**：`单价 6 位 → 金额 2 位` 的舍入差**不回写均价**，否则均价会随出库次数漂移。

#### 三、三种方法对报表口径的统一

**这是本节最容易被忽略、也最重要的一条**：

| 统一项 | 说明 |
|---|---|
| **数量口径** | 三种方法**完全一致**——数量不因计价方法而变化 |
| **金额口径** | 三种方法**完全一致**——结存金额 = Σ 成本层金额；**成本层只是把"均价"这一层拆成"多层"** |
| **报表形态** | 三种方法**完全一致**——同一套页面、同一套列、同一套对平式 |
| **唯一差异** | **均价的展示**：移动加权平均给权威均价；个别计价**给 `--`**；先入先出法给**派生均价 + 「派生 · 非计价依据」标注** |
| **`E-02` 一律生效** | 「批次行金额之和 = 均价行金额」对**三种方法**都成立（这正是成本层与均价层的关系） |

> **为什么敢于说"报表口径不变"**：因为成本层是**均价层的细化**，不是**另一套账**。Σ 成本层金额 ≡ 均价层金额是**由构造成立**的——每一笔入库都同时写"均价层 +1 笔"和"成本层 +1 层"，出库时两边同步减。所以对外的数量、金额、报表形态**一个字都不用改**。

#### 四、必守边界

| 边界 | 说明 |
|---|---|
| **按核算单元串行** | 同一核算单元内的事件**必须串行**处理（否则均价池会并发污染）；**跨核算单元可并行** |
| **锁按维度键顺序获取** | 防死锁（`1.3.9`） |
| **计量层是纯函数** | 结果幂等由计量层自己保证（`1.3.5`） |
| **负库存期间的均价不可对外** | 见 `2.1` SR01_F02 |

##### 2.3.1.4 SR03_F03：〈货主分层与两级作价〉

**2.3.1.4.1 *功能访问路径**

**调用路径**：**非页面功能**。规则定义见 `1.3.3`（R1–R5）；结果呈现在 `2.4` SR04_F01「结存流水数据」的三个维度与 `2.5` SR05_F01「存货记账明细台账」。

**后端菜单注册**：无需注册菜单。

**前置条件**：单据行上带**一级货主 + 二级产权人**（二级产权人**行级必填**）。

**2.3.1.4.2 *功能描述**

**一级与二级的分工**：

| 层级 | 是什么 | 是不是会计主体 | 均价池 | 出凭证 | 进存货总额 |
|---|---|---|---|---|---|
| **一级货主** | = **法人主体**（与账套同一概念） | **是** | **有**（会计口径，唯一权威） | **有** | **进**（限 `is_internal = 1`） |
| **二级产权人** | 内部管理维度（可为个人 / 部门 / 事业部 / 代采项目） | **否** | **另有**一本**管理口径**的自有均价池 | **不出** | **不进** |

**两级作价的两种来源**（这是"两级"的实质）：

| 层级 | 价格类型 | 中文名 | 性质 | 财务的角色 |
|---|---|---|---|---|
| 一级 | `transfer_price` | 一级货权转移价 | **交易数据** | **只取价 + 校验，不定价** |
| 二级 | `internal_price` | 二级内部结算价 | **政策数据**（带生效期的价目表：固定价 `FIXED` / 成本加成率 `MARKUP`） | 维护价目表 |

> **一级作价是"交易数据"这句话的含义**：跨法人转移在核算上**是一笔销售 + 一笔采购**，所以价格必须由业务侧以**交易事实**给出。**财务系统不能替它定价**——替它定价等于财务替业务确认了交易价格，这是审计上最忌讳的一类越权。

**五类动作在两级上的写法**（本节的规则表，唯一出处）：

| 事件 | 一级层（会计） | 二级自有池（管理口径） |
|---|---|---|
| 采购入库 / 其他入库（挂二级 `i`） | `+A`（实际成本） | `own_amount: +A`（**同额**） |
| 销售出库 / 其他出库（挂二级 `i`） | −（数量 × 一级层当期池均价） | `own_amount: −`（数量 × 二级 `i` 当期**自有均价**） |
| **二级重分配（`i → j`）** | **`0`**（不动一级余额、不出凭证） | `i`：−（数量 × 自有均价`_i`）、`j`：**+ 同一个数**（**同额平移**） |
| 调拨（**同法人**跨仓） | 调出 `−`、调入 `+`**同额** | 跟随：调出方二级 `−`、调入方二级 `+` |
| **一级货权转移（跨法人）** | 转出 −（数量 × 池均价）；转入 **+（数量 × `transfer_price`）** | 转出方二级 −（数量 × 自有均价）；转入方二级 **+（数量 × 一级货权转移价）** |

三条概括：

1. **入池额 = 该笔进入本核算单元一级层时的实际成本额**；
2. **出池额 = 出池数量 × 该二级当期自有移动加权均价**；
3. **二级重分配是唯一例外——转入额直接取转出方的出池额**（保证本核算单元内的差异不因重分配而变动）。

**二级层「一个数量、三个金额」**（完整定义见 `1.3.3`）：

| 金额 | 能否加总 | 用途 |
|---|---|---|
| `alloc_amount`（二级分摊金额） | **能**（Σ = 一级层金额，硬校验） | 会计口径的成本还原 |
| `internal_amount`（二级内部结算金额） | **不能** | 二级内部考核（管理口径） |
| `own_amount`（二级自有结存金额） | **不能**（与一级层之差 = 池化差异 `D`） | 该二级自己的成本还原（管理口径） |

**池化差异 `D`**（核算单元级 · 派生 · **不落库**）：

```
D = 一级层金额 − Σ(各二级 own_amount)
```

`D` **只在「二级自有出池价 ≠ 一级层对这一笔的出账价」时变动**（出库、跨核算单元动作）；**二级重分配不动 `D`**。`D` **不进存货总额（R4）、不进跌价基数、不出凭证（R5）**。

**口径分叉（三条并存的线，不要混读）**：

| 线 | 等式 | 是不是校验 |
|---|---|---|
| **V3**（会计） | Σ `alloc_amount` = 一级层金额 | **是硬校验**——不平**整单回滚** |
| **M1**（管理） | Σ `own_amount` + `D` = 一级层金额 | **是恒等式，不是校验** |
| **M3**（管理 · 并排对账） | `own_amount − alloc_amount` = 该二级分摊到的池化差异 | **是恒等式，不是校验** |

> ⚠️ **`M1` / `M3` 抓不到错，`M2` 与 `E-13` 才抓得到。** `D` 是"一级层金额 − Σ 自有金额"的**定义式重排**：自有数字怎么错，等式都成立。真正抓错的是：
> - **`M2`（逐事件）**：任一出池行的 `own_amount_delta` 必须 = `delta_qty` × **该二级当期自有均价**（**二级重分配的转入行是显式例外**——它取转出方的出池额）；
> - **`E-13`（余额层）**：`t_owner_balance_l2.own_amount` 必须等于从 `t_owner_allocation`（二级分摊账）**重放**出来的 Σ `own_amount`。
>
> 「两列对上了」≠「算对了」。这条必须在 UAT 里单独验。

##### 2.3.1.5 SR03_F04：〈负库存与跨期处理〉

**2.3.1.5.1 *功能访问路径**

**调用路径**：**非页面功能**。配置入口在 `2.1` SR01_F02「负库存管理配置」；挂账结果呈现在 `2.6` SR06_F03「负库存挂账表」；期间状态影响全部页面。

**后端菜单注册**：无需注册菜单。**`[反结账]` 一期不设页面按钮**，走线下审批 + 后台执行（`1.3.7`）。

**前置条件**：该核算单元的负库存策略与期间状态已解析。

**2.3.1.5.2 *功能描述**

**一、负库存两阶段闭环**

| 阶段 | 触发 | 引擎动作 |
|---|---|---|
| **① 允许并挂账** | 出库时账面数量不足，且策略 = 允许 | 按策略**允许过账**；生成**挂账记录**；该核算单元标记「待修正」；**均价对外置 `—`** |
| **② 补正并闭环** | 后续入库到达 | 先**冲销挂账**、再按实际入库成本**重算均价**；挂账记录**闭环关闭** |

**闭环的三个硬约束**：

| 约束 | 说明 |
|---|---|
| **不允许"只记账、不动库存"的便捷开关** | **设计禁令**——那等于给空转业务（虚进虚出）发工具。数量与金额必须**同进同出** |
| **负库存期间的均价不得进对外报表** | 报表显示 `—` + 「该核算单元存在未平负库存」标注 |
| **挂账记录只增不删** | 补正后关闭状态，记录本身留存 |

**二、四条路的边界（锁账之后不能乱走）**

| 路 | 前提 | 做法 | 回执 / 校验 |
|---|---|---|---|
| **正常过账** | 期间未锁账 | 按 `(biz_date, seq_in_day)` 顺序过账 | — |
| **改单** | 期间**未**锁账 | 追加 **reverse + new positive** 两组事件，`version_no +1` | 幂等键含 `version_no` |
| **反结账** | 期间**已**锁账，且**上次结账本身错了** | 审批 + 留痕 → 重开期间 → 改单 | `E-09`（未按流程执行） |
| **当期补录单 `PERIOD_ADJUST`** | 期间**已**锁账，且**只是漏了一笔** | 一律按**当期口径**的量价补记，**不回填历史期间** | **不新增凭证模板**（复用既有模板） |

**三、锁账规则**

- **日结只校验**（数量对账、`M1` 校验、「重算 ≡ 投影」自检）；
- **月结锁账**（`t_period.is_closed`）；
- 已锁账期间写入 → `E-07`；已锁账期间被访问的操作类型非法 → `E-03`；
- **反结账权限独立**，与日常核算权限分离。

**四、自检（必须跑的三次）**

**「重算 ≡ 投影」自检**：同一批事件用**两条路**（引擎重算 / 余额投影重建）各算一遍，**结果必须相等**。

| 何时跑 | 范围 |
|---|---|
| **日结** | 当日增量 |
| **月结** | **全量** |
| **反结账 / 跨期补录后** | **必须重跑** |

> **为什么必须有这条自检**：本系统存在一类**外部对账查不出来**的故障——某笔**增量落库成功而事件写日志失败**（或反之），于是**余额与事件流分叉**。此时的表象是：**数量仍对得上业务快照、金额仍对得上总账**，两个外部对账**都通过**，但系统内部已经不自洽。这条自检是唯一能抓到它的手段。

##### 2.3.1.6 举例演练

**演练一：移动加权平均的入库与出库**（原文 `§四.3.1` / `§四.3.2`）

**起点**：商品 `M0001`（标品手机），移动加权平均；仓库 `WH01`；一级货主 `OWN-A`；期初为 0。

| 序 | 业务日期 | 单号 | 单据类型 | 动作 | 过账后（数量 / 金额 / 均价） |
|---|---|---|---|---|---|
| 1 | 2026-04-02 | `PO-202604-0001` | 采购入库 `PO_IN` | +100 台 @ 10.000000 = 1,000.00 | 100 / 1,000.00 / **10.000000** |
| 2 | 2026-04-05 | `PO-202604-0002` | 采购入库 `PO_IN` | +100 台 @ 20.000000 = 2,000.00 | 200 / 3,000.00 / **round(3,000.00 ÷ 200, 6) = 15.000000** |
| 3 | 2026-04-12 | `SO-202604-0001` | 销售出库 `SO_OUT` | −50 台 | 150 / 2,250.00 / **均价不变 15.000000** |

**第 3 步的算式**：`round(50 × 15.000000, 2) = 750.00`；`2,250.00 = 3,000.00 − 750.00`；**出库不重算均价**（15.000000 保持）——这正是"单价 6 位、金额 2 位、出库不回写均价"三条精度规则的合力。

**演练二：一级与二级产权人结存**（原文 `§四.3.2.11`）

**起点**：商品 `M0001`（移动加权平均）；仓库 `WH01` / `WH02`；一级货主 `OWN-A` / `OWN-B`；二级产权人 `OWN-A-1`（A·电商事业部）/ `OWN-A-2`（A·线下事业部）/ `OWN-B-1`（B·直营事业部）；资产类型一律 `OWN`（自有）。三个核算单元：`A@WH01` / `A@WH02` / `B@WH01`。

**单据序列**：

| # | 日期 | 单据 | 单号 | 动作 |
|---|---|---|---|---|
| 1 | 03-02 | 采购入库 | `PO-202603-0001` | `OWN-A@WH01` +100 @ 10.000000 |
| 2 | 03-05 | 采购入库 | `PO-202603-0002` | `OWN-A@WH02` +50 @ 12.000000 |
| 3 | 03-08 | **二级重分配 `OWNER_REASSIGN`** | `AL-202603-0001` | `OWN-A-1 → OWN-A-2`，`WH01` 20 件，内部结算价 11.000000 |
| 4 | 03-12 | 销售出库 | `SO-202603-0001` | `OWN-A-1` 出 30（`WH01`） |
| 5 | 03-18 | **一级货权转移 `OWNER_TRANSFER`** | `OT-202603-0001` | `OWN-A → OWN-B`，`WH01` 20 件，作价 11.500000 |
| 6 | 03-25 | 销售出库 | `SO-202603-0002` | `OWN-B-1` 出 10（`WH01`） |

**三个维度的结存**：

| 维度 | 结存 |
|---|---|
| **仓库维度**（跨货主合并） | `WH01` 60 / 615.00；`WH02` 50 / 600.00；**合计 110 / 1,215.00** |

**池化差异 `D`**（`D` = 该核算单元一级层金额 − 该单元 Σ `own_amount`，**逐核算单元算、带符号**）：

| 核算单元 | 一级层金额 | 单元内 Σ `own_amount` | 池化差异 `D` |
|---|---|---|---|
| `A@WH01` | 500.00 | 300.00 + 200.00 = 500.00 | **0.00** |
| `A@WH02` | 600.00 | 600.00 | **0.00** |
| `B@WH01` | 115.00 | 115.00 | **0.00** |
| **合计** | **1,215.00** | **1,215.00** | **0.00** |

> ⚠️ **本例 `D` 全域为 0，是巧合、不是恒等**——每个二级的**入池价恰好等于所在核算单元的一级层均价**：`OWN-A-1` 在 `A@WH01` / `A@WH02` 的入池价就是本单元均价（10.000000 / 12.000000）；`OWN-A-2` 按转出方自有均价 10.000000 平移进来，仍等于本单元均价；`OWN-B-1` 按作价 11.500000 入池，而 `B@WH01` 的一级层均价正是 11.500000。**一旦二级入池价与所属单元均价出现价差，`own_amount` 与 `alloc_amount` 两列立刻分开**——价差算例见《财务库存中心（一期）计算逻辑（通俗版）》`§四`「二级自有均价池：同一核算单元内两个二级各有其价」与 `§五`。
>
> **自有均价逐核算单元滚，同一个二级在两个单元里各有其价**：`OWN-A-1` 在 `A@WH01` 是 10.000000、在 `A@WH02` 是 12.000000——粒度与一级层均价相同。**别把它当成「一个二级一个价」。**

三条读法：

1. **`alloc_amount` 逐笔都按一级层成本口径**：重分配两侧各 ±（20 × 10.000000）= ±200.00，**在同一个核算单元内相抵为 0**——这正是「重分配不动一级层」在二级层的投影；货权转移**转入侧按作价**（20 × 11.500000 = 230.00）、**转出侧按一级层均价**（20 × 10.000000 = 200.00），差 **30.00** 就是**集团内未实现损益**（见下方合并口径）。`alloc_amount` 因此**可加总**，且合计必然等于一级层金额——这就是 V3 的出口硬校验①。
2. **`internal_amount` 只在重分配上偏离 `alloc_amount`，且只差在转入侧**：`OWN-A-2` 记 +220.00（20 × 内部结算价 11.000000）而不是 +200.00，差 **20.00** = 20 × (11.000000 − 10.000000) = **二级内部未实现毛利**。**转出侧按转出方自己的账面口径扣**——若两侧都按内部结算价记，这两个数会在同一个核算单元内自我抵消，`internal_amount` 就永远等于 `alloc_amount`，「差额 = 内部未实现毛利」这条也就落不了地。
3. **`own_amount` 是第三个金额，走管理口径的自有均价池**（`2.3.1.4`）：**入池按实际成本、出池按该二级自己的当期自有均价、二级重分配同额平移**，与左边两列**并排展示、互不加总**。`OWN-A-2` 三列对照最能说明问题——`alloc_amount` **200.00** / `own_amount` **200.00** / `internal_amount` **220.00**：**多出来的 20.00 只活在内部结算口径里**，**既不进会计等式、也不进自有池**，这正是 R5「二级内部结算价与二级自有均价池都不影响会计」的落点。
4. **三条对平在二级层都能复算**：`V3` Σ `alloc_amount` = 1,215.00 = 一级层金额 ✓；`M1` Σ `own_amount` + `D` = 1,215.00 + 0.00 = 1,215.00 ✓；`M3` Σ(`own_amount` − `alloc_amount`) = 0.00 = −`D` ✓。⚠️ **`M1` / `M3` 是恒等式、不是校验**——`D` 就是「一级层金额 − Σ `own_amount`」的**定义式**，自有数字怎么错 `D` 就跟着错成多少，两条式子**永远成立**。**真正抓错的是 `M2`（逐事件出池价一致，二级重分配的转入行是显式例外）与 `E-13`（余额层投影能重放）。**

> **三个维度对同一批单据给出的数量必须相等（110）**（→ V1）；**一级货主维度与仓库维度的金额也必须相等（1,215.00）**（→ V2）；**二级维度的 `alloc_amount` 合计同样等于 1,215.00**（→ V3）。三者**互为验算**，下一节直接验。

**对平验算**：

| # | 验算 | 结果 |
|---|---|---|
| **V1** | Σ仓库数量 110 = Σ一级数量 110 = Σ二级数量 110 | ✅ |
| **V2** | Σ仓库金额 1,215.00 = Σ一级金额 1,215.00 | ✅ |
| **V3** | Σ二级 `alloc_amount` 1,215.00 = 一级层金额 1,215.00（**即出口硬校验①**） | ✅ |
| **`M1`** | Σ二级 `own_amount` 1,215.00 + 池化差异 `D` 0.00 = 一级层金额 1,215.00（**管理口径**） | ✅ |
| **`M3`** | Σ(`own_amount` − `alloc_amount`) 0.00 = −`D`（**并排对账**） | ✅ |

**合并口径（单独一段，不要与上面三张表混读）**：一级货权转移跨法人，`OWN-B` 取得成本中含 20 × (11.500000 − 10.000000) = 30.00 的**未实现内部损益**；其中已售 10 件**已实现**、剩余 10 件**未实现 5.00**。按集团内未实现损益抵消（`2.8` SR08_F01 的抵消模板）后，**集团存货 = 1,100.00 + 115.00 − 5.00 = 1,210.00**，与未抵消口径 1,215.00 差 5.00。

> **这里必须分清两个口径**：**对平（V1 / V2 / V3）验的是"三个投影是否同源"，用未抵消口径**；**存货总额用抵消后口径**。**不要拿 1,210.00 去和 1,215.00 对**——它们回答的是两个不同的问题。

**个别计价 / 先入先出法下的关键差异**：

- 同一套流水，若核算单元配**个别计价**，出库**不按均价结转**，而是**按行上指定的 SN 逐台取成本层**；
- **★ `alloc_amount` 不能沿用「数量 × 一级均价」这条短路**，必须 = **该行实际结转的一级层成本（逐 SN 归集）**，否则 **V3 硬校验① 当场不平**；
- **反例**：某单元 4 台合计 49,000.00、派生均价 12,250.000000；出 1 台 `SN-0003`（实际成本 11,500.00）——按均价算是 12,250.00、实际结转 11,500.00，**差 750.00 → 不自平 → 整单回滚 + 告警**；
- **另注**：`unit_price`（移动平均单价）在个别计价单元**仍是派生值**（结存金额 ÷ 结存数量），仍须满足 `E-02`。**这就是 P16 余额管理报表·批次余额页签上「移动平均单价」与「成本层单价」两列并存的原因**：前者是对账 / 展示用的加权平均，**后者才是计价依据**。

**演练要点**：

1. **R3**：会计口径的均价池**只在一级货主层**建立；二级层另有**管理口径**的自有均价池。
2. **R4**：存货总额 = Σ 一级层中 `is_internal = 1` 的金额；**二级层绝不相加**（**含二级自有均价池**）。
3. **R2**：二级重分配**不出会计凭证**，差额进二级内部损益（管理口径）。
4. **`alloc_amount` 能加总，`internal_amount` 不能**——这是"会计口径"与"管理口径"的分水岭。
5. **个别计价 / 先入先出法下 `alloc_amount` 必须逐 SN / 逐层归集**，不能走派生均价短路。
6. **`E-12`（二级结存投影不一致）**：二级结存表是分摊账的**物化投影**，两者必须一致。
7. **二级结果是「一个数量、三个金额」**：`alloc_amount`（会计分摊）**能**加总回一级层（V3 / 出口硬校验①）；`internal_amount`（内部结算）**不能**；`own_amount`（自有成本）**也不能**——Σ `own_amount` + 池化差异 `D` 才等于一级层金额（`M1`，**管理口径**）。报表上**并排展示 `alloc_amount` + `own_amount` 两列**与一列派生自有均价，`internal_amount` **不展示、不进任何等式**。

**演练三：负库存的两阶段闭环**（原文 `§四.4 异常处理`）

**起点**：商品 `M0001`（标品手机，移动加权平均）；仓库 `WH01`；一级货主 `OWN-A`；资产类型 `OWN`（自有）；**期初为 0**。

**策略**（`2.1` SR01_F02 的 P02 页面）：**允许负库存**（`allow_negative` = 1）；缺口上限 50 件（`max_negative_qty`）；最长挂账 7 天（`max_pending_days`）；暂估取价来源 = 最近采购订单价（`LATEST_PO_PRICE`）——该核算单元此前最近一张采购订单价 = 10.000000，故 **`P_est`（暂估单价）= 10.000000**。

> ⚠️ **本例能走通，前提是这条策略配成了「允许负库存」。** 配成「不允许」（`allow_negative` = 0）时，第 1 步不会挂账，而是**当场拒单**、回执 `E-NEGATIVE-QTY`（负数量错误），单据停在待处理——**根本没有挂账这条线**。

| 序 | 日期 | 单号 | 动作 | 引擎动作（数量 / 金额 / 均价） |
|---|---|---|---|---|
| 1 | 04-02 | `SO-202604-0001` | 销售出库 30 台 | 余额 `0 − 30` = **−30 台**；金额 `−round(30 × 10.000000, 2)` = **−300.00**；**均价强制锁定为 `P_est` = 10.000000**；写挂账记录（`2.6` SR06_F03），`resolve_status`（冲平状态）= **未冲平**，`negative_qty` = −30、`est_out_cost` = 10.000000；`cost_status` = `PENDING`（待处理·挂起） |
| 2 | 04-05 | `PO-202604-0003` | 采购入库 50 台 @ 12.000000 = 600.00 | ① **先冲平缺口** ΔQ = 30：`+30 台 / +round(30 × 10.000000, 2) = +300.00` → 余额归零；② **剩余 50 − 30 = 20 台按实际成本入池**：`+20 台 / +round(20 × 12.000000, 2) = +240.00` → 结存 **20 台 / 240.00 / 12.000000** |
| 3 | 04-05 | 自动 | 价差结转 | `cost_diff_amount`（成本补差金额）= (`P_actual` 12.000000 − `P_est` 10.000000) × ΔQ 30 = **60.00** → 自动出【成本调整单 `COST_ADJUST`】计损益；`resolve_status` 转**已冲平**；`cost_status` 转 `CALCULATED`（已核算） |
| 4 | 04-05 | 日结 | 校验 | 数量对账 + `M1` + **「重算 ≡ 投影」自检**全过；`E-11`（负库存挂账未闭环）不再报出 |

**钱的账**（这一步必须平，不平就说明算错了）：

| 去向 | 算式 | 金额 |
|---|---|---|
| 暂估出库成本（进销成本） | 30 × `P_est` 10.000000 | 300.00 |
| 成本调整单（补进销成本） | `cost_diff_amount` | +60.00 |
| **已售 30 台最终成本** | 30 × `P_actual` 12.000000 | **360.00** |
| 在库结存 | 20 × 12.000000 | **240.00** |
| **合计** | 360.00 + 240.00 | **600.00** = 采购入库金额 ✓ |

**三条读法**：

1. **均价是「锁定」的，不是「算」出来的**：期初为 0 时 `金额 ÷ 数量` = 0 ÷ 0，**除法无解**——`−300.00 ÷ (−30)` 这个式子根本不存在。所以负库存出库的结存均价**必须**直接取 `P_est` 锁定（`2.1` SR01_F02 的 `est_price_source` 行）；**不要**理解成"算出来恰好等于 10.000000"，换个 `P_est`，除法给出的会是一个虚假均价。
2. **冲平与入池是两步，不能一把压进池子**：把 600.00 直接加到 −300.00 上，得到 `20 台 / 300.00 / 15.000000`——**错**。正确顺序是**先按 `P_est` 把缺口归零、再把剩余按 `P_actual` 入池**。
3. **价差走成本调整单、不回写原分录**：60.00 计进损益，**已售 30 台的原始出库分录不动**——这就是「调价不追溯」（`1.3.4`）。另外：负库存期间的均价**不可对外**（`2.4` SR04_F02 显示 `—` + 标注）；挂账记录**只增不删**（`2.6` SR06_F03）。

**演练四：锁账与跨期处理（四条路的对照）**（原文 `§四.4` 五、人工处置路径）

**起点**：承接演练三的期末状态——`04` 期月结锁账时，`A@WH01` 结存 **20 台 / 240.00 / 12.000000**。`05-06` 发现 `04` 期在 `04-28` 漏推了一张采购入库 `PO-202604-0009`（100 台 @ 13.000000 = 1,300.00）。

**先看走哪条路**（四条路各管一段，**不能互换**）：

| 情形 | 走哪条路 | 引擎动作 | 落在哪一期 |
|---|---|---|---|
| 期间正常未锁账 | **正常过账** | 按 `(biz_date, seq_in_day)` 顺序过账 | 当期 |
| `04` 期**未**锁账 | **改单** | 追加 **reverse + new positive** 两组事件，`version_no + 1`；幂等键含 `version_no` | 仍是 `04` 期 |
| `04` 期**已**锁账，且**上次结账本身错了** | **反结账** | 审批 + 留痕（谁 / 何时 / 因何 / 重开哪个月），`reopen_count`（反结账次数）+ 1 → 重开 `04` 期 → 再按改单处理 | 重开后的 `04` 期 |
| `04` 期**已**锁账，只是**漏了一笔**（**本例**） | **当期补录单 `PERIOD_ADJUST`**（跨期补录单） | 一张**独立类型**的单据，**一律按当期（`05` 期）口径的量价**补记；原业务日期只进摘要与追溯字段；**不回填 `04` 期** | `05` 期 |

**本例走 `PERIOD_ADJUST`，逐笔**：

| 序 | 动作 | 引擎动作（数量 / 金额 / 均价） |
|---|---|---|
| 1 | 补录单落库 | 单据类型 `PERIOD_ADJUST`（跨期补录单）；`biz_date`（业务日期）= 补录归属日 `05-06`；原业务日期 `04-28` 只进摘要与追溯字段 |
| 2 | 按**当期口径**取量价 | `+100 台 @ 13.000000 = +1,300.00`——**不沿用 `04` 期口径**，即使 `04` 期当时的结存均价是 12.000000 |
| 3 | `05` 期过账 | `20 + 100` = **120 台**；`240.00 + 1,300.00` = **1,540.00**；均价 `round(1,540.00 ÷ 120, 6)` = **12.833333** |
| 4 | 出凭证 | **不新增凭证模板**（`2.8` SR08_F01），复用既有入库模板；**凭证日期 = 记账期间首日**（`05-01`）——**不是**补录当天，**也不是**原业务日期 `04-28` |
| 5 | `04` 期 | **一个数字都没变**：`20 台 / 240.00 / 12.000000` 原样保留、仍可查；`04` 期不重算、不重出报表 |
| 6 | 自检 | 跨期补录后**必须重跑**「重算 ≡ 投影」自检 |

> ⚠️ **第 4 步最容易做错**：`04-28` 的业务、`05-06` 的补录、`05-01` 的记账期间首日——三个日期各有各的用途。**凭证日期必须落在补录单记账的那个期间**（`05` 期首日），原业务日期只用来追溯；若凭证日期取"系统当前日期"，跨期补录的凭证就会落错期间。

**四条边界**（都是回执，不是静默处理）：

| 触发 | 回执 |
|---|---|
| `04` 期已锁账时**直接往 `04` 期写** | `E-07`（已锁账期间被写入） |
| 对已锁账期间发起**非法操作类型** | `E-03`（期间状态非法） |
| 反结账**未按审批留痕流程**执行 | `E-09`（反结账未按审批留痕流程执行） |
| 挂账未闭环 | `E-11`（负库存挂账未闭环）——日结校验 |

**两条读法**：

1. **补录单修不了「结错」，反结账修不了「漏单」**：补录的语义是「这笔在 `04` 期**从未存在**」；结错的语义是「`04` 期**有这笔、但做错了**」。**用补录去修结错，等于用一个业务单据去掩盖一个程序性错误**——审计上再也分不清「错误」与「遗漏」。
2. **没锁账就别开补录单**：`04` 期未锁账时走**改单**（reverse + new positive，`version_no + 1`），历史里留下可追溯的改单链。补录单是**已锁账期间的专用通道**，不是常规修数工具。

**页面定义**：〔图〕见原文 `§三.5 结存流水数据`（搜索条件 16 项 · 按钮 8 个 · **字段 96 项，分三个维度变体**）。

**2.4.1.2.2 *功能描述**

**本页的核心设计：三个维度不是三套算法，是同一批数据的三种分组。**

| 维度 tab | 聚合键（分组键） | 取数表 | 跨货主行为 |
|---|---|---|---|
| **仓库维度** | `(仓库, 商品, 资产类型)` | 核算单元层库存余额表（`t_inventory_balance_unit`） | **跨货主合并**——同仓、同商品下**所有**核算单元（各一级货主）合并为一行；**二级产权人不进核算单元**，不参与本维度合并 |
| **一级货主维度** | `(一级货主, 仓库, 商品, 资产类型)` | 核算单元层库存余额表（`t_inventory_balance_unit`） | 不合并——**一个核算单元一行** |
| **二级产权人维度** | `(二级产权人, 一级货主, 仓库, 商品, 资产类型)` | 二级货主结存表（`t_owner_balance_l2`） | 不合并——一行 = 一个二级产权人 × 一级货主 × 仓库 × 商品 × 资产类型 |

**切换维度只换分组键，不换数据集、不换取数口径**——这是本页最重要的一条读法。三者共用同一套查询条件。

**仓库维度的跨货主合并规则**（合并行必须可拆回，否则不可审计）：

| 列 | 合并算法 |
|---|---|
| `current_qty`（当前结存数量） | Σ 各核算单元数量，**直接求和** |
| `current_total_cost`（当前结存总额） | Σ 各核算单元金额，**直接求和** |
| `current_unit_cost`（当前结存均价） | 金额之和 ÷ 数量之和——**加权平均，不是各单元均价的算术平均**；分母为 0 时显示 `—` |
| `pricing_method`（计价模式） | 合并行内各核算单元方法**全同** → 显示该方法；**不同** → 显示 `混合`（灰底 Tag） |
| `has_negative`（负库存标记） | **任一**子单元为负即置位 |
| `updated_at`（最后更新时间） | 取子单元中的**最大值** |

**合并行的均价展示按方法分流**（混合行取更保守的一档）：

| 合并行内的方法 | `current_unit_cost`（当前结存均价）展示 |
|---|---|
| 全移动加权平均 | 派生均价 |
| 全先入先出法 | 派生均价 + 标注「派生 · 非计价依据」 |
| **全个别计价** | **`--`** |
| 混合、**不含**个别计价（移动加权平均 + 先入先出法） | 派生均价 + 标注「派生 · 混合口径」 |
| **混合、含个别计价** | **`--`** + Tag「混合口径 · 拆回货主看明细」 |

> **为什么含个别计价就压成 `--`**：合并行里个别计价单元的量会被一个加权均价掩盖，这正是"个别计价不显示均价"要避免的误导。**宁可少给一个数，也不给一个会被读成「这批货就值这个单价」的数。**

> **合并行必须可拆回**：仓库维度的 `[查看]` 行详情弹窗除当前行字段外，**须列出构成该行的核算单元明细**（一级货主 / 二级产权人 × 数量 / 金额 / 均价 / 计价模式）。**没有这个出口，「跨货主合并」在审计上就是一笔糊涂账。**

**同一列名在不同维度下含义不同**（必须按维度读）：

| 列 | 仓库维度 | 一级货主维度 | 二级产权人维度 |
|---|---|---|---|
| `current_unit_cost`（当前结存均价 · **会计口径**） | 合并行加权均价；**含个别计价则 `--`** | 核算单元的**权威均价**（移动加权平均单价即此值） | **不独立建会计均价池，继承所属一级层核算单元**；该单元为个别计价时**同样继承 `--`** |
| `current_total_cost`（当前结存总额 · **会计口径**） | 各核算单元金额**直接求和** | 核算单元金额（**权威**） | **派生值**：数量 × 所属核算单元当期**一级层均价**（**不落库**） |
| **`own_unit_price`（二级自有均价）** | **无此列** | **无此列** | **管理口径**：该二级自己的移动加权平均 = `own_amount ÷ qty`（派生 · **非计价依据**） |
| **`own_amount`（二级自有结存金额）** | **无此列** | **无此列** | **管理口径 · 落库**；与 `current_total_cost` 之差 = 该二级分摊到的池化差异 |
| `batch_no`（批次号） | 恒为 `—` | 恒为 `—` | 恒为 `—` |

> **批次号在结存余额口径下三个维度都恒为 `—`**：核算单元是三轴聚合，批次不属于聚合键，**强行展示会打散聚合**。**仅记账流水口径**该列有值（见 `2.5` SR05_F01）；批次层的现时存量另由 `2.4` SR04_F03 承载。

> ⚠️ **「数量 × 一级层均价」不是 `alloc_amount` 的通用算式**——它只是**结存一侧**的派生写法；**发生额一侧必须取实际结转额**。移动加权平均下两种写法等价；**个别计价 / 先入先出法下不等价**（一级层金额是各成本层的**和**，派生均价只是它的**商**）。把结存一侧的派生写法搬去算发生额，**是个别计价 / 先入先出法下最容易犯的错**——出口硬校验①会当场不平、整单回滚。

**维度间对平**（完整定义与前提见 `1.3.2`）：V1 数量守恒 · V2 一级层金额守恒 · V3 Σ `alloc_amount` = 一级层金额（**硬校验**）· M1 / M3（**恒等式，不是校验**）。

| 三维度切换 | 换分组键，不换数据集 |
| `[查看]` | 行详情弹窗；**仓库维度须列出构成明细**（可拆回） |
| `[导出]` | 导出 CSV，**每次最多导出 25,000 行**；导出字段为**当前维度结果集的全部字段** |
| 导出条数选择 | 点击导出时可通过下拉菜单选择需要导出的条数 |
| 结果集排序 | 按分组键升序（查询结果集必须按指定的键升序排列） |

##### 2.4.1.4 SR04_F03：〈余额管理报表〉

**2.4.1.4.1 *功能访问路径**

**导航路径**：`财务库存中心` → `结存查询` → `余额管理报表`（页内四个页签：批次余额 / 仓库余额 / 一级货主余额 / 二级产权人余额）

**后端菜单注册**：· 在 backend 中添加：「结存查询」>「余额管理报表」中的功能。

**前置条件**：**批次余额页签**要求商品为**批次管理**品类（`is_batch_managed` 是物料主数据属性），**非批次管理品类不出现在「批次余额」页签**；**其余三个页签（仓库 / 一级货主 / 二级产权人）不受此限**。

**页面定义**：〔图〕见原文 `§三.16 余额管理报表`——**四个页签**（批次余额 / 仓库余额 / 一级货主余额 / 二级产权人余额），搜索条件 **9** 项 · 按钮 **6** 个 · 字段 **52** 项（**17 / 10 / 11 / 14**，四个页签各一组）。原文 `§三.16` 对四个页签各给一张字段说明表。

**2.4.1.4.2 *功能描述**

**要解决的问题**：**批次层的现时存量在别处没有落点。** 结存流水数据的三轴聚合把批次打散（`batch_no` 恒为 `—`）；`2.5` SR05_F03「存货计价批次追踪」追的是**采购批次的暂估 → 到票**（一进一出对账），**不是余额管理**。本页补的正是这个缺口。

**本页 = P05 的三种分组视图 + 一个批次层副本**：**仓库余额 / 一级货主余额 / 二级产权人余额三个页签就是 P05 结存余额口径的三种分组视图**（列集与取数表完全一致，不新增口径）；**批次余额页签是本页的增量**——**它是 P05 的批次层副本**（同一份数据上多一个批次轴）：

| 对比 | P05 结存流水数据 | **P16 余额管理报表 · 批次余额页签** |
|---|---|---|
| 轴 | 三轴（商品 / 仓库 / 一级货主） | 三轴 **+ 批次轴 + 二级产权人轴** |
| 数量来源 | 核算单元层余额表 / 二级货主结存表 | **二级货主分摊账**（按 $(核算单元, batch\_no, owner\_l2)$ 归集） |
| 用途 | "按维度看结存" | "这个批次现在剩多少、值多少、放了多久" |

> **为什么数量取二级分摊账**：**同时带 `batch_no` 与 `owner_l2` 两轴的只有二级货主分摊账**——批次层库存余额表没有二级轴，二级货主结存表没有批次轴，**两条余额表各缺一轴，谁单独都撑不起本页**。按 $(核算单元, batch\_no, owner\_l2)$ 归集分摊账，等价于**给二级货主结存表补上一个批次轴**。

**两条恒等式（日结必须校验）**：

| # | 等式 | 对平的轴 |
|---|---|---|
| ① | Σ<sub>owner_l2</sub> 本页签 `qty` = 该批次的批次层结存数量（`t_inventory_balance_batch.qty`） | **批次轴上的对平** |
| ② | Σ<sub>batch_no</sub> 本页签 `qty`（同一核算单元 × 同一二级产权人）= P05 二级产权人维度对应各行的 `current_qty` **合计** | **二级轴上的对平** |

> **② 要按「合计」读**：二级货主结存表的键含**资产类型**，而本页签没有这一轴（自有与受托代销的量按批次天然分开，**同一批次不会跨资产类型**），故只能与其各资产类型行**合计**对平。
>
> **两条等式都只对批次管理品类成立。**

**两列均价并存（批次余额页签的关键设计）**：

| 列 | 含义 | 为什么要有 |
|---|---|---|
| `unit_price`（移动平均单价 · **一级层**） | **恒等于**同一核算单元均价行的 `unit_price`，日结逐行校验 `E-02` | 对账 / 展示用的**加权平均**——**三种方法一律生效** |
| `layer_unit_cost`（成本层单价） | **仅个别计价 / 先入先出法单元有值**；移动加权平均单元恒为 `—` | **才是计价依据**——个别计价 / 先入先出法的出库按它结转 |

> **两列并存不是冗余**：`E-02`（批次行校验）靠 `unit_price` 恒等来兜底，而**实际出库成本**靠 `layer_unit_cost` 逐层取。**前者是对账口径，后者是计价口径**——混用会把个别计价的账算错。
>
> **`E-02` 的作用域是「批次行」**：同一核算单元内所有**批次行**共用同一个一级层均价、恒等；**不含二级产权人行**——二级产权人有自己的价（`own_unit_price` / `own_amount`），`E-02` 不覆盖它。

**管理口径两列**（`own_unit_price` / `own_amount`）：与会计口径的 `amount` / `unit_price` **并排展示、互不加总**；两列之差 = 该行分摊到的池化差异（`1.3.3`）。`own_amount` **不进存货总额（R4）、不出凭证（R5）**。

**库龄六桶**：`aging_bucket`（库龄区间）取值 **0-30 / 31-60 / 61-90 / 91-180 / 181-360 / 360 天以上**，**口径与 `2.7` SR07_F01 库存表的六桶一致，不另立边界**。

**其他规则**：

- **零余额批次行仍然保留**（`qty = 0`），用于**追溯已出清的批次**——出清的批次不能被"清理"掉，它对账时要能查到；
- **批次是核算单元内部的成本明细，不是一条新的核算轴**：`(商品, 仓库, 一级货主)` 仍是核算单元，**均价池、加锁、凭证、跌价都不受影响**；
- **二级产权人不是会计轴**：同一核算单元内多个二级产权人**在会计口径上共用同一个一级层均价**，故**批次余额页签**的 `amount` / `unit_price` 与二级产权人**无关**，一律取所属核算单元的一级层现行值；**同一页的「二级产权人余额」页签另有管理口径的 `own_unit_price` / `own_amount` 两列**，两者并排、互不加总。

##### 2.4.1.5 举例演练

**场景（承 `2.3.1.6` 演练二的结存）**：`WH01` 上同商品 `M0001` 有三行核算单元数据——`OWN-A`（移动加权平均，60 台 / 615.00）、`OWN-B`（个别计价，20 台 / 300.00）。

| 步 | 维度 | 看到什么 |
|---|---|---|
| 1 | **一级货主维度** | 两行：`OWN-A@WH01` 60 / 615.00 / **均价 10.250000**；`OWN-B@WH01` 20 / 300.00 / **`--`** |
| 2 | **仓库维度**（跨货主合并） | **一行**：`WH01` 80 / 915.00；均价 = `915.00 ÷ 80` = **11.437500**；计价模式显示 **`混合`** |
| 3 | 观察均价列 | 因合并行**含个别计价** → 均价压成 **`--`** + Tag「混合口径 · 拆回货主看明细」 |
| 4 | 点该行 `[查看]` | 弹窗除当前行外，**列出构成明细**：`OWN-A` 60 / 615.00 / 10.250000 / 移动加权平均；`OWN-B` 20 / 300.00 / `--` / 个别计价 |
| 5 | 对平 | **V1**：Σ仓库 80 = Σ一级 (60 + 20) 80 ✓ ｜ **V2**：Σ仓库 915.00 = Σ一级 (615.00 + 300.00) 915.00 ✓ |

**演练要点**：

1. **数量与金额的合并是直接的，均价不是**——均价必须"金额之和 ÷ 数量之和"，**不是各单元均价的算术平均**（若按算术平均，本题会得到 (10.25 + 15.00) ÷ 2 = 12.625000，**是错的**）。
2. **含个别计价就把均价压成 `--`**——宁可少给一个数，也不给一个会被误读的数。
3. **`[查看]` 是审计出口**——合并行不能拆回，就等于把三个货主的货混成一个无法解释的数。
4. **同一列在不同维度含义不同**：均价在仓库维度是"加权派生值"，在一级货主维度是"权威均价"，在二级产权人维度是"继承自所属一级层"。**按维度读，不要跨维度比。**

##### 2.5.1.2 SR05_F01：〈存货记账明细台账〉

**2.5.1.2.1 *功能访问路径**

**页面定义**：〔图〕见原文 `§三.7 存货记账明细台账`（搜索条件 10 项 · 按钮 5 个 · 字段 19 项）。

**2.5.1.2.2 *功能描述**

**要解决的问题**：结存页给的是**一个数**，本页给的是**这个数的来历**。任何一笔结存金额，都必须能在这本台账上一行一行地找到它是怎么滚出来的。**这是全系统审计追溯的主要出口。**

**本页就是 `t_calc_log`（计算过程留痕表）的查询视图**——它是全系统的**真相源**（`2.3` SR03_F01 不变量①）。

**"记账流水口径"是本页与结存页最大的不同**：

| 口径 | 批次号 `batch_no` | 页面 |
|---|---|---|
| **结存余额口径** | 恒为 `—`（三轴聚合，批次不进聚合键） | P05 结存流水数据 |
| **记账流水口径** | **有值**（本页） | **P07 存货记账明细台账** |

**每一行带的三个快照**（这是本页最有价值的设计）：

| 快照列 | 含义 |
|---|---|
| `bal_qty_snapshot`（结存数量快照） | **过账后**的在库量 |
| `bal_price_snapshot`（结存均价快照） | **过账后**的均价 |
| `bal_cost_snapshot`（结存金额快照） | **过账后**的总额 |

> **为什么每一行都要存快照**：只存"发生额"的话，想还原"6 月 15 日那天这批货值多少"，必须从期初开始把几百行累加一遍——**慢，而且一旦中间某行被改过就永久错**。存快照后，**任一时刻的余额都能从当行直接读出**，并且**相邻两行的快照链必须连续**（前一行 `bal_*_snapshot` + 本行 `change_*` = 本行 `bal_*_snapshot`）——**快照链断裂就是数据被动过的证据**。

**`posting_seq`（全局过账序号）**：

| 性质 | 说明 |
|---|---|
| 单调递增 | **全局**唯一，记录**实际生效顺序** |
| 与排序键的关系 | 同一天内也按它排序，**而非** `biz_date + seq_in_day` |
| 用途 | **审计追溯与事件重放的对齐依据**——排障时按它复现过账次序、核对快照链是否连续 |

**穿透能力**：`[穿透详情]` 从一笔流水穿透到它的**全部来源**——原始报文（`2.2` SR02_F01）、命中的计价规则、当时的取价结果、引擎计算的中间过程。

**异常标记** `is_abnormal`：

| 取值 | 含义 |
|---|---|
| `0` | 正常 |
| `1` | 负库存 |
| `2` | 尾差清零 |

**货权主体的命名例外**：本页的货权列名为 `owner_info`（货权主体），**不拆成 `legal_owner_id` / `amiba_owner_id` 两列**。这是全系统**三处命名例外之一**（`1.3.3` 与原文 `§三` 章首注），**另两处**是 `2.5` SR05_F02 的 `sn_code`（SN / IMEI / 车架号，三义合一）与同页的 `in_time`（入库日期范围）。

##### 2.5.1.3 SR05_F02：〈序列号资产台账〉

**2.5.1.3.1 *功能访问路径**

**导航路径**：`财务库存中心` → `单据与台账` → `序列号资产台账`

##### 2.5.1.4 SR05_F03：〈存货计价批次追踪〉

**2.5.1.4.1 *功能访问路径**

**导航路径**：`财务库存中心` → `单据与台账` → `存货计价批次追踪`

**后端菜单注册**：· 在 backend 中添加：「单据与台账」>「存货计价批次追踪」中的功能。

**前置条件**：采购入库单已过账。

**页面定义**：〔图〕见原文 `§三.9 存货计价批次追踪`（搜索条件 6 项 · 按钮 5 个 · 字段 14 项）。

**2.5.1.4.2 *功能描述**

**要解决的问题**：采购入库有**两个时间点**——货到（暂估入账）与票到（实际成本）。两个时点之间账面是"暂估"的，**这段时间里卖掉的货，成本是暂估的**。本页把这个缺口**钉在批次上**：这个批次估了多少、实了多少、差多少、差的部分有多少已经跟着货卖出去了。

**批次的生命周期（本页的四段）**：

| 段 | 列 | 说明 |
|---|---|---|
| **① 数量盘子** | `init_qty`（批次初始量）/ `remain_qty`（在库剩余量）/ `sold_qty`（已售出数量） | 三者的关系：`init_qty` = `remain_qty` + `sold_qty` + 报废 / 调整量 |
| **② 两个价** | `po_est_cost`（PO 暂估单价）/ `actual_cost`（发票最终单价） | 货到时按暂估、票到时按实际 |
| **③ 价差** | `diff_unit_cost`（单位价差） | `actual_cost − po_est_cost` |
| **④ 到票** | `invoice_status`（到票状态） | 未到票 / 部分到票 / 已到票 |

**价差怎么处理（关键规则）**：

| 情形 | 处理 |
|---|---|
| 到票时**剩余在库**部分 | 调整该批次剩余部分的成本，**重算均价** |
| 到票时**已售出**部分 | 价差**跟随已售数量**分摊——**只调差额，不动已结转的出库成本**（**调价不追溯**，`1.3.4`） |
| `[查看分摊与出库明细]` | 展开该批次的价差分摊明细与每一笔出库的去向 |

> **"调价不追溯"在这里的具体含义**：票到之后，**已经卖出去的那批货，成本不会回头改**。因为改了就意味着一笔已结转的销售成本被重算，而对应期间的报表已经出过了。**差额走当期调整**，这是会计上唯一站得住的写法。

**与 `2.4` SR04_F03 的分工**（两页都带批次，容易混）：

| 页 | 看什么 |
|---|---|
| **P09 存货计价批次追踪** | 采购批次的**暂估 → 到票**（一进一出的对账） |
| **P16 余额管理报表 · 批次余额页签** | 批次**现在剩多少、值多少钱、放了多久** |

**同一张批次层库存余额表，两个视角**，互不替代。

### 2.6 系统需求SR06: 对账与风险监控

> **本章回答「这个数可不可信」。** `2.4` 与 `2.5` 是在**展示**账面，本章是在**证伪**账面——三账对不上在哪、成本跳变有没有异常、负库存还挂着多少。**本章的每一页都是给财务"发现问题"用的，不是给业务"看结果"用的。**

#### 2.6.1 功能需求

##### 2.6.1.1 *系统功能需求列表

| 系统功能需求编号 | 系统功能需求名称 | 简述 | 优先级 | 对应原型页 |
|---|---|---|---|---|
| SR06_F01 | 核对表 | 三账（WMS 实物 / 业务可用 / 财务账面）数量对账，差异根因研判与链路排查 | 高 | P10 核对表 |
| SR06_F02 | 成本波动表 | 监控单价跳变，按波动率分级预警，主管复核闭环 | 高 | P11 成本波动表 |
| SR06_F03 | 负库存挂账表 | 负库存缺口的挂账、补差、冲平闭环监控 | 高 | P15 负库存挂账表 |

##### 2.6.1.2 SR06_F01：〈核对表〉

**2.6.1.2.1 *功能访问路径**

**导航路径**：`财务库存中心` → `对账与监控` → `核对表`

**后端菜单注册**：· 在 backend 中添加：「对账与监控」>「核对表」中的功能。

**前置条件**：业务侧已推送 `snapshot`（数量快照）；WMS 实物数可取。

**页面定义**：〔图〕见原文 `§三.10 核对表`（搜索条件 4 项 · 按钮 6 个 · 字段 11 项）。

**2.6.1.2.2 *功能描述**

**要解决的问题**：实物、业务、财务三本账**天然会不一致**——实物操作与系统指示永远有偏差。**本系统的立场不是"追求完全一致"，而是"可见、可对、可催"**：差在哪、差多少、是什么原因，都必须看得见。

**三账与两个差异**：

| 列 | 含义 |
|---|---|
| `wms_qty`（WMS 物理在架数） | 实物层 |
| `biz_inv_qty`（业务库存可用总数） | 业务层 |
| `fin_inv_qty`（财务账面结存数） | 财务层（本系统） |
| `wms_diff`（实物 vs 财务差异） | `wms_qty − fin_inv_qty` |
| `biz_diff`（业务 vs 财务差异） | `biz_inv_qty − fin_inv_qty` |

**对账的两种节奏**（`2.3` SR03_F01 的自检在此落地）：

| 节奏 | 范围 | 内容 |
|---|---|---|
| **日结** | 当日增量 | 数量对账 + `M1` 校验 + **「重算 ≡ 投影」自检** |
| **月结** | **全量** | 全量对账 + 全量自检 + 金额对账（含容差） |

**差异根因初步研判** `diff_type`：按差异的形态给出初步分类（如：单据未推 / 单据未过账 / 实物未回传 / 批次不一致 / 待确认），**供人工研判的起点，不是结论**。

**`[差异链路排查]`**：从差异行出发，追到构成这个数字的**上游链路**（报文 → 事件 → 过账 → 投影），把差异定位到**具体哪一环**。

> **对账维度未决项（`1.2`）**：本期数量对账按**物理层** `(商品, 仓库, 批次)` 对；**「能否上到货主层」取决于业务侧是否也建货主维度，尚未拍板**。若业务侧不建，**同仓不同货主的货会被混在一起对，差异互相抵消**——这是已知的一期局限，**不预设结论**。

> ⚠️ **数量对得上 ≠ 系统自洽**：存在一类**外部对账查不出来**的故障——**增量落库成功而事件写日志失败**（或反之），此时**数量仍对得上业务快照、金额仍对得上总账**，两个外部对账都通过，但**余额与事件流已经分叉**。**唯一能抓到它的是「重算 ≡ 投影」自检**（`2.3` SR03_F01）——所以这条自检必须跑，不能被"对账都过了"替代。

**危险动作**：`[执行全仓手动对账任务]`——重跑对账会覆盖当期对账结果，按 `1.3.8` 走统一危险动作流程。

##### 2.6.1.3 SR06_F02：〈成本波动表〉

**2.6.1.3.1 *功能访问路径**

**导航路径**：`财务库存中心` → `对账与监控` → `成本波动表`

**后端菜单注册**：· 在 backend 中添加：「对账与监控」>「成本波动表」中的功能。

**前置条件**：核算引擎已过账，且已计算变动前后的均价。

**页面定义**：〔图〕见原文 `§三.11 成本波动表`（搜索条件 5 项 · 按钮 5 个 · 字段 14 项）。

**2.6.1.3.2 *功能描述**

**要解决的问题**：均价**不正常的跳变**是绝大多数核算错误的**共同表象**——价格取错、数量录反、批次串了、单位换算错了，最后都表现为"这个商品的均价今天突然变了 40%"。**盯住均价跳变，就盯住了大半个错误面。**

**波动是怎么算的**：

| 列 | 算法 |
|---|---|
| `prev_unit_cost`（变动前均价） | 本笔过账**前**的核算单元均价 |
| `curr_unit_cost`（变动后均价） | 本笔过账**后**的核算单元均价 |
| `cost_diff_abs`（单价变动绝对值） | `curr_unit_cost − prev_unit_cost` |
| `fluctuation_rate`（波动幅度） | `cost_diff_abs ÷ prev_unit_cost` |
| `alert_level`（预警级别） | 按波动幅度落级（阈值**须双方书面确认**，见 `1.2`） |
| `review_status`（复核状态） | 待复核 / 已复核 |

**复核闭环**：`[复核审批 (限主管)]`——预警不是通知，是**待办**。**主管复核后才有结论**（确认为正常波动 / 确认为错误并转处理），**不允许静默关闭**。

> **阈值是"建议值"，不是"判定依据"**：设计文档给出的波动率阈值**必须经业务与财务双方书面确认后**才能作为验收标准（`1.2`）。在此之前，本页的预警级别**只作提示**。

**本页与 `2.5` SR05_F01 的关系**：波动表的每一行都对应一条记账流水（`journal_no`），**点进去即穿透到台账**——**波动表负责"发现"，台账负责"查明"**。

##### 2.6.1.4 SR06_F03：〈负库存挂账表〉

**2.6.1.4.1 *功能访问路径**

**导航路径**：`财务库存中心` → `对账与监控` → `负库存挂账表`

**后端菜单注册**：· 在 backend 中添加：「对账与监控」>「负库存挂账表」中的功能。

**前置条件**：存在已过账的负库存（`2.1` SR01_F02 配置为「允许」）。

**页面定义**：〔图〕见原文 `§三.15 负库存挂账表`（搜索条件 6 项 · 按钮 6 个 · 字段 16 项）。

**2.6.1.4.2 *功能描述**

**要解决的问题**：负库存已经发生（`2.1` SR01_F02 允许过账了），**接下来必须有人把这些缺口一笔一笔地平掉**。本页就是这些缺口的**追踪清单**。

**一行 = 一个未平（或已平）的负库存缺口**：

| 阶段 | 列 | 说明 |
|---|---|---|
| **缺口** | `out_journal_no`（出库流水号）/ `biz_bill_no`（关联销售单号）/ `negative_qty`（负库存缺口量） | 哪一笔出的、缺多少 |
| **暂估** | `est_out_cost`（暂估出库单价）/ `est_price_source`（暂估取价来源） | 出库时按什么价记的、这个价从哪来 |
| **时长** | `pending_days`（挂账天数）/ `是否超期`（查询条件，**派生**） | 挂了多久；超期是**计算出来的**，不是独立字段 |
| **冲平** | `resolve_status`（冲平状态）/ `in_journal_no`（冲平采购流水号）/ `actual_in_cost`（采购实际单价）/ `resolved_time`（冲平解决时间） | 哪一笔入库把它平掉的、实际成本多少 |
| **补差** | `cost_diff_amount`（成本补差金额） | `actual_in_cost − est_out_cost` 对应的差额 |

**补差的两种路径**：

| 路径 | 触发 | 说明 |
|---|---|---|
| **自动补差** | 后续采购入库到达，按规则匹配 | 策略 = 自动补差时（`2.1` SR01_F02） |
| **`[强制手动匹配采购单]`** | 自动匹配不上（如入库单跨期、数量不对应） | 人工指定用哪张采购单来平——**这是唯一需要人判断的地方** |

**`[查看补差明细]`**：展开该缺口从开账到关闭的**全部动作**。

**必守边界**：

| 边界 | 说明 |
|---|---|
| **挂账记录只增不删** | 冲平后状态变更，**记录本身永久留存**（审计要求） |
| **负库存未平期间，该核算单元的均价不可对外** | `2.4` SR04_F02 显示 `—` + 标注 |
| **不允许"只记账、不动库存"的便捷开关** | **设计禁令**——那等于给虚进虚出（空转业务）发工具 |
| **挂账未闭环 → `E-11`（负库存挂账未闭环）** | 日结校验 |

##### 2.6.1.5 举例演练

**场景**：某核算单元（`M0001` / `WH01` / `OWN-A`，移动加权平均）发生一笔负库存，随后采购到货补正。

| 步 | 动作 | 系统行为 | 报表呈现 |
|---|---|---|---|
| 1 | 期初 0，销售出库 30 台 | 策略 = 允许 → **过账**，生成挂账记录 | P15 出现一行：`negative_qty` 30，`est_out_cost` 按暂估取价，`pending_days` 起算 |
| 2 | 同期 | 该核算单元标记「待修正」，均价对外置 `—` | P06 该行均价显示 `—` + 负库存 Tag |
| 3 | 3 天后采购入库 50 台 @ 12.000000 | 触发补正：先冲销挂账、再按实际成本重算均价 | P15 该行 `resolve_status` 变为已冲平，`in_journal_no` / `actual_in_cost` / `resolved_time` 回填 |
| 4 | 补差核算 | `cost_diff_amount` = (`actual_in_cost` − `est_out_cost`) 对应的差额 | P15 显示补差金额 |
| 5 | 日结 | 跑数量对账 + `M1` 校验 + **「重算 ≡ 投影」自检** | P10 核对表差异为 0；`E-11` 不再报出 |

**演练要点**：

1. **负库存不是错误，是待办**——允许过账但必须挂账、必须闭环。
2. **挂账期间均价不能对外**——用受污染的数当权威均价，比不给数危害大。
3. **补差的自动 / 手工是两条路**，手工那条需要人判断（跨期、数量不对应时自动匹配不上）。
4. **`E-11` 与「重算 ≡ 投影」自检都要跑**——前者管挂账闭环，后者管余额与事件流是否分叉，**互不替代**。

### 2.7 系统需求SR07: 跌价准备与期间报表

> **本章是月结的两个终点**：**库存表**回答"这批货值不值账面上这个钱"（跌价），**进销存周期表**回答"这个月进了多少、出了多少、剩多少"（收付实现）。两页都是**按月定格**的报表——一旦该期间锁账，报表就必须与当时一致（这正是引入会计期间的原因）。

#### 2.7.1 功能需求

| SR07_F02 | 进销存周期表 | 按会计期间出期初 / 入库小计 / 出库小计 / 纯成本调整 / 期末的收发存报表 | 高 | P13 进销存周期表 |

##### 2.7.1.2 SR07_F01：〈库存表（库龄与跌价双轨）〉

**2.7.1.2.1 *功能访问路径**

**导航路径**：`财务库存中心` → `报表与期间` → `库存表`

**后端菜单注册**：· 在 backend 中添加：「报表与期间」>「库存表」中的功能。

**前置条件**：核算引擎已过账，且**库龄推导已执行**（异步任务）。

**页面定义**：〔图〕见原文 `§三.12 库存表`（搜索条件 6 项 · 按钮 6 个 · 字段 15 项）。

**2.7.1.2.2 *功能描述**

**要解决的问题**：库里的货**不是永远值账面那个钱**——放了 3 个月的旧款手机、上市一年半的老型号，账面还按成本挂着，实际上已经卖不到那个价。**跌价准备就是把这部分差提前认出来。**

**库龄六桶**（与 `2.4` SR04_F03 余额管理报表的**批次余额**页签**共用同一套边界，不另立**）：

| 列 | 区间 |
|---|---|
| `aging_0_30` | 0-30 天量 / 额 |
| `aging_31_60` | 31-60 天量 / 额 |
| `aging_61_90` | 61-90 天量 / 额 |
| `aging_91_180` | 91-180 天量 / 额 |
| `aging_181_360` | 181-360 天量 / 额 |
| `aging_360_plus` | 360 天以上量 / 额 |

**起算点**：库龄 = **当前日期 − 入库日期**（`in_date`）。**库龄是从入库那天起算在库天数**，与批次 / SN 无关——批次只决定"哪一批"，库龄说的是"放了多久"。

**跌价双轨（本页的核心）**：

| 轨道 | 起算 | 适用 |
|---|---|---|
| **库龄法** | 入库日 | 通用——所有品类 |
| **3C 上市周期法** | **上市日**（非入库日） | 3C 新品——一款机型上市越久越不值钱，与它什么时候进我们仓库无关 |

**分段比例（默认值，按商品类别可配）**：

| 库龄法分段 | 比例 | | 上市周期法分段 | 比例 |
|---|---|---|---|---|
| 0-180 天 | 0% | | 0-90 天 | 0% |
| 181-360 天 | 5% | | 91-180 天 | 10% |
| 361-720 天 | 30% | | 181-365 天 | 25% |
| 720 天以上 | 50% | | 365 天以上 | 40% |

**双轨取孰高**：

```
provision_amount = max( 按库龄法的跌价准备额, 按上市周期法的跌价准备额 )
```

> **为什么要双轨取孰高**：两条轨道盯的是**两种不同的贬值原因**。库龄法盯"压在我们手里多久"，上市周期法盯"这款在市场上过时了多久"。**一台刚进仓的上一代旗舰**——库龄很低（库龄法算 0），但已上市 400 天（上市周期法算 25%）。**只按库龄算，会完全漏掉这类贬值**。取孰高，是为了**不让任一条轨道的盲区漏掉减值**。

**计提范围（红线）**：**仅对 `is_internal = 1` 的一级货主计提**。受托代管、借入他方货物虽然建四轴余额、记数量记金额，但 `is_internal = 0`，**不计入存货总额、不进跌价基数、不出凭证**（仅备查登记）。

**本期计提额**：

```
本期应计提 = 本期应有准备（provision_amount） − 上期已计提
```

**跌价凭证按法人分别出**（`2.8` SR08_F01 模板「跌价准备」）。

**页面能力**：

| 按钮 | 说明 |
|---|---|
| `[重新执行库龄推导 (异步任务)]` | **危险动作**（`1.3.8`）：异步重算覆盖当期推导结果 |
| `[导出资产减值测试底稿 (Excel)]` | 出具**资产减值测试建议表**，辅助财务计提资产减值准备 |
| `[生成跌价计提凭证建议]` | **危险动作**（`1.3.8`）：生成凭证建议，按法人分列 |

**快照定格**：`快照基准日期` 是**参数型条件**（不是普通筛选）——本页要的是"**截至某一天**的存货状态与跌价测算"，不是"当前"。**这个参数让月结报表可在事后复现**。

> **三个"看起来像筛选、其实是参数"的条件**：本页的 `快照基准日期`、`2.7` SR07_F02 的 `会计期间`、以及 `2.7` SR07_F02 的 `报表聚合维度`。它们**改变的是这张报表的"是什么"，不是"筛掉哪些行"**。与普通筛选条件区分开，是这两页的读法要点。

##### 2.7.1.3 SR07_F02：〈进销存周期表〉

**2.7.1.3.2 *功能访问路径**

**导航路径**：`财务库存中心` → `报表与期间` → `进销存周期表`

**后端菜单注册**：· 在 backend 中添加：「报表与期间」>「进销存周期表」中的功能。

**前置条件**：该会计期间已过账（**不要求已锁账**——锁账前财务需要用本页做结账前检查）。

**页面定义**：〔图〕见原文 `§三.13 进销存周期表`（搜索条件 7 项 · 按钮 5 个 · 字段 22 项）。

**2.7.1.3.2 *功能描述**

**要解决的问题**：这是**法定的"收发存"表**——每个会计期间的期初、本期收、本期发、期末，**是财务出具存货报表与总账核对的基准**。

**报表骨架（一条恒等式）**：

```
期初数量 + 入库小计 − 出库小计 + 纯成本调整 = 期末数量
```

| 段 | 列 | 说明 |
|---|---|---|
| **期初** | `begin_qty` / `begin_unit_cost` / `begin_total_cost` | 期初数量 / 单价 / 金额 |
| **入库小计** | `in_purchase`（采购入库）/ `in_sale_return`（销退入库）/ `in_transfer`（调拨调入）/ `in_profit`（盘盈入库）/ **`in_total`（入库小计）** | 四类入库 + 小计 |
| **出库小计** | `out_sale`（销售出库）/ `out_purchase_return`（采退出库）/ `out_transfer`（调拨调出）/ `out_loss`（盘亏出库）/ **`out_total`（出库小计）** | 四类出库 + 小计 |
| **纯成本调整** | `cost_adjust_amount` | **不出入库、只改金额**的调整额 |
| **期末** | `end_qty` / `end_unit_cost` / `end_total_cost` | 期末数量 / 单价 / 金额 |

> **`cost_adjust_amount`（纯成本调整额）为什么必须单列**：有些业务动作**只动金额、不动数量**——采购到票的价差调整、舍入差异结转、跌价计提。若把它们混进"入库"或"出库"，**数量就平不了了**（数量没动，却被算成进出）。**单列一栏，让数量与金额各归各位**。

**`报表聚合维度`（参数型条件）**：决定本表按哪个维度展开——一级货主 / 二级产权人 / 仓库 / 商品类目 / 商品。**它是参数不是筛选**（见 SR07_F01 末注）。

**`会计期间`（参数型条件）**：本表的期间归属。`YYYY-MM`。

**导出能力**：

| 按钮 | 说明 |
|---|---|
| `[导出标准收发存报表 (Excel/PDF)]` | 标准收发存报表 |
| `[★ 导出金蝶标准凭证引入表 (Excel)]` | **一期与金蝶的接口方式**——导出标准凭证引入表，由财务**手工引入**金蝶。**一期不直推**（`2.8` SR08_F01） |

**2.8.1.2.2 *功能描述**

| **③** | **凭证日期 = 记账期间首日** |
| **④** | **二级重分配不产生凭证**（R2）；**`PERIOD_ADJUST`（跨期补录单）不新增模板**（复用既有模板） |

> **①"不平拒绝落库"的分量**：这一条意味着**引擎宁可让一笔业务处理失败，也不让一张不平的凭证进库**。不平的凭证一旦落库，总账就会带着一个说不清的差额往前走，而**后面每一期都要背着它**。**在源头拒绝，是唯一便宜的处理方式。**

**13 个凭证模板**：

| # | 模板 | 触发 |
|---|---|---|
| 1 | **采购入库** | 采购入库过账 |
| 2 | **销售出库** | 销售出库过账 |
| 3 | **调拨** | 同法人跨仓调拨 |
| 4 | **盘亏** | 盘点差异（亏） |
| 5 | **盘盈** | 盘点差异（盈） |
| 6 | **跌价准备** | 月结跌价计提（**按法人分别出**） |
| 7 | **舍入差异结转（月末）** | 月结统一结转出库舍入差异 |
| 8 | **采购退货出库** | 采购退货过账 |
| 9 | **销售退货入库** | 销售退货过账 |
| 10 | **一级货权转移 `OWNER_TRANSFER`** | 跨法人货权转移（**必作价、必出凭证、必产生会计损益**，R1） |
| 11 | **集团内未实现损益抵消** | 合并层抵消（见下） |
| 12 | **其他入库（受赠，`OTHER_IN`）** | 受赠入库（借库存商品（不含税公允价值）／贷营业外收入） |
| 13 | **其他出库（`OTHER_OUT`）** | 其他出库过账 |

**集团内未实现损益抵消（模板 11）**：

**场景**：`OWN-A` 把 20 台成本 10.000000 的货以 11.500000 转给 `OWN-B`。从集团角度，**这批货还在集团内**，那 20 × (11.500000 − 10.000000) = **30.00 的"利润"并没有真的赚到**——它只是从一个主体挪到了另一个主体的账上。

| 状态 | 抵消 |
|---|---|
| 已售出的部分 | **已实现**——不用抵消 |
| **仍在库的部分** | **未实现**——必须抵消 |

在本例中，已售 10 台（已实现）、剩余 10 台（未实现 5.00）。**抵消后集团存货 = 1,100.00 + 115.00 − 5.00 = 1,210.00**，与未抵消的 1,215.00 差 5.00。

> **`is_related_party`（是否关联方）决定是否需抵消**。不是关联方的跨法人转移不产生未实现损益。

> ⚠️ **不要拿抵消后的数去对平**：**对平（V1 / V2 / V3）验的是"三个投影是否同源"，用未抵消口径**；**存货总额用抵消后口径**。两者回答**两个不同的问题**（`2.3.1.6` 演练二）。

**一期与金蝶的接口方式（红线）**：

| 项 | 一期做法 |
|---|---|
| 生成 | 凭证清单 + 会计科目映射 |
| 导出 | **Excel 导出**（标准凭证引入表） |
| 引入 | **财务手工引入金蝶** |
| **不做的** | **不直推金蝶总账**（二期） |

> **一期不直推的原因不是技术做不到，是口径责任还没定清**：自动过账意味着本系统的科目映射直接决定总账的形态，一旦映射有误，**错误会静默地进入法定账**。一期用"导出 + 人工引入"，让**财务在引入那一刻有一次复核机会**。

**舍入差异结转（模板 7）**：**只在出库产生的**舍入差异由专门科目归集，**月结时统一结转**（`2.3` SR03_F02）。**入库不回改金额，所以入库不产生舍入差异。**

##### 2.8.1.3 SR08_F02：〈价值数据回传业务侧〉

**2.8.1.3.1 *功能访问路径**

**调用路径**：**非页面功能**——由系统按周期（建议**月度**）主动推送（`object = value_feedback`），或由业务侧按需拉取。

**后端菜单注册**：无需注册菜单。

**前置条件**：核算引擎已过账；回传周期已锁账（保证回传的数是**定格**的）。

**2.8.1.3.2 *功能描述**

**要解决的问题**：业务侧有实物、有数量，但**不知道这批货值多少钱**。价值回传就是把这个"钱"的口径交给业务——**但必须交得让业务无法误读。**

**回传内容**：

| 内容 | 说明 |
|---|---|
| **成本单价** | 该核算单元的当期均价（按方法分流，个别计价给 `--`） |
| **库存金额** | **存货口径**（`is_internal = 1` 的一级货主层） |
| **库龄** | 库龄天数 / 库龄区间 |
| **跌价准备** | 该商品 / 品类的跌价准备建议额 |

**★ 两个金额口径必须并列，且都带标注**：

| 口径 | 标注 | 含义 |
|---|---|---|
| **存货口径** | `（存货口径·一级货主层·is_internal=1）` | **业务侧唯一可用的口径**——这是会计上的存货金额 |
| **内部结算口径** | `（管理口径·非会计损益）` | 二级内部结算价口径，**不是存货金额** |

> ⚠️ **这是回传功能里最容易出事故的一处**：业务侧拿到两个金额，**很可能把"内部结算金额"当成"库存金额"**去算 KPI 或对账。**因此回传报文里两个字段必须同时出现、各自带标注**，**并且业务侧只被允许使用存货口径**。**只回传一个数，反而更危险**——因为业务会用它能拿到的那个。
>
> **二级自有均价（`own_unit_price`）与二级自有结存金额（`own_amount`）也在回传范围内**，同样标注**管理口径 · 非计价依据**，**不进存货总额、不出凭证**。

**口径标注规则（强制）**：

| 数据 | 标注 |
|---|---|
| 库存金额 | `（存货口径·一级货主层·is_internal=1）` |
| 库存数量 | `（权属口径·一级货主层）` 或 `（物理口径·仓库）` |
| 内部结算损益、二级自有均价 | `（管理口径·非会计损益）` |

> **任何对外分发的报表与指标必须带口径标注**（`1.3.3`）。**没有标注的数，在跨部门流转中一定会被用错口径**——这不是"加个注释更严谨"，而是唯一能防住口径混用的手段。

**回传的幂等与版本**：`value_feedback` 走与 `document` 相同的信封（`2.2.1.2.2`），`schema_version`（契约版本号）变化时业务侧必须适配后才接收。

## 3. 附录

### 3.1 术语定义

> 术语口径**以原文 `§一.4 术语表` 为准**，本表仅作索引与补充。**计价方法术语在正文一律用中文名**，下表的枚举码仅供系统对接使用。

| 术语 | 含义 |
|---|---|
| **一级货主** | **法人主体（公司主体）**，与 `owner_l1`（一级货主） / 账套是**同一概念**。存货均价池、凭证、损益、跌价基数都以它为准 |
| **二级货主（二级产权人）** | 内部管理维度，即页面上的**二级产权人**——**产权人可以是个人，也可以是部门 / 事业部 / 代采项目**。**不是法人、不是会计主体**，不进存货总额；在**二级分摊账**（会计口径）与**二级自有均价池**（管理口径）两处体现 |
| **二级自有均价池** | **管理口径**：每个二级产权人**自己的一本**移动加权平均账（`own_amount`）。入池按**实际成本**、出池按**该二级当期自有均价**，二级重分配**同额平移**。与一级层金额之差即**池化差异 `D`**。**不进存货总额、不进跌价基数、不出凭证** |
| **存货核算单元** | `(商品, 仓库, 一级货主)`。**计价方法的作用粒度**——均价池、成本层、凭证、跌价基数都属于核算单元，**不属于批次行** |
| **库存维度（四轴）** | `(商品, 仓库, 批次, 一级货主)`。余额表主键；移动加权平均下批次只影响库龄与跌价、不进均价池；个别计价 / 先入先出法下批次即成本层 |
| **作价** | 货权转移时给转移的货**定一个价并生成凭证**。一级用 `transfer_price`（一级货权转移价），二级用 `internal_price`（内部结算价） |
| **内部结算价** | 二级重分配用的考核价（`internal_price`），是**政策数据**，来自带生效期的价目表；**不影响会计** |
| **二级分摊金额** | `alloc_amount`。= 数量 × 一级均价。**能**加总回一级层 |
| **二级内部结算金额** | `internal_amount`。按 `internal_price`（内部结算价）累计。**不能**加总，差额 = 内部未实现毛利 |
| **二级自有结存金额** | `own_amount`。按**二级自有均价池**结转的结存金额。**不能**加总，与一级层金额之差 = 池化差异 `D` |
| **池化差异 `D`** | 核算单元级、**派生、不落库**：`D = 一级层金额 − Σ(各二级 own_amount)`。**不进存货总额、不进跌价基数、不出凭证** |
| **货权变更单** | 一期由库存中心出的临时单据：`OWNER_TRANSFER`（一级转移）/ `OWNER_REASSIGN`（二级重分配）。按**可剥离**形态设计，二期搬迁到产权交易中心 |
| **内部交易标识** | `is_internal`。存货总额**只累加** `is_internal = 1`；跌价**只对** `is_internal = 1` 计提 |
| **会计期间** | 财务结账的最小时间单位（`YYYY-MM`：年-月）。`t_period`（会计期间表） + `is_closed`（是否已锁账）：**日结只校验、月结锁账** |
| **反结账** | 重新打开已锁账期间。**允许，但必须走审批并留痕**（谁 / 何时 / 因何 / 重开哪个月）。与补录单语义不同，**不能互相代替** |
| **跨期补录单** | `PERIOD_ADJUST`。已结账期间发现遗漏时的**唯一通道**，**一律按当期口径量价**，原业务日期仅供追溯；**不新增凭证模板** |
| **过账顺序** | `(biz_date, seq_in_day)`（业务日期, 当日序号）。同日**入库优先**、同类型按单号。`doc_no`（业务单号）**不可**用作排序键 |
| **增量（delta）** | 核算引擎返回的是**增量**（数量与金额的变化量），**不是新余额**；余额 = 累计 delta |
| **幂等（三层）** | 传输幂等 `batch_id + doc_no + line_no`；事件幂等 `(doc_type, doc_no, version_no)`；结果幂等（**纯函数**） |
| **移动加权平均** | `MOVING_AVG`。每次入库时用**累计金额 ÷ 累计数量**更新单位成本（在**核算单元层**）。**一期全局默认方法** |
| **个别计价** | `INDIVIDUAL`。每件 / 每批存货按**各自实际成本**单独结转。**一期启用**，适用于 SN 管理的高值整机 |
| **先入先出法** | `FIFO`。出库按**最早入库**的成本层**逐层结转**。**一期启用** |
| **库龄** | 商品**在库天数**，从**入库日期**起算 |
| **上市周期** | 3C 新品**自上市日**起算的天数，用于新品跌价计提 |
| **跌价准备** | 按**库龄法 / 上市周期法双轨取孰高**，对呆滞或贬值库存计提的减值。**仅对 `is_internal = 1` 计提** |
| **舍入差异** | 因金额精度处理产生的累计差额（**只在出库产生**），需**专门科目**归集，月结统一结转 |
| **成本层** | `t_inventory_layer`（库存成本层表）。个别计价 / 先入先出法单元承载批次 / SN 级成本的结构；**是均价层的细化，不是另一套账** |
| **全局过账序号** | `posting_seq`。**全局单调递增**，记录实际生效顺序；审计追溯与事件重放的对齐依据 |
