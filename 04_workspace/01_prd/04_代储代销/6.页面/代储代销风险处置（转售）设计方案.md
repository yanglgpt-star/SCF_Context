# 代储代销风险处置（转售）设计方案

> 版本：V2.3（原型落地稿）
> 日期：2026-10-26
> 载体：金融助手 - 代储代销（`金融助手-代储代销-整合版-2.8.html`）
> 关联文档：《代储代销需求文档-V2.7》《代储代销差价补偿金管理方案》《批量销售设计方案（形态二专项）》

---

## 1. 方案背景

### 1.1 现有业务与资金链路

代储代销当前闭环（见 V2.7 第 2.1 节）：

```
供应商申请 → 平台审核定价 → 入库生成电子仓单 → 平台拨付保证金（≤ 评估货值 70%）
→ 平台代销（定向销售 / 批量销售）→ 采购商支付 → 出库 → 清分结算 → 供应商实收
```

清分结算口径（现有）：销售回款扣回 **保证金（`deposit_amount`，保证金金额）**、**服务费（`service_fee`）**、**仓储费（`storage_fee`）** 后，余款退回供应商。

### 1.2 为什么需要转售登记

平台在货物入库后即先行垫付保证金，回款依赖后续销售。当货物卖不动时，业务上会**线下找渠道把货卖掉**（线下人工转售）。这类成交游离在系统之外，平台无法追溯：

- 卖了多少、什么价
- 钱有没有回来、回来多少
- 谁批准的、依据是什么

本次要补的就是这一环：**把线下已经发生的转售事实，连同凭证，登记回系统并留痕审批。**

### 1.3 本期定位

不做风险自动识别，不做系统内转售交易，**只做「线下人工转售」的登记与凭证回传**。

本期按**一次性处置**设计：一张代储订单最多发起一次转售，**转售范围 = 该订单当前剩余的全部可售库存**，不拆分、不分批。是否走转售由人工判断。

---

## 2. 建设目标

1. 运营可在代储订单上**人工发起**一次线下转售登记，处置剩余全部库存。
2. 登记单承载**成交信息 + 回款信息 + 凭证**，形成可追溯的处置记录。
3. 登记单经人工审核后生效，经办与复核留痕。
4. 生效后**一次性扣减全部剩余可售库存**，避免重复处置。
5. 不改变既有销售、出库、清结算、差价补偿金的任何流程。

## 3. 范围与边界

### 3.1 本期范围

| # | 内容 |
|---|---|
| 1 | 代储订单管理列表：操作列新增「转售登记」入口 |
| 2 | 新增「线下转售登记单」弹窗：登记成交、回款、凭证，提交审核 |
| 3 | 新增「转售登记单」列表 / 详情 / 审核（作为代储订单管理的二级视图） |
| 4 | 凭证回传：附件自由上传，**不预设类型、不强制归类** |
| 5 | 审核通过后扣减该订单全部剩余可售库存 |

### 3.2 本期明确不做

| 不做项 | 说明 |
|---|---|
| 自动风险识别与打标 | 不做到期未售、货值下跌的自动判定；是否转售由人工确定 |
| 多次 / 分批转售 | 一个代储订单只允许一次转售，且必须处置全部剩余数量 |
| 定向转售（系统内成交） | 不生成销售订单，不改造 `POST /api/sale/create` |
| 销售订单来源标识 | 不新增 `source_type`（来源类型）字段 |
| 最低销售单价豁免 | 不改造现有销售校验 |
| 清结算 / 资金划转联动 | 不做保证金核销、不自动生成差价补偿金应收单 |
| 货权转移 | 货权仍在供应商，不做过户登记 |
| 出库指令改造 | 不新增/修改出库指令逻辑 |
| 风险台账与看板 | 不做独立统计视图 |

## 4. 与既有能力的关系

| 既有能力 | 本方案的处理 |
|---|---|
| 定向销售 / 批量销售 | **零改动**。转售是线下行为，不进入销售订单链路 |
| 出库指令管理 | **零改动**。线下转售的货物如何出库，沿用线下操作与既有流程，本单只登记 |
| 清结算中心 | **零改动**。转售回款仅在本单登记，不进清结算、不自动核销保证金 |
| 差价补偿金应收 | **零改动**。转售差价不自动生成应收单，如需补收仍走人工创建 |
| 电子仓单 | 不变 |

> 一句话：本方案是**旁路登记**，不插入任何既有主流程。

## 5. 单据模型

### 5.1 粒度与数量口径

**一张转售登记单 = 一个代储订单（`storage_order_no`） + 一次线下转售成交，且覆盖全部剩余库存。**

```text
转售数量（resale_qty）= 发起时的可售库存（stock_quantity）
```

- 转售数量由系统带出、**只读不可改**
- **一个代储订单最多一张有效转售单**：已存在「草稿 / 待审核 / 已通过」的转售单时，不得再次发起
- 已被驳回或已作废的单据不计入占用，可重新发起

### 5.2 编号规则

沿用既有编号体系（V2.7 名词定义），新增：

| 单据 | 格式 | 示例 |
|---|---|---|
| 转售登记单 | `FX` + YYYYMMDD + 4 位流水号 | `FX202610260001` |

> `FX` 取「风险处置」之意，保持后续扩展空间；本期单据类型固定为「线下人工转售」。

### 5.3 状态机

```text
草稿 → 待审核 → ┬─ 已通过（终态，扣减库存）
                └─ 已驳回 →（可修改后重新提交）

草稿 / 已驳回 → 已作废
```

- **已通过**是唯一生效点：此刻扣减全部剩余可售库存，单据转为只读，不可编辑。
- 已驳回、已作废的单据不占用库存，运营可修改或重新发起。
- 经办与复核分离：操作人不得审核本人发起的登记单（与差价补偿金规则一致）。

## 6. 页面设计（原型改造）

### 6.1 代储订单管理列表

**操作列新增**：「转售登记」，与「销售」「详情」并列。

| 行状态 | 入口表现 |
|---|---|
| 拨付状态 = 已拨付，可售库存 > 0，无转售单 | ✅ 可点击「转售登记」 |
| 已有「草稿 / 待审核」的转售单 | 入口置灰，悬停提示「转售单 FXxxxx 处理中」 |
| 已有「已驳回」的转售单 | 入口可用，点击进入**原单编辑**（沿用原单号重提） |
| 已通过转售（可售库存已清零） | 入口隐藏 |
| 拨付状态 = 待拨付，或可售库存 = 0 | ❌ 隐藏 |

**新增列**：「转售状态」（未转售 / 处理中 / 已转售），置于「拨付状态」之后。一次性处置后「已转售数量」始终等于原可售库存，因此该列比数量列更有信息量。

### 6.3 转售登记单列表（二级入口）

**入口**：代储订单管理页 → 二级入口「转售登记单」。

**查询条件**：登记单号、代储订单编码、供应商、单据状态、成交日期、发起时间。

**列表字段**：登记单号 / 代储订单编码 / 供应商 / 货物信息 / 转售数量 / 转售单价 / 转售金额 / 回款金额 / 回款日期 / 状态 / 创建人 / 创建时间 / 操作（详情、审核、编辑、作废）。

**详情分区**：交易信息 — 回款信息 — 转售说明 — 凭证附件 — 审核记录（含驳回意见）。

### 6.4 审核

复用既有审批弹窗形态（同差价补偿金）：展示登记单全部信息与凭证，操作 `[通过] [驳回]`，驳回必填意见。

## 7. 字段与校验

### 7.1 转售登记单字段（新表 `fa_resale_registration`）

| `registration_no` | 登记单号 | 是 | `FX` + YYYYMMDD + 4 位流水 |

| `supplier_id` / `supplier_name` | 供应商 ID / 名称 | 是 | 带出只读 |

| `resale_price` | 转售单价 | 是 | > 0，保留两位小数 |
| `resale_amount` | 转售金额 | — | = 转售单价 × 转售数量，系统计算 |
| `deal_date` | 成交日期 | 是 | ≤ 当日 |
| `buyer_name` | 买家名称 | 是 | 线下买家或渠道名称 |
| `buyer_contact` | 买家联系方式 | 否 | |

| `refund_method` | 回款方式 | 是 | 银行转账 / 现金 / 其他 |

| `resale_reason` | 转售原因及说明 | 是 | 人工填写，说明为什么走线下转售 |
| `attachment` | 凭证附件 | 是 | 至少 1 个；**自由上传，不设类型枚举** |
| `remark` | 备注 | 否 | |
| `status` | 单据状态 | 是 | 草稿 / 待审核 / 已通过 / 已驳回 / 已作废 |
| `create_by` / `create_time` | 创建人 / 创建时间 | — | 系统 |
| `audit_by` / `audit_time` | 审核人 / 审核时间 | — | 系统 |
| `audit_remark` | 审核意见 | 否 | 驳回时必填 |

### 7.2 校验规则

| # | 规则 |
|---|---|
| 1 | 同一代储订单只允许一张有效转售单（草稿 / 待审核 / 已通过）；重复发起时提示既有单号 |
| 2 | 转售数量固定等于发起时的可售库存（`stock_quantity`），不可手工修改 |
| 3 | 转售单价 > 0；转售金额由系统计算，不可手工覆盖 |
| 4 | 回款金额 > 转售金额时给出提示，需在说明中解释（允许超额，不拦截） |
| 5 | 成交日期、回款日期均不得晚于当日 |
| 6 | 转售原因、凭证附件必填 |
| 7 | 经办人不得审核本人发起的登记单 |
| 8 | 已通过的单据不可编辑；作废需填写作废原因 |

## 8. 与库存、资金的口径

### 8.1 库存（已确认）

登记单审核通过后，该代储订单的剩余可售库存**一次性清零**：

```text
审核通过后可售库存 = 0
（即：入库数量 − 历史已销售数量 − 本次转售数量 = 0）
```

- 转售数量在通过前即为全部剩余，因此不存在多次累加
- **不生成出库指令**，不改变电子仓单状态
- 线下的实际出库由仓库按既有线下流程执行，**系统不做出库确认、不与仓库对账**
- 驳回、作废的单据不扣减库存

### 8.2 资金

- 回款金额仅做**登记**，不进入清结算中心，不核销保证金，不生成差价补偿金应收
- 若转售收入不足以覆盖已拨保证金，缺口仍由运营线下判断，按需人工创建差价补偿金应收单（既有能力，本次不改）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 凭证类型 | **不固定**。附件由人工自由上传，系统不预设类型、不强制归类 |

| 5 | 已驳回单据的处理 | **修改后重提**，沿用原单号，保留连续性 |

## 11. 验收要点

1. 待拨付或无可用库存的订单不出现「转售登记」入口。
2. 转售数量自动带出全部剩余库存且不可编辑。
3. 代储订单列表正确展示「转售状态」（未转售 / 处理中 / 已转售）。
4. 已存在有效转售单的订单，入口置灰并提示既有单号；已通过的入口隐藏。
5. 必填校验、日期校验、凭证至少 1 个等校验全部生效；附件可自由上传、不分类。
6. 经办人无法审核本人发起的登记单。
7. 审核通过后：单据只读、该订单可售库存清零、转售状态变为「已转售」。
8. 驳回或作废后：库存不受影响；驳回的单据可修改后重提、沿用原单号。
9. 回款只允许登记一笔，界面不提供分次录入。
10. 转售登记**不产生**销售订单、出库指令、清结算记录、差价补偿金应收单。
11. 转售登记单可从代储订单详情跳转查看，形成完整追溯。
