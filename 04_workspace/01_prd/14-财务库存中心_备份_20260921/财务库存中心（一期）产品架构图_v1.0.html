03

核算引擎

四层结构 + 三条不变量 + 三种幂等。这三件事是引擎的全部要害，也最容易被说混。

三条不变量

引擎的要害
#不变量含义错在哪
1 返回 delta，不返回新余额 measure() 只回答"这笔让余额变多少"，不读当前余额 若返回新余额，measure 就必须读余额 → 不再是纯函数 → 无法重放、无法测试、并发下必错
2 事件是真相源，余额是投影 t_calc_log append-only；删除任何一行都会让重放结果与当前余额不一致 若把 t_calc_log 当"操作日志"，就会出现"改单 = 删旧行"→ 历史成本不可追溯
3 锁单位 = 核算单元 加锁粒度 (物料, 仓库, 一级货主)；跨单元按维度键顺序加锁防死锁 锁整张表 → 吞吐崩塌；锁单行 → 同一核算单元并发写会串

三种幂等不是一回事

最常被混
层幂等键防什么谁负责
传输幂等 batch_id + doc_no + line_no 同一条报文重推（网络重试） 适配层
事件幂等 (doc_type, doc_no, version_no) 同一版本的同一单据被算两次 引擎
结果幂等 无键 —— 纯函数 只要输入相同，输出必相同 measure()
为什么必须三条都有：只有传输幂等 → 业务侧从两批推出同一张单，重复入账； 只有事件幂等 → 网络重试把一行推成两行，line_no 相同但 batch_id 不同时仍会重复； 两者都有但 measure 不纯 → 重放结果与当前余额不一致。
C-21 已指出 事件幂等键按单据，部分行重推会被静默漏掉——须按行。

货主分层

这是整套系统存在的理由。场景分三组——动物理量的、只动权属的、账面进出而实物不动的； 后两组才是货主分层模型存在的理由。

一级货主= 法人主体（legal_entity） 存货核算的边界

存货核算单元 = (物料, 仓库, 一级货主) —— 均价池只在这一层建立（批次不进均价池，只影响库龄与跌价）。
存货总额 = Σ 一级层 is_internal = 1 的金额——二级层绝不相加。

二级货主= 内部管理维度（部门 / 事业部 / 代采项目） 不进存货总额

一个数量：alloc_amount —— 硬校验，Σ 必须等于一级层金额。
两个金额：internal_amount —— 不做等式校验， 差额 = internal_pl 内部未实现毛利。

R1 · 一级货权转移

必作价（transfer_price 是交易数据，不配置只取价 + 校验）· 必出凭证 · 必产生会计损益

R2 · 二级重分配

必按internal_price（政策数据，带生效期价目表）作价， 差额进二级内部损益（管理口径），不出会计凭证

R3 · 均价池层级

存货均价池只在第一层建立——二级层没有自己的均价池

R4 · 存货总额

= Σ 一级层 is_internal = 1 的金额； 二级层绝不相加

R5 · 二级价不影响会计

二级内部结算价不进入会计口径——只服务管理报表

R2 取价：一个价、三个数

字段含义FIXEDMARKUP
price_base基准价NULL成本基数
markup_rate加成率 (10,7)NULL有值
price_value最终取值有值有值
三铁律：按业务日期取价 → 取到即快照 → 调价不追溯。 price_type 是行属性、不进主键。

调拨 vs 一级货权转移

判据只一条
情形单据适配层行为
调出仓与调入仓属同一一级货主TRANSFER收
属不同一级货主OWNER_TRANSFER业务推 TRANSFER → 拒绝
回执 E-CROSS-LEGAL-ENTITY。 不做自动升级——自动升级等于财务替业务定价。

C 组 · 账面进出、实物不动S-18
  • XY-1直发 / 直运
  • XY-2库内转手
  • XY-3纯单据空转
不是新单据类型，是 A 组两个场景的组合——单看每笔都正常，合起来才是"货没动"。
逆向与期间5
  • 改单（追加两组事件）
  • 作废 / 红冲

虚进虚出 —— 同一个词底下三种截然相反的账务处理

最容易做错
形态是什么该不该在账上走一遍进销仓库落点
XY-1 直发 / 直运 供应商直接发客户，从不入我方仓 必须 记两笔进销 IN_TRANSIT / VIRTUAL
XY-2 库内转手 货在同一仓不动、货主连续转手 严禁 记进销 → 应走 OWNER_TRANSFER 不落新仓
XY-3 纯单据空转 走单走票不走货 / 融资性贸易 不应确认收入 不落新仓
三条判断（为什么系统不能自己下判据）：
① 全额法 / 净额法是会计政策，不是系统问题
与 D-07「视同销售是税务判断不是会计判断」同一条原则。
② 权属由一级货主定，与仓库类型无关
直发期间照常 is_internal = 1，计入存货总额—— 不要因为仓是虚拟的就把权属配成 0。
③ 判据不能由系统下
"供应商上午送到、客户下午自提"与真正的空转，在单据上长得一模一样。 系统给特征（提示核对，不拦截），业务给声明。
设计禁令：绝不能提供"只记账、不动库存"的便捷开关——那等于给空转业务发工具。 虚拟仓 / 在途仓因此必须是受控的 A 级主数据。
另有一条边界：纯撮合（不持货权）根本不该产生任何出入库单据。
