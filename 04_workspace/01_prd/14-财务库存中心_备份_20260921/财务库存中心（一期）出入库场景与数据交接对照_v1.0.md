## 0. 三句话先记住

**第一句：单据分三组，后两组才是这套模型存在的理由。**

| 组 | 场景 | 物理数量 | 一级货主 | 二级货主 |
|---|---|---|---|---|
| **A 组 · 伴随物理移动** | 采购、销售、退货、其他出入库、盘点、调拨 | **变** | 采购/销售时变，调拨时不变 | 采购时确立，销售时清零 |
| **B 组 · 不动实物只动权属** | **货权转移、货主重分配** | **不变（= 0 变化）** | 货权转移**变** / 重分配**不变** | 重分配**变** |
| **C 组 · 账面进出、实物不动** | **虚进虚出**（直发 / 库内转手 / 空转，见 §5） | **±（一进一出，净 0）** | 视形态 | 视形态 |

B 组是「货没动、归属变了」的一类。**如果只把货主当成采购/销售单据上的两个字段，B 组就无处表达**——而代采、仓储监管这条线上，B 组才是主线。这也解释了为什么必须有独立的货权变更单，而不是硬塞进采购/销售单据里。

**C 组是最容易被漏的一组**——因为它**不是一种新单据，而是 A 组两个场景的特定组合**：采购入库记一笔、销售出库记一笔。**单独看每一笔都正常，合起来才是"货没动"。** 而它底下三种形态的账务处理**截然相反**（见 §5）：直发**必须**记成进销，库内转手**严禁**记成进销，纯空转**根本不该存在**。

**第二句：财务从不采信业务推来的金额。**
业务给的是**事实**（某天、某仓、某物料、进出多少数量）与**原始价格输入**（采购价、税率、运费、关税）。成本、出库成本、库存金额一律由财务算——业务推了也会被忽略，只会造成口径混乱。唯一的例外是**作价**：一级 `transfer_price`（转移作价） 是交易数据、二级 `internal_price`（内部结算价） 来自财务价目表，两者都是"取到即快照"，财务只取价+校验、不做定价。

**第三句：一张单该推哪类，问一句就够。**
> **调出与调入是不是同一个一级货主？**
> 是 → `TRANSFER`（调拨，按成本同额，无损益）
> 不是 → `OWNER_TRANSFER`（一级货权转移，视同销售，必作价、必出凭证、必有损益）

业务**不得推错**；财务侧适配层会**拒绝并回执 `E-CROSS-LEGAL-ENTITY`（跨法人错误码）**，**不做自动升级**——自动升级等于财务替业务定价。

## 2. 入库场景

### 2.0 先说清楚：什么是「通用行字段」

下面每个场景都写「**通用行字段 + 本场景差异字段**」。**通用行字段就是字段定义 `§4.1` 单据头 + `§4.2` 单据行这两张表**——**11 类单据每一类都有，且含义完全相同**；各场景只列**自己多出来的**那些。所以看到"通用行字段"就回这两张表：

**头级（字段定义 `§4.1`，所有单据共用）**

| 中文字段 | 字段 | 必填 | 说明（例：一张采购入库单） |
|---|---|---|---|
| 单据号 | `doc_no` | Y | **同一 `doc_type` 内唯一**（例：`PO-202601-0001`） |
| **单据类型** | **`doc_type`** | Y | 11 类之一（例：`PO_IN`）——**调拨出/入两条腿都是 `TRANSFER`，不拆** |
| **业务日期** | **`biz_date`** | **Y** | **A 级。必须是真实业务发生日，不能填推送日**（例：`2026-01-15`） |
| 单据状态 | `biz_status` | N | `DRAFT` / `SUBMITTED` / `APPROVED` / `EFFECTIVE` / `VOID`，缺省 `EFFECTIVE`（例：`EFFECTIVE`） |
| 法人 | `legal_entity` | Y | （例：`OWN-A`）——行级可覆盖 |
| 往来单位编码 | `counterparty_code` | 条件 | 供应商 / 客户 / 往来单位（例：采购入库为供应商 `S001`，销售出库为客户 `C001`） |
| 审核留痕 | `approved_by` / `approved_at` | 条件 | **「必审」= 单点审核动作 + 留痕**（O-19，不建审批流引擎）（例：`zhangsan` / `2026-01-15T09:12:00+08:00`） |
| 备注 | `remark` | N | （例：空） |

**行级（字段定义 `§4.2`，所有单据共用）**

| 中文字段 | 字段 | 必填 | 说明（例：一张采购入库单） |
|---|---|---|---|
| 行号 | `line_no` | Y | **`doc_no` 内从 1 递增**（例：`1`） |
| 出入方向 | `is_in` | Y | `0` = 出 / `1` = 入。**调拨两行靠它与 `warehouse_code` 区分**（例：`1`） |
| 物料编码 / 仓库编码 | `material_code` / `warehouse_code` | Y | （例：`M0001` / `WH01`） |
| **一级货主** | **`owner_l1`** | **Y** | **四轴之一，缺失拒绝入账**（例：`OWN-A`） |
| 二级货主 | `owner_l2` | N | 内部管理维度，**不进余额表主键、不进存货总额**（例：`OWN-A-1`） |
| 批次号 | `batch_no` | N | 空 = 不按批次管理（例：`B20260115001`） |
| 数量 / 计量单位 / **基本单位数量** | `qty` / `unit` / `base_qty` | Y | **`base_qty` 才是核算口径**，`qty × unit` 只作展示（例：`100.0000` 箱 → `3600.0000` 个） |
| 不含税金额 | `amount_ex_tax` | Y | **入账基数**（例：`1106.19`）。**出库类业务不给金额**——出库成本由财务按均价结转，与这里无关 |
| 税率 / 税额 | `tax_rate` / `tax_amount` | N | 税率缺省 `0.13`（例：`0.13` / `143.81`） |
| 分摊附加费用 | `allocated_cost` | N | 运费 / 关税 / 其他费用，按 `t_cost_allocation_rule` 分摊（例：运费 `200.00`） |
| 结算状态 | `settle_status` | N | `ESTIMATED` / `SETTLED` / `ADJUSTED`——暂估冲回的入口（例：`SETTLED`） |
| 暂估引用单号 | `estimate_ref_doc` | 条件 | （例：`PO-202601-0001`，指向被冲回的暂估单） |
| 是否关联方 | `is_related_party` | N | 决定合并抵消（例：`0` 对外 / `1` 集团内） |

> **本章及后续所有场景的示例取值统一取自设计文档**，便于与算例互相验算：字段口径见 `§7.2` / `§7.3` 各模板的「示例」列，数值见 `§3.7.6`（调拨）与 `§3.7.7`（货权转移 + 二级重分配）。**示例只说明"该填成什么样"，不是必须照抄的值。**

### S-01 采购入库 `PO_IN`

**触发**：供应商到货验收入库。

**① 业务给什么** = **通用行字段（见 `§2.0`）+ 下表这 3 项 `PO_IN` 差异化字段**

| 中文字段 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 供应商编码 | `supplier_code` | Y | `PO_IN` 的差异化必填字段（例：`S001`） |
| **运费 / 关税 / 报关费（分摊）** | `allocated_cost` | N | **+ 分摊方式与分摊基准（按金额/数量/重量）**（例：运费 `200.00`，分摊基准 `AMOUNT`） |
| 结算状态 | `settle_status` | N | 暂估场景给 `ESTIMATED`（见 S-02）（例：`ESTIMATED` → 发票到后 `SETTLED`） |

> **本场景的两个"必须给对"**：① `base_qty`（核算口径，不是 `qty`）——换算率缺失**拒绝入账，不做 1:1 兜底**；② `amount_ex_tax`（入账基数）——含税金额 `1250.00` **只用于核对，绝不入成本**。

**② 财务做什么**

```
1  校验：四轴主数据存在？换算率有？金额对齐（qty × convert_rate = base_qty）？
2  拆税额：不含税金额 = 含税金额 / (1 + 税率)；税额 = 含税金额 − 不含税金额
3  分摊附加费用 → 写入本行 allocated_cost（不入月末，一经落行成本即确定）
4  F1 移动平均入库（在核算单元层 (物料, 仓库, 一级货主)）：
      new_qty    = old_qty + base_qty
      new_amount = old_amount + (不含税金额 + 本行分摊费用)
      new_price  = round(new_amount / new_qty, 6)
5  落 t_document_line + t_inventory_balance（走 balance += delta，乐观锁 version）
6  写 t_calc_log（事件流，只增不删）→ 行置 cost_status = CALCULATED
7  生成凭证（模板 8.1.1）
```

**③ 影响什么**
- `t_inventory_balance`（库存余额表）：该核算单元的四轴记录 —— 数量 ↑、金额 ↑、**移动平均单价被重算**
- `t_calc_log`（核算事件日志表）：一条 `MA_IN`（移动平均入库事件） 事件
- `t_voucher_header/detail`（凭证头/明细表）：一张凭证 —— 借 库存商品 [不含税+分摊费用] / 借 进项税 [税额] / 贷 应付账款 [含税]

**④ 有什么用**
- **这是唯一会改变移动平均单价的单据方向**。别的场景（出库、调拨、货权转移的转入侧除外）都在消费这个价，只有采购在**生产**它。
- **采购入库 = 货主的诞生点**，是所有计价方法的第一个成本层/均价池建立的地方。
- 税额单独拆分是为了**进项税凭证**；含税入成本会同时虚增存货、少计进项税，两个错一起犯。

**⑤ 契约现状**：已覆盖（契约 `§2.2` + `§9.1`、字段定义 `§4.2`）。
**⚠️ 但有一条必须 W1 谈死**：**运费、关税是否计入存货成本、怎么分摊**。这一项漏掉，采购入库成本必然对不上，而且发现时往往已经跨月。

### S-02 采购入库（暂估）`settle_status = ESTIMATED`

**触发**：货到票未到。金额是估的。

**① 业务给什么**：同 S-01，但结算状态 `settle_status = ESTIMATED`，金额为暂估价。

**② 财务做什么**：走**与正常采购入库完全相同的模板**（8.1.1）。暂估不是特殊单据，只是同一个单据上多一个状态位。金额照常进成本、照常改均价。

**③ 影响什么**：与 S-01 相同。差别只在于：这笔成本是**暂挂的**——后续 S-03 会来冲它。

**④ 有什么用**：解决"货已入库、票未到，账上不能没数"。没有暂估，要么月末凭空挂账、要么存货少计。

### S-03 发票到达（结算事件）

**触发**：发票到了，暂估价可以变成实际价。

**① 业务给什么**：**重推该行**（或推一条结算事件），带结算状态 `settle_status = SETTLED` + **暂估引用单号 `estimate_ref_doc` 指向原暂估单**。

**② 财务做什么**

```
1  按 estimate_ref_doc 定位原暂估行
2  追加【反向事件】冲掉暂估金额 → settle_status = ADJUSTED
3  追加【据实事件】按发票不含税金额重新入库 → settle_status = SETTLED
4  每一步各出一张凭证
5  差额处理：D-04 锁定「不追溯、只调当期」
```

> **不走"直接改暂估金额"**——事件只增不删，冲回与据实是**两个事件**，不是一次 UPDATE。

**③ 影响什么**：`t_calc_log`（核算事件日志表） 两条新事件（一负一正）；该核算单元均价被重算；两张凭证。

**④ 有什么用**：**没有这个事件，暂估就永远冲不掉**——存货科目挂着估计值过年，审计一来就是问题。

**⑤ 契约现状**：契约 `§2.3` 已补为必推项（v1.2 变更第 12 项，F19 / D-04）。
> ⚠️ **G-01（缺口）**：字段定义 `§2.1` 的 `object`（报文对象） 枚举只有 `master_data`（主数据） / `document`（单据） / `doc_action`（单据动作） / `snapshot`（快照），**"发票到达"没有明确归属**。契约说"另推一次该行（或推结算事件）"——若重推整行则归 `document` 可解释，若推独立结算事件则枚举里无处安放。**建议 W1 明确取哪一种**，否则业务侧与适配层会各写各的。
> **一期兜底**：业务侧推不出结算事件时，财务可**手工补录**——但**每笔须留痕**，月结时须能列出"手工补录清单"。

### S-04 销售退货入库 `SO_RET`

**触发**：客户退回。

**① 业务给什么**：同销售出库的字段，**外加原销售出库单号 `orig_so_doc`**——这个字段是必填，不是可选。

**② 财务做什么**

```
1  按 orig_so_doc 追溯【原出库时的成本单价】——不是当前均价
2  按原出库成本取负回冲：
      库存商品 ↑ [原出库成本]；主营业务成本 ↓ [原出库成本]
3  入数量，但【不重算】成本层——用原价
```

**③ 影响什么**：数量 ↑、金额 ↑（按原成本）；但**不回改已结转的历史成本**。凭证模板 8.1.9。

**④ 有什么用**
- **按原出库价冲回而不是按当前均价**，这条不是可选项。若按当前均价重算，一次退货会**改变已结转的历史成本**——当期损益被退货"重写"，前期的报表也就跟着变了。
- `orig_so_doc`（原销售出库单号） 就是为这件事存在的。**业务不给这个单号，退货就无法正确处理**（`E-SRC-DOC-MISSING`（缺来源单号错误码） 行级拒绝）。

### S-05 其他入库 `OTHER_IN`

**触发**：不属于采购、但实物确实入库。契约 `§2.2` 把这一类写成三个词（借用归还 / 赠品 / 样品回收）——**它不是一类，是五类**。这五类的**金额来源不同、权属不同、出不出凭证也不同**。混成一行写，最直接的后果是**把"必须有估价金额"这条要求，扣到了根本不需要估价的场景头上**。

#### 按「金额从哪来」切成五类

| # | 子场景 | 典型触发 | **金额来源** | 一级货主 | 计入存货总额 | 出凭证 |
|---|---|---|---|---|---|---|
| **IN-1** | 原物归还 | 借出后归还、送出的样品回收 | **原借出 / 原送出的结转金额**，**回冲、不重估** | 我方 | 计入 | 出（原科目反向） |
| **IN-2** | 受赠入库 | 供应商赠送、促销赠品、活动物料 | **供应商开票价 / 公允价值**（业务给） | 我方 | 计入 | 出（营业外收入，或冲减采购成本） |
| **IN-3** | 受托代销 · 寄售 | 代销他人的货，实物进我方仓 | **委托方代销价 / 对账单金额**（**外部**给） | **外部法人** | **不计入** | 不出（备查登记） |
| **IN-4** | 借入他方货物 | 临时借用他方货 | **出借方作价**（外部给） | **外部法人** | **不计入** | 不出（备查登记） |
| **IN-5** | 无对价杂项 | 找回货、无原单退回、来源说不清的 | **财务手工估价** | 我方 | 计入 | 出（营业外 / 待处理） |

> **一句话**：**"必须有估价金额"只对 IN-5 成立。** 前四类都有真实金额——要么我方账上已有（IN-1），要么是别人给的（IN-2 / IN-3 / IN-4）。若一律要求手工估价，**估出来的数与真实发生额对不上，还会凭空多出一笔损益**。

#### ① 业务给什么 —— 其他入库各子场景的差异字段与举例

> 五个子场景**共用 §2.0 的全部通用行字段**，区别只在下面这几项。**标 ★ 的是 G-08 建议新增、现契约还没有的字段**——加它们的原因就写在举例里：没有这几项，财务无法判断"这笔金额该取数还是该估价"。

| 子场景 | 差异字段 | 必填 | 说明与举例 |
|---|---|---|---|
| **IN-1** 原物归还 | `reason` | Y | （例：`RETURN_BORROW` 借用归还 / `RETURN_SAMPLE` 样品回收） |
| | **★ `orig_doc_no`** | **Y** | **原出库单号**——回冲金额靠它查（例：`OT-202601-0005`，对应那次借出/送样） |
| | `orig_qty` | Y | 原出库数量，用于算"归还了几成"（例：`10.0000`） |
| | **★ `valuation_source`** | Y | **金额从哪来**的标记，本类恒为 `ORIG_DOC`（原单回冲） |
| **IN-2** 受赠入库 | `reason` | Y | （例：`GIFT_RECEIVED`） |
| | `counterparty_code` | Y | 赠送方，走 §2.0 头级字段（例：`S001`） |
| | **★ `valuation_source`** | Y | `EXTERNAL`（外部给价） |
| | **★ `valuation_basis`** | Y | **公允价值依据**——谁给的、按什么（例：`供应商开票价 1,000.00` 或 `同类市场报价`） |
| **IN-3** 受托代销 · 寄售 | **`owner_l1`** | **Y** | **必须是外部法人**（例：`OWN-D`，其 `is_internal = 0`）——**这是本类与普通入库唯一的、也是最关键的区别** |
| | `counterparty_code` | Y | 委托方（例：`OWN-D`） |
| | `reason` | Y | （例：`CONSIGNMENT_IN`） |
| | **★ `valuation_source`** | Y | `EXTERNAL` |
| | **★ `valuation_basis`** | Y | 委托方给的对账价（例：`对账单 2026-01#3, 单价 10.00`） |
| **IN-4** 借入他方货物 | **`owner_l1`** | **Y** | **外部法人**（例：`OWN-D`） |
| | `counterparty_code` / `reason` | Y | 出借方 / （例：`OWN-D` / `BORROW_IN`） |
| | **★ `valuation_source`** / **★ `valuation_basis`** | Y | `EXTERNAL` / 出借方作价（例：`借出方作价 10.00`） |
| **IN-5** 无对价杂项 | `reason` | Y | **必须写明为什么没有对价**（例：`RECOVERED_STOCK` 找回货 / `UNMATCHED_RETURN` 无原单退回） |
| | **★ `valuation_source`** | Y | **`FINANCE_ESTIMATE`——全五类里唯一用这个取值的** |
| | **★ `valuation_basis`** | Y | 财务估价依据 + **估价人**（例：`按最近一次采购价，李四 2026-02-03`） |

> **这张表就是 G-08 的落地形态**：四个 ★ 字段加上去，业务侧才能把"这笔金额是回冲的、是别人给的、还是财务估的"表达出来；不加，就只能一律填一个 `reason` 字符串，**财务拿到手要人工逐笔判**。

#### IN-1 原物归还 —— **最容易被写错的一类**

**① 业务给什么**：通用行字段 + 原因 `reason` + **原出库单号**（哪一单借出的 / 哪一单送出的）。
**② 财务做什么**：按**原出库时的结转金额**回冲（归还部分按原结转单价计）。**归还时重新估价是错的。**
**③ 影响什么**：数量 ↑、金额 ↑（按原额入池）。均价随之变动——**归还额是一笔"按原价买入"的入库，它会拉动均价**，拉动方向取决于原额与当前均价的高低。
**④ 为什么不能重估**
- 借出、送样时是按**当时的均价**结转出账的。归还时若按**今天的均价**入账，一借一还之间就凭空长出一个差额——**这笔差额是假的**，既不是我方的收入也不是损失。S-04 销售退货入库按**原出库价**冲回（不按当前均价重算），**是同一条道理**，两处的方向也一致。
- **部分归还的处理**：借出 10 件只还回 8 件，**剩下 2 件要在归还当期转为费用出库**（走 OUT-1 / OUT-2），不能无限期挂在"借出"上。所以业务推归还单时**必须给原单号与原数量**，否则财务算不出"该回冲多少、该转费用多少"。
- 这条要求决定了 `OTHER_IN` 需要 **`orig_doc_no`（原单号）字段**——现在的差异化字段只有 `reason`（见 **G-08**）。

#### IN-2 受赠入库

**① 业务给什么**：通用行字段 + `reason` + **供应商开票价，或公允价值的取值依据**。
**② 财务做什么**：按**不含税公允价值**入存货；对方开票的按票面确认进项税。**对方不开票的，依据由业务提供、财务复核——不是"财务拍一个数"。**
**③ 影响什么**：数量 ↑、金额 ↑、均价重算。
**④ 一条铁律**
> **受赠要不要确认进项税、赠出要不要视同销售，都是税务判断，不是会计判断。** 会计上：受赠侧按公允价值进存货、赠出侧进成本费用；税务上按税法另行判断。**两者不要互相推导**（与 D-07 同源）。

#### IN-3 受托代销 · 寄售 / IN-4 借入他方货物 —— **实物进来了，但不是我的存货**

**① 业务给什么**：通用行字段 + `reason` + **一级货主 = 委托方 / 出借方（外部法人）** + 对方给的对账价。
**② 财务做什么**：**建一条四轴余额记录、记数量、记金额，但 `is_internal = 0`，不计入存货总额**（D-06 / R4）。只做**备查 / 代销库存**管理。
**③ 影响什么**
- **数量上"进来了"**——它算在**物理在库数量**里，业务系统的数量对账要含它。
- **金额上"不是我的"**——它**不在存货总额里**，不进跌价基数，不参与均价池。
- 所以同一时点会**出现两个数**：`在库数量`（含它）与 `权属数量`（不含它）。框架 `§3` 已写明一期**允许分叉**，但要求**对账时各用各的口径**：**数量对账用「在库数量」，存货金额对账用「权属数量」**。
**④ 为什么必须能表达"权属不属我方"**：这是**没有采购单、货却进了我方仓**的唯一合法表达方式——契约 11 类单据里没有"代销入库 / 借入"这类类型，`OTHER_IN` 是它唯一的落点。**所以它承担的是一类有真实金额、却不进存货总额的入库**，不能按普通入库处理。

#### IN-5 无对价杂项 —— **只有这一类才真的需要财务估价**

**① 业务给什么**：通用行字段 + `reason` + **说清为什么没有对价**。
**② 财务做什么**：**必须有估价金额**（业务给不出时财务手工维护），按估价入库。
**③ 影响什么**：数量 ↑、金额 ↑（按估价）、均价重算。
**④ 有什么用**：给"不属于采购、又不属于上面四类"的实物入库一个兜底入口。
> **盘盈不走这里。** 盘点后 `实盘 > 账面` 由 `STOCKTAKE`（S-06）自动派生，走「待处理财产损溢」。两者都表现为"多出来的货"，但**一个是有账可查的盘点差异、一个是无来源的杂项**，凭证科目完全不同，不要混。

> ⚠️ **契约 `§10.2` 已把"其他出入库的具体场景清单"列为待确认项**。上面五类是按**金额来源**推出来的骨架，**贵司实际会出现哪几类、每类叫什么名字，要 W1 逐个确认后写进契约**。这一类的风险不是"填不对"，而是**什么都能往里塞**——塞进来又不给金额、又不给原单号，到财务手上就是一笔无法解释的调整。

### S-06 盘盈入库（由 `STOCKTAKE` 派生）

**触发**：盘点后 `实盘数量 > 账面数量`。

**① 业务给什么**：推的是**盘点单**（`STOCKTAKE`），带账面数量 `book_qty` 与实盘数量 `actual_qty`。

**② 财务做什么**

```
1  diff_qty = actual_qty − book_qty
2  diff > 0 → 自动生成【盘盈入库单】：入库金额 = diff_qty × 当前成本单价
3  进入通用入库链路（同 S-01 的 4–7 步）
```

**③ 影响什么**：数量 ↑、金额 ↑；凭证走**待处理财产损溢**（8.1.5）。

**④ 有什么用**：让"账实不符"有一个受控的处理通道，而不是手工调余额。差异必须**当期处理完毕**，滚动到下期就越滚越大。

> **关于 `book_qty`（账面数量） 给不给**：契约 `§9.4` 写的是可选（"如不给，财务侧按自己的账面比对"）。**建议财务侧一律以自己账面算 diff**，业务侧的 `book_qty` 只用于比对告警——见 `S-34` 与 G-04。

### S-09 期初余额导入（上线一次性）

**触发**：系统上线，把存量库存一次性导进来。

**① 业务（或双方）给什么**：`(物料, 仓库, 批次, 一级货主)` 四轴 + 期初数量 + 期初金额/单价。

**② 财务做什么**：落 `t_initial_balance`（期初余额表），带 **`import_batch_id`（导入批次号）**——期初导错要能**整批撤销重导**，不能靠人工逐行改。

**③ 影响什么**：这是所有存量成本的**第一笔事件**，后续所有移动平均都从这里长出来。

**④ 有什么用 / 最危险的一点**
> **货主维度必须导。** 若有货但没落货主，**四轴从第一天就是坏的**——后面每一笔成本都串味，且无法追溯修复。这也是为什么 O-07（业务侧是否也建货主维度）是契约里唯一的外部依赖项。

> ⚠️ **G-02（缺口）**：字段定义 `§2.1` 的 `object`（报文对象） 枚举**没有期初余额的位置**。期初既不是 `master_data`（不是档案），也不是日常 `document`（不是业务单据流），更不是 `snapshot`（不是对账快照）。**建议加一个 `object = initial_balance`**，或明确归入 `document` 并单列 `doc_type = INIT`，否则期初走哪条通道在报文层是未定义的。

## 3. 出库场景

### S-10 销售出库 `SO_OUT`

**触发**：发货给客户。

**① 业务给什么**：单据号/行号、业务日期、推送时间 `pushed_at`、客户编码 `customer_code`、物料编码/仓库编码、**一级货主 `owner_l1`**、二级货主（可选）、**批次号/序列号（3C 整机必填）**、数量/计量单位、**基本单位数量 `base_qty`**。

> **出库单不需要提供成本、金额**——由财务侧按移动平均单价结转。

**② 财务做什么**

```
1  校验：物料/仓库/客户有效？出库数量 ≤ 当前库存？（负库存见 S-13 注）
2  取当前核算单元 (物料, 仓库, 一级货主) 的移动平均单价
3  F2：out_amount = round(base_qty × current_price, 2)
      记录本次舍入差异 → 累加到 t_inventory_balance.rounding_diff_acc
4  扣减余额：new_qty = old_qty − base_qty；new_amount = old_amount − out_amount
5  写 t_calc_log（MA_OUT）→ 行置 CALCULATED
6  生成凭证（8.1.2）：借 主营业务成本 / 贷 库存商品
```

**③ 影响什么**：数量 ↓、金额 ↓、**单价不变**（出库不改变均价）；`rounding_diff_acc`（舍入差异累计） 累加；一张凭证。

**④ 有什么用**
- **这是唯一会从成本池抽出金额的地方**，销售出库 = 货主的消亡点。
- **出库是舍入差异的唯一来源**。入库金额是确定的入账数，只舍入单价到 6 位；出库金额是**算出来的**（`数量 × 6位单价`），落在 2 位上必然有尾差。月末用一张独立凭证结转（8.1.7）。
- **SN 必须出现在出库行上**，否则二期个别计价（每台单独结转）无法落地。

---

### S-11 采购退货出库 `PO_RET`

**① 业务给什么**：+ **原采购入库单号 `orig_po_doc`（必须可追溯）**。
**② 财务做什么**：按**当前核算单元均价**结转成本。
**③ 影响什么**：数量 ↓、金额 ↓、均价**重算**（与销售出库不同！）；凭证 8.1.8。
**④ 有什么用 / 一条容易误解的**
> **按当前均价结转、而不是按原入库价**——所以与原入库价必然不同。**这个差额是已实现的退货损失/收益，正常进损益，不做追溯调整。**
> 对比：销售退货入库（S-04）反而要按**原出库价**冲回。两者的口径**方向相反**，别记混：
> - 采购退货出库 → **按当前均价**（差额进损益）
> - 销售退货入库 → **按原出库成本**（不能重写历史）

---

### S-12 其他出库 `OTHER_OUT`

**触发**：不进入销售、但实物确实出库。契约 `§2.2` 列了五个词（领用 / 报废 / 赠出 / 借出 / 样品送出）——**同样不是一类，是六类**。这六类里**五类的金额是"当前均价"、一类的金额是零**，而"要不要回来"这一问又把它们分成两组。

#### 按「金额怎么定、会不会回来」切成六类

| # | 子场景 | 典型触发 | **金额怎么定** | 一级货主 | 对存货总额的影响 | 出凭证 |
|---|---|---|---|---|---|---|
| **OUT-1** | 内部领用 · 自用 | 部门领用、办公消耗 | **当前均价**结转，进费用 | 我方 | 数量 ↓、金额 ↓ | 出（管理费用 / 销售费用） |
| **OUT-2** | 报废 · 毁损 | 质检不合格、过期、损坏 | **当前均价**；**残值收入与赔偿要抵减损失** | 我方 | 数量 ↓、金额 ↓ | 出（待处理财产损溢 → 费用） |
| **OUT-3** | 赠出 · 送样 | 送客户样品、促销赠品 | **当前均价** | 我方 | 数量 ↓、金额 ↓ | 出（销售费用） |
| **OUT-4** | 借出（**可归还**） | 借给客户 / 关联方试用 | **当前均价**，但**登记为可回收**，归还时按原额回冲（对接 IN-1） | 我方 | 数量 ↓、金额 ↓ | 出（暂挂，**不是费用**） |
| **OUT-5** | 委托代销发出 | 发往渠道代销，**权属仍属我方** | **当前均价**，**转「发出商品」** | 我方 | 数量 ↓、金额 ↓（**科目位移，不是费用**） | 出（库存商品 → 发出商品） |
| **OUT-6** | 货权已转、实物才出库 | 代采已转货权未提货，之后发货 | **不作金额**（金额在货权转移时已出账） | **外部法人** | **数量 ↓、金额 0** | 不出 |

> **一句话**：**出库不是"都是费用"。** OUT-4 借出与 OUT-5 委托代销发出，货还在我方账上（一个是可回收的暂挂、一个是换个科目放着）——**只有 OUT-1 / OUT-2 / OUT-3 是真正的费用出库**。把六类都当费用，借出的货一出去就变成成本，回来时又凭空多一笔收益。

#### ① 业务给什么 —— 其他出库各子场景的差异字段与举例

> 六个子场景**共用 §2.0 的全部通用行字段**。**注意**：出库类业务**不给金额**——`amount_ex_tax` 在 OUT-1 ~ OUT-5 一律留空，出库成本由财务按均价结转；**唯一例外是 OUT-6，它的金额是显式的 0**（不是留空）。**标 ★ 的是 G-08 建议新增的字段。**

| 子场景 | 差异字段 | 必填 | 说明与举例 |
|---|---|---|---|
| **OUT-1** 内部领用 · 自用 | `reason` | Y | （例：`INTERNAL_USE`） |
| | `dept_code` | Y | **领用部门**——决定进哪个费用科目（例：`D-ADMIN` 行政 → 管理费用 / `D-SALES` → 销售费用） |
| **OUT-2** 报废 · 毁损 | `reason` | Y | （例：`SCRAP_DAMAGE` 损坏 / `SCRAP_EXPIRED` 过期） |
| | **★ `residual_amount`** | N | **残值 / 赔偿金额**，用于抵减损失（例：残料入库 `50.00`、保险赔偿 `300.00`；无则留空） |
| | **★ `residual_source`** | 条件 | 残值来源（例：`SCRAP_SALE` 残料变卖 / `INSURANCE` 保险赔付 / `EMPLOYEE` 责任人赔偿） |
| **OUT-3** 赠出 · 送样 | `reason` | Y | （例：`GIFT_OUT` / `SAMPLE_OUT`） |
| | `counterparty_code` | Y | 受赠方 / 送样对象（例：`C001`） |
| **OUT-4** 借出（**可归还**） | `reason` | Y | （例：`LEND_OUT`） |
| | **★ `is_recoverable`** | **Y** | **`1` = 可归还**——**这个标记是 OUT-4 与 OUT-3 唯一的分界线**（例：`1`）；标了它才配 IN-1 的归还回冲 |
| | `counterparty_code` | Y | 借出对象（例：`C001`） |
| | **★ `due_date`** | Y | **约定归还日期**，用于出超期清单（例：`2026-04-30`） |
| **OUT-5** 委托代销发出 | `reason` | Y | （例：`CONSIGNMENT_OUT`） |
| | `counterparty_code` | Y | **受托方编码**（例：`C002`）——**一级货主仍是我方 `OWN-A`，不变** |
| | **★ `account_subject`** | Y | 结转去向，本类恒为 **`发出商品`**（与 OUT-1~3 的"费用"区分） |
| **OUT-6** 货权已转、实物才出库 | **`owner_l1`** | **Y** | **外部法人**（例：`OWN-D`）——**货权已不在我方，只是代它发货** |
| | `reason` | Y | （例：`SHIP_FOR_OWNER`） |
| | **★ `orig_owner_transfer_doc`** | **Y** | **对应的货权转移单号**——证明"金额已在那一单出账"（例：`OT-202601-0001`） |
| | **★ `amount_ex_tax`** | **Y** | **显式填 `0.00`**——不是留空。留空会被当成"待财务结转"，填 0 才是"本单不结转金额" |

> **这张表的三个分界点**：`is_recoverable`（OUT-4 与 OUT-3）· `account_subject`（OUT-5 与 OUT-1~3）· `amount_ex_tax = 0`（OUT-6 与其余五类）。**三个字段都不存在，业务就只能靠 `reason` 里写自由文本**——这正是 G-08 要求补的原因。

#### OUT-1 / OUT-2 / OUT-3 真正的费用出库 —— 三类的差别只在科目

**① 业务给什么**：通用行字段 + 原因 `reason` + **领用人 / 报废原因 / 受赠方**。
**② 财务做什么**：按**当前均价**结转，按类别映射科目：内部领用 → **管理费用**；报废毁损 → **待处理财产损溢**，查明原因后转费用或应收赔偿；赠出 · 送样 → **销售费用**。
**③ 影响什么**：数量 ↓、金额 ↓（按当前均价），**均价不变**。
**④ 两条容易漏的**
- **报废必须问残值与赔偿**：有残料入库的要先扣减，有责任人 / 保险赔偿的要转应收。**按全额进损失是错的**——那会把可收回的部分一次性费用化。
- **报废 ≠ 盘亏**：盘亏由 `STOCKTAKE`（S-13）自动派生并走同一「待处理财产损溢」科目；**报废是业务主动推的单**，两者科目相同、**来源与单据类型不同**，不要合并。
> **D-07 已锁定**：赠品 · 样品 · 内部领用 · 报废走**销售费用 / 管理费用**；**是否视同销售是税务判断，不是会计判断**——会计上先进成本 / 费用，税务上按税法另行判断，**两者不要互相推导**。

#### OUT-4 借出 —— **与 OUT-3 送样的分界，业务必须自己分清**

**① 业务给什么**：通用行字段 + `reason` + **借出对象、约定归还日期、借出单号**。
**② 财务做什么**：按当前均价结转并**登记为可回收**（不直接进费用）。归还时按**原结转金额**回冲——这条与 IN-1 是同一件事的两端。
**③ 影响什么**：数量 ↓、金额 ↓；归还时反向。**一借一还之间不产生任何损益。**
**④ 为什么必须与送样分开**
- **借出是可逆的，送样是不可逆的。** 若业务把借出也按送样推，货一出去就全额进销售费用；等还回来时又要作为"受赠"或"归还"入账——**中间无端多出一笔费用、一笔收益，两边都错**。
- 所以 `OTHER_OUT` 需要能区分「可回收 / 不可回收」——现在差异化字段只有 `reason`，**只能靠业务在原因里写清楚，财务人工判**（见 **G-08**）。

#### OUT-5 委托代销发出 —— **货出去了，但还是我的存货**

**① 业务给什么**：通用行字段 + `reason` + **受托方编码** + 发出数量。
**② 财务做什么**：按当前均价结转，**科目从「库存商品」转到「发出商品」**——**权属未转移，仍在存货总额内**（D-06 委托代销 = 计入）。
**③ 影响什么**：数量（物理在库）↓、**存货总额不变**（只是科目位移）。真正的销售在受托方售出、我方开票时才确认收入与结转成本。
**④ 为什么要单独一类**：这是 **IN-3 的镜像**——受托代销是别人把货放我这（`is_internal = 0`、不计入），委托代销是我把货放别人那（`is_internal = 1`、**仍计入**）。两者都发生在"货不在我仓"的时候，**方向相反，别写反**。

#### OUT-6 货权已转、实物才出库 —— **数量动、金额不动**

**① 业务给什么**：通用行字段 + `reason` + **对应的货权转移单号**。
**② 财务做什么**：**只减物理数量，不作任何金额结转**——这批货的金额已经在**货权转移那一刻**（S-20）出账了。
**③ 影响什么**：物理在库数量 ↓、**存货金额与总额都不动**。
**④ 为什么会有这一类**
- 框架 `§7.4` 的代采链路是：**先采购入库（货权在垫资方）→ 再货权转移给客户 → 最后物理发货**。走到第三步时，"货权已经不在我方、但货还物理在库里"——**发货这个动作只动数量**。
- 框架 `§3` 已写明一期**允许数量口径与金额口径分叉**，这一类就是分叉的收敛点：物理数量走出去，账上金额早在第二步就清掉了。
- **契约 11 类单据里没有对应类型**（见 **G-09**）——现在只能塞进 `OTHER_OUT`，但 `OTHER_OUT` 的表征是"按当前均价结转金额"，与这类"金额为 0"的语义**正好相反**。

> ⚠️ **契约 `§10.2` 已把"其他出入库的具体场景清单"列为待确认项**。上面六类是按**金额怎么定、会不会回来**推出来的骨架，**W1 要逐类确认后写进契约**（同 S-05）。

### S-13 盘亏出库（由 `STOCKTAKE` 派生）

**触发**：`实盘数量 < 账面数量`。
**② 财务做什么**：`出库成本 = |diff_qty| × 当前成本单价`；凭证走待处理财产损溢（8.1.4）。
**④ 有什么用**：与 S-06 对称。

> **负库存怎么办（与盘点相关的独立话题，F20）**：**不做一刀切禁止**——"先出后入"在贸易/电商下真实存在（先发货、后到票）。改为**按容差参数 `NEGATIVE_STOCK_TOLERANCE`（负库存容差）** 控制，**一期阈值 = 0（等于禁止）**，由财务部按品类确认后调高。
> 三种情形：余额 ≥ 0 正常过账 / 余额为负但在容差内 **允许过账 + 告警** / 超出容差 **拒绝过账并回执**。**不允许出负数量且无任何记录**——负库存必须可见、可查、可催票。

### S-14 调拨（出库腿）`TRANSFER` `is_in = 0`

**触发**：同一一级货主下，货从一个仓转到另一个仓。

**① 业务给什么**

| 中文字段 | 字段 | 说明 |
|---|---|---|
| 单据号 / 行号 | `doc_no` / `line_no` | 同一次调拨共用**一个单号**（例：`TR-202601-0001`，两行 `line_no` = `1` 调出 / `2` 调入） |
| **调出仓库 / 调入仓库** | **`out_warehouse_code` / `in_warehouse_code`** | **两个仓都必须给**（例：`WH01` → `WH02`） |
| **一级货主** | **`owner_l1`** | **调出、调入两边必须相同**（例：`OWN-A`；两边不同即拒绝，回执 `E-CROSS-LEGAL-ENTITY`） |
| 物料编码 / 数量 / 基本单位数量 / 批次号 | `material_code` / `qty` / `base_qty` / `batch_no` | （例：`M0001` / `10.0000` / `10.0000` / 空） |

**② 财务做什么**

```
0  前置判定：调出仓与调入仓是否同一一级货主？
      否 → 拒绝并回执 E-CROSS-LEGAL-ENTITY，要求改推 OWNER_TRANSFER（不自动升级）
1  【先出】按调出仓做调拨出库：出库成本 = base_qty × 调出仓单价；扣减调出仓余额
2  【后入】按【同一金额】做调拨入库：调入金额 = 调出成本金额
      并入调入仓库存 → 重算调入仓的移动平均单价
3  两仓分别记 t_calc_log（同一事务内）
4  生成凭证（8.1.3）：借 库存商品-调入仓库 / 贷 库存商品-调出仓库
```

**③ 影响什么**：**调出仓**数量↓金额↓；**调入仓**数量↑金额↑；**调入仓均价按合并后金额重算**（数值见设计算例 3.7.6）；公司层面**总库存金额不变**。

**④ 有什么用**：让"货在仓间移动"与"货权不变"这两件事能分开表达。**调拨不产生任何损益**——这一点与一级货权转移（S-20）形成鲜明对比。

**⑤ 契约现状与落库展开规则**
业务侧推 **1 张单、2 个仓**；适配层展开为 **2 行**：

```
doc_no = TR-202601-0001
  line 1: warehouse_code=WH01(调出), is_in=0, line_no=1
  line 2: warehouse_code=WH03(调入), is_in=1, line_no=2
两行 doc_type 都是 TRANSFER，共用同一个 doc_no
```

> **为什么不能拆成两张单**：① `doc_no`（单据号） 唯一性被破坏；② 传输幂等键 `batch_id + doc_no + line_no` 对不上，**重推即重复入账**。
> **为什么 `doc_type` 不设 `TRANSFER_OUT` / `TRANSFER_IN` 两个值**：判据是 **`doc_type` 数的是一张单据从哪来、干什么的，不是数它动了几行**。转出/转入是**行上的属性**（`warehouse_code`（仓库编码） + `is_in`（出入方向）），不是两个单据类型。

> ⚠️ **G-03（缺口）**：调拨报文的**字段形态没有示例**。字段定义 `§4.3` 写的是头级 `out_warehouse_code`（调出仓库编码） / `in_warehouse_code`（调入仓库编码），**推 1 行**；而 `§4.2` 落库后是行级 `warehouse_code`（仓库编码）+ `is_in`（出入方向），**2 行**；`§9` 的报文示例只有 `OWNER_TRANSFER`（一级货权转移），**没有调拨的例子**。两种形态都对，但**业务侧看不到"该按哪种填"**。**建议在 `§9` 补一条调拨报文示例**，否则极易出现业务推 2 行、而适配层期待 2 个仓字段（或反之），当场对不上。

## 4. 货权变更场景（不动实物）—— 一级与二级调拨专章

> 产权交易中心一期不落地，由库存中心出**临时货权变更单**承载。按**可剥离形态**设计：单据自带价格与 `price_source`（作价来源）、`is_accounting_event`（是否会计事件） 显式分列一二级、**不直接改余额只产生事件**——二期是**搬迁不是重写**。
>
> **可剥离的 5 条原则**（决定二期不返工）：① 单据自带价格与价格来源，取价逻辑不写在核算引擎里；② 状态机自洽；③ 对手方是**货主编码**而非客户/供应商档案；④ `is_accounting_event` **显式分列**，一级/二级不靠散落的 `if 单据类型` 判断；⑤ **不直接改余额**，只产生事件，余额改动仍归核算引擎。

### 4.1 S-20 一级货主之间的调拨 = 一级货权转移 `OWNER_TRANSFER`

> **先说清一件事：这不是调拨，是交易。** 调出与调入不属于同一法人时，货权换了主体——**视同销售**。业务侧不能推 `TRANSFER`。

#### 四个子形态（都在 `OWNER_TRANSFER` 一个类型里）

| 子形态 | 转出/转入 `is_internal`（是否计入存货） | 物理是否移动 | 合并抵消 | 典型场景 |
|---|---|---|---|---|
| **① 集团内跨法人、货同仓** | 1 / 1 | **不动** | **需抵消** | 集团内调剂 |
| **② 集团内跨法人、货也移动** | 1 / 1 | 移动 | **需抵消** | 跨法人调仓 |
| **③ 对外转移、货留我方仓** | 1 / 0 | **不动** | 无需 | **代采已转货权、客户未提货；受托代销** |
| **④ 对外转移、货随货权走** | 1 / 0 | 移动 | 无需 | 正常销售但走货权单（少见） |

> **形态③ 是这套模型最该被理解的一个状态**：货在库里，业务系统看是"有 3 台货"，财务看是"**0 存货**"。**两个数字都对，只是口径不同**——所以必须把两个词分开命名：
> - **在库数量**（物理在库，仓库口径）→ **数量对账用这个**
> - **权属数量**（归属某法人，货主口径）→ **存货金额用这个**
>
> 若混用，这几天的对账必然爆出假差异。

#### ① 业务/财务给什么

| 中文字段 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 单据号 / 行号 / 业务日期 / 推送时间 | `doc_no` / `line_no` / `biz_date` / `pushed_at` | Y | （例：`OT-202601-0001` / `1` / `2026-01-31` / `2026-01-31T18:30:00+08:00`） |
| **单据类型** | **`doc_type`** | Y | `OWNER_TRANSFER` |
| 物料编码 / 仓库编码 | `material_code` / `warehouse_code` | Y | **货权变更不移动实物时，仓库不变**（例：`M0001` / `WH01`） |
| 批次号 / 序列号 | `batch_no` / `SN` | 条件 | （例：空 / `SN2026011500001`） |
| 基本单位数量 | `base_qty` | Y | （例：`40.0000`） |
| **转出一级货主 / 转入一级货主** | **`from_owner_l1` / `to_owner_l1`** | **Y** | 转出法人 / 转入法人（例：`OWN-A` → `OWN-B`） |
| **转移作价** | **`transfer_price`** | **Y** | **一级作价——交易数据，来自销售单/合同/逐笔录入。财务只取价+校验，不做定价**（例：`12.000000`；同批**成本价是 `10.000000`**——**作价与成本是两个价**，见 `③`） |
| **作价来源** | **`price_source`** | **Y** | `TRANSFER`（一级交易价；来自销售合同的场景也写 `TRANSFER`，不写业务系统的单据名） |
| **是否会计事件** | **`is_accounting_event`** | **Y** | 一级转移 = **1** |
| 是否关联方 | `is_related_party` | Y | 决定是否需合并抵消（F11）（例：集团内 `1`，对外 `0`） |
| 对手方合同号 | `counterparty_contract_no` | 条件 | 关联合同号，便于关联交易披露（例：`HT-2026-0117`） |
| **触发方式** | — | — | **一期临时**：一级由业务+财务发起；**二期由产权交易中心触发** |

> **上面这套取值就是设计文档 `§3.7.7` 算例 7 的 UAT 基线**：40 件、作价 `12.00`、转出方成本 `10.00` → 转出方确认毛利 `80.00`，转入方按 `12.00` 建层。**这两个价在字段上是两个字段，在会计上是两笔分录**（视同销售 + 成本结转），不要合并成一个。

**取价三条铁律**：按**业务日期**取价 → 取到即**快照**（写进单据行与 `t_calc_log`）→ 调价**不追溯**。

#### ② 财务做什么

```
1  取价：按 biz_date 取 transfer_price，快照进单据行与事件；price_source = TRANSFER
2  判 is_internal：= 1（集团内）→ 标记需合并抵消，is_accounting_event = 1
3  转出方：按【本层核算单元均价】结转出库成本（注意：作价与成本是两个价）
4  转入方：按【transfer_price】入库 → 重建该核算单元的移动平均均价
5  凭证 8.1.10（视同销售 + 成本结转）
6  集团内 → 合并层生成抵消凭证 8.1.11
```

#### ③ 影响什么

| 对象 | 影响 |
|---|---|
| `t_inventory_balance`（库存余额表） | **转出方**：数量↓金额↓（层可清零）；**转入方**：**新增一整条四轴记录**，数量↑金额↑（按作价） |
| **转入方均价** | **被作价拉高**——作价 1,040 而非成本 1,000，若该法人后续继续采购或出库，成本基础已不同 |
| **转出方均价** | **不变**（按本层成本全额转出，剩余库存的均价不因转出而变） |
| `t_owner_transfer`（货权转移单表） | 新增一行（含 `from/to_owner_l1`、`transfer_price`（转移作价）、`price_source`（作价来源）） |
| 会计损益 | **有**（作价 − 转出方成本 = 已实现毛利） |
| 合并层 | 集团内需抵消：抵消内部购销 + 抵消存货中的未实现毛利 |
| **存货总额** | 集团内一减一增，**合并后不变**；对外则**减少**（变成应收账款） |

#### ④ 有什么用

- **R1：一级货权转移必作价、必出凭证、必产生会计损益。** 一级是法人 → 跨法人转移即真实交易。
- 让"货没动、权属换了人"能表达。**这条链路如果不存在，"先采购入库（货权在垫资方）→ 再货权转移给客户 → 最后物理发货"的代采链路就无法建模**。
- **一条容易踩的边界**：产权交易中心「不参与对外审计、开票」**≠「不参与会计」**。集团内跨法人转移是**关联交易**——不开票，但按 R1 仍**必须**出凭证、确认损益、合并抵消（O-12：**一期即需做**）。一句话分工：**交易中心决定"交易是否成立"，库存中心决定"会计怎么记"**。

#### ⑤ 撤销规则

**已核算的一律不可撤，只能反向货权变更单 + 红字凭证。** 一级的反向会产生红字凭证与一笔反向的关联交易——**这是合规要求，不是实现选择**。这条要写进操作规范，否则业务会以为撤单"点一下就没了"。

> ⚠️ **G-04（缺口 · 物理是否移动无字段表达）**：当前 `OWNER_TRANSFER`（一级货权转移） 的行字段里只有**一个 `warehouse_code`（仓库编码）**，**没有任何字段表达"这次货权转移是否同时移动货物、从哪个仓移到哪个仓"**。而 ① 与 ②、③ 与 ④ 的区别恰恰就在这里。
> - 契约 `§9.6` 写的是「货权变更**不移动实物**，仓库不变」——只覆盖了形态①③；
> - 框架案例 7.4 的标题是「对外货权转移 + **货留我方仓**」——同样只覆盖不移动的形态。
>
> **形态②④（货随货权走）在两份文档里都没有字段支撑。** 若不支持，应在契约里**显式写"一期货权转移不承载物理移动，货要动请另推调拨单"**；若支持，需加 `out_warehouse_code`（调出仓库编码） / `in_warehouse_code`（调入仓库编码）。**两者选一，不能留着不写**——否则业务侧按形态②推单时，财务侧只能猜。

> ⚠️ **G-05（缺口 · 资金占用费沉淀不下来）**：框架案例 7.3 / 7.4 的分录里都有一笔**「其他业务收入 - 资金占用费」**（转移作价 5,200 = 货款 5,000 + 资金占用费 200），并明确「**资金占用费不进存货成本**」。
> 但 **契约与字段定义里完全没有这个字段**，而设计凭证模板 `8.1.10` 写的是：
> ```
> 贷：主营业务收入   [transfer_price × 数量]     ← 全额记主营
> ```
> **两处对不上**：案例 7.3 拆成"主营业务收入 5,000 + 其他业务收入-资金占用费 200"，模板 8.1.10 把 5,200 全额记主营。
> **根因是报文里没有这个字段**——模板只能全额记，案例是手工假设了拆分。**建议 W1 明确**：① 加 `funding_charge` 字段并同步改 8.1.10；或 ② 确认一期作价**不含**资金占用费，把案例 7.3 的表述改为"若含资金占用费则需单列"。**不能两处并存。**

### 4.2 S-21 二级货主之间的调拨 = 二级货主重分配 `OWNER_REASSIGN`

> **这一条与上面那条是不同的物种。** 二级货主**不是法人、不是会计主体**——所以这笔"调拨"**只走管理口径，不出凭证、不确认会计损益**。

#### ① 业务/财务给什么

| 中文字段 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 单据号 / 行号 / 业务日期 | `doc_no` / `line_no` / `biz_date` | Y | （例：`OT-202601-0002` / `1` / `2026-01-31`——二级重分配与一级转移**同样走 `OT-` 单号段**，靠 `doc_type` 区分） |
| **单据类型** | **`doc_type`** | Y | `OWNER_REASSIGN` |
| 物料编码 / 仓库编码 | `material_code` / `warehouse_code` | Y | （例：`M0001` / `WH01`——**仓库不变**） |
| 基本单位数量 | `base_qty` | Y | （例：转入 `L2-1` `25.0000` + 转入 `L2-2` `15.0000`，合计 `40.0000`） |
| **转出二级货主 / 转入二级货主** | **`from_owner_l2` / `to_owner_l2`** | **Y** | 转出 / 转入二级货主（**同一法人内**）（例：`L2-0` → `L2-1`） |
| 一级货主 | `owner_l1` | Y | 一级货主**不变**（例：`OWN-B`，**不是 `OWN-A`**——一级转移已在上一张单里完成） |
| **内部结算价** | **`internal_price`** | **Y** | **政策数据**，取 `t_internal_price` 价目表（例：`13.00`） |
| **作价方式** | **`price_type`** | **Y** | `FIXED` / `MARKUP`，**行属性、不进主键**（否则同一格子里两条行互相竞争）（例：`FIXED`） |
| 作价来源 | `price_source` | Y | `INTERNAL` |
| 取价基数 | `price_base` | **MARKUP 必填** | = 当时**该一级货主层**均价——**层级别取错，取到二级层全错**（例：`12.000000`，是 **`OWN-B` 的**一级层均价，不是 `OWN-A` 的 `10.000000`） |
| 加成率 | `markup_rate` | **MARKUP 必填** | （例：`0.1000000` = 10%） |
| 取到的价 | `price_value` | Y | 实际取到的价（快照）（例：`FIXED` → `13.000000`；`MARKUP` → `12.00 × 1.10 = 13.200000`） |
| **是否会计事件** | **`is_accounting_event`** | **Y** | 二级重分配 = **0** |
| **触发方式** | — | — | **一期由财务发起** |

> **上面这套取值取自设计文档 `§3.7.7` 算例 7 第二步**，可直接对账验算：`Σ alloc_amount` = `300.00 + 180.00` = **`480.00`**（硬校验，必须等于一级层金额）；`Σ internal_amount` = `325.00 + 195.00` = **`520.00`**（**不做等式校验**）；差额 **`40.00`** 即二级内部未实现毛利。
>
> **取价规则**：二级作价**必须配置**——是**政策数据**，做成**带生效期的价目表 `t_internal_price`**：按**业务日期**取价、**取到即快照**进单据行、**调价不追溯**。一期配在库存中心，二期随交易中心迁移。
> **「一个价、三个数」**：`MARKUP` 时 `price_base` / `markup_rate` / `price_value` **三个都要落库**。只存 `price_value` 是不够的——日后无法回答"这个价怎么来的"。
> ```
> MARKUP: price_base = 12.000000 · markup_rate = 0.1000000 · price_value = 13.200000
> FIXED : price_base = null       · markup_rate = null       · price_value = 13.000000
> ```

#### ② 财务做什么

```
1  取价：按 biz_date 查 t_internal_price
       FIXED  → price_value = 固定价
       MARKUP → price_base = 当时该【一级货主层】均价
                price_value = price_base × (1 + markup_rate)
2  读一级层均价 → alloc_amount = qty × 一级均价        （会计分摊额）
3  按 internal_price 累计 → internal_amount = qty × internal_price  （内部结算额）
4  【硬校验】Σ alloc_amount = 一级层金额    ← 不平则整单回滚 + 告警
5  写 t_owner_allocation
      【不动一级余额】【不出凭证】
6  差额 = internal_amount − alloc_amount = internal_pl（内部未实现毛利）
      → 进二级内部损益，【管理口径·非会计】，【不做等式校验】
```

#### ③ 影响什么 —— **一个数量、两个金额**

| | `alloc_amount`（会计分摊额） | `internal_amount`（内部结算额） | `internal_pl`（内部未实现毛利） |
|---|---|---|---|
| 算法 | `qty × 一级均价` | 按 `internal_price`（内部结算价） 累计 | `Σ internal_amount − Σ alloc_amount` |
| 口径 | **一级货主层 · 存货口径** | **管理口径 · 非会计** | **管理口径 · 非会计损益** |
| **能否加总回一级层** | **能** | **不能** | — |
| 校验 | **硬校验**（不平整单回滚） | **不做等式校验** | — |
| 用途 | 二级数量与金额的成本还原 | 二级考核、内部分润 | 内部损益分析 |

**一级层三件事全不变**：数量、金额、均价**三项都不动**。凭证与会计损益**都不产生**。

#### ④ 有什么用

- **R2：二级重分配必作价（内部结算价）**，差额进二级内部损益，但**不确认会计损益、不出会计凭证**。
  **为什么**：二级非会计主体 → 内部结算不动法人会计；但公司内部按内部转移定价考核（**这是贵司的公司特性**，不是通用做法）。
- **R4 / R5：二级层绝不相加进存货总额；二级内部结算价不影响会计。** 一个数量、两个金额是唯一的表达方式。
- **内部毛利不创造利润**：一笔货若分段转移后最终对外卖出，各段毛利之和 = 不分段时的总毛利。内部结算价是**旁路**。

> **⚠️ 最容易犯的错**：对 `internal_amount`（内部结算额） 做等式校验——**那是把管理口径当会计口径用，是红线复发的一种形态**。

#### ⑤ 撤销规则

反向分摊记录（`t_owner_allocation`（二级分摊账表） 追加反向行），**不动一级余额、不需红字凭证**（本来就没凭证）。

> ⚠️ **G-06（缺口 · 分摊账的展开与符号未定义）**
> 报文里是**「一条 from/to」**，而 `t_owner_allocation` 的结构是**「一行一个 `owner_l2`（二级货主） + 数量」**——暗示要写成**两行**（转出方、转入方各一行）。但契约与字段定义**都没写展开规则**，也**没定义 `qty`（业务数量） 的符号**。这会导致一个实质问题：
>
> `internal_pl`（内部未实现毛利） 的定义是 `internal_amount − alloc_amount`。若写成两行且转出方 `qty` 取负：
> ```
> 转出行：alloc = −200, internal = −220, internal_pl = −20
> 转入行：alloc = +200, internal = +220, internal_pl = +20
> Σ internal_pl = 0     ← 与框架案例 7.2 期望的「二级内部损益 +20.00」对不上
> ```
> **建议 W1 明确三件事**：① 展开为几行；② `qty` 的符号约定；③ `internal_pl` 是**按行读**还是**净额读**。按现在的写法，"二级内部损益 +20.00"这个读数**在 2 行结构下取不出来**。

## 5. 虚进虚出（账面进出、实物不动）

### 5.0 先说清楚：虚进虚出不是一个单据类型

**虚进虚出 = 账面上记了一次入库、也记了一次出库，但实物没有真实进过我方仓库，或者根本没有移动过。**

它**不是第 12 类单据**，而是 **A 组两个场景的特定组合**——采购入库一笔 + 销售出库一笔。**所以它最容易漏：单独看每一笔都正常，合起来才是"货没动"。** 这也是它没并进 §0 的 A / B 两组、而要单独成章的原因。

### 5.1 按「该不该在账上走一遍进销」切成三类

**判断轴不是金额**——三类**都有真实合同、发票与金额**，没有一类是"财务估价"（那是 `S-05` 的 `IN-5`）。**真正的分轴是"这笔业务该不该在账上走一遍进销"**：

| # | 形态 | 实物 | 商业实质 | **正解** | 现有单据能否表达 |
|---|---|---|---|---|---|
| **XY-1** | **直发 / 直运** —— 供应商直接发客户 | 真实存在，但**从不入我方仓** | 有 | **必须**记两笔进销；仓库落 `IN_TRANSIT`（在途）/ `VIRTUAL`（虚拟仓） | **能**；缺配对键与建仓规则（`G-10`） |
| **XY-2** | **库内转手** —— 货在同一仓不动，货主连续转手 | 真实存在，**仓位不变** | 有 | **不应**记进销；应记 `OWNER_TRANSFER`（一级货权转移，作价） | **能**；但系统看不出实物动没动（`G-12`） |
| **XY-3** | **纯单据空转** —— 走单走票不走货 / 融资性贸易 | **不存在，或同一批货被反复计价** | **无** | **不应确认收入** | **不能**；系统没有识别手段（`G-12`） |

> **一句话**：**同一个词底下，三种截然相反的账务处理——`XY-1` 必须进销，`XY-2` 严禁进销，`XY-3` 根本不该存在。**
>
> 所以业务侧说"虚进虚出"时，**财务必须先问一句：货到底有没有、动没动？** 不问这一句就下单，账必错。

**还有一条边界要先划掉**：**纯撮合（不持货权）根本不该产生任何出入库单据。** 如果业务在撮合业务上推了 `PO_IN` / `SO_OUT`，那不是"虚进虚出处理得对不对"的问题，而是**业务定性错了**——该先纠正定性，不是给它找一个单据类型。

### 5.2 `XY-1` 直发 —— 唯一必须记成进销的一类

**链路**：供应商发货 → 客户收货。我方**既没见到货、也没进过仓**，但购销两段合同都在我方名下（代采垫资的典型形态，框架 `§7.4`）。

**两笔怎么写**：

| 序 | 单据 | 仓库 | 数量 | 金额 |
|---|---|---|---|---|
| ① | `PO_IN` 采购入库 | `WH-VT`（在途仓 / 虚拟仓） | **+** | `amount_ex_tax` = 采购价——**真实价，不是财务估价** |
| ② | `SO_OUT` 销售出库 | **同一个** `WH-VT` | **−** | 不给金额；财务按该一级货主层均价结转 |

**三条要点**：

1. **全额法还是净额法，是会计政策问题，不是系统问题。** 购销两段的风险报酬是否都在我方（收入准则下的主要责任人 / 代理人判断）决定用哪种。**代采垫资持货权阶段**（框架 `§1.2`：`is_internal = 1`）走全额法。**这与 D-07「是否视同销售是税务判断不是会计判断，两者不要互相推导」是同一条原则**——系统保证两种都能落，**不替业务定性质**。
2. **货不在仓，但货权是真实的。** 不要因为是虚拟仓就把 `is_internal` 配成 0——**权属由一级货主决定，与仓库类型无关**（D-06）。直发期间货权在我方，就 `is_internal = 1`、**计入存货总额**。
3. **进销必须配对。** 直发在数量上应满足"入库 = 出库"（按实际发货量）。**报文里没有配对键**，这笔账对不出来——见 `G-10`。

**⚠️ 直发会造出"两个口径"的第三种分叉**（框架 `§2.5` 已有两种）：

| # | 分叉形态 | 典型场景 | 是否挂到期末 |
|---|---|---|---|
| ① | 货在我方库、**权属已不属我方** | 代采已转货权、客户未提货；受托代销 | **会**（持续状态） |
| ② | **权属属我方**、货不在我方库 | 在途 | **会** |
| ③ | **货不在任何库、权属只是路过** | **`XY-1` 直发** | **正常不挂**（同日进、同日出）；**跨期时挂成在途存货** |

**③ 的性质与前两种不同**：它是**瞬时**的，正常情况下来去同日、期末为零。**但若采购与销售跨期**（1/31 入库、2/1 出库），期末就会真实挂出一笔在途存货——**D-06 已定"在途计入"，所以这笔是真的**，不是错误。→ **因此对账要加一条**：**虚拟仓 / 在途仓的余额必须能单独列示**，否则"在库数量对账"与"存货金额对账"的差会凭空多出一笔，且找不到源（`G-11`）。

### 5.3 `XY-2` 库内转手 —— 系统能标记，但判不了

**形态**：一批货**一直在同一个仓位里没动**，货主却是 A → B → C 连着转手。每一手都可能有真实合同与发票。

**为什么记成进销是错的**：这批货的**物理量在账上动了两次，而实物一次没动**。框架 `§2.1` 的 B 组（货权转移 / 货主重分配）**就是为它准备的**——用 `OWNER_TRANSFER`（一级货权转移）表达"货没动、货主变了"，作价、损益、凭证一样不少，**只是不让物理台账凭空动两次**。

**⚠️ 但判据不能由系统下**，因为三件事长得很像：

| 情形 | 实物动了吗 | 正解 |
|---|---|---|
| 供应商上午送到、客户下午自提（**同日、同仓、同批次**） | **动了**（真实进仓、真实出仓） | **正常进销**，不是虚进虚出 |
| 货在 `WH01` 没动，A 卖给 B 再卖给 C | **没动** | `OWNER_TRANSFER` |
| 采购入库后存放几天再销售出库（**隔日、有库龄**） | **动了** | **正常进销** |

**第一行与第三行都是正常的**，区别只是第三行有库龄可查、第一行没有——而**系统手里只有单据，看不到实物有没有动过**。所以：

- 系统能给的是**特征**：同日 + 同仓 + 同批次 + 同物料的一对进销 → **提示核对**（**不是拒绝**，因为上表第一行合法）
- 系统给不了的是**结论**：这批货到底动没动，**只有业务知道** → **必须靠业务声明**（`G-12`）

> **这条不要指望"算法识别"。** 把"同日同仓"当违规去拦截，第一个月就会误伤"上午到、下午提"的正常业务；而真正要防的空转，恰恰会把日期拆开、把仓库换掉来规避。

**顺带一个业务侧要意识到的既定行为**：若这批货与我方**同物料同仓**的常规库存共用一个均价池，那笔过单的采购价会**并进池子、把现有存货的均价拉一下**。**这是移动加权平均的既定行为（不是缺陷）**，但过单越频繁，均价被拉得越频繁——**做成本分析时会看到一个与自营无关的波动**。

### 5.4 `XY-3` 纯单据空转 —— 系统不做判断，但必须把事实留痕

**红线**：走单走票不走货（融资性贸易 / 空转贸易 / 循环贸易）是**监管明令禁止**的，对国资与上市公司尤其如此。

**但"有没有商业实质"是审计与监管的判断，不是系统的判断。** 系统替业务下这个结论，既越权也不可靠。系统该做的是三件事，**没有一件是"判定违规"**：

| # | 系统该做什么 | 怎么做 |
|---|---|---|
| 1 | **暴露事实** | 业务推单时声明**这批货有没有实际物理移动**（建议字段 `has_physical_movement`，见 `G-12`）；系统落库留痕。**不声明比声明错更危险**——谎报是业务的责任，没留痕是系统的责任 |
| 2 | **暴露链条** | 同一批货的货权转了一圈（A→B→C→A）时，**合并层面必须抵消**。集团内已由 R1 / O-12 覆盖；**跨集团是真外部交易，系统无权否定** |
| 3 | **不留后门** | **绝不能提供"只记账、不动库存"的便捷开关**——那等于给空转业务发工具。虚拟仓 / 在途仓因此**必须是受控的 A 级主数据**（谁能建、谁能用、`is_inventory_accounted` 怎么配），不能是任何人可建的业务参数（`G-10`） |

## 6. 逆向与期间场景

### S-30 改单 `CHANGE`

**① 业务给什么**：单据号 `doc_no` / 行号 `line_no` / 版本号 `version_no` + **变更后的完整行内容**。

**② 财务做什么**

```
原单 cost_status = PENDING   → 直接以新内容替换，无需冲销
原单 cost_status = CALCULATED → ① 追加【反向事件】（金额取负），version_no = 旧值 + 1
                                ② 追加【新内容的正向事件】，version_no = 再 + 1
原期间已锁账（is_closed = 1）  → 【拒绝改单】：结错了走反结账，漏一笔走当期补录单
```

**③ 影响什么**：`t_calc_log`（核算事件日志表） 追加两条事件；余额走 `balance += Σdelta`；**原事件保留不删**；旧凭证红冲、新凭证重建。

**④ 有什么用 / 这条最容易被实现错**
> **改单不是"撤销 + 重做"，是追加两组事件。** 差别在重放：把原事件删掉再重推，重放时会得到**与原路径不同**的结果，引擎的三种幂等、重放一致性、可审计性会一起失效。
> **`t_calc_log` 是只增不删的事件流，是真相源**；余额、报表、快照都只是它的**投影**。

### S-31 作废 `VOID`

**① 业务给什么**：作废单号清单 + 作废时间 + 作废原因。

**② 财务做什么**

```
cost_status = PENDING    → 直接置 biz_status = VOID，【不产生核算事件】
cost_status = CALCULATED → 追加【反向事件】；生成【红字凭证】冲销原凭证；
                           原行置 red_flag = 1、记 red_ref_doc = 原单号
原期间已锁账             → 【拒绝作废】：走反结账或当期补录单
```

**③ 影响什么**：余额反向；新增红字凭证（`is_red = 1`），**原凭证不改**；`red_flag = 1`。

**④ 有什么用 / 一个必须记牢的判据**
> **作废闸门 = `cost_status`（核算状态），不是"有无下游引用"。**
> 这是最容易被实现成"看有没有被引用过"的一条——**那样会漏放**。已核算的一律不可撤，只能反向单 + 红字凭证。
> **报表口径统一为 `biz_status = EFFECTIVE AND red_flag = 0`。**

### S-32 跨期补录 `PERIOD_ADJUST`

**触发**：已锁账期间发现**漏记**一笔。（注意：是"漏了"，不是"结错了"。）

**① 谁推**：**财务侧的单据，业务不推。**（11 类里唯一不由业务推送的一类，另一类是 S-21 二级重分配由财务发起。）

**② 财务做什么**：必审（单点审核动作 + `approved_by`（审核人） / `approved_at`（审核时间） 留痕）；**一律按当期口径量价**——补录出库按**当期均价**结转、建**当期成本层**。原业务日期**仅供追溯，不用于取价**。

**③ 影响什么**：当期余额与凭证；`t_document_line.period`（单据行期间） 与 `doc_date`（单据日期） 所属期间**不同**。

**④ 为什么用当期口径（E-10 的理由）**
> 排序键是 `(业务日期, 当日序号)`，而 `seq_in_day` 是**当天按顺序分配**的。要按原业务日期回填，就必须复原"那一天的第 N 个序号"——**事后无法复原**。所以一期用**"当期补录单"换取"历史不可改"**，用**"反结账须批"换取"错误仍可修"**。
> **按历史原值算，报得出来，但报的是假数。**

---

### S-33 反结账

**触发**：已锁账期间发现**结错了**（与 S-32 的"漏了"语义不同）。

**② 财务做什么**：须走审批并留痕（**谁 / 何时 / 因何 / 重开哪个月**）→ `is_closed = 0` → 追加修正事件 → 按 `(业务日期, 当日序号)` 重放受影响区间 → 重新出该期间快照（`snapshot_version + 1`，**旧版本保留**）→ 重建受影响区间凭证 → 重新锁账。

**④ 三条路不能互相代替（E-09 / E-10）**

| 情形 | 走哪条路 | 留痕 |
|---|---|---|
| 锁账后发现**"上次结错了"** | **反结账**（重开期间重算） | 反结账审批单 |
| 锁账后发现**"漏了一笔"** | **当期补录单 `PERIOD_ADJUST`（期间补录）** | 补录单 + 审核人/时间 |
| 未锁账期间发现错误 | **直接改单**（`version+1` 新事件） | 事件流 + 红字凭证 |

> **反结账不是"回滚"**，是**"重新打开期间 + 追加修正事件"**。`t_calc_log`（核算事件日志表） 的 `before_*` / `after_*` 是**审计快照**，不是"回滚依据"——把它们当回滚输入，会让三种幂等一起失效。

---

### S-34 盘点 `STOCKTAKE`

**① 业务给什么**：单据号/行号、业务日期（**盘点基准日**）、推送时间 `pushed_at`、物料编码/仓库编码、**一级货主 `owner_l1`**（盘点属于哪个法人的存货）、**实盘数量 `actual_qty`**、账面数量 `book_qty`（可选）、批次号/序列号、**基本单位数量 `base_qty`**。

**② 财务做什么**：算 `diff_qty = actual_qty − book_qty`；`diff > 0` → 派生盘盈入库单（S-06）；`diff < 0` → 派生盘亏出库单（S-13）；`diff = 0` → 仅登记盘点记录。

**③ 影响什么**：视 diff 方向；凭证走**待处理财产损溢**。

**④ 有什么用**：把"账实不符"纳进受控通道，差异**当期处理完毕**。

> ⚠️ **G-07（缺口 · `book_qty`（账面数量） 冲突时以谁为准未定）**：契约 `§9.4` 把 `book_qty` 写成可选，并说"如不给，财务侧按自己的账面比对"。但**如果业务侧给了 `book_qty` 而它与财务侧账面不同**，以谁为准？
> **建议明确：财务侧一律以自己账面算 `diff`（差异），业务侧 `book_qty` 仅用于比对告警。** 理由是财务侧的账面是核算结果、是权威；若采信业务侧账面，等于让业务侧间接改财务余额。这一条不写清，实现时必然有人按"以业务为准"做。

## 7. 全场景共同影响的面

### 7.1 余额表 `t_inventory_balance` —— 四轴

```
键 = (物料, 仓库, 批次, 一级货主)
```

**为什么保留批次行、均价却不在批次**：批次行是因为**库龄与跌价要按批次算**；但**均价只归核算单元**——即 `batch_no IS NULL` 的那一行是"均价行"，批次行只是拆分明细。

> 若按批次建均价池，同一核算单元内会出现**多个互相独立的均价**，出库时取哪个批次池的价就成了不可判定的问题。所以：**均价归核算单元 `(物料, 仓库, 一级货主)`，批次只做拆分与库龄/跌价基数。**

**期初 / 期间 / 结账相关的三张表**：`t_initial_balance`（期初余额表，上线一次性）、`t_balance_snapshot`（余额快照表，反结账时 `snapshot_version`（快照版本）+ 1）、`t_period`（会计期间表，`is_closed`（是否已锁账） 锁账）。

### 7.2 事件流 `t_calc_log` —— 只增不删

| 列 | 作用 |
|---|---|
| `(biz_date, seq_in_day)` | **唯一的过账顺序**（`doc_no`（单据号） 不可作排序键） |
| `delta_qty`（数量增量） / `delta_amount`（金额增量） | **引擎返回的是增量，不是新余额**；余额 = 累计 delta |
| `(doc_type, doc_no, version_no)` | **事件幂等键**——重复事件返回**零 delta 且不报错** |
| `idempotency_key` = `batch_id + doc_no + line_no` | **传输幂等键**——重推直接丢弃 |
| `price_source`（作价来源） / `price_base`（取价基数） / `markup_rate`（加成率） / `price_value`（取到的价） | 作价"一个价三个数"落点，事后可复现 |
| `before_*` / `after_*` | **审计快照，不是回滚依据** |

### 7.3 三个状态位（两状态 + 一标记）

| 字段 | 位置 | 来源 | 取值 | 报表口径 |
|---|---|---|---|---|
| `biz_status`（业务状态） | 单据头 | **业务**（B 级） | `DRAFT`（草稿）/`SUBMITTED`（已提交）/`APPROVED`（已审核）/`EFFECTIVE`（已生效）/`VOID`（作废） | — |
| `red_flag`（红冲标记） | 单据行 | **财务** | 0 / 1 | **`biz_status = EFFECTIVE AND red_flag = 0`** |
| `cost_status`（核算状态） | 单据行 | **财务** | `PENDING`（待核算）/`CALCULATED`（已核算）/`ROLLED_BACK`（已回滚） | **作废闸门** |

> **两列语义不同**——业务"作废"是业务事实，财务"红冲"是账务处理结果。两者可以不同步（已核算的作废只能走反向单 + 红字凭证）。**契约只约定 `biz_status`（B 级），红冲标记由财务侧独立维护。**

### 7.4 凭证影响（按场景对照）

| 场景 | 凭证模板 | 借贷要点 |
|---|---|---|
| 采购入库 | 8.1.1 | 借 库存商品 [**不含税** + 分摊费用] / 借 进项税 / 贷 应付账款 [含税] |
| 销售出库 | 8.1.2 | 借 主营业务成本 / 贷 库存商品 |
| 调拨（同法人） | 8.1.3 | 借 库存商品-调入仓 / 贷 库存商品-调出仓 |
| 盘亏 / 盘盈 | 8.1.4 / 8.1.5 | 走待处理财产损溢 |
| 跌价准备 | 8.1.6 | **记变动额不是应有额** |
| 舍入差异结转（月末） | 8.1.7 | abs(rounding_diff) |
| 采购退货出库 | 8.1.8 | 按**当前均价**结转 |
| 销售退货入库 | 8.1.9 | 按**原出库成本**回冲，**不重算** |
| **一级货权转移** | 8.1.10 | 视同销售 + 成本结转（**作价与成本是两个价**） |
| **集团内未实现损益抵消** | 8.1.11 | 合并层，`voucher_source = CONSOLIDATE` |
| **二级重分配** | **无** | R2 / R5 |

> **凭证日期 = 记账期间首日**，不是系统当前日期。同一业务期间的单据必须落进同一会计月——若取"系统当前日期"，月结时凭证会散在两个期间里，对账永远对不上。
> **借贷必须相等**（`Σ借 = Σ贷`），且**按法人分账**。生成后立即校验，不平则**拒绝落库并告警**——不允许"先入库、后补平"。

### 7.5 报表口径

- **存货总额 = Σ 一级货主层中 `is_internal = 1` 的金额**（R4）。**二级货主层绝不相加。**
- **两个数量口径分开命名**：在库数量（物理，仓库口径，**对账用**）/ 权属数量（货主口径，**金额用**）。
- **两个金额口径必须并列回传、必须标注**（C-17）：

| 金额 | 口径标注 | 能否加总 | 用途 |
|---|---|---|---|
| `alloc_amount`（会计分摊额） | 一级货主层 · 存货口径 | **能** | 对外唯一权威值 |
| `internal_amount`（内部结算额） | 管理口径 · 非会计 | **不能** | 二级考核，**禁止单独当"库存金额"用** |

> **若不区分口径**，业务侧必然挑一个当"库存金额"——**红线三以新形式复发**，而且这次是"契约里写了、实现里没区分"，更难发现。

### 7.6 对账口径（两张不同的对手）

| 对账 | 对手 | 维度 | 频率 |
|---|---|---|---|
| **数量** | 业务库存中心的**日切快照** | **物理层 `(物料, 仓库, 批次)`**（O-07 未决前不上货主） | **日清** |
| **金额** | **金蝶总账**（不是业务系统！） | `(法人, 物料, 仓库)`，法人层 + 合并层 | **月结** |

> **为什么金额的对手不是业务系统**：业务侧**没有金额权威**——它的"库存金额"多为数量 × 最新采购价，与移动平均口径必然不同。拿业务金额去核财务金额，**对出来的全是假差异**。
> **为什么数量维度不含货主**：O-07（业务侧是否建货主维度）**不由我方单方决定**。在 O-07 有结论前按物理层对账——跨法人转移在两边都不改变物理总量，能对上。**代价**：权属挂错（货在但记在错的一级货主名下）**在物理层对不出来**，只能靠财务侧四轴余额自检。
> **第三条要补的规则（`S-18` 直发）**：**虚拟仓 / 在途仓的余额必须能单独列示**。跨期直发会在期末真实挂出一笔在途存货——**数量口径与金额口径都要能把它单独摘出来**，否则两张表的差会凭空多出一笔，且找不到源（`G-11`）。

### 8.1 已有明确结论、不需再议的（避免会上重复讨论）

| 事项 | 结论 | 出处 |
|---|---|---|
| 调拨 vs 跨法人转移的判定 | 同一一级货主 = `TRANSFER`；不同 = `OWNER_TRANSFER`（一级货权转移）。**拒绝并回执，不自动升级** | 设计 `§3.3.4` |
| `doc_type`（单据类型） 是否拆 `TRANSFER_OUT`/`TRANSFER_IN` | **不拆**。判据：`doc_type` 数的是一张单据从哪来、干什么，不是数它动了几行 | 设计 `§3.3.4` |
| 采购退货 vs 销售退货的成本口径 | 采购退货**按当前均价**；销售退货**按原出库成本回冲** | D-07 / 设计 `8.1.8`/`8.1.9` |
| 以旧换新 / 换货 | **拆两笔独立业务**，不走特殊单据类型 | D-07 |

| 负库存 | 容差可配，**一期阈值 = 0**（等于禁止）；不允许出负数量且无记录 | D-05 / 设计 `5.6.2` |
| 迟到单据 | **已锁账期间禁止入账**；跨期漏记走当期补录单，**一律按当期口径量价** | E-04 / E-10（与契约 v1.1 相反，**须明确告知业务侧**） |
| 金额对账的对手 | **金蝶总账**，不是业务系统 | F04 |
| 作废闸门 | **`cost_status`（核算状态）**，不是"有无下游引用" | C-01 |

## 9. 一页速查

**给业务库存中心的一句话**：
> 你给**事实与原始价格输入**（编码、数量、日期、批次、货主、采购价、税率、运费关税、暂估与发票两个事件），**不要给成本与金额**；两个金额口径（存货 / 内部结算）**必须成对回传、必须标注**。

**给财务侧的一句话**：
> 你**只采信事实、只取价不定价**；一级作价来自交易数据、二级来自你的价目表；**二级层的一个数量两个金额，绝不相加进存货总额**。

**八个最容易踩的点**：

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 把跨法人的单推成 `TRANSFER`（调拨） | 推 `OWNER_TRANSFER`（一级货权转移）；财务侧拒绝不升级 |
| 2 | 核算用了 `qty`（业务数量） 而不是 `base_qty`（基本单位数量） | **核算一律 `base_qty`**；换算率缺失拒绝入账，**不 1:1 兜底** |
| 3 | 对 `internal_amount`（内部结算额） 做等式校验 | 那是管理口径，**不做等式校验**；只硬校验 `Σ alloc_amount` |
| 4 | 改单/作废实现成"删行重推" | **追加反向事件**；`t_calc_log`（核算事件日志表） 只增不删 |
| 5 | 拿业务金额去核财务金额 | 金额的对手是**金蝶总账**；数量对手才是业务快照 |
| 6 | 把 `OTHER_IN` 一律当"要财务估价" | **只有 `IN-5` 无对价杂项才估**；`IN-1` 按原单回冲、`IN-2` 业务给价、`IN-3`/`IN-4` 对方给价 |
| 7 | 把受托代销货 / 借入货按普通入库记进存货总额 | 一级货主是**外部法人**，`is_internal = 0`——**进在库数量、不进存货总额**（`IN-3`/`IN-4`） |
| 8 | 把"虚进虚出"当成一种做法去处理 | **先问"货有没有、动没动"**：直发**必须**记进销、库内转手**严禁**记进销、纯空转**不该确认收入**——三种账务截然相反（§5） |

**数量口径 vs 金额口径（对账前必须先分清）**：

| | 数量 | 金额 |
|---|---|---|
| 权威 | 业务库存中心 | 财务库存中心 |
| 对手 | 业务日切快照 | 金蝶总账 |
| 维度 | `(物料, 仓库, 批次)` | `(法人, 物料, 仓库)` |
| 频率 | 日清 | 月结 |
| 要求 | **完全一致** | **允许不一致，但必须可解释** |
| 差异性质 | **数据问题** | 多数是**口径问题** |
