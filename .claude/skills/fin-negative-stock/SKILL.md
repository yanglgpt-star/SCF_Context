## 一、闸门在哪：**计量前即拦截**（原文 `§四.4` `:3924`）

**校验前移**——出库**在算出金额之前**先判余额：

```
measure_outbound(event, ctx)
  assert base_qty > 0                                # 数量 ≤ 0 直接拒收
  tolerance = ctx.param("NEGATIVE_STOCK_TOLERANCE")  # 默认 0（= 禁止负库存）
  if balance.qty − out_qty < −tolerance:
      raise RejectError("E-NEGATIVE-QTY")            # 行级拒收，附现有数量
  # 通过后才算金额、才写余额
```

> **不通过 → 不进计量、不写余额**。全部错误码**都在过账之前产生**，拒收必须说清**哪一行、哪个字段、错在哪**。

**成因三类**（原文 `:3916`）：① 出库早于入库到账（先发货后到票）；② 排序键把出库排到了入库之前；③ 上游漏推一张入库单。

## 二、两阶段闭环（**容差 > 0 时才走到**）（原文 `:3941`）

```
【阶段一：负库存出库】
实物出库缺口 ΔQ → 取暂估单价 P_est → 记负数量（−ΔQ）与负金额
              → 均价【强制锁定】为 P_est（禁止"金额 ÷ 负数"产生数学异常）
              → 写挂账表 inv_negative_stock_log，状态 OPEN
              → 单据核算状态 cost_status = PENDING（挂起，未定稿）
                          ↓ 采购补录
【阶段二：采购到货冲平】
采购入库（Q_in, P_actual） → 冲平缺口 ΔQ
                        → 剩余（Q_in − ΔQ）按 P_actual 写入在库均价
                        → 价差 ΔCost =（P_actual − P_est）× ΔQ
                        → 自动出【成本调整单 COST_ADJUST】计损益
                        → 挂账置 RESOLVED，cost_status 转 CALCULATED
```

⚠️ **不允许「出负数量且无任何记录」**——负库存必须**可见、可查、可催票**。挂账表就是「可见」的载体：`OPEN` → `RESOLVED`，每一步都留痕。

> 指针：原文 `§四.4`（`:3914`）；挂账表页面见 `§三.15 负库存挂账表`（`:1353`）。

## 三、容差参数与系统行为（原文 `:3962`）

| 情形 | 系统行为 | 结果 |
|---|---|---|
| 出库后余额 ≥ 0 | 正常过账 | 不告警 |
| 余额为负且 \|负数\| ≤ 容差 | **允许过账**，成本按当前均价结转，**出告警**（进对账异常池） | 负但可见、可查、可催票 |
| 余额为负且 \|负数\| > 容差 | **拒绝过账**，返回 `E-NEGATIVE-QTY` | 行级拒收，需人工处置 |

**`NEGATIVE_STOCK_TOLERANCE`（负库存容差参数）默认 `0`** → 一期**任意负余额即超容差 → 拒收**，即**一期默认禁止负库存**；容差不是写死，而是**预留可配、默认关闭**。

## 四、配置项：负库存风控策略（原文 `§三.2` `:630`）

配置落 `cfg_negative_stock_rule`（负库存风控策略配置表），**粒度 = 适用一级货主 × 适用仓库 × 适用品类/SKU**：

| 字段 | 中文名 | 说明 |
|---|---|---|
| `allow_negative` | 允许负库存 | `0` 严格禁止（Hard Stop）/ `1` 允许负库存 |
| `max_negative_qty` | **缺口上限件数** | 允许超卖件数上限 |
| `max_pending_days` | **最长挂账天数** | 逾期未平**阻断出库** |
| `est_price_source` | **暂估单价来源** | `LATEST_PO_PRICE` 最近采购订单价 / `BENCHMARK_PRICE` 基准供货价 / `MOVING_AVG_PRICE` 当前移动平均价 |
| `alert_email` | 告警接收人 | 告警邮件 |
| `status` | 状态 | `ACTIVE` 生效 / `INACTIVE` 停用 |

⚠️ **条件行联动（最容易漏）**：「缺口上限件数 / 最长挂账天数 / 暂估单价来源」三项**仅在「是否允许负库存」选「允许负库存」时出现且必填**；选「严格禁止」时**隐藏**——不允许负库存则不存在缺口，三项无意义。

## 五、人工处置四条路（原文 `:3973`）

| 情形 | 处置通道 |
|---|---|
| 上游漏推一张入库单 | 业务**补单**，重推后按排序键自动重算 |
| 业务日期 / 当日序号有误 | 业务侧**排序键复核**——同日**入库优先**；**业务单号不可作排序键** |
| 真实先出后入、财务确认可承受 | 财务部按品类**调高容差**（默认 0），容差内允许 + 告警 |
| **已锁账期间发现漏记** | 走**当期补录单**（必审，**一律按当期口径量价**，原业务日期仅供追溯） |

### ⚠️ 三条路不可互换（原文 `:3982`）

| 路 | 什么时候用 |
|---|---|
| **改单** | **未锁账** |
| **反结账** | 已锁账、**结错了**（须审批留痕） |
| **当期补录单** | 已锁账、**漏了一笔**（必审） |

**补录是「这笔在原期间从未存在」的语义，不能用反结账代替补录**——混用会让审计无法区分「错误」与「遗漏」。

> 期间与锁账的完整规则（日结 / 月结 / 反结账流程 / 期间闸门）→ 走 `fin-period-close`。

## 六、易错点

| 易错 | 正确 |
|---|---|
| 说负库存会「先算金额再判余额」 | **校验前移**——余额不足**在计量前**就拦下 |
| 说负库存时均价 = 金额 ÷ 数量 | **强制锁定为暂估单价 `P_est`**——否则「金额 ÷ 负数」是数学异常 |
| 忘了阶段二是**两步**（冲平 + 剩余入池） | 冲平缺口 ΔQ 后，**剩余（Q_in − ΔQ）按实际单价写入在库均价** |
| 忘了自动出成本调整单 | 价差 ΔCost =（`P_actual` − `P_est`）× ΔQ，**自动出成本调整单计损益** |
| 一期就允许负库存 | **一期默认禁止**（容差 = 0）；容差、缺口上限、挂账天数**预留可配、默认关闭** |
| 「严格禁止」时也填缺口上限 | 三项**隐藏**，根本不填 |
| 用反结账代替补录 | **不可互换**——错误 vs 遗漏，语义不同 |
