# 采购计划管理系统 - 完整需求提示语

## 系统概述

采购计划管理系统是一个供应链金融后端系统，核心能力：
1. 采购计划的全生命周期管理（创建 → 执行 → 关闭）
2. 自动匹配采购计划 → 判断订单合规性
3. 三段供应链订单流转（供应商 → 企业1 → 企业2 → 企业3）
4. 对接外部平台（无仓、金融助手；🔄 二期：市场助手）

---

## 一、业务架构

### 1.1 供应链关系

```
三级采购：供应商 → 采购企业1 → 采购企业2 → 采购企业3
二级采购：供应商 → 采购企业1 → 采购企业2
```

- 差价1/账期1 = 采购企业2 与 采购企业1 之间
- 差价2/账期2 = 采购企业3 与 采购企业2 之间（仅三级采购）

### 1.2 外部平台角色

| 平台 | 角色 | 职责 |
|------|------|------|
| 无仓 | 外部订单平台 | 推送第一段订单信息、生成第一段和第三段采购单 |
| 金融助手 | 本系统（判断引擎） | 订单判断、生成计划子编码、返回结果给无仓 |
| 市场助手 | 🔄 二期：外部订单平台 | 接收第二段信息并生成第二段采购单 |

### 1.3 订单流转流程

```
无仓 → IF02（金融助手判断）
  │
  ├── 判断拒绝 → 返回 reject + 原因
  │     └── 系统自动尝试下一个匹配计划（跨计划重试）
  │
  └── 判断通过 → 金融助手：
        ├── 生成计划子编码 plan_sub_code（格式：{计划编码}-{3位流水号}）
        ├── 返回 pass + plan_sub_code + matched_plan_code 给无仓
        │
        └── 无仓收到结果后：
              ├── 生成第一段采购单（携带 plan_sub_code）
              ├── 🔄 二期：同步第二段信息 + plan_sub_code → 市场助手
              │     └── 市场助手生成第二段采购单（携带 plan_sub_code）
              └── 生成第三段采购单（携带 plan_sub_code）
               
               全部通过 IF03 回传系统入库
```

### 1.4 关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 订单是否携带计划编码 | ❌ 不携带 | 无仓推送时不知道计划编码 |
| 如何关联计划 | 系统自动匹配 | 订单到达后根据品牌+品类+金额匹配执行中的计划 |
| 匹配失败处理 | 跨计划重试 | 匹配到的计划判断拒绝后自动尝试下一个匹配计划 |
| 三段订单如何关联 | 计划子编码 | 每次 IF02 通过生成唯一子编码，三段共用 |
| 采购层级控制 | 枚举字段（二级/三级） | 显式声明比隐式推断更可靠 |
| 差价类型 | 比例+固定二选一 | 业务需要同时支持百分比加成和固定金额加成 |
| 品牌/品类输入 | 字典下拉选择 | 避免同一品牌不同命名导致数据混乱 |
| 企业字段输入 | 可搜索下拉框 | 支持大量企业时快速筛选 |
| 计划唯一性 | 条件唯一键 | 金额不参与唯一性（允许编辑），关闭计划不参与校验（允许重建） |

## 三、核心业务规则

### 3.1 计划唯一性约束

```
二级采购：品牌 + 品类 + 采购企业1 + 采购企业2 + 预计开始日期 + 预计结束日期
三级采购：品牌 + 品类 + 采购企业1 + 采购企业2 + 采购企业3 + 预计开始日期 + 预计结束日期
```

- 仅对 **计划状态 ≠ 关闭** 的有效计划进行校验
- 采购总金额不参与唯一性（允许编辑调整）
- 差价、账期不参与唯一性（属于计划参数）

### 3.2 订单自动匹配规则

订单到达 IF02 时，系统自动匹配执行中的计划，条件（全部满足）：

| 条件 | 说明 |
|------|------|
| 计划状态 | 必须是 **执行中** |
| 品牌一致 | 订单品牌与计划品牌完全一致 |
| 品类一致 | 订单品类与计划品类完全一致 |
| 剩余额度充足 | 目标金额 − 已完成金额 ≥ 订单总价 |
| 单价范围 | 计划定义时，订单单价必须在最低~最高范围内 |
| 数量范围 | 计划定义时，订单数量必须在最低~最高范围内 |

匹配优先级（三层递进）：

1. 执行时间升序 — 最早执行的最优先
2. 完成率降序 — 完成率越高越优先
3. 剩余金额升序 — 剩余越少越优先

跨计划重试：匹配到的计划判断拒绝时，自动按优先级尝试下一个，直至通过或全部拒绝。

### 3.3 订单判断规则

判断按以下阶段依次执行，任一阶段不通过则拒绝：

```
1. 订单归属 → 企业标识是否在计划层级范围内
2. 订单内容 → 品牌 / 品类 / 单价范围 / 数量范围 / 总价校验
3. 金额监控 → 已采购总价是否超过目标金额
4. 🔄 二期：供应商资质 → 开票率 / 合作期限 / 贸易金额
```

### 3.4 差价计算规则

```
差价类型=比例：企业2采购价 = 企业1采购价 × (1 + 差价比例%)
差价类型=固定：企业2采购价 = 企业1采购价 + 差价固定金额
```

类型二选一，比例和金额不能同时填，不能同时为空。

### 3.5 计划子编码规则

- 生成时机：IF02 判断通过时
- 格式：`{计划编码}-{3位流水号}`，如 `PL202606280001-001`
- 流水号：每个计划独立计数，从 001 开始，每次通过 +1
- 共享：三段采购单（企业1/2/3）共享同一子编码

### 3.6 关闭规则

| 结束方式 | 执行状态 | 含义 |
|---------|---------|------|
| 金额达标自动关闭 | 已完成 | 采购目标达成，正常结束 |
| 手动提前终止 | 已关闭 | 未达目标但主动终止 |

### 3.7 删除约束

- 仅 **待执行** 状态可删除
- 已执行的只能关闭，不可物理删除
- 删除采用软删除

### 3.8 修改约束

| 计划状态 | 允许修改 | 不允许修改 |
|---------|---------|-----------|
| 待执行 | 全部字段（含采购层级） | — |
| 执行中 | 差价类型/比例/金额、账期、订单要求、🔄 供应商资质（二期） | 采购层级、品牌、品类、采购企业、总金额、日期 |
| 已完成/已关闭 | — | 全部 |

### 3.9 完成率口径

```
已完成总金额 = 计划下所有通过判断的订单总价之和（三段累加）
完成率 = 已完成总金额 / 采购总金额 × 100%
```

## 四、接口定义

### 4.1 IF01 采购计划推送接口

调用方 → 无仓（推送执行中的计划）

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| plan_code | 字符串 | 是 | 计划编码 |
| brand | 字符串 | 是 | 品牌 |
| category | 字符串 | 是 | 品类 |
| expected_start_date | 日期 | 是 | 预计开始 |
| expected_end_date | 日期 | 是 | 预计结束 |
| total_amount | Decimal | 是 | 总金额 |
| companies | 数组 | 是 | 企业列表（长度随层级变化） |

**接口超时**：10s

### 4.2 IF02 订单判断接口

无仓 → 金融助手（推送订单信息，不携带计划编码）

**请求参数**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| order_no | 字符串 | 是 | 订单号 |
| enterprise | 整数 | 是 | 所属企业（1/2/3） |
| brand | 字符串 | 是 | 品牌 |
| category | 字符串 | 是 | 品类 |
| sku_code, sku_name | 字符串 | 是 | 商品信息 |
| unit_price, quantity, total_price | Decimal/Int | 是 | 价格数量 |
| supplier | 字符串 | 是 | 供货方 |
| supplier_qualification | JSON | 🔄 二期 | 含开票率/合作期限/贸易金额；一期可不传或传入空值 |
| purchaser | 字符串 | 是 | 采购方 |
| order_time | 时间戳 | 是 | 下单时间 |

**返回参数**：

| 字段 | 说明 |
|------|------|
| code | 200=成功 |
| matched | 是否匹配到计划 |
| matched_plan_code | 匹配到的计划编码 |
| plan_sub_code | 计划子编码（通过时生成） |
| match_reason | 无匹配时的说明 |
| result | pass / reject / no_match |
| reason | 拒绝原因汇总（多条以「/」分隔） |
| reject_detail | 🔄 全部拒绝原因详情，逐条记录每个匹配计划的拒绝原因 |

### 4.3 IF03 采购单接收接口

无仓 → 系统（回传已确认的采购单；🔄 二期：市场助手）
无仓 → 系统（IF04 订单取消通知）

**请求参数**：

| 字段 | 必填 | 说明 |
|------|------|------|
| plan_code | 是 | 匹配的计划编码 |
| plan_sub_code | 是 | 子编码（IF02 通过时生成） |
| order_no | 是 | 订单号 |
| enterprise | 是 | 所属企业（1/2/3） |
| purchase_order_no | 是 | 采购单号 |
| order_items | 是 | 明细列表 |

## 六、边界情况处理

### 6.1 正常流程

```
创建计划 → 执行（推送无仓）→ 无仓回传订单 → 自动匹配 → 判断通过 → 生成子编码 → 返回无仓 → 三段订单生成 → IF03入库 → 金额达目标 → 关闭
```

### 6.2 异常流程

| 场景 | 处理 |
|------|------|
| 无仓推送时无匹配计划 | 返回 no_match + 原因说明 |
| 匹配到计划但判断拒绝 | 跨计划重试，全部拒绝则记录全部日志 |
| 接口调用超时（10s） | 按失败处理，触发重试（最多 3 次） |
| 🔄 二期：定时任务重复推送 | 仅推送"待执行"计划，已执行的自动跳过 |
| 唯一性校验不通过 | 提示已有相同条件的计划编码和状态 |
| 订单取消 | IF04 回传 → 扣减金额 → 重新计算完成率 → 必要时回退计划状态（已完成→执行中） |
| 退货/退款 | 二期处理：扩展 IF04 或新增接口 → 扣减金额 → 回退 |

### 6.3 二期预留

- IF04 订单取消（已实现）：扣减金额、重新计算完成率、已完成→执行中回退
- 退货/退款反向流程（二期）：扩展 IF04 或新增接口
- 金额冲销日志
- 已关闭计划因退货回退为执行中

## 七、全局约束

- 品牌、品类必须从字典中选择
- 状态枚举值按业务流程顺序编排（1/2/3），异常用 99
- 日期格式统一 YYYY-MM-DD
- 金额保留两位小数，以元为单位
- 列表页默认 20 条/页，支持 10/50/100 切换
- 搜索条件页面刷新后重置
- 0 表示"不限制"（订单要求字段）

- 差价：类型下拉切换，联动显示/隐藏比例或金额输入框
- 采购层级：切换时联动显示/隐藏企业3、差价2、账期2
- 日志详情：点击"查看详情"展开三栏布局的规则判断明细
- 空数据：表格无数据时显示「暂无数据」
- 状态标签：颜色区分（待执行-橙、执行中-蓝、已完成-绿、已关闭-灰）
