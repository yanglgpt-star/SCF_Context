# 产品需求文档规范（PRD）

本规范分两层：
1. **通用PRD框架**（适用于所有产品需求文档）
2. **后端/供应链金融 专项规范**（适用于供应链金融、后端系统类需求）

---

## 一、文档基础规范

### 1.1 版本管理
- 版本记录核心字段：版本号、作者、操作、日期、说明，以表格呈现。
- 版本号格式：`V+数字.数字`（如 V1.0、V1.3）。初始版本 V1.0，功能优化升次版本号，重大重构升主版本号。

### 1.2 文档结构（标准章节框架）

```
一. 文档概述
  1.1 愿景及目标【必选】
  1.2 全局约束【选择】
  1.3 名词定义【推荐】
  1.4 参考资料【选择】

二. 业务概述
  2.1 业务蓝图【必选】
  2.2 业务需求
  2.3 方案概述

三. 系统用例需求
  3.1 功能用例
    3.1.x XXXX用例
  3.2 接口定义【选择】

四. 非功能性需求
  4.1 上线方案【推荐】
  4.2 兼容性要求【选择】
  4.3 性能要求【推荐】
  4.4 监控/埋点需求【选择】

五. 风险分析【选择】
```

章节层级：`1. 一级` → `1.1 二级` → `1.1.1 三级`，逻辑连贯，目录与正文一一对应并标注页码。

### 1.3 名词定义规范
- 单独设立"名词定义"章节，统一定义专业术语、自定义字段。
- 全文术语表述一致，同一概念不得混用多种叫法。

## 二、文档概述规范

### 2.1 愿景及目标【必选】
- 说明当前业务现状与痛点。
- 明确系统建设目标：销售端、库存端、商家端、履约端等各端能力。
- 涉众表格：列出涉众角色、期望与利益、优先级。

### 2.2 全局约束【选择】
针对整体功能页面的全局交互约束，示例内容：
- 页面字体、字号、间距统一规定（如微软雅黑，标题12号，正文10号）。
- 状态枚举值按业务流程顺序编排（1、2、3…），异常状态用 99、98 等。
- 文本框校验：通过则自动清空，不通过则报错并全选内容。
- Datalist 分页：支持 10/50/100/500 行，含上下翻页、滚动条、勾选/反选。
- 明细查看界面支持 ESC 键退出；PC 界面切换保留搜索条件；PDA 点击返回至上一页面。
- 搜索/重置按钮位置规则：一行条件放最右，两行以上固定在第二列最后。

### 2.3 参考资料【选择】
- 文档资料以附件插入；关联需求标注需求 ID 和链接；竞品提供访问信息或截图。
- 建议借鉴成熟产品，杜绝闭门造车。

---

## 三、业务概述规范

### 3.1 业务蓝图【必选】
梳理流程后需判断：
1. 涉及信息流动吗（物流能变成信息流吗）？
2. 业务逻辑能封装进系统吗？
3. 涉及哪些业务对象？需要系统管理吗？

流程图选型：
- **跨部门业务**：使用泳道图或业务序列图。
- **单角色简单业务**：使用活动图（选择）。
- 序列图需标注参与角色，按时间顺序呈现交互步骤，体现接口调用、数据写入、状态变更等核心节点。

### 3.2 业务需求
通过流程图梳理改进项，从业务角度说明系统具备的能力。

表格格式：

| 编号 | 需求领域 | 需求项 | 涉及系统 | 重要级 |
|------|---------|--------|---------|--------|

### 3.3 方案概述
- **UML时序图**【必选】：梳理上下游交互和内部逻辑，作为系统设计依据。
- **产品结构图**【选择】：适用于功能复杂的系统（思维导图或产品蓝图）。
- **系统用例图**【必选】：或脑图方式，描述本文档涉及的需求点/功能列表，建议与功能用例目录对应。

系统用例表格：

| 用例编号 | 系统用例名称 | 需求类型 | 简述 |
|---------|------------|---------|------|

## 四、系统用例需求规范

### 4.1 用例规约核心字段

| 字段 | 说明 |
|------|------|
| 用例名称 | 简洁命名 |
| 用例编号 | 唯一标识 |
| 用例简述 | 一句话概述用例作用 |
| 用例图（选择） | 状态机变化或简要流转图 |
| 主执行者 | 操作人员/定时任务等 |
| 辅助执行者 | 应用层等 |
| 涉众利益 | 涉及人员 |
| 前置条件 | 用例执行的必要前提 |
| 事件流–主要路径 | 正常流程的步骤描述 |
| 替代流程 | 异常/例外流程 |
| 页面交互图 | 菜单路径 + 界面原型 + 查询条件表 |
| 后置条件 | 用例执行后的主要结果 |
| 字段列表 | 过程操作涉及的实体和字段 |
| 业务规则 | 流程约束与合规性补充 |
| 补充说明 | 研发/测试需关注但未编写在用例中的内容 |
| 遗留问题 | 待确认的不明确问题 |

### 4.2 事件流描述规范
- 按步骤顺序描述，明确每步的后端处理逻辑（数据校验、接口调用、表写入/更新）。
- 格式：`步骤号、角色+操作；系统响应；`
- 替代流程标注触发条件，编号用 `2.1、2.1.1` 等子编号形式。

### 4.3 状态机设计规范
- 明确核心业务对象的状态类型（初始、处理中、已完成、已取消）及触发条件。
- 状态机可用表格或 UML 图表示。
- 明确状态流转限制（如"已关闭状态不可再次收货"），禁止非法状态切换。

### 4.4 页面交互图规范
- 注明菜单路径。
- 提供界面原型（线框图亦可，或上传 Axure/蓝湖链接）。
- 查询条件表格：

| 序号 | 查询条件 | 是否必须 | 模糊查询 | 备注 |
|------|---------|---------|---------|------|

### 4.5 接口定义规范【选择】
可并入用例规约，也可单列。每个接口需包含：
- **接口名称**、**接口描述**（功能用途、调用方、被调用方）。
- **请求参数**：字段名称、字段描述、示例、逻辑验证规则（必填/非必填）。
- **返回参数**：字段名称、字段描述、示例、备注。
- **响应要求**。

## 五、非功能性需求规范

### 5.1 上线方案【推荐】
- 是否需要初始化数据；历史数据是否需特殊处理。
- 涉及报表取值逻辑变更，需通知数据团队。
- 涉及多版本兼容/灰度切换，单独说明。

### 5.2 兼容性要求【选择】
- 硬件兼容：手持设备分辨率要求。
- 机型兼容：适配机型范围。

### 5.3 性能要求【推荐】
描述速度、容量、能力，示例：
- 搜索响应时间 ≤ 1s。
- 支持 1000 个用户同时使用，10w 单时 CPU 占用率 < 50%。
- 系统在 2 分钟内完成导出 1w 条记录。

### 5.4 监控/埋点需求【选择】
- 埋点区分前台（用户行为）和后台；控制埋点生命周期。
- 监控主路径错误，订单处理失败需日志报警。

## 六、风险分析【选择】

| 风险 | 可能性 | 严重性 | 应对策略 | 可应对性 |
|------|-------|-------|---------|---------|

说明风险产生原因、可能危害、出现频率，以及预防和应对措施。不包含系统技术实现层面风险。

## 七、后端/供应链金融 专项规范

> 适用于供应链金融、后端服务类需求文档，与前述通用框架配合使用。

### 7.1 业务用例设计（后端视角）
- 用例分类原则：按业务场景（准入进件、额度管理、融资申请、还款申请、监控管理）和操作对象（供应商、核心企业、平台方、仓储方）分类，避免交叉或遗漏。
- 序列图明确参与角色（如供应商、采购商、监管方、资金方），体现接口调用、数据写入、状态变更等节点，标注各步骤责任方。

### 7.2 业务规则规范
- 按功能模块（采购、销售、监控等）分类管理。
- 规则表述使用"必须""禁止""允许""自动"等明确词汇。
- 全局规则在文档概述集中说明，局部规则在对应用例规约中补充。

### 7.3 数据设计规范
- **表结构**：明确核心表关联关系（主键、外键逻辑）。
- **字段设计**：语义化命名（如 `receipt_status` 表示收货单状态），明确类型、长度、是否必填、默认值。
- **特殊字段**：枚举字段（如 `receipt_type`）、关联字段（如 `source_no`）需标注取值范围或关联表。

**数据校验规则**：
- 商品校验：多码校验先查商品中心条码，以 `sku_code` 作为统一出参；非标品按单位和数量区间校验。
- 数量校验：非称重商品不允许录入小数点；称重商品小数最多四位。
- 生产日期不可大于当前日期，效期超期触发拒收逻辑。
- 字段校验反馈：通过则清空文本框，不通过则报错并全选内容。

### 7.4 接口设计规范（后端）
- 所有订单下传和回传接口按"地点+商家"到 `mst_company_warehouse` 映射仓库和货主。
- 接口调用失败需返回明确错误码和错误信息。
- 单据落地后调用主数据接口补全商品信息；接口触发的状态变更需同步至关联表。

### 7.5 异常处理规范
- 明确异常类型（数量超范围、商品不存在、储位未维护、接口调用失败）及对应处理逻辑。
- 异常日志记录：订单号、商品编码、错误原因、发生时间、操作人。

### 7.6 分阶段实现规范
- 明确一期/二期功能边界，标注当前实现范围和后续迭代计划。
- 一期未实现的功能需提供过渡处理方式，确保业务连续性。

### 7.7 多端适配规范
- PC 端与 PDA 端业务逻辑、数据校验规则、状态流转保持一致。
- PDA 端特殊适配：扫描提示音区分成功/失败、ESC 键退出弹窗、界面滚动条和冻结窗口配置。

## 八、文档维护规范

### 8.1 遗留问题管理
- 每个遗留问题需说明：问题描述、影响范围、待确认方。
- 按模块分类记录，明确解决优先级和计划时间，迭代时同步更新状态（已解决/待讨论/延期）。

### 8.2 文档更新规范
- 触发条件：功能优化、业务规则变更、接口调整、问题修复后及时更新。
- 更新审核：修改后需经审批人确认，同步至版本记录章节。
